## Abstract

- Propose `SELECTION |> atDepth(DISTANCE)` to retain exactly the steps at
  `DISTANCE`, using the shortest-path distances already defined for `depth`.
- Keep the selected steps' order, fields, distances and observations. A later
  walk still measures from its own input, and accepted `depth`, state, path
  and hypothetical-difference stages retain their behavior.
- Reuse `depth`'s limit validation, undefined deferral, argument evaluation,
  shadowing and transaction contract. Recognize only the contextual pipeline
  call; ordinary identifiers and calls named `atDepth` remain ordinary.
- This continuous Reasoning enhancement requires pre-executed accepted-syntax
  counterparts, independent per-case lexer-token comparison and every hard
  build, test and backward-compatibility criterion.
- The isolated prototype reuses the accepted ranked selection and bounded
  walks. The required caller-owned Rust improvement pass completed with
  justified no change; the rejected implementation remains isolated.
- **Rejected:** the full test suite fails the existing
  `property_selectors::the_appended_cases_use_selectors_and_run_every_assertion`
  expectation at `tests/property_selectors.rs:888:9`. The new selector-bearing
  case is outside that test's accepted title whitelist. Passing the core
  evaluator and token policy does not satisfy the every-test-passes criterion.

## Motivation

- A graph query can ask for one layer rather than every step up to a radius:
  direct supports, direct consequences or the next layer of an explanation.
- Accepted `depth(n)` includes nearer steps. Expressing one exact layer with
  accepted stages requires removing the selection at `depth(n - 1)`, with a
  separate zero-distance branch.
- Name that graph selection directly without changing traversal, provenance,
  numeric coercion, model membership or any accepted source form.
- The caller's one uniform draw selected Reasoning enhancement, index 3 of
  the five live eligible categories, with probability `1/5` and no redraw.
  Graph-layer selection is the proposal's primary purpose.

## Rationale

- Exact equality selects a layer; `depth` remains the inclusive radius.
  Reuse its shortest distances rather than traversal discovery order, so a
  shortcut into a node keeps that node in its nearer layer.
- Preserve the typed `Ranked` selection, its parallel distance vector and
  last walking direction. Equality uses the existing retaining helper;
  neither a new provenance graph nor an extra output field is needed.
- Use a separate argument-bearing AST variant rather than changing the
  fields of accepted `Expr::Depth` or extending argument-free `Stage`.
  Existing calls named `atDepth` do not become stages.
- Keep `depth`'s evaluation, observations, strict validation, snapshots,
  deferral and shadowing. A new numeric conversion, coercing helper or
  special case for distance zero would give the two stages different rules.
- This is a Reasoning enhancement because it selects a graph-query layer,
  not a cross-language alias or a new runtime-category feature. The caller's
  confirmed draw and continuous mode remain unchanged.

## Specification

This is the rejected prototype's proposed contract, not accepted behavior.
Its specification, grammar, reference, datasets and exports remain isolated.

- Retain exactly the steps at `DISTANCE`, with their order and `node`,
  `holds`, `rule`, `state` and `from` unchanged. The distance is the shortest
  path from the latest walk's input, not the first-discovered path.
- `why` includes its inputs at 0. `affects` uses nonempty paths, including
  paths between multiple inputs, so its zero layer is empty. Unwalked
  references and unwalked model members are at 0.
- State, radius, exact-layer, path and hypothetical-difference filters
  preserve distances and direction. A later walking stage resets both from
  its own input. All source value and structural observations survive,
  including observations of excluded steps.
- Evaluate the source first, then evaluate the distance once at its stage,
  retaining its effects and dependencies. Reuse `depth`'s non-negative
  integer number validation, including negative zero and saturating
  conversion for large finite integers. A distance beyond every layer
  selects nothing.
- `null` or undefined makes the reasoning expression undefined, stored as
  `null` in declarations. Do not execute later stages or evaluate their
  arguments. Quantifiers, member reads and method reads defer as for `depth`.
- Check operation bindings before source selection, as for accepted
  argument-bearing stages. Local/parameter, state-variable, function and
  class bindings named `atDepth` shadow it. A binding added after a standing
  selection affects its next evaluation; a failed refresh rolls back its
  triggering statement.
- Recognize only the identifier `atDepth` immediately after `|>`, followed
  by a `(` token and one full expression ending in `)`. Whitespace is
  allowed; a logical newline between the name and `(` is not. Preserve the
  parser's existing nesting, chain and adjacent-statement boundaries.
- Add no runtime lexer keyword, prefix form or general-call lowering.
  Ordinary names, parameters, properties, functions, methods and calls keep
  their accepted meaning.
- Apply normal lexical scopes and class bindings, reasoning-observer
  detection, dependency/observation tracking, `.value` capture, hypothetical
  execution and rollback. A `.value` in the distance freezes when its
  declaration is stored.
- Render `SOURCE|>atDepth(DISTANCE)` canonically in declarations, conditions,
  rules and graph keys, rendering each operand once.

## Errors

- Invalid distances use `TypeError("<distance> is not a non-negative integer")`,
  naming the expression's path or canonical source. This includes negative
  numbers, fractions, NaN, infinities, booleans, strings, lists, objects,
  instances, classes, functions, dates and regular expressions; `null` and
  undefined defer rather than raise.
- `c |> why |> atDepth(-1)` raises
  `TypeError("-1 is not a non-negative integer")`.
- A bare or shadowed stage raises
  `TypeError("atDepth is not an operation")`; a bare stage is a parse-time
  error, while shadowing is checked before selecting the source.
- Invalid sources keep their errors before distance evaluation:
  `1 |> atDepth(missing)` raises `TypeError("Cannot explain 1")`, and
  `missing |> atDepth(-1)` raises `ReferenceError("missing is not defined")`.
- `|> atDepth()` raises `SyntaxError("Unexpected ')'")`;
  `|> atDepth(1, 2)` and `|> atDepth(1,)` raise
  `SyntaxError("Expected ')' but found ','")`. A missing closing parenthesis
  raises `SyntaxError("Expected ')' but found end of input")`.
- Runtime errors retain the running statement's position and rollback;
  outside the new contextual form, preserve every accepted diagnostic.

## Examples

The isolated prototype's proposed specification case:

```
seed = 2
left = seed + 1
right = left + 1
top = right + left
hop = 1
selected = top |> why |> atDepth(hop)
assert(selected.map(.node).sort(), ["left", "right"])
hop = 2
assert(selected.map(.node), ["seed"])
hop = 0
assert(selected.length, 1)
assert(selected[0].node, "top")
assert(selected[0].holds, 7)
assert(selected[0].from.sort(), ["left", "right"])
hop = 3
assert(selected, [])
```

- The candidate's `Nucleoid preserves impact layers across filters` reference
  case specifies filtered impact layers, reactive held values and null deferral.
- Its `Exact-depth selections keep a model's layers distinct` example specifies
  unwalked model layers 0 and 1.
- These are exactly the three pre-executed r3 counterparts: only the
  `selected` right-hand side changes in each. Statement identities, order,
  assertions and expected returns remain protected; no other executable
  document case is added or rewritten.
- None of these proposed executable-document additions is integrated.

## Backwards Compatibility

- The proposed new pipeline-call form previously failed at parse time with
  `TypeError("atDepth is not an operation")`. Accepted `depth`, prefix
  reasoning, filters, ordinary names and calls are protected.
- Independent Nucleoid-source replay passed for the pinned accepted sources
  and original r3 counterparts, with their assertions, explicit returns and
  coverage preserved. This finite evidence is not a proof over all programs.
- Existing public items, signatures and old AST-variant fields remain in the
  prototype, but adding public `Expr::AtDepthSelection { source, limit }`
  breaks downstream exhaustive `Expr` matches. The evaluator demonstrated
  rustc `E0004` against a match covering all 33 accepted variants; adding the
  new arm compiles. Passing Nucleoid-source replay does not negate this Rust
  source-compatibility and human-owned release-review implication.
- No version, dependency or rejected public-API change is integrated.
