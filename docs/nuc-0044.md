# NUC 44 -- Comma-Free Explicit Object Properties

```
NUC: 44
Title: Comma-Free Explicit Object Properties
Author: Can Mingir <canmingir@gmail.com>
Status: Accepted
Type: Standards Track
Category: Syntax enhancement
Created: 16-Oct-2026
```

## Abstract

- Optionally omit an object-property comma when a fully parsed ordinary
  explicit value leaves an existing string, identifier or numeric key
  immediately followed by a colon.
- Preserve the complete existing ordered object AST and runtime semantics.
  Comma-bearing forms remain supported; canonical records still quote keys
  and separate fields with commas.
- The accepted [specification contract](../nucleoid.spec.md#comma-free-explicit-object-properties)
  and five appended entries define this implementation.

## Motivation

- Record construction is central to structured data, reactive models and
  projections; explicit colons already distinguish many property boundaries.
- Recent NUCs broadened collections, text and control flow. This bounded
  syntax change broadens data construction rather than adding another
  numerical helper or function-header variant.
- Existing dependencies, scopes, receivers, aliases, snapshots and
  transactional failures already provide the required behavior.

## Rationale

- Honor the caller's single sealed syntax-improvement draw without redrawing.
  Selection considered reasoning, dependencies, functions/scope, control flow,
  collections/text, modeling and diagnostics, with no math ban or rotation.
- Recognize only an unconsumed existing key/colon pair after the original
  value parser succeeds. Complete expression priority is more important than
  maximizing comma omission.
- Keep comma priority and the original identifier-shorthand qualification.
  Do not speculatively parse, stop a value early, rewind, catch parser errors,
  reinterpret a value or introduce new layout or key grammar.
- Reject universal comma removal, newline-separated arbitrary list values,
  pipeline redesign and unrelated runtime changes from this revision.
- Preserve all 587 historical measured programs and all 25 earlier canonical
  training files; only eight pre-executed V3 counterpart programs are appended.
- Retain computed-string write, caught-error representation, queued receiver
  and column-1 multiline exporter limitations instead of repairing them.

## Specification

- Change only the expression parser's private `object_literal` separator
  decision, after the existing key, colon, whole value and ordered-entry push.
- Parse each explicit value with the original full ordinary expression parser
  before considering a next field. Existing operator, postfix, assignment,
  function, arrow, call and nested-object priorities win.
- Apply the original newline/semicolon skipping and try the original comma
  first. When a comma is present, take exactly the existing loop path.
- Without a comma, after the original skipping, inspect exactly two
  unconsumed tokens. Continue the loop only for
  `(Str | Identifier | Number) Colon`; consume neither token in this guard.
  Otherwise retain the original `expect(RightBrace)` path and diagnostics.
- Reuse the original string/identifier/number key parser, numeric formatting,
  colon expectation and full ordinary value parser. No keyword, template,
  computed, dotted, class-reference or negative-number key is added.
- An identifier shorthand still requires a following comma or right brace
  through only the original newline/semicolon layout. Commas around shorthand
  remain wherever that rule needs them; explicit and comma-bearing forms
  may mix and retain optional trailing commas.
- Do not skip layout between a prospective key and colon. The lexer keeps
  its existing delimiter-dependent layout; no new indentation inside bare
  braces or colon continuation is introduced.
- Keep ordered entries and all duplicate-key evaluations before replacement.
  Canonical AST rendering remains quoted and comma-separated, preserving graph
  keys and reasoning source. No public AST, token, lexer or Rust API changes.
- Actual reads determine reactive dependencies. Preserve alias identities,
  local and parameter scopes, class receivers, noncapture, live functions,
  `.value` snapshots, transactions, whole caught errors and rollback.
- Keep existing nesting, operator-chain, postfix, propagation and execution
  limits. The guard neither bypasses expression checks nor adds a field cap.
- Lists, calls, parameters, statement-leading blocks, anonymous braced arrow
  bodies, the CLI and the statement exporter retain their original grammar.
  Parenthesized object expressions and named-arrow object returns still use
  the existing object-expression path.
- Trace live explicit fields to `Nucleoid constructs comma-free explicit records`.
  Trace keys and replacement to
  `Nucleoid preserves comma-free record keys and replacement order`.
  Trace nested objects and retained list/call commas to
  `Nucleoid nests comma-free records without changing list or call separators`.
- Trace parameter scope and frozen reads to
  `Nucleoid preserves scope and snapshots in comma-free records`.
  Trace an actually evaluated missing value, whole caught error, state rollback
  and recovered dependencies to `Nucleoid rolls back failed comma-free record values`.
- These five spec entries retain 28 assertions and explicit returns `"F"`
  and `"old"`. The appended routing reference, sensor README and independent
  class-rule examples retain 12 additional assertions.

```
amount = 4
unit = "C"
reading = {amount: amount unit: unit active: true}
assert(reading.amount, 4)
assert(reading.unit, "C")
assert(reading.active, true)
amount = 9
assert(reading.amount, 9)
unit = "F"
assert(reading.unit, "F")
reading.unit
```

## Errors

- No new error kind or runtime message is introduced. Existing errors are
  propagated by the ordinary key, value and closing-brace paths.
- Exact `record = { amount other }` keeps
  `SyntaxError("Expected ':' but found identifier 'other'")` at line 1, column 19.
  Exact `record = { amount: 1 next }` keeps
  `SyntaxError("Expected '}' but found identifier 'next'")` at line 1, column 22.
- Exact `record = { amount\n: amount }` keeps
  `SyntaxError("Expected ':' but found end of line")` at line 1, column 12.
  Exact `record = { amount:\namount }` keeps
  `SyntaxError("Unexpected end of line")` at line 2, column 1.
- Exact `record = {\n    amount: amount,\n}` keeps
  `SyntaxError("Expected a key but found an indented block")` at line 2, column 5.
  Exact `record = { amount: }` keeps
  `SyntaxError("Unexpected '}'")` at line 1, column 21.
- Exact `record = { amount: 1,, next: 2 }` keeps
  `SyntaxError("Expected a key but found ','")` at line 1, column 24.
  A recognized next explicit field still needs its ordinary value.
- Full expression priority is observable: exact
  `record = { amount: 1 [next]: 2 }` keeps
  `SyntaxError("Expected '}' but found ':'")` at line 1, column 28;
  `record = { amount: 1 -2: 2 }` keeps the same message at line 1, column 24.
- The missing read in the rollback spec entry retains
  `ReferenceError("missing is not defined")`; compare the whole caught error
  against `ReferenceError(...)`, not its unsupported `message` property.
- The inherited computed-string write retains
  `SyntaxError("Cannot assign to record[\"1\"]")`. The V1 preparation program
  observed it at line 10, column 1 after four assertions; no baseline or
  candidate existed then. The V3 spec entry uses supported `record.state`.
- `value` remains the reserved snapshot API. The inherited queued-method
  receiver failure still raises `ReferenceError("this is not defined")`;
  no new receiver-property propagation is claimed.
- Existing `SyntaxError("Expressions are nested too deeply")`,
  `SyntaxError("Expression has too many operands")` and
  `SyntaxError("Expression has too many parts")` remain unchanged.
  Physical columns may differ only where source commas were omitted.

## Reference Implementation

- The accepted implementation adds only a non-consuming two-token continuation guard in
  `src/lang/ast/parser.rs::object_literal`; key, shorthand, value, comma and
  closing-brace parsing remain shared with the accepted path.
- `tests/comma_free_object_properties.rs` embeds the eight exact V3 accepted
  controls, checks their full ordered ASTs and canonical source against the
  new forms, and checks assertions, returns and executed coverage in both.
- Focused regressions cover keys, mixed separators, inherited layout,
  shorthand exclusions, expression precedence, exact errors, duplicate
  evaluation, aliases, dependencies, snapshots, scope/receivers, rollback,
  native input, generated exports and resource/progress limits.
- Append only the eight paired programs and delete their 24 designated
  explicit-property commas. This source-rewrite boundary did not replace
  the independent lexer measurements or per-case acceptance gate.
- Add four self-contained canonical monitoring, shipment, keyed-state and
  class-record training cases in `dataset/nucleoid.synth.25.jsonl`.
  Keep the 24 earlier synthesized shards and ARC raw-exact.
- Regenerate `dataset/nucleoid.spec.jsonl` from the root specification and
  `tests/nucleoid.spec.rs` from that export using the sanctioned flags.
  Do not change the exporter or hand-edit either generated file.
- Keep all existing regression sources unchanged except the explicitly
  required dataset counts and the two formerly invalid rows in
  `tests/object_shorthand.rs`: `record = { amount: 1 label: 2 }` and
  `record = { amount: 1; label: 2 }`. Migrate only those rows into active
  positive regressions against accepted comma-bearing controls, checking
  full ordered AST/canonical equivalence, both field values, expected returns
  and executed assertions. Keep the malformed-input function and every
  other source, error kind, message and position unchanged.
- No runtime, canonical generator, CLI, exporter, manifest, lock, dependency,
  version, edition or MSRV change is part of this revision.
- Independent evaluation accepted the frozen R2 Draft blob
  `dbe7025636d70e6c6e931ba3d36ecbf2c2b63634` against accepted revision
  `7d12357d7243476f073b573c474a2bc1e85d9a14`, after the required Rust pass
  returned `NO_CHANGE`. The frozen R1 remains unevaluated, not rejected.
- All 595 paired cases passed: eight use fewer lexer tokens, 587 are
  unchanged, and none increased. Total tokens changed from 57,059 to 57,035.
  No increase was offset by another case's savings.
- All 2,706 protected assertions executed and all 46 explicit expected returns
  matched. Accepted-syntax compatibility, complete ordered ASTs, canonical
  forms, top-level positions, generated exports and training checks passed.
  No measured case, assertion, return or executed coverage was weakened.
- The independent ordinary suite passed 1,279 checks, including one doctest;
  14 tests remained intentionally ignored, and six authorized ignored audits
  passed separately. Formatting and warning-denied Clippy passed.
- Native evidence captured 64 candidate CLI launches and 32 pinned accepted
  controls. Own and inherited PATHs were empty; 16 actual Win32 creation
  probes returned error 2 before and after the native phases.
  Embedded test grandchildren were covered by compiled assertions, not
  individually OS-traced or counted among those 96 captures.
- Computed-key writes, caught-error members, reserved `value`, queued receiver
  behavior and column-1 multiline exporter limits remain inherited.
  Status/index updates record the result without changing the evaluated
  implementation. Immutable baselines, full per-case reports and both frozen
  handoffs remain in the session workspace.
