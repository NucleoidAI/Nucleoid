# NUC 26 -- Logical Compound Assignment

```
NUC: 26
Title: Logical Compound Assignment
Author: Copilot <223556219+Copilot@users.noreply.github.com>
Status: Accepted
Type: Standards Track
Category: Syntax enhancement
Created: 15-Oct-2026
Requires: 13
```

## Abstract

- Add optional `&&=` and `||=` spellings of existing logical assignments.
- Lower `target &&= rhs` exactly to `target = target && (rhs)` and
  `target ||= rhs` exactly to `target = target || (rhs)`.
- Reuse typed logical and assignment AST nodes, bounded plain-path targets,
  existing runtime behavior, and expanded canonical rendering.
- This syntax improvement passed independent per-case evaluation with no token
  increase, behavior failure, or accepted-syntax compatibility regression.

## Motivation

- Expanded logical assignments repeat names and dotted property paths.
- Compact spelling should preserve operand-valued short-circuiting without
  replacing a declarative relationship with a conditional write.
- Reactive fallbacks, required conditions, local parameters, and method
  receivers benefit from the same optional syntax.
- Token acceptance belongs to the independent per-case evaluator, not to
  estimates or aggregate savings during preparation.

## Rationale

- Existing `Expr::Logical`, `Expr::Assign`, and `Stmt::Assign` already express
  the exact behavior; no new AST or runtime node kind is needed.
- The whole right operand is grouped, so `a &&= b || c` is
  `a = a && (b || c)`, not `(a = a && b) || c`.
- Sharing NUC 13's validation preserves its resource bounds and rejects
  computed receivers before target cloning.
- A standing assignment is always installed, including when logical evaluation
  skips its right operand. JavaScript-style conditional writes are rejected.
- `=`, `&&`, `||`, `and`, `or`, and all five accepted arithmetic compounds remain
  available with their previous parsing and behavior.
- Word compound aliases, nullish coalescing, computed compound targets,
  single-evaluation temporaries, new mutation modes, and runtime changes are
  outside this proposal.
- Dependencies are already accepted; no pending NUC is required or combined.
- Adding variants to the public exhaustive Rust `Token` enum is source-breaking
  for downstream exhaustive matches. A human-owned API semantic-versioning
  decision is necessary before release; this revision changes no project
  version, lockfile, dependency, or minimum-Rust metadata.

## Specification

### Tokens and lowering

- Recognize each adjacent three-character operator as one lexer token.

| Form | Exact expansion | Existing logical operator |
| --- | --- | --- |
| `target &&= rhs` | `target = target && (rhs)` | `LogicalOp::And` |
| `target ||= rhs` | `target = target || (rhs)` | `LogicalOp::Or` |

- Parse the full right operand with the existing assignment-expression grammar,
  below pipelines, logical operators, comparisons, and arithmetic.
- Keep assignment precedence and right associativity, including mixed
  compounds: `a ||= b &&= 9` lowers to `a = a || (b = b && 9)`.
- Convert a top-level assignment expression to the existing `Stmt::Assign`;
  nested assignments remain `Expr::Assign`.
- Build an existing `Expr::Logical` as the assignment value, move its right
  operand, and clone only its validated bounded target once.
- Canonical source and graph keys use the expanded AST, never the compound
  token; no renderer or runtime change is introduced.
- The opening compound-assignment contract in `nucleoid.spec.md` is normative.
- `Nucleoid keeps logical compound assignments equivalent` covers both
  operators, operand values, and full-right-operand grouping.

```
value = 0
value ||= 7
assert(value, 7)
value &&= 9
assert(value, 9)
```

### Targets and resource bounds

- Reuse NUC 13's plain-path restriction for both new operators.
- Accept a name or dotted path rooted in a name, `$Class`, `this`, or `self`;
  a class or receiver root requires at least one property.
- Parentheses may group a qualifying path without changing its AST.
- Reject a computed target before cloning, including a call, index, slice,
  assignment, function, or operator expression in its receiver chain.
- Validate receiver links iteratively and allow at most 128 dotted links in
  the entire target, including links across parenthesized groups.
- Keep the existing shared 64-level expression/statement nesting budget and
  existing per-chain bounds; right-associative compounds consume that budget.
- Keep every previously accepted ordinary `=` target unchanged, including
  computed property receivers.
- The normative opening target/resource contract is tested by
  `compound_assignments_reject_non_path_targets_before_cloning`,
  `compound_target_limits_include_parenthesized_member_chains`,
  `compound_assignment_chains_respect_existing_resource_limits`,
  `nested_compound_targets_cannot_expand_exponentially`, and
  `malformed_compound_targets_do_not_change_state`.

### Relationships, short-circuiting, and snapshots

- A standing assignment always records the expanded relationship and replaces
  the previous one, even if the logical operator returns its left operand.
- Only the logical evaluation skips its right operand; the assignment itself
  is not conditional on target truthiness.
- Logical evaluation returns existing operand values, not coerced Booleans.
- Preserve the existing distinction between standing declarations and local
  assignment statements or assignment expressions.
- Self-references to variables and instance properties read current values;
  other evaluated right-hand reads remain dependencies.
- Re-evaluation uses that current value exactly as the expanded assignment
  does; a prior successful fallback need not become false again.
- Preserve existing null/deferred assignment handling rather than importing
  another language's truthiness or null-assignment rules.
- Preserve `.value` snapshot freezing before declaration evaluation, including
  a snapshot read in an otherwise skipped logical operand.
- Class-level self-reference retains `TypeError("Circular Dependency")`,
  including when the logical right operand would be skipped.
- `Nucleoid keeps logical compound assignments reactive` covers both reactive
  operators, current-value re-evaluation, and snapshots.
- `Nucleoid short circuits logical compound operands` covers skipped throwing
  calls and returned operand values.
- The inherited assignment contract and focused runtime regressions additionally
  cover replacement of old relationships, null/deferred handling, snapshot
  errors, and class cycles without adding unpaired measured cases.

```
enabled = false
fallback = false
enabled ||= fallback
assert(enabled, false)
fallback = true
assert(enabled, true)
fallback = false
assert(enabled, true)
```

### Scope, expression returns, and rollback

- Names, dotted properties, local parameters, and `this`/`self` use the existing
  assignment dispatch with no additional receiver evaluation mode.
- Assignment expressions return their assigned value and preserve nested
  short-circuiting and right associativity.
- `Nucleoid preserves logical compound property and local assignments` covers
  both receiver spellings, local assignment expressions, nested returns, and
  an explicit expected final return of `9`.
- Failed assignments and triggered standing-rule failures retain existing
  transaction rollback, prior dependencies, and propagation-queue behavior.
- `Nucleoid rolls back failed logical compound assignments` covers failures
  from both operators and restores each prior target value.
- The opening normative assignment contract and focused runtime tests cover
  unchanged graph keys, dependencies, class cycles, and recovery.

### Syntax compatibility

- Preserve `target = target && (rhs)`, `target = target || (rhs)`,
  `target = target and (rhs)`, and `target = target or (rhs)`.
- Preserve accepted `+=`, `-=`, `*=`, `/=`, and `%=` syntax, precedence,
  associativity, validation, and lowering.
- Longest matching does not consume adjacent unary signs or reinterpret
  existing equality, inequality, comparison, or `=>` tokens.
- `&& =` and `|| =` are not compound tokens; `and=` and `or=` are not aliases.
- A slash in an operand position, including after either logical compound,
  keeps the existing regex lookahead for `/=/`, escapes, classes, and flags.
- Regex contents containing compound characters remain regex contents.
- A slash following an operand still denotes division or division assignment.
- Diagnostics describe the new tokens exactly as `'&&='` and `'||='`.
- Unchanged accepted source programs and supplied extra-baseline counterparts
  must execute under the candidate alongside the compact document forms,
  preserving ordered canonical assertions, expected returns, and actual
  executed assertion coverage.

## Errors

- Introduce no new runtime error type; lower to the existing assignment and
  logical-expression error paths.
- Invalid compound targets fail during parsing and cannot be caught by the
  language's `try`; runtime assignment and operand failures remain catchable.

| Condition | Exact error | Trace |
| --- | --- | --- |
| Non-path compound target | `SyntaxError("Invalid compound assignment target")` | Normative target contract; parser target tests; `malformed_compound_targets_do_not_change_state` |
| More than 128 target links, including grouped paths | `SyntaxError("Expression has too many parts")` | Normative resource contract; `compound_target_limits_include_parenthesized_member_chains` |
| Excessive expression nesting or compound chaining | `SyntaxError("Expressions are nested too deeply")` | Normative nesting contract; `compound_assignment_chains_respect_existing_resource_limits` |
| Excessive operator operands | `SyntaxError("Expression has too many operands")` | Existing chain bounds; robustness regressions |
| Missing right operand at end of input | `SyntaxError("Unexpected end of input")` | `compound_assignment_diagnostics_name_exact_tokens_and_targets` |
| Missing right operand at end of line | `SyntaxError("Unexpected end of line")` | Same diagnostic regression |
| Parenthesized right operand ending after a binary operator | `SyntaxError("Unexpected ')'")` | Same diagnostic regression |
| Logical compound token in operand position | `SyntaxError("Unexpected '&&='")`, `SyntaxError("Unexpected '||='")` | Same diagnostic regression |
| Separated symbolic operator or unsupported word compound | `SyntaxError("Unexpected '='")` | `separated_logical_assignments_and_word_compounds_are_not_added` |
| Undefined target or evaluated operand named `missing` | `ReferenceError("missing is not defined")` | Existing assignment contract; logical runtime diagnostic regression |
| `this`/`self` used without an instance | `ReferenceError("this is not defined")` | Existing receiver contract; logical runtime diagnostic regression |
| Reserved `value` property assigned | `TypeError("Cannot use 'value' as a property")` | Existing assignment dispatch; logical runtime diagnostic regression |
| Property `reading` assigned on a number | `TypeError("Cannot assign 'reading' on number")` | Existing assignment dispatch; logical runtime diagnostic regression |
| Class-level self-reference closes a dependency cycle | `TypeError("Circular Dependency")` | Normative assignment contract; class-cycle and diagnostic regressions |
| An evaluated operand or standing rule throws | The original thrown value, including `"UNREACHABLE"`, `"BLOCKED"`, or `"REQUIRED"` | Short-circuit and rollback spec cases; ordinary runtime regressions |

- Undefined paths retain the existing `ReferenceError("<name-or-path> is not defined")`
  format; snapshot freezing may raise that error even when logical evaluation
  would skip the snapshot operand.
- Other malformed operands retain the existing `Unexpected <token description>`
  and `Expected <token description> but found <token description>` diagnostics.
- Existing runtime/resource errors remain unchanged, including
  `SyntaxError("Statements are nested too deeply")`,
  `TypeError("Maximum expression depth exceeded")`,
  `TypeError("Maximum statement depth exceeded")`, and
  `TypeError("Propagation did not settle")`.
- Error positions and caught position-free error values are unchanged.

## Reference Implementation

- `src/lang/ast/lexer.rs` adds private raw and public token variants for
  `&&=` and `||=`, descriptions, and longest matching.
- `src/lang/ast/parser.rs` uses one private typed compound-operator selection,
  the shared plain-target validator, and existing binary/logical lowering.
- Runtime evaluation, public AST types, canonical generation, and graph
  machinery are unchanged.
- Lexer/parser unit tests and `tests/diagnostics.rs`, `tests/robustness.rs`,
  and `tests/logical_compound_assignments.rs` cover exact lowering, legacy
  forms, resource limits, diagnostics, relationships, scopes, returns, graph
  identity, and rollback.
- Five appended spec cases, one reference case, and one snippet in each of
  `README.md` and `docs/examples.md` match the caller's eight pre-executed
  accepted-syntax baselines.
- Preparation is pinned to accepted Git revision
  `f38719e5ff4070e598efc50e950623e31dfe6228`; its immutable artifact contains
  451 executed cases, including those eight counterparts.
- Existing document case order, generated stable IDs, ordered canonical
  assertions, expected returns, and assertion coverage are preserved.
- Reference prose, the two new canonical synthesized logical-assignment
  records, and generated normative JSONL/Rust exports are synchronized.
- The inherited tracked conflict fragments in `tests/dataset.rs` are resolved
  to the JSONL-only harness; count protections are retained against the actual
  specification and synthesized splits without recreating Markdown datasets.
- Development and legacy-syntax checks do not constitute acceptance;
  `evaluate_proposal`, per-case token verdicts, final status, and integration
  belong to the independent evaluator and coordinating caller.
- The public enum additions require a human-owned API semver decision; package
  versions and release metadata remain untouched.
