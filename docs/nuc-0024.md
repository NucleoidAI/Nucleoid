## Abstract

- A named definition or method may optionally omit parentheses around one ordinary parameter identifier and its existing ordinary-identifier annotation before a real indented colon suite.
- `def double amount: int:` with that suite is exactly `def double(amount: int):` with the same suite.
- Preserve `Some(annotation)` parameter metadata and the complete named block AST; introduce no runtime type constraint, lookup, dependency, token, public AST or API.

## Motivation

- The parameter name, annotation colon, annotation name and suite colon already identify one typed input unambiguously.
- Remove redundant parameter delimiters without changing bodies, assertions, calls, argument binding or live relationships.
- Keep the accepted explicit form and all other accepted signatures available.

## Rationale

- Extend only accepted [NUC 19](nuc-0019.md) indented blocks and [NUC 20](nuc-0020.md) typed parameter metadata; combine no pending proposals.
- Reuse the existing single-parameter and suite parsers rather than introduce another grammar abstraction.
- Require real indentation, not merely a newline, to preserve mandatory-parenthesis diagnostics for unsupported prefixes.
- Look ahead without consuming tokens; skip no logical newline, semicolon or comment-induced logical break within the header.
- Keep NUC19's exact untyped guard separate so its suite colon can never become an annotation colon.
- Keep both existing immediate arrow guards unchanged.
- Retain parentheses for empty/multiple, defaulted/destructured/variadic, multiline bare signatures, inline/braced bare suites and calls.
- Keep annotations as stored ordinary identifiers, not a type system or variable-resolution operation.

## Specification

### Immediate grammar and lowering

- The authoritative [typed indented-block section](../nucleoid.spec.md#bare-typed-single-parameter-indented-block-definitions) defines the candidate behavior.
- Parse `def` and its required ordinary definition name exactly as before.
- Recognize only immediate `Identifier(parameter)`, `Colon`, `Identifier(annotation)`, `Colon` tokens after that name.
- The token immediately after the suite colon must be `Newline` or `Indent`.
- Looking past only `Newline` and `Semicolon` layout from that body start, the first other token must be `Indent`.
- The guard consumes no prefix, separator or body token.
- Use the existing `parameter()` for the typed prefix, preserving exactly `Parameter { name, type_name: Some(annotation) }`.
- Use the unchanged `suite()` and named `FunctionBody::Block`; body statements, positions and explicit returns retain their existing meaning.
- Blank/comment lines and normal semicolons after the initial body newline remain valid when a real indent follows.
- Header-line semicolons, logical header breaks, comments-only bodies, missing indentation and typed bare inline/braced suites do not qualify.
- Any nonqualifying prefix retains the existing mandatory-parenthesis fallback without consuming it.
- NUC19 untyped indented blocks still use `type_name: None`; their suite colon is not parsed as an annotation.
- Existing untyped `Identifier, Arrow` and typed `Identifier, Colon, Identifier, Arrow` guards remain immediate and unchanged, including their EOF body errors.
- Preserve all parenthesized typed/untyped, nullary/multiple, trailing-comma/multiline, indented/inline/braced signatures, class lists and anonymous forms.
- Add only one ordinary parameter name and one ordinary annotation name.
- Missing/dotted/union/generic/keyword/literal annotations, other parameter forms, return annotations, anonymous colon functions, omitted call parentheses and automatic identifier invocation are not added.

### Runtime and canonical equivalence

- An undeclared annotation such as `ArbitraryType` remains metadata, not a dependency or a name to resolve.
- Missing/null/extra/string arguments, local parameter shadowing and literal local offsets retain their accepted behavior.
- Blocks without `return` still yield `null`; an explicit bare `return` retains its meaning.
- Both explicit return paths retain their execution and live external dependencies.
- Named replacement, live callable references and `.value` definition snapshots are unchanged; a snapshot freezes the definition, not external body inputs.
- Methods retain the same `this`/`self` receiver, and `init` retains construction/adoption behavior.
- Parent construction and explicit or bare `super` retain their existing paths.
- Failed definitions preserve caught `ReferenceError` values, transaction rollback, dependency edges and subsequent recovery.
- Inherited parameter-dependent local and nested noncapturing failures remain paired, not repaired, captured or bypassed.
- Canonical generator and named graph identities are unchanged; public tokens, AST/Value/API, runtime, coercion, numeric operations, built-ins, class/call/scope/dependency logic and all bounds are unchanged.

## Errors

- Introduce no new error kind or message.
- Nonqualifying tokenizable headers retain the mandatory-parenthesis error before consumption; lexical errors still precede parsing.
- Exact diagnostic positions follow the actual source spelling, not a forced legacy header width.
- These errors follow the normative typed-block boundary section and unchanged runtime/bound rules.

| Input or condition | Exact error | Position |
| --- | --- | --- |
| `def f amount: int:` at EOF, missing-indent/comments-only body, header-line semicolon, typed inline/braced or multiple/default/return-annotation prefix | `SyntaxError("Expected '(' but found identifier 'amount'")` | line 1, column 7 |
| Missing/dotted/generic/keyword/literal annotation or logical break inside the parameter/colon/annotation/suite-colon prefix | `SyntaxError("Expected '(' but found identifier 'amount'")` | line 1, column 7 |
| `def f amount: int \| str:` | `SyntaxError("Unexpected character '\|'")` | line 1, column 19 |
| Logical newline immediately after `def f` | `SyntaxError("Expected '(' but found end of line")` | line 1, column 5 |
| Semicolon immediately after `def f` | `SyntaxError("Expected '(' but found ';'")` | line 1, column 6 |
| `def f:` with an indented body | `SyntaxError("Expected '(' but found ':'")` | line 1, column 6 |
| `class Gauge:` then indented `def reading amount: int, other:` | `SyntaxError("Expected '(' but found identifier 'amount'")` | line 2, column 17 |
| `def f(amount:):` | `SyntaxError("Expected a type but found ')'")` | line 1, column 15 |
| `def f(amount = 1): return amount` | `SyntaxError("Expected ')' but found '='")` | line 1, column 14 |
| `def f() -> int: return 1` | `SyntaxError("Expected ':' but found '-'")` | line 1, column 9 |
| Indented `return amount +)` after a qualifying header | `SyntaxError("Unexpected ')'")` | line 2, column 21 |
| Indented `return @` after a qualifying header | `SyntaxError("Unexpected character '@'")` | line 2, column 12 |
| Exact EOF after the retained `def f amount: int =>` arrow | `SyntaxError("Unexpected end of input")` | line 1, column 21 |
| Final newline after that retained arrow | `SyntaxError("Unexpected end of line")` | line 2, column 1 |
| Undefined body dependency `missing` | `ReferenceError("missing is not defined")` | top-level statement |
| Inherited parameter-dependent local/nested noncapturing failure | `ReferenceError("amount is not defined")` | top-level statement |
| `this`/`self` without an instance | `ReferenceError("this is not defined")` | top-level statement |
| Non-callable parameter shadows `operation` | `TypeError("operation is not a function")` | top-level statement |
| Excessive expression nesting | `SyntaxError("Expressions are nested too deeply")` | existing parser rules |
| Excessive operand chain | `SyntaxError("Expression has too many operands")` | existing parser rules |
| Excessive postfix chain | `SyntaxError("Expression has too many parts")` | existing parser rules |
| Excessive statement nesting | `SyntaxError("Statements are nested too deeply")` | existing parser rules |

- Existing parenthesized/class/anonymous diagnostics retain their actual messages and positions.
- Runtime errors retain top-level statement positions; caught error values omit positions.
