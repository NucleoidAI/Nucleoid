# NUC 12 -- Expression-Bodied Named Functions

```

Author: Copilot <223556219+Copilot@users.noreply.github.com>
Status: Accepted
Type: Standards Track
Created: 12-Oct-2026
```

## Abstract

- A named function or method may use `=> expression` instead of a block containing one `return expression`.
- The compact form has the same runtime semantics as that explicit return; existing block definitions remain valid.

## Motivation

- Single-return functions repeat a return keyword and block-layout tokens without adding behavior.
- Reuse the existing arrow token to reduce lexer tokens without introducing a keyword.
- Evaluate savings separately for every executable case; an increase rejects the proposal.

## Rationale

- Keep `def`, the name and the parameter list so declarations remain unambiguous.
- Keep existing parameter annotations and parsing.
- Lower the compact form to the existing named-function block and return representation, not the anonymous expression-body execution path.
- Keep canonical AST and dependency-graph rendering unchanged.
- Do not infer a return from an ordinary block's last expression; existing no-return functions still return `null`.
- Do not replace multi-statement functions or introduce arrow statement blocks.

## Specification

### Definition

- After a named function's parameter list, accept either the existing block suite or `=>` followed by an expression.
- Use the existing expression grammar and precedence, including assignment expressions and anonymous functions.
- The expression begins on the definition's logical line; existing parenthesized continuation permits physical line breaks.
- Braces in a named expression body denote an object literal, not a statement block.

```
def next(number: int) => number + 1
def twice(number: int) => next(number) * 2
```

- Each compact definition is equivalent to its explicit-return block.

```
def next(number: int):
    return number + 1

def twice(number: int):
    return next(number) * 2
```

### Runtime behavior

- The implicit return evaluates its expression exactly where an explicit return would.
- Argument binding, parameter annotations, reactive dependencies, redefinition, recursion and transaction rollback retain the behavior of the [main specification](../nucleoid.spec.md); this proposal does not depend on other pending proposals.
- Live callable references follow redefinitions; `.value` references keep their captured definition.
- Methods retain receiver binding; `this` and `self` remain equivalent.
- An `init` method uses the existing initializer path; construction still returns the instance, not the expression's value.
- Assignment expressions return the assigned value with the same effects as an explicit return of that assignment.
- A returned anonymous function keeps its existing execution and binding semantics.
- A block function without an explicit return still returns `null`.

```
class Gauge:
    def init(amount: int) => this.amount = amount
    def reading() => self.amount
    def set(amount: int) => this.amount = amount
```

### Compatibility and evaluation

- All previously accepted syntax remains valid.
- Only an entire single-return body is eligible for an automatic compact rewrite.
- Preserve case identities, canonical assertions, expected returns and executed assertion coverage.
- Add accepted-syntax equivalents for every new normative case before changing the runtime.
- Count runtime lexer tokens, including layout and excluding `Eof`, through the gate in [NUC 1](nuc-0001.md#proposal-evaluation).
- Accept only with no increased, missing, unpaired or behavior-invalid cases; keep baseline and report artifacts in the session workspace.

## Errors

- No new runtime error kind or message is introduced.
- Existing parameter, expression, invocation and transaction errors retain their exact types and messages.

| Condition | Error |
| --- | --- |
| Missing expression at the end of input after `=>` | `SyntaxError("Unexpected end of input")` |
| Missing expression before a logical line break after `=>` | `SyntaxError("Unexpected end of line")` |
| A named arrow body starts with `{ return ... }` | `SyntaxError("Expected a key but found keyword 'return'")` |
| An object literal key is followed by `=` rather than `:` | `SyntaxError("Expected ':' but found '='")` |
| Reading an undefined binding | `ReferenceError("<name> is not defined")` |
| Calling a defined, non-null binding that is not a function | `TypeError("<callee> is not a function")` |

## Reference Implementation

- The prototype is implemented in [`Parser::function_statement`](../src/lang/ast/parser.rs), lowering to `FunctionBody::Block` containing `Stmt::Return(Some(expression))`.
- The existing class-method parser and [`ClassData::adopt_initializer`](../src/nuc/class.rs) are reused; no additional runtime value, function kind, keyword or dependency is needed.
- Normative coverage in [`nucleoid.spec.md`](../nucleoid.spec.md) is provided by:
  - `Nucleoid keeps expression bodied named functions reactive`.
  - `Nucleoid keeps expression bodied methods and initializers equivalent`.
  - `Nucleoid preserves expression body returns and callable references`.
- Parser unit tests compare desugared ASTs and canonical rendering, including methods, object literals, returned lambdas and parenthesized continuations; [`diagnostics`](../tests/diagnostics.rs) and [`robustness`](../tests/robustness.rs) cover syntax errors, prior block behavior and failed redefinition rollback.
- Proposal evaluation accepted all 355 paired cases: 26 used fewer lexer tokens, 329 used the same and none used more; no behavior or coverage issues were reported.
- The measured corpus used 29,957 tokens before and 29,733 after, saving 224 tokens; the decision remains per case rather than aggregate.
