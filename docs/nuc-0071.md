## Abstract

- Lists and class instance lists gain the read-only query `distinct`.
  `RECEIVER.distinct()` returns a new list of the receiver's items without
  repeats, keeping the first occurrence of each in receiver order, and
  `RECEIVER.distinct(selector)` returns the distinct values of
  `selector(item)` the same way.
- Two values are repeats when the deep equality of `assert`, `includes` and
  `indexOf` matches them ([NUC 61](nuc-0061.md)). A value is kept when no
  value already kept matches it, so `xs.distinct()` returns the list that
  `xs.reduce((kept, x) => kept.includes(x) ? kept : kept.concat([x]), [])`
  evaluates to, and `xs.distinct(f)` returns `xs.map(f).distinct()`.
- Values are compared, never converted: `1`, `"1"` and `true` stay three
  values, `null` and undefined are one, `0` and `-0` are one, and every NaN is
  kept, because NaN matches nothing.
- The selector is called once for every item, in order, with only the item,
  as [NUC 68](nuc-0068.md)'s `sum` and [NUC 69](nuc-0069.md)'s `max` call
  theirs. A supplied selector that is not a function raises
  `TypeError("distinct expects a function")`.
- `distinct` follows NUC 61's shared query rules beside `sum`, `max` and
  `min`. It accepts every receiver the list queries accept, reads the
  receiver before its arguments, never writes it, and stays live in
  declarations and class-level rules like `map`, `filter` and `sum`.
- At the accepted revision these calls raise
  `TypeError("<receiver>.distinct is not a function")`. No syntax, keyword,
  error type or public Rust API is added. The authoritative contract is
  [List and population distinct values](../nucleoid.spec.md#list-and-population-distinct-values).

## Motivation

- World models keep sets of values: the regions that have orders, the
  categories a warehouse stocks, the tags in use, the colors present in a
  grid, the customers who bought. Each is the distinct values of a list or of
  a class's instances, and it has to stay true while the model changes.
- The accepted spelling is an accumulating `reduce` over `includes` and
  `concat`. For a list,
  `rooms = visits.reduce(lambda a, x: a.includes(x) ? a : a.concat([x]), [])`
  is 32 lexer tokens where `rooms = visits.distinct()` is 7. For a
  population,
  `regions = Order.reduce(lambda a, o: a.includes(o.region) ? a : a.concat(o.region), [])`
  is 34 tokens where `regions = Order.distinct(order -> order.region)` is 12,
  and the class-level rule
  `$Warehouse.categories = Item.filter(item -> item.warehouse == $Warehouse and item.qty > 0).distinct(item -> item.category)`
  is 31 tokens where its accumulator is 53.
- The accumulator is easy to get subtly wrong. Without the seed `[]` the first
  item becomes the accumulator, so
  `[3, 1].reduce(lambda a, x: a.includes(x) ? a : a.concat([x]))` raises
  `TypeError("number.includes is not a function")`. With `concat(x)` instead
  of `concat([x])`, list items are spread into the result. Its callback reads
  every item through a parameter, so a declaration over a list with a `null`
  item settles to `null`: `r = [1, null].reduce(...)` stores `null`, while
  `r = [1, null].distinct()` stores `[1, null]`.
- Lambdas cannot capture the parameters of an enclosing function, so a helper
  that takes a selector cannot call it inside its accumulator:
  `def g xs f => xs.reduce(lambda a, x: a.includes(f(x)) ? a : a.concat([f(x)]), [])`
  raises `ReferenceError("f is not defined")` when called, and the values have
  to be mapped first.
- Kotlin, C# and Java streams name the operation `distinct`, SQL writes
  `SELECT DISTINCT`, and Ruby and lodash write `uniq`. JavaScript has only
  `new Set(...)`, and LLM-written code such as `orders.distinct(o => o.region)`
  raises `TypeError("orders.distinct is not a function")` at the accepted
  revision; `Set` is not defined.
- NUC 68 and NUC 69 added the totals and extremes of lists and populations;
  this NUC adds their distinct values with the same receivers, selector and
  liveness rules.

## Rationale

- **Category and mode.** The caller selected the Utility enhancement
  category by one uniform draw over the four eligible registry categories,
  index 2 with probability 1/4 and no redraw, in continuous mode, so the
  token non-regression gate applies. Each new case is paired with the most
  compact accepted-syntax counterpart found, recorded in the evaluation
  baseline.
- **One more shared query.** `distinct` is an operation of the read-only list
  query that serves `map`, `filter`, `reduce`, `sum`, `max`, `min` and
  NUC 61's queries. Lists, list properties, call results such as
  `filter(...)`, `map(...)`, `flatMap(...)` and `slice(...)`, ranges,
  `.value` snapshots, selected versions, class instance lists and
  `Name.list()` therefore accept it through one implementation, with the
  receiver, argument and liveness rules they already share.
- **Exactly the equality of `includes`.** A value is kept when no value
  already kept matches it under the deep equality that `includes` uses, in
  the same direction as `kept.includes(value)`. The result is therefore the
  accumulator's result by construction, including where deep equality is
  unusual, and `distinct`, `includes`, `indexOf` and `assert` never disagree
  about what a repeat is.
- **First occurrences, in receiver order.** The kept value is the first
  occurrence, unchanged and not copied: an object stays the same object, and
  `[-0, 0].distinct()` keeps `-0`. Removing an earlier occurrence moves the
  value to its next occurrence. Kotlin's `distinct`, Java's ordered
  `Stream.distinct`, Ruby's `uniq` and Python's `dict.fromkeys` keep first
  occurrences in order too.
- **The selector selects values, as in `sum`, `max` and `min`.**
  `Order.distinct(order -> order.region)` lists the regions, and for every
  selector `xs.distinct(f)` equals `xs.map(f).distinct()`, as `xs.sum(f)`
  equals `xs.map(f).sum()` and `xs.max(f)` equals `xs.map(f).max()`. The
  sets a world model keeps are sets of values: regions, categories, tags,
  colors.
- Rejected: returning the first item for each selected value, as Ruby's
  `uniq { ... }`, Kotlin's `distinctBy`, C#'s `DistinctBy` and lodash's
  `uniqBy` do. A selector would then mean a value in `sum`, `max` and `min`
  but a key in `distinct`, and `xs.distinct(f)` and `xs.map(f).distinct()`
  would differ; NUC 69 likewise returns the selected value rather than the
  item. The first item for each value stays expressible with accepted
  queries, as
  `Order.filter(order -> Order.map(each -> each.region).indexOf(order.region) == Order.indexOf(order))`.
- **Compared, never converted.** `distinct` is an equality query like
  `includes`, not a numeric query like `sum`, so values keep their kinds:
  `[1, "1", true].distinct()` has three values. A date matches the number of
  its milliseconds, as it does in `includes` and `assert`.
- Rejected: the numeric conversion of `sum`, `max` and `min`, under which
  `"2"` and `2` would be one value and every object NaN.
- **NaN is kept every time.** NaN matches nothing, not even NaN, so
  `[0 / 0, 0 / 0].distinct()` has two values, as `[0 / 0].includes(0 / 0)` is
  `false`.
- Rejected: JavaScript `Set`'s SameValueZero, which treats NaN as one value
  and would make `distinct` and `includes` disagree.
- **`null` and undefined are one value.** Deep equality matches them, so the
  first of them is kept, unchanged. An undefined item or selector result is
  kept like any other value, as `map` and `concat` keep it: after
  `delete third.region`, `Order.distinct(order -> order.region)` lists the
  other regions and one undefined value.
- Rejected: the undefined gate of `sum`, `max` and `min`, under which one
  missing value would make the whole result undefined. Those queries do
  arithmetic, where an unknown operand makes an unknown total; `distinct`
  does none.
- **Objects match on contents.** Two records with the same defined
  properties are one value, in any key order. Every instance holds its own
  `id`, so distinct instances never match each other, and the same instance
  twice is one value. Functions and regular expressions match nothing, not
  even themselves, so each one is kept, as `includes` never finds them.
- **The quirks of deep equality carry over exactly.** A record with a
  `null` property matches a later record that holds that property as
  undefined beside one other property, but not the other way round: after
  `a = {k: null, m: 1}` and `b = {k: {}.none, m: 1, z: 5}`,
  `[a, b].distinct()` keeps only `a` and `[b, a].distinct()` keeps both, as
  `[a].includes(b)` is `true` and `[b].includes(a)` is `false`. A record
  holding an instance's `id` and fields matches that instance, and a list
  nested more than 64 levels deep matches nothing, not even itself, while an
  object always matches itself. Changing these would change `includes` and
  `assert`, which this NUC does not do.
- **Comparisons do not subscribe.** As NUC 61 specifies for `includes`, a
  comparison reads the objects it compares without subscribing to their
  properties. A declaration that uses `distinct` follows its list or
  population, its argument expressions and what the selector reads, so after
  `first = {k: 1}`, `records = [first, {k: 2}]` and
  `kept = records.distinct()`, setting `first.k = 2` leaves `kept` at two
  records until the list itself changes. The accumulator spelling behaves the
  same way.
- Rejected: subscribing to every property of every compared object, which
  would make each distinct query depend on whole records and differ from
  `includes`. Records whose fields matter are better selected:
  `records.distinct(record -> record.k)` reads `k` and stays live.
- **No artificial null read.** `distinct()` reads items, not bindings, so a
  `null` item is kept and does not settle a declaration to `null`, as in
  `sum()` and `max()`. A selector's own reads follow the existing rules:
  `Order.distinct(order -> order.region)` over a `null` region settles a
  declaration to `null`, as the same callback does in `map`.
- **The selector is called like `map`'s callback.** It runs once per item, in
  order, with only the item; further parameters stay `null`. Every item is
  visited, so every item's reads are dependencies.
- **A supplied selector must be a function.** Any other first argument,
  including `null`, raises `TypeError("distinct expects a function")` after
  the arguments are evaluated, even on an empty receiver, as `sum`, `max`,
  `min`, `map` and `filter` raise for their callbacks.
- Rejected: property-name selectors such as lodash's
  `uniqBy(orders, "region")`, and equality functions such as C#'s
  `Distinct(comparer)`. A two-parameter function is still a selector and
  receives `null` as its second argument.
- **Extra arguments** are evaluated once, left to right, and ignored, as
  every list query does.
- **Instance lists.** On a class name, `Name.distinct(...)` is the population
  query even when the class declares an instance method `distinct`, as
  NUC 68 made `Name.sum(...)`. The method stays reachable through each
  instance, and `Shelf.distinct(each -> each.distinct())` lists its distinct
  results.
- **Bounded cost.** The receiver and the arguments are evaluated once per
  call and the selector once per item. Each value is hashed once by a
  structural key that every pair of deep-equal values shares, and compared
  with deep equality only against kept values with the same key. An object
  holding a property whose value is undefined is also compared with the kept
  objects that hold a `null` property and as many defined properties,
  because deep equality lets it match such an object, whose `null` property
  it holds as undefined, outside its key. A value is compared with each kept
  value at most once, so a call costs at most `n * k` comparisons for `n`
  values and `k` kept values, the comparisons of the accumulator, and close
  to linear time for numbers, strings, lists of them, records and instances.
  The worst case needs many kept records with `null` properties and new
  records holding undefined ones, with equal numbers of defined properties.
  Nothing is copied, the call keeps its ordinary rendering in graph keys and
  `why`, and rendered size stays linear in the source.
- Rejected: the plain scan over every kept value, which the accumulator
  performs. It gives the same results, but 20,000 distinct numbers would need
  about 200 million comparisons.
- **Not added.** A global `distinct(...)`, the names `unique` and `uniq`,
  item-returning `distinctBy`, a set type, distinct characters of a string,
  counting or grouping queries, equality functions and property-name
  selectors.

## Specification

### Distinct values

- `RECEIVER.distinct()` returns a new list of the receiver's items in
  receiver order, without any item that matches an item before it.
  `RECEIVER.distinct(selector)` does the same for the values
  `selector(item)`, so it returns the distinct selected values.
- A value is kept when no value already kept matches it under the deep
  equality of `assert`, `includes` and `indexOf`, compared as
  `kept.includes(value)` compares. Kept values are the first occurrences,
  unchanged.
- The receiver is a list, however it is reached: a variable, a property, a
  call result such as `filter(...)`, `map(...)`, `flatMap(...)`,
  `slice(...)` or `concat(...)`, a range, a literal, a `.value` snapshot or a
  selected version. It may also be a class's instance list, named by the
  class or by a variable that holds the class, in population order; a range
  of one and `Name.list()` are lists.
- An empty receiver gives `[]`.

```
visits = ["lab", "den", "lab", "hall", "den"]
rooms = visits.distinct()
assert: rooms, ["lab", "den", "hall"]
visits.shift()
assert: rooms, ["den", "lab", "hall"]
visits = []
assert: rooms, []
cart = {lines: [{sku: "pen", qty: 2}, {sku: "ink", qty: 1}, {sku: "pen", qty: 5}]}
skus = cart.lines.distinct(line -> line.sku)
cart.lines.push({sku: "cap", qty: 3})
assert: skus, ["pen", "ink", "cap"]
```

```
class Order(region, rush):
    this.region = region
    this.rush = rush
regions = Order.distinct(order -> order.region)
assert: regions, []
first = Order("north", false)
second = Order("south", true)
third = Order("north", true)
rushed = Order.filter(order -> order.rush).distinct(order -> order.region)
first.region = "east"
assert: regions, ["east", "south", "north"]
assert: rushed, ["south", "north"]
delete third.region
assert: regions, ["east", "south", null]
```

### Equality

- Values are compared, never converted. Numbers, strings, booleans, dates,
  lists, objects and classes are different values unless deep equality
  matches them: `1`, `"1"` and `true` are three values, and a date matches the
  number of its milliseconds.
- `null` and undefined are one value; the first of them is kept, unchanged.
  An undefined item or selector result is kept like any other value.
- `0` and `-0` are one value, and the first is kept with its sign.
- NaN matches nothing, so every NaN is kept.
- Lists match when they have the same length and their items match in
  order. Objects match when they hold matching values for the same defined
  properties, in any order. Every instance holds its own `id`, so distinct
  instances never match each other. Functions and regular expressions match
  nothing.
- The quirks of deep equality carry over exactly:
  - after `a = {k: null, m: 1}` and `b = {k: {}.none, m: 1, z: 5}`,
    `[a, b].distinct()` keeps only `a` and `[b, a].distinct()` keeps both,
    as `[a].includes(b)` is `true` and `[b].includes(a)` is `false`;
  - a record holding an instance's `id` and fields matches that instance;
  - a list nested more than 64 levels deep matches nothing, not even itself,
    while an object always matches itself.
- A comparison reads the objects it compares without subscribing to their
  properties. A declaration that uses `distinct` follows its list or
  population, its argument expressions and what the selector reads; changing
  a property of a compared object does not re-evaluate it.
- `distinct()` reads items, not bindings: a `null` item is kept without
  settling a declaration to `null`. Reads inside a selector follow the
  existing rules, so a selector that reads a `null` binding or property
  settles a declaration to `null`.

```
inputs = [2, "2", true, 2, null, "2", null]
kinds = inputs.distinct()
assert: kinds, [2, "2", true, null]
inputs.push(-0)
inputs.push(0)
assert: String(1 / kinds[4]), "-Infinity"
inputs.push(0 / 0)
inputs.push(0 / 0)
assert: kinds.length, 7
places = [{x: 1, y: 2}, {y: 2, x: 1}, {x: 2, y: 1}]
spots = places.distinct()
assert: spots, [{x: 1, y: 2}, {x: 2, y: 1}]
```

### Selectors

- A selector is called once for every item, in order, with the item as its
  only argument; further parameters are `null`. The call order and the
  argument are those of `map`, and `RECEIVER.distinct(selector)` equals
  `RECEIVER.map(selector).distinct()`.
- A supplied first argument that is not a function, including `null`, raises
  `TypeError("distinct expects a function")`, even on an empty receiver.
- Every supplied argument, including unused extras, is evaluated once, left
  to right, after the receiver and before the first selector call.
- A null or undefined receiver keeps the existing method-call route: the call
  yields undefined without evaluating its arguments.

```
seen = []
def zone(stop, position):
    seen.push(position ?? stop.city)
    return stop.zone
stops = [{city: "Oslo", zone: 1}, {city: "Rome", zone: 3}, {city: "Bergen", zone: 1}]
def zones() => stops.distinct(zone)
assert: zones(), [1, 3]
assert: seen, ["Oslo", "Rome", "Bergen"]
limit = 2
def band stop => stop.zone > limit ? "far" : "near"
bands = stops.distinct(band)
limit = 0
assert: bands, ["far"]
```

### Liveness and transactions

- `distinct` never writes its receiver. A declaration that uses it depends on
  the list or the population, on its argument expressions and on whatever the
  selector reads, as for `map`, `filter` and `sum`, and not on the properties
  of the objects it compares.
- Pushing, popping, shifting or replacing a list, creating or deleting an
  instance, and changing a property that a selector reads re-evaluate the
  declaration, in receiver order.
- In a class-level rule, each instance evaluates its own distinct values, and
  `$Class` inside a selector or a filter is the instance the rule is
  evaluated for.
- Selector errors propagate through the existing transaction, so a failed
  standing re-evaluation rolls back the change that triggered it, including a
  list write or a new instance, and the list keeps its order.

```
class Customer(name): this.name = name
class Order(customer, region):
    this.customer = customer
    this.region = region
$Customer.regions = Order.filter(order -> order.customer == $Customer).distinct(order -> order.region)
$Customer.spread = $Customer.regions.length
ada = Customer("ada")
Order(ada, "north")
big = Order(ada, "south")
Order(ada, "north")
assert: ada.regions, ["north", "south"]
big.region = "north"
assert: ada.spread, 1
```

### Cost

- The receiver and the arguments are evaluated once per call, and the
  selector once per item.
- Each value is hashed once, by a structural key that deep-equal values
  share, and compared with deep equality only against kept values with the
  same key. An object that holds a property whose value is undefined is also
  compared with the kept objects that hold a `null` property and as many
  defined properties, the only values that can match it outside its key.
  NaN, functions and regular expressions match nothing and are kept without a
  comparison.
- A value is compared with each kept value at most once, so a call makes at
  most `n * k` comparisons for `n` values and `k` kept values, and close to
  `n` for numbers, strings, booleans, dates, lists of them, records and
  instances.
- Unit tests count these comparisons exactly: none for 20,000 distinct
  numbers, strings, lists or records, one per repeated value, none for NaN,
  functions and regular expressions, and one for each pair of a `null` holder
  and an undefined holder that could match.

## Reference Implementation

- `src/lang/ast/array.rs`: `list_query`, the read-only query shared by lists
  and class instance lists, gains `distinct` beside `sum`, `max` and `min`.
  It validates the optional selector with the shared `optional_selector`,
  whose message is `distinct expects a function`, selects the values with the
  shared `Runtime::select_items`, once per item and in order, and returns the
  list that `Runtime::distinct_values` keeps. Lists reach the query through
  `call_list_method` and populations through `call_class_method`, unchanged,
  so the receiver and the arguments are evaluated once by the existing routes
  and the null-receiver route stays in front of it.
- `src/lang/ast/object.rs`: the crate-private `Runtime::distinct_values`,
  beside `deep_equal`, passes the values to the private
  `Runtime::distinct_by(values, matches)` with `deep_equal(kept, value)` as
  `matches`, the comparison `includes` makes, and a value is kept unless
  `matches` holds for a value already kept. `Runtime::equality_key` gives each
  value a 64-bit hash that every pair of deep-equal values shares: numbers and
  dates by their numeric value with `-0` folded into `0`, strings, booleans
  and classes by their contents, lists by their length and items to eight
  levels, a top-level object by its defined properties combined in any key
  order, and a nested object by the number of its defined properties. NaN,
  functions and regular expressions get no key and are kept without a
  comparison.
- Every kept value is filed in a bucket by its hash, and every kept object
  that holds a `null` property is also filed, with its hash, in a second map
  by its number of defined properties. A value is compared with the kept
  values in its bucket and, when it is an object holding an undefined-valued
  property, with the `null` holders of its size whose hash differs from its
  own; a holder with the same hash is in its bucket and was compared there.
  Each value is therefore compared with each kept value at most once. Every
  kept value that deep equality can match is among these candidates: a match
  whose kept object holds no `null` property has the same defined properties
  and values, and so the same hash, and every match has the same number of
  defined properties. Hash collisions cost comparisons but never change a
  result.
- Two unit tests in `src/lang/ast/object.rs` count the comparisons through
  `distinct_by` exactly.
  `values_are_compared_only_with_kept_values_that_share_their_key` finds 0
  comparisons for 20,000 distinct numbers, strings, two-item lists, records
  holding `null`, records holding undefined, and both kinds of record
  together; 19,990 for 20,000 numbers modulo ten; one per duplicate, 20,000,
  for repeated numbers, `null` holders and undefined holders; and 0 for two
  NaNs, a function twice and a regular expression twice.
  `undefined_holders_are_compared_once_with_null_holders_of_their_size` finds
  one comparison when `{k: null, m: 1}` precedes a record holding `k` as
  undefined beside `m: 1` and `z: 5`, keeping only the first; none in the
  other order, keeping both; none against a `null` holder of another size;
  and one when a `null` holder shares the hash of an undefined holder.
- `src/terminal/completion.rs`: the list members that lists and instance
  lists offer include `distinct`, and the completion unit test covers
  `scores.distinct` and `User.distinct`.
- `tests/list_distinct.rs` holds 21 tests. They cover the appended document
