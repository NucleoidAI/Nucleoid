Status: Accepted
Type: Standards Track

Created: 15-Oct-2026

## Abstract

- A named indented block definition may optionally omit parentheses around two or more comma-separated untyped ordinary identifier parameters.
- `def add left, right:` followed by an indented body is exactly `def add(left, right):` followed by that same body, including methods and `init`.
- Extend accepted NUC19's indented-block shorthand and reuse accepted NUC27's complete-list lookahead without changing accepted syntax or runtime behavior.

## Motivation

- Multi-input blocks, initializers and methods can express their existing parameter lists without two delimiter tokens.
- Preserve every parenthesized alternative; this optional spelling changes neither argument syntax nor the meaning of a block.
- Prepare exactly the caller-selected syntax improvement, without a category redraw, runtime feature or pending dependency.

## Rationale

- Require a complete ordinary-identifier/comma list and real indentation before recognizing the optional form; never partially consume an unsupported prefix.
- Share the touched multiple-parameter arrow scan instead of duplicating it; keep the existing single untyped/typed arrow and block guards exact.
- Distinguish the final suite colon from a type annotation by consuming only untyped identifiers and commas after successful block lookahead.
- Let the existing suite parser consume all colon, layout and body tokens; ordinary indented bodies may contain their existing statements and inner blocks.
- Exclude typed/mixed multiple bare headers, inline/braced bare suites, trailing bare commas, defaults, destructuring, rest, return annotations and call-site omission.
- Preserve uncapped flat parameter lists and all existing expression nesting and chain bounds.
- Keep historical NUC19/27 exclusions as descriptions of their own scope; qualify only current normative and reference boundaries.

## Specification

### Grammar and lowering

- The authoritative [bare multiple-parameter indented block definitions](../nucleoid.spec.md#bare-multiple-parameter-indented-block-definitions) section governs this candidate.
- Parse `def` and the required ordinary definition name exactly as before.
- Look ahead without consuming or allocating for `Identifier Comma Identifier (Comma Identifier)* Colon`.
- Require at least two untyped ordinary identifiers, with no parameter-count cap; each comma must immediately lead to another identifier token.
- Skip no logical newline, semicolon, indentation token or comment-induced logical break anywhere within that header.
- Require the token immediately after the colon to be `Newline` or `Indent`; from that initial body break, look past only `Newline` and `Semicolon` tokens and require the first non-layout token to be a real `Indent`.
- A colon immediately followed by `Semicolon` does not qualify, regardless of later indentation; blank/comment lines before a genuine indented body keep the existing suite grammar.
- Reuse NUC27's allocation-free, linear complete-list scan for both terminators; only its existing immediate `Arrow` continues to qualify an arrow.
- Once block lookahead succeeds, consume identifiers in order as `Parameter { name, type_name: None }`, consuming only the commas between them; leave the final colon for unchanged `suite()`.
- Produce the exact named `FunctionBody::Block`, metadata and canonical rendering of the parenthesized counterpart, not an anonymous function or an implicit return.
- Methods and `init` share `function_statement`, so the same optional header applies without any receiver, initializer or runtime dispatch change.
- If lookahead fails, consume nothing and retain the existing single-parameter guards or parenthesized parser, including unsupported-prefix error messages and positions.

### Behavior and compatibility

- Multiple statements, local assignments, branches, nested definitions and existing inner inline/braced statements retain the ordinary suite grammar.
- Explicit `return expression`, bare `return` and no return preserve their existing behavior; bare/no return yield `null`, never an implicit last-expression result.
- Preserve parameter order, missing/null/extra argument binding, local shadowing, non-callable/null callable parameters and the existing noncapturing function scope.
- Preserve objects, lists, templates, returned anonymous functions, expression precedence, receiver spellings, initializer adoption and explicit/bare `super`.
- Preserve reactive body inputs and arguments, live callable aliases, `.value` definition snapshots, redefinition, graph keys/dependencies, reasoning, transactions, caught errors and rollback.
- Preserve NUC27 arrows and NUC18/19/20/24 single-parameter untyped/typed arrow/block guards exactly.
- Preserve all parenthesized empty/untyped/typed/mixed, trailing-comma/multiline, arrow/indented/inline/braced forms, calls, anonymous functions, class parameter syntax and word/keyword meanings.
- Add no typed/mixed multiple bare headers, inline/braced bare suites, trailing bare commas, defaults, destructuring, rest parameters, return annotations or call-parenthesis omission.
- Introduce no lexer/public AST/runtime/generator/API change, dependency, MSRV or project-version change; existing resource bounds and inherited scope/propagation failures are not repaired.
- Append exactly the five supplied spec cases and one each for reference, README and examples after all historical cases in each measured document.
- Preserve every historical title/order, ordered canonical assertion, expected return and executed assertion; rewrite only eligible untyped multiple-parameter indented headers.
- Keep relevant canonical synthesized records and generated normative JSONL/Rust exports synchronized, preserving stable IDs, descriptions, assertions, returns and ARC annotations; retain documented and tested legacy forms.

- This complete forms example is the first new spec entry without its title comment.

```nuc
def add left, right:
    total = left + right
    return total
def scaled left, right, factor:
    return (left + right) * factor
def largest left, right:
    if left > right:
        return left
    return right
assert(add(2, 3), 5)
assert(scaled(2, 3, 4), 20)
assert(largest(7, 3), 7)
assert(largest(2, 9), 9)
```

## Errors

- Introduce no new error kind or runtime message; nonqualifying tokenizable headers reach the existing parenthesized parser without prefix consumption.
- The following exact errors and positions trace to the normative boundary section and parser tests; ordinary body syntax retains its existing errors.

| Exact input or condition | Exact error | Position |
| --- | --- | --- |
| `def f left, right`, or `def f left, right:` without a real indented body | `SyntaxError("Expected '(' but found identifier 'left'")` | line 1, column 7 |
| `def f left, right: return left` or `def f left, right: { return left }` | `SyntaxError("Expected '(' but found identifier 'left'")` | line 1, column 7 |
| `def f left, right:;` even before a later indented body | `SyntaxError("Expected '(' but found identifier 'left'")` | line 1, column 7 |
| `def f left, right,:` with a body, missing parameters, typed/mixed headers, defaults/destructuring/rest or logical breaks within the bare header | `SyntaxError("Expected '(' but found identifier 'left'")` | line 1, column 7 |
| `def f this, right:` with an indented body | `SyntaxError("Expected '(' but found keyword 'this'")` | line 1, column 7 |
| Logical newline immediately after `def f` | `SyntaxError("Expected '(' but found end of line")` | line 1, column 5 |
| Semicolon immediately after `def f` | `SyntaxError("Expected '(' but found ';'")` | line 1, column 6 |
| `def f(left, right:):` with a body | `SyntaxError("Expected a type but found ')'")` | line 1, column 20 |
| Qualifying `def f left, right:` then newline and four-space-indented `return left +)` | `SyntaxError("Unexpected ')'")` | line 2, column 19 |
| Same header/layout then `return { left = 1 }` | `SyntaxError("Expected ':' but found '='")` | line 2, column 19 |
| Same header/layout then `return @` | `SyntaxError("Unexpected character '@'")` | line 2, column 12 |
| Evaluated body or object field reads undefined `missing` | `ReferenceError("missing is not defined")` | existing top-level statement position |
| A returned anonymous function reads uncaptured parameter `left` | `ReferenceError("left is not defined")` | existing top-level statement position |
| `this` or `self` without an instance receiver | `ReferenceError("this is not defined")` | existing top-level statement position |
| A non-callable parameter shadows `operation` | `TypeError("operation is not a function")` | existing top-level statement position |
| Excessive body expression nesting | `SyntaxError("Expressions are nested too deeply")` | existing expression position |
| Excessive body operator chain | `SyntaxError("Expression has too many operands")` | existing expression position |
| Excessive body postfix chain | `SyntaxError("Expression has too many parts")` | existing expression position |

- Lexical failures precede parsing; caught error values omit source positions as before.
- Removing header delimiters can shift later columns on that line; unsupported prefixes and body-line diagnostics retain their existing positions.

## Reference Implementation

- The isolated prototype changes only the private parser in [`src/lang/ast/parser.rs`](../src/lang/ast/parser.rs); `suite()`, lexer, public AST, generator and runtime remain unchanged.
- A shared complete-list helper recognizes the immediate arrow or colon terminator without consuming layout; a separate real-indent guard admits only the new block form.
- Keep the existing NUC27 parameter parser path for arrows; for bare multiple blocks consume only ordinary identifiers/commas so the last colon remains the suite delimiter.
- The 14 portable ordinary behavior regressions in [`tests/bare_multiple_indented_blocks.rs`](../tests/bare_multiple_indented_blocks.rs) cover exact AST/metadata/canonical equivalence, normal layout, both return branches, nested/inner blocks, receivers/init/super, arity/shadowing, object/list/template/noncapturing behavior, live snapshots/redefinition/graphs, rollback, exact errors/positions and flat lists through 1,024 parameters with unchanged nesting/chain bounds; default execution does not invoke Git.
- Two additional historical audits are explicitly opt-in with `#[ignore]`, preserving their complete bodies and assertions: `all_historical_measured_asts_and_the_eight_appended_counterparts_remain_exact` checks the historical measured corpus and paired additions; `synchronized_synthesized_records_keep_complete_asts_and_protected_fields` checks the affected synthesized sources against the pinned accepted revision.
- These audits require Git and the objects for accepted revision `49bc92a9412dbbdc2d1989c34b21d470f1e49e4c`; source archives may have no Git and shallow checkouts may lack those objects. With the prerequisites available, run `cargo +stable-x86_64-pc-windows-gnu test --locked --target x86_64-pc-windows-gnu --test bare_multiple_indented_blocks -- --ignored` to select both audits; neither silently falls back or skips its assertions when explicitly selected.
- Existing header suites replace only newly valid negative entries with positive exact-equivalence checks and still-invalid boundary variants; other unsupported typed, inline, braced and separator assertions remain intact.
- The executable documents contain exactly the eight supplied pre-executed paired additions and eligible existing header-only rewrites; regenerate normative JSONL and exported Rust tests from their source.
