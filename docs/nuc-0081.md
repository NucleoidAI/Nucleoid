## Abstract

- Object literals gain spread entries. `{...SOURCE, key: value}` copies the
  entries of the object `SOURCE` holds into the new object, in their
  insertion order, so `{...point, z: 0}` extends a record and
  `{...defaults, ...overrides}` merges two.
- Entries apply from left to right, and each source is evaluated once. A
  later entry for a key the object already holds replaces its value and
  keeps the key's first position, as a repeated key does in an accepted
  literal. A spread copies exactly the entries an entry loop visits: `null`
  values are copied, undefined slots are not.
- A `null` or undefined source copies nothing, and reading a `null` source is
  an ordinary null read, so a declaration waits for an unknown source. Every
  other value that is not an object raises
  `TypeError("<source> is not an object")`, the message of
  [NUC 72](nuc-0072.md)'s entry loops.
- A spread in a standing declaration stays live. It depends on the entries it
  copies and observes its source's set of entries, so changing, deleting or
  adding an entry, or replacing the binding its source reads, evaluates the
  declaration again. A derived record stays equal to the explicit record
  that names every entry its source holds. Programs without spreads
  propagate exactly as before.
- While a property declaration evaluates its value, a spread of the object
  that owns the property leaves that property out, so the class-level rule
  `$Order.view = {...$Order, paid: false}` never copies an older view into a
  newer one.
- No keyword, token or error type is added. Three adjacent dots start a spread
  only where an object-literal entry may begin, as [NUC 74](nuc-0074.md)
  recognizes them only in parameter lists. Every accepted program keeps its
  parse and behavior; only inputs that raised
  `SyntaxError("Expected a key but found '.'")` at such an entry change. The
  public `Expr` enum gains `Expr::SpreadObject`, the public `ast` module gains
  the enum `ObjectEntry`, and the public `ShapeKey` enum gains
  `ShapeKey::Entries`; they need human SemVer review. No project version is
  changed. The authoritative contract is
  [Object spread entries](../nucleoid.spec.md#object-spread-entries).
- **Outcome: Accepted.** The independent evaluation and the caller's
  integrated-tree checks passed all three hard criteria, and the independent
  evaluator decided Accepted. The required token comparison ran in
  continuous mode: 11 cases use fewer tokens, 926 the same and none more. No
  policy check failed. The evaluation corrects one claim above: where the
  parser backtracks, some spreads that raised a different syntax error at
  the accepted revision now run too, such as `{x, y} = {...p}`; every
  changed input was an error at the accepted revision.

## Motivation

- A world model derives records from records: an order line from a product,
  a shipping label from a customer and an order, the settings in effect from
  defaults and a user's preferences, a sale beside the regular listing, an
  instance's public view. Each derived record keeps the fields of its source
  and changes or adds a few.
- Accepted Nucleoid cannot copy an object's entries. `{...a}` raises
  `SyntaxError("Expected a key but found '.'")`, `Object.assign({}, a)`
  raises `ReferenceError("Object is not defined")`, `JSON` is not defined,
  and computed writes such as `a[k] = 2` raise
  `SyntaxError("Cannot assign to a[k]")`, so NUC 72's entry loops can read
  every entry but cannot write one into another object. NUC 74 lists
  call-site spread among what it does not add.
- The accepted spellings therefore name every field by hand, as
  `line = {name: item.name price: item.price size: item.size qty: item.qty total: item.price * item.qty}`
  does. They repeat the source for every field and break as the model grows:
  - a field the source gains later is missing from every derived record that
    does not name it ahead of time, as `size: item.size` does above;
  - merging records needs `??` for every key both may hold,
    `{size: custom.size ?? defaults.size gift: custom.gift ?? defaults.gift}`,
    and still misses keys neither literal names;
  - [NUC 67](nuc-0067.md)'s destructuring shortens the reads, but a
    destructured name of a missing or deleted key reads `null`, and the
    null-read rule then settles every record that reads it to `null`;
  - a class-level rule that copies its receiver lists each field, and a rule
    that reads its own property raises `TypeError("Circular Dependency")`.
- JavaScript's `{...a, b: 1}`, Python's `{**a, "b": 1}`, Kotlin's
  `a.copy(b = 1)`, C#'s `a with { B = 1 }` and Rust's `S { b: 1, ..a }` all
  derive one record from another, and LLMs write the JavaScript form
  constantly. In accepted Nucleoid the JavaScript form raises
  `SyntaxError("Expected a key but found '.'")`, the Python and Rust forms
  raise other syntax errors, `a.copy(b = 1)` reads `null` and
  `a with { B = 1 }` raises `ReferenceError("with is not defined")`. This
  NUC adds only the JavaScript form.
- Each of the eleven new cases uses 14 to 25 fewer lexer tokens than the most
  compact behavior-equivalent accepted program found for it.

## Rationale

- **Category and applicability.** The caller selected Runtime features by one
  tool-backed uniform draw over the five categories NUC 1's registry marks
  eligible for automatic selection: index 1 with probability 1/5 and no
  redraw, in continuous mode. Runtime applicability is
  `existing_comparable`: object literals, property reads and their liveness
  exist, and for every case whose sources have a known shape an accepted
  literal that names the sources' entries explicitly is behavior-equivalent,
  including liveness on copied keys and on keys named ahead of time, because
  a slot that reads a missing property is not an entry: `{y: a.missing}` is
  `{}`. The token non-regression gate therefore applies, and each new case is
  paired with the most compact accepted counterpart found, recorded in the
  evaluation baseline.
- **Optional evidence.** No hint was supplied. Advisory usefulness is
  unscored (`missing_rubric`), not zero. Strategy learning is
  `not_configured`, so this revision is unattributed, with no policy,
  selection receipt, trial or reward.
- **Three dots, only at an entry.** A spread begins with three `Dot` tokens at
  consecutive columns of one line, recognized only where the object-literal
  parser would read a key. NUC 74 recognizes rest parameters the same way.
  The lexer is unchanged, so every other occurrence of adjacent dots keeps
  its accepted tokens and diagnostics, including `[...xs]` and the pinned
  `f(...xs)`.
  - Rejected: a `...` token, which would change how every accepted program
    with adjacent dots lexes.
- **Mixing with other entries.** Keyed, shorthand and spread entries mix in
  any order. A spread is followed by a comma, by the closing brace, or
  directly by a keyed entry, as [NUC 44](nuc-0044.md) lets a keyed entry
  follow any complete value. A spread that follows a value needs a comma,
  because the value parser reads the dots as a member access and NUC 44 does
  not stop a value early, so `{y: 2 ...a}` keeps its accepted error.
  Shorthand entries ([NUC 17](nuc-0017.md)) keep needing a comma or the
  closing brace after them, and one trailing comma is allowed.
- **Expressions only.** A brace that begins a statement stays a block, and an
  anonymous arrow body in braces stays a block; `({...a})`, `lambda p: {...p}`
  and named arrows such as `def f p => {...p}` write objects. NUC 67's
  destructuring patterns are statements and are unchanged:
  `{x, ...rest} = p` still raises `SyntaxError("Unexpected ','")`.
- **A separate syntax-tree variant.** A literal holding at least one spread
  parses to `Expr::SpreadObject(Vec<ObjectEntry>)`. Every other literal keeps
  `Expr::ObjectLiteral(Vec<(String, Expr)>)` with its exact syntax tree and
  `Debug` text, which existing tests construct and the historical seals
  hash. Rejected: changing the entries of `ObjectLiteral`, which would break
  those tests and every downstream match.
- **Left to right, later wins, first position kept.** Entries apply in source
  order, and a key keeps the position it first took, as a repeated key does
  in an accepted literal, where `{x: a.x, y: a.y, x: 9}` lists `x` first.
  JavaScript and Python order merged keys the same way. Entry loops, the
  only channel that shows order, therefore list `x` first in
  `{...point, x: 5}`.
- **The entries an entry loop visits.** A spread copies what NUC 72 calls an
  object's entries: an instance's `id` first, then its other properties in
  the order they were stored; `null` values; not undefined slots. JSON
  serialization and deep equality see the same entries. A copy is shallow: a
  nested object or list is the same value in both records.
- **Copied `null` values stay values.** A spread reads entries, not bindings,
  as [NUC 80](nuc-0080.md)'s `average()` reads items without settling a
  declaration to `null`. The null-read rule keeps a `null` read from being
  coerced, and a copied `null` is not coerced. Rejected: the rule for copied
  values, under which `{...defaults, size: 3}` would be `null` whenever
  `defaults` held any `null`, even one the override replaces.
- **Unknown sources wait.** A `null` source holds no entries, and reading it is
  a null read like any other, so `card = {...owner, seen: true}` is `null`
  while `owner` is `null` and becomes a record when `owner` holds one, as
  `{name: owner.name seen: true}` does. An undefined source, such as a
  property never set, holds no entries: `{...box.lid, open: false}` is
  `{open: false}` until `box.lid` is set, as `{color: box.lid.color open: false}` is.
  - Rejected: `TypeError` for `null` and undefined sources, as entry loops
    raise. A loop is a one-shot action, for which an unknown source is an
    error; a declaration stands, and an error would fail it when declared
    instead of letting it follow its source. JavaScript also copies nothing
    from `null` and `undefined`.
- **Other values are errors.** Lists, strings, numbers, booleans, classes,
  functions, dates and regular expressions raise
  `TypeError("<source> is not an object")`, with the source in canonical
  form, as entry loops do. JavaScript copies the indices of lists and strings
  and nothing from other values; Python raises `TypeError` for all of them.
  Rejected: copying indices, which would key an object `"0"`, `"1"`, a shape
  no accepted program builds; an error can become behavior later without
  breaking programs that depend on it.
- **The declared property is left out.** While a property declaration
  evaluates its value, a spread of the object that owns the property skips
  it. A declaration never depends on itself: the runtime already removes its
  own key from its dependencies, and a class-level rule that reads its own
  destination raises `TypeError("Circular Dependency")`. Without the skip,
  `$Order.view = {...$Order, paid: false}` would copy the previous view into
  each new one, nesting one more copy at every change.
  - Variables need no skip, because a variable is not an entry of an object.
  - An assignment used as an expression evaluates its value before its
    target, as accepted, so it has no declared property while the value is
    evaluated and copies every entry. Evaluating the target first would
    change accepted programs.
- **Live like the explicit record.** A spread depends on each entry it reads,
  as `{x: a.x}` depends on `a.x`, except an entry that a later keyed entry of
  the same literal replaces, which cannot reach the result. `why` therefore
  lists exactly the dependencies of the explicit record that names the same
  entries. One new observation covers what no accepted read can, the set of
  an object's entries: it is recorded beside the graph-shape observations of
  reasoning, touched only when that object gains or loses an entry, and
  queued as a shape change is.
  - Rejected: a snapshot, which would silently diverge from its source as the
    model grows.
  - Rejected: a hidden graph node for the entry set, which `--graph` would list
    as a pending node and `why`'s `from` lists and `model |> why` would show,
    so equivalent programs would reflect differently.
  - Rejected: treating a spreading declaration as a reasoning observer. It is
    an ordinary declaration and stays in `model` and in `why` traversals.
- **Accepted propagation is untouched.** No accepted program records an
  entry-set observation, so the observers a key-set change consults are
  always none, and nothing is queued or drained that was not before. The
  only cost to accepted programs is one lookup when an object gains or loses
  a key.
- **Evaluate once, render once.** Each source is evaluated once per evaluation
  of the literal and rendered once in graph keys, block keys and `why` rules,
  so cost and rendered size stay linear in the source. NUC 67's destructuring
  copies its value into every target; a spread copies nothing in the syntax
  tree, and nested spreads and default-bearing functions render linearly.
- **Not added.** List spread `[...xs]`, which `xs.concat(...)` already writes
  in fewer tokens; call-site spread `f(...xs)`, whose syntax error accepted
  tests pin; rest patterns such as `{x, ...rest} = p`; computed keys
  `{[k]: v}`; `Object.assign`, `Object.keys` and similar helpers; deep
  copies; spreading lists or strings into indices; comma-free spreads after a
  value; omitting keys other than the declared property; spreads in
  parameter defaults; and spreads in statement-leading braces.

### Counterparts

- Every new case is paired with the most compact behavior-equivalent accepted
  program found: the same canonical assertions in the same order and the
  same expected return, executed by the accepted runtime with every
  assertion running. Counterparts keep every line that holds no spread byte
  for byte and make no constant or hand-evaluated substitution: every copied
  value is read from its source at run time.

## Specification

### Syntax

- An object literal entry is a keyed entry `key: value`, a shorthand entry
  `name`, or a spread entry `...SOURCE`. A spread entry begins with three
  `Dot` tokens at consecutive columns of one line, where a key could begin:
  first in the braces or after a comma, with the line breaks a key allows
  before it.
- `SOURCE` is one expression, parsed as an entry's value is. It ends at a
  comma, at the closing brace, or before a following keyed entry written
  without a comma.
- A spread is followed by a comma, by the closing brace, or directly by a
  keyed entry, as in `{...base qty: 1}`. An entry that follows a value needs a
  comma before a spread, and so does a spread that follows a spread. One
  trailing comma is allowed: `{tag, ...base stock: 0,}`.
- Spreads are allowed in every object literal written as an expression:
  assignment values, arguments, list items, returns, named-arrow bodies,
  `lambda` bodies, parenthesized expressions, template interpolations, nested
  literals, constructors, methods, class-level rules, blocks, branches,
  loops, `try` and `suppose` suites.
- A brace that begins a statement stays a block and an anonymous arrow body
  in braces stays a block. Lists, calls, parameter defaults and destructuring
  patterns are unchanged.
- A literal with at least one spread parses to
  `Expr::SpreadObject(Vec<ObjectEntry>)`, whose entries are
  `ObjectEntry::Property(key, value)` and `ObjectEntry::Spread(source)` in
  source order. A literal without one keeps `Expr::ObjectLiteral` exactly as
  before.

### Evaluation

- The entries are evaluated once each, from left to right. A keyed entry
  stores its value under its key. A spread evaluates its source once and
  copies the source's entries in their insertion order. The result is a new
  object that belongs to no class, as every object literal is.
- The entries copied are exactly those an entry loop visits: an instance's
  `id` first, then the properties its constructor assigns, its class-level
  rules derive and later assignments store, in the order each was first
  stored; every property of a literal or other object whose value is not
  undefined, including `null` values. A slot whose value is undefined is not
  an entry and is not copied.
- A copied value is the value itself, so an object or list it holds is the
  same value in both records.
- An entry for a key the object already holds replaces its value and keeps
  the key's first position: with `point = {x: 1, y: 2}`, `{...point, x: 5}`
  lists `x` then `y` with `x` 5, and `{x: 9, ...point}` lists `x` then `y`
  with `x` 1.
- Copying an entry is not a read of a binding, so a copied `null` does not
  settle a declaration to `null`. The source expression's reads follow the
  existing rules.

```
base = {name: "tea", price: 4, stock: 10}
sale = {...base, price: 3, tag: "sale"}
floor = {price: 9, ...base}
assert: [sale, floor], [{name: "tea", price: 3, stock: 10, tag: "sale"}, {price: 4, name: "tea", stock: 10}]
assert: [sale == base, floor == base, base.tag], [false, false, null]
```

### Sources

- An object source, whatever produced it, has entries: an object literal, an
  instance, an object a function or method returns, the step objects `why`
  and the reasoning stages return, a `suppose` block's escaped copy, and
  every other object. Inside a class-level rule `$Class` is the instance and
  can be spread.
- A `null` source copies nothing. Reading a `null` binding or property is a
  null read as everywhere, so a declaration whose source reads `null` stores
  `null` until its source holds an object. The literal `null` is not a read,
  so `{...null, y: 1}` is `{y: 1}`.
- An undefined source, such as a property that was never set, copies
  nothing, and the declaration follows the property when it is set.
- An undefined name raises `ReferenceError("<name> is not defined")`, as
  before.
- Every other source raises `TypeError("<source> is not an object")`, where
  `<source>` is the source expression in canonical form: a list, a string, a
  number, a boolean, a class outside a class-level rule, a function, a date
  and a regular expression. After `sizes = [1, 2]`, `{...sizes}` raises
  `TypeError("sizes is not an object")`, and `{..."ab"}` raises
  `TypeError("\"ab\" is not an object")`. The error is positioned at the
  running top-level statement and rolls back its transaction.

```
owner = null
card = {...owner, seen: true}
assert: card, null
owner = {name: "ada", role: "dev"}
assert: card, {name: "ada", role: "dev", seen: true}
box = {}
packed = {...box.lid, open: false}
assert: packed, {open: false}
box.lid = {color: "tan", size: 3}
assert: packed, {color: "tan", size: 3, open: false}
```

### The declared property

- While a property declaration evaluates its value, a spread of the object
  that owns the declared property leaves that property out, neither copying
  it nor depending on it. This holds for property statements at the top
  level and in blocks, branches and loops, constructor statements such as
  `this.copy = {...this}`, class-level rules applied to each instance, value
  assignments such as `cart.copy := {...cart}`, and the functions and
  methods their values call.
- An assignment used as an expression, such as the body of
  `v -> (o.v = {...o})`, is not a declaration while its value is evaluated
  and copies every entry, including the property's previous value.

```
class Order(total, items):
    this.total = total
    this.items = items
$Order.view = {...$Order, paid: false}
order = Order(10, 2)
order.total = 12
order.total = 14
assert: order.view, {id: "order", total: 14, items: 2, paid: false}
```

### Dependencies

- Evaluating a source records its reads as usual. A spread then depends on
  every entry it reads, `<object id>.<key>`, including undefined slots,
  except an entry that a later keyed entry of the same literal replaces, and
  observes the set of entries of the source object.
- In a standing declaration, changing a copied entry, deleting an entry,
  adding an entry, and replacing the binding the source reads each evaluate
  the declaration again. An object gains or loses an entry when a property
  it did not hold is assigned, a constructor or class-level rule stores a new
  property, a property is deleted, or a named instance is created again or
  deleted. Rollback restores entries and observations together and queues
  nothing.
- A declaration that spreads therefore stays equal to the explicit record
  that names every entry its source holds, now or later. Evaluating it again
  creates a new object, as every object literal declaration does, so
  properties assigned to the derived record itself are lost, as they are for
  `b = {x: a.x}`.
- `.value` freezes as everywhere: `{...a.value}` copies from the object `a`
  holds when the declaration is stored, follows that object's entries, and
  does not follow a later binding of `a`. A value assignment such as
  `b := {...a}` copies once and observes nothing.
- Two class-level rules that spread the same receiver read each other's
  properties, which raises `TypeError("Circular Dependency")` when an
  instance applies both: when an instance is created after both rules, or
  when the second rule is declared over existing instances. The failing
  statement rolls back. Rules that read each other explicitly fail earlier,
  when the second rule is declared, because their reads are static.

```
base = {name: "tea", price: 4}
item = {...base, qty: 2}
line = {...item, total: item.price * item.qty}
base.price = 5
base.size = "large"
delete base.name
assert: line, {price: 5, size: "large", qty: 2, total: 10}
```

### Transactions

- A literal with spreads creates its object as every object literal does,
  and a declaration that spreads is filed, evaluated again and rolled back as
  every declaration is. Entry-set observations are recorded in the
  transaction with the graph-shape observations of reasoning, so rollback
  restores them.
- A caught failure in `try`, a failed top-level statement, the end of a
  `suppose` block and an error inside one leave every object's entries in
  their order, every spread record's value and every observation exactly as
  they were. A source change whose re-evaluation fails rolls back with it.

### Rendering and reflection

- Graph and block keys, conditions and `why` rules render a spread as `...`
  followed by its source in canonical form, between the quoted keyed
  entries: `view = {...lab,"unit":"C"}`. Each source renders once, so
  rendered size stays linear in the source, and the rendering parses back to
  the same literal. Default-bearing declarations render spreads inside their
  suite form, as in `return {...o,"n":n}`.
- Entry-set observations are not graph nodes or value dependencies. `why`
  lists the same `from` dependencies as the explicit record naming the same
  entries, `affects`, `model` and every reasoning stage are unchanged, and a
  declaration that spreads stays an ordinary declaration rather than a
  reasoning observer. The `--graph` listing and the terminal graph view show
  each observation under `observes` as `{...<object id>}`.

### Compatibility

- The lexer and its tokens are unchanged, and every accepted program keeps
  its parse, positions, diagnostics and behavior. An accepted program records
  no entry-set observation, so every key-set change it makes finds no
  observer and queues nothing.
- These inputs keep their exact accepted results. Each source starts with the
  line `a = {x: 1}` unless it says otherwise and ends without a final newline:

| Exact second line, or source | Unchanged result |
| --- | --- |
| `b = {..a}` | `SyntaxError("Expected a key but found '.'")`, line 2, column 7 |
| `b = {. . .a}` | `SyntaxError("Expected a key but found '.'")`, line 2, column 8 |
| `b = {...5}`, which lexes as two dots and `.5` | `SyntaxError("Expected a key but found '.'")`, line 2, column 7 |
| `b = {y: 2 ...a}` | `SyntaxError("Expected a property but found '.'")`, line 2, column 13 |
| `b = {y: 2...a}` | `SyntaxError("Expected a property but found '.'")`, line 2, column 12 |
| `b = {y: 2; ...a}` | `SyntaxError("Expected '}' but found '.'")`, line 2, column 12 |

## Reference Implementation

- `src/lang/ast/mod.rs`: the public variant
  `Expr::SpreadObject(Vec<ObjectEntry>)` and the public enum
  `ObjectEntry { Property(String, Expr), Spread(Expr) }`, whose `value`
  returns either entry's expression. `contains_reasoning` looks through
  spread entries, and the evaluator sends the variant to the existing
  object-literal node.
- `src/lang/ast/parser.rs`: `object_literal` reads each entry through
  `object_entry`, which recognizes three adjacent dots with NUC 74's
  `starts_rest_parameter` check where a key would be read and parses the
  source as an entry value. The key and value code moved into `object_entry`
  unchanged, without its comment, and the separator handling after an entry
  is untouched. `object_expression` builds `Expr::SpreadObject` only when an
  entry is a spread, so every other literal is the `Expr::ObjectLiteral` it
  was.
- `src/lang/ast/object.rs`: `Object::resolve` sends `Expr::ObjectLiteral`
  and `Expr::SpreadObject` to their evaluators and returns the existing
  `<node> is not an object` error for any other node, as `Array::resolve`
  does for lists. `evaluate_spread_object` evaluates the entries from left to
  right. `spread_entries` matches every `Value` variant: it rejects a source
  that is not an object, `null` or undefined with NUC 72's message, copies
  nothing from `null` and undefined, records the source's `ShapeKey::Entries`
  observation, and walks the source's properties in order. It skips the
  declared property, tracks every other slot unless a later keyed entry of
  the same literal replaces it, and copies every value that is not
  undefined.
- `src/lang/evaluation.rs`: each tracking frame records the key its
  assignment declares as `target`, and `anchored` marks a declaration of a
  property of the active class-level receiver, the slot the existing
  self-anchor rule watches, in place of the second key the frame held
  before. `evaluate_assignment` takes
  the declared key by value and removes `frame.target` from the
  declaration's dependencies, as it removed the excluded key before.
  `Runtime::declares` finds a declared key among the frames a read reaches.
  `track`, `track_property_version`, `track_shape` and `declares` share that
  rule through `Tracking::reachable`, `reachable_mut` and `barrier`: the
  frames from the innermost isolated frame inward, or every frame when none
  is isolated. Re-evaluations, value assignments and `suppose` blocks run
  behind an isolated frame, so a statement they run never sees the key of a
  declaration around them. The unit test
  `reads_reach_every_frame_up_to_the_innermost_isolated_frame` pins the rule
  for all four functions.
- `src/graph.rs`: the public `ShapeKey::Entries(ObjectId)`, displayed as
  `{...<id>}`. `is_observer` counts only node and model observations, so a
  declaration that spreads stays an ordinary declaration, and
  `dependencies_into` skips entry observations, which therefore never order
  the propagation queue.
- `src/state.rs`: `assign_property` for a key the object did not hold,
  `remove_property` for a key it held, `insert_object` when a named object
  gains or loses keys, and `remove_object` for an object with keys queue the
  observers of that object's entries through the existing
  `queue_shape_change`. Rollback restores state and observations directly and
  queues nothing.
- `src/lang/ast/generator.rs`, `src/expression.rs` and
  `src/nuc/expression.rs` render, walk and freeze the new variant as they do
  object literals, rendering each source once.
