# NUC 31 -- Implicit Iterator Indented Loops

```
NUC: 31
Title: Implicit Iterator Indented Loops
Author: Copilot <223556219+Copilot@users.noreply.github.com>
Status: Accepted
Type: Standards Track
Category: Syntax enhancement
Created: 15-Oct-2026
```

## Abstract

- Optionally spell `for it of NAME:` with a genuine indented body as `for NAME:` with that same body.
- `NAME` is exactly one ordinary identifier used as the iterable expression; the iteration variable is the existing local name `it`.
- Lower to the existing `Stmt::For` without adding tokens, public AST variants, runtime types or general iterable support.
- Preserve all accepted explicit `of`/`in` loops, source expressions, suites, diagnostics and behavior.

## Motivation

- Named class populations and lists often need only the conventional iteration binding `it`.
- Omit the repeated `it of` header while preserving the complete executed body.
- Prepare only the caller-selected syntax improvement, retaining category draw `0` without another draw or a pending proposal dependency.

## Rationale

- Inspect the complete immediate identifier/real-indented-colon path before consuming the old explicit variable.
- Reuse the allocation-free real-indented-suite predicate already required by accepted bare single-untyped, single-typed and multiple-parameter function blocks.
- Keep the exact colon, immediate newline/indent and subsequent real-indent predicates; `:;` must not qualify.
- Leave expression and body parsing to their existing parsers rather than speculating, catching errors, rewinding or cloning an AST.
- Do not infer an omitted source, general expression source, inline/braced body, callable invocation or new iteration behavior.
- The accepted root specification and `src/nuc/for.rs` govern existing loops; no Draft NUC is a required dependency.

## Specification

### Grammar and lowering

- The authoritative [implicit iterator indented loops](../nucleoid.spec.md#implicit-iterator-indented-loops) section specifies the accepted grammar and inherited behavior.
- Consume `for` exactly as before, then non-consumingly recognize `Identifier Colon`.
- Require the token immediately after the colon to be `Newline` or `Indent`.
- Starting immediately after the colon, inspect only existing `Newline`/`Semicolon` layout; the first other token must be a real `Indent`.
- Do not skip logical header breaks or separators before the identifier or colon.
- Blank/comment lines and normal body separators remain accepted suite layout; an immediate semicolon after the colon never qualifies.
- After qualification, select variable string `it`, parse `NAME` through ordinary `expression()` and parse the entire body through unchanged `suite()`.
- Produce exactly `Stmt::For { variable: "it", iterable: Expr::Identifier(NAME), body }` of the corresponding explicit `for it of NAME:` program.
- Preserve the complete body AST, top-level statement positions and canonical `for it of NAME` generation; nested statements and graph keys retain the explicit form.
- On failed lookahead, consume nothing and run the original ordinary-variable/`of`/`in` path, with its exact messages and positions.
- Retain all explicit `for variable of expression` and `for variable in expression` forms, arbitrary source expressions and inline/braced/indented suites.
- Add no omitted-source, inline/braced/missing-indent, parenthesized, property/index/call/literal/class-reference or other expression-source shorthand.
- Introduce no keyword/token/public AST/runtime/generator/API, dependency, MSRV or project-version changes.

### Existing loop behavior

- Evaluate the source once, before declaring the iteration binding, and walk its current snapshot once.
- A class value supplies the current ordered registered instances; a list supplies only object references still registered with a class.
- Skip primitives, null elements, unregistered references, plain `Object()` instances and literal objects in lists, preserving order and duplicate visits.
- This is not primitive-array iteration, a standing/reactive declaration or callable auto-invocation.
- Later body/source mutations do not extend the snapshot; later dependency changes or new instances do not re-run the body.
- Each visited instance pushes a scope, declares local `it` and enters imperative mode; completion, return and error restore the mode and scope.
- Nested `it` shadows and restores outer/global bindings. `for it:` evaluates its outer source named `it` before introducing the inner binding.
- `this`/`self`, methods, inherited behavior, graph/value/shape dependencies, transactions and rollback remain those of explicit loops.
- Multiple statements, conditions, nested loops and blocks retain accepted control flow.
- Explicit/bare returns propagate out of the loop; an empty or normally completed loop yields `null`. No implicit final-expression return or new closure capture is added.
- Existing body nesting, operand, postfix and runtime limits remain unchanged.
- Extracting the shared guard preserves all accepted single/multiple, typed/untyped function block and arrow predicates, parameter grammar, suite grammar and diagnostics.

### Executable cases and synchronization

- Append exactly the eight caller-supplied, pre-executed accepted-syntax counterparts: five specification cases and one each for reference, README and examples.
- Rewrite only their eligible `for it of NAME:` headers to `for NAME:`.
- Preserve every source/body/assertion line otherwise, case identity, per-document order, expected return and executed assertion coverage.
- Preserve all 483 historical measured programs exactly; no historical header qualifies for this rewrite.
- The resulting preparation corpus has 333 specification, 67 reference, 18 README and 73 examples cases: 491 total.
- The 35 new protected assertions actually execute, including both rollback catches. Return-flow expects `2`; rollback/recovery expects `14`.
- Keep current reference prose synchronized and source-regenerate specification JSONL and exported Rust tests.
- Preserve all 1,081 synthesized records and ARC byte-for-byte; no eligible historical training header exists, so add no artificial training records or Markdown mirrors.

- The first new specification case, without its title comment, is:

```nuc
class Entry
first = Entry()
first.amount = 2
second = Entry()
second.amount = 5
values = [first, 99, second, null, { amount: 9 }]
seen = []
total = 0
for values:
    seen.push(it.amount)
    total += it.amount
assert(seen, [2, 5])
assert(total, 7)
empty = []
for empty:
    total += 100
assert(total, 7)
```

## Errors

- Introduce no new error kind or message.
- Nonqualifying prefixes retain the original explicit-loop diagnostics; qualification never swallows a body error.
- Exact error examples and inherited runtime/resource errors follow the normative section.

| Exact input or condition | Exact error | Position |
| --- | --- | --- |
| `for values:` at EOF, with no indent, with only comments, with an inline/braced body or with immediate `:;` | `SyntaxError("Expected 'of' in for statement")` | line 1, column 11 |
| `for values.items:`, `for values[0]:` or `for values():` | `SyntaxError("Expected 'of' in for statement")` | line 1, column 11 |
| `for values` followed by a logical newline before the colon | `SyntaxError("Expected 'of' in for statement")` | line 1, column 5 |
| `for (values):` | `SyntaxError("Expected a name but found '('")` | line 1, column 6 |
| `for :` | `SyntaxError("Expected a name but found ':'")` | line 1, column 6 |
| Qualifying `for values:` followed by four-space-indented `it.amount +)` | `SyntaxError("Unexpected ')'")` | line 2, column 17 |
| Qualifying header followed by four-space-indented `it.amount = @` | `SyntaxError("Unexpected character '@'")` | line 2, column 17 |
| Undefined named source `missing` | `ReferenceError("missing is not defined")` | existing enclosing top-level statement position |
| Noniterable named source `broken`, including literal null | `TypeError("broken is not iterable")` | existing enclosing top-level statement position |
| Evaluated undefined body name `missing` | `ReferenceError("missing is not defined")` | existing enclosing top-level statement position |
| Unbound body receiver `this` or `self` | `ReferenceError("this is not defined")` | existing enclosing top-level statement position |
| Excessive body expression nesting | `SyntaxError("Expressions are nested too deeply")` | existing expression position |
| Excessive body operand chain | `SyntaxError("Expression has too many operands")` | existing expression position |
| Excessive body postfix chain | `SyntaxError("Expression has too many parts")` | existing expression position |
| Excessive statement nesting | `SyntaxError("Statements are nested too deeply")` | existing statement position |

- Lexical errors still precede parsing; a shorter header does not change later physical body-line positions.
- A thrown value, caught error without a position, failed transaction and subsequent recovery retain explicit-loop behavior.
- Literal null as a named source raises the existing noniterable error, rather than silently deferring or skipping the loop.
