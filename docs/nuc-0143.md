# NUC 143 -- Reactive Squaring

```

Title: Reactive Squaring
Author: Copilot <223556219+Copilot@users.noreply.github.com>

Category: Utility enhancement
Created: 25-Nov-2026
```

## Abstract

- Add only native static `Math.square(value)` as a bounded numeric utility:
  intrinsically convert the first value, then multiply that converted value
  by itself with ordinary `f64` multiplication.
- Preserve Math's supplied-Undefined gate, eager argument evaluation,
  numerically ignored extras, dependencies, deferral, shadowing and rollback.
- The caller's one uniform draw from the live eligible registry selected
  Utility enhancement. This continuous proposal requires paired lexer-token
  comparison and every hard criterion.
- **Accepted:** every hard criterion and independent policy check passed.
  The caller integrated the unchanged frozen candidate and rechecked the
  hard criteria before recording this outcome.

## Motivation

- Reactive squared magnitudes and error terms repeat a computed quantity on
  both sides of multiplication. A named helper evaluates that argument once
  while retaining ordinary multiplication's rounding and overflow behavior.
- The accepted native runtime rejects `Math.square(3 + 2)`, while the
  independent accepted expression `(3 + 2) * (3 + 2)` returns `25`.
- Request no exponentiation replacement, aliases, grammar change, new public
  Rust API, dependency, option, version change or ARC change.

## Rationale

- A standard numeric built-in is a Utility enhancement, not an optional
  cross-language alias. Preserve the caller's confirmed category and its
  one uniform draw from the live five eligible categories, 20% each.
- Reuse Math's intrinsic first-value conversion and unary dispatcher with
  one added arm, `first * first`. Keep the argument evaluator, parser,
  dependency graph, scope and transaction machinery unchanged.
- A repeated expression is a useful accepted numeric counterpart, not a
  promise to duplicate its side effects: this helper evaluates its argument
  once. Do not lower it to `powf`, exponentiation, shadowable `Number`/Math
  helpers, fused arithmetic or another numerical model.
- Limit the feature to native static `Math.square(value)`. Do not add a
  global or lowercase alias, receiver method, population/list aggregate,
  configuration, public Rust API, dependency, version or ARC change.

## Specification

- The normative contract is
  [Reactive squaring](../nucleoid.spec.md#reactive-squaring), demonstrated by
  `Nucleoid keeps squares reactive` and
  `Nucleoid preserves squaring argument dependencies`.
- Evaluate every supplied expression exactly once, left to right, using
  ordinary native Math dispatch. Preserve every expression's effects,
  strict errors, reads and subscriptions, including extras and expressions
  after a supplied Undefined.
- Retain the pre-conversion any-supplied-top-level-Undefined gate, including
  extras. Such calls return Undefined. Nested Undefined does not trigger
  this gate; it participates in the existing intrinsic conversion instead.
- Otherwise intrinsically convert only the first supplied value with
  `Value::to_number` and return exactly `first * first` using ordinary
  `f64` multiplication. Omission supplies numeric NaN.
- Keep numeric, literal-null zero, Boolean, trimmed numeric text,
  empty/singleton list and millisecond-date coercions. Invalid conversions
  give numeric NaN, not new errors. Extras are not converted or used
  numerically, even when they are NaN.
- Non-NaN results retain ordinary multiplication bits: both zero signs
  square to positive zero; finite values may round, underflow to a
  subnormal or positive zero, or overflow to positive infinity; either
  infinity sign squares to positive infinity. NaNs are classified as NaN
  without payload or sign promises.
- Literal-null conversion does not override live-input or parameter-null
  deferral. Named functions, independent class rules and instances,
  deletion/recovery, captured values/classes, ordinary AST/graph source,
  call frames and existing transaction rollback behavior remain unchanged.
  Inherited graph-dependent rollback ordering limitations are not repaired.
- Conversion never resolves shadowable `Number` or another Math helper.
  State/local `Math` bindings and ordinary `.Math`/`.square` members keep
  ordinary lookup. Native `Math.square` value reads stay Undefined and
  non-callable.
- Only formerly failing native `Math.square(...)` calls gain these results.
  Previously successful calls gated by supplied Undefined remain successful
  Undefined; accepted shadowed-member calls and all other native names keep
  their behavior. The repeated-multiplication spelling stays supported.
- Preserve every historical executable case, assertion, expected return
  and coverage. Add exactly the caller's two paired measured programs,
  changing only their squared-expression construction; each retains six
  canonical assertions in order and explicit expected return `1`.

```
sample = {amplitude: 3}
offset = 2
squared = Math.square(sample.amplitude + offset)
assert(squared, 25)
sample.amplitude = -4
assert(squared, 4)
offset = 1
assert(squared, 9)
sample.amplitude = 0
assert(squared, 1)
offset = -1
assert(squared, 1)
sample.amplitude = 3
assert(squared, 4)
1
```

## Errors

- Add no arity, conversion, range or numeric errors.
- Strict missing reads keep `ReferenceError("<name> is not defined")`,
  including ignored extras and arguments following Undefined. The first
  failed eager argument still stops later arguments.
- Unsupported native names keep
  `TypeError("Math.<name> is not a function")`, and `Math.random()` keeps
  `TypeError("Math.random is not supported")`, after the unchanged gate.
- A numeric `Math = 7` binding keeps
  `TypeError("number.square is not a function")`. Unsupported list and
  population members retain their ordinary receiver-specific errors.
- Error positions, caught values, frames and rollback retain existing
  behavior; no error is intercepted or converted into a numeric result.

## Reference Implementation

- The isolated prototype adds only `"square" => first * first` to
  `src/builtins/numeric.rs`'s existing unary match. The supplied-Undefined
  gate and first-value conversion remain before that dispatcher.
- Focused native regressions compare value-kind conversion and boundary/
  sampled `f64` results to accepted multiplication, and exercise ignored
  extras, eager effects/errors, subscriptions, deferral, shadowing, captured
  values/classes, ordinary AST/graph source, frames, independent class rules
  and bounded rollback/recovery shapes.
- The two measured source programs, language-reference prose and quick
  reference, README prose, four self-contained synthesized JSONL records
  and source-generated specification exports are synchronized.
- No lexer/parser acceptance changes: `docs/nucleoid.ebnf` is unchanged.
