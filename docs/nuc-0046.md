# NUC 46 -- Colon-Free Indented Exception Suites

```
NUC: 46
Title: Colon-Free Indented Exception Suites
Author: Can Mingir <canmingir@gmail.com>
Status: Accepted
Type: Standards Track
Category: Syntax enhancement
Created: 16-Oct-2026
```

## Abstract

- Optionally omit the suite colon after `try` or a complete existing `catch`
  header only before a genuine indented body; each clause qualifies separately.
- Preserve exactly `Stmt::Try { body, parameter, catch }`, all accepted forms,
  the canonical generator and the existing transactional runtime.
- The accepted contract is
  [Colon-free indented exception suites](../nucleoid.spec.md#colon-free-indented-exception-suites).

## Motivation

- Transactional error recovery is fundamental to reactive models: failed
  updates must leave existing relationships usable before recovery continues.
- Recent accepted NUCs covered list projection, text replacement, conditional
  alternatives, explicit records and assertion spelling. Exception suites
  broaden that coverage without another math utility or function-header variant.
- Existing catch bindings, rollback and return flow already provide the
  semantics. Removing redundant fixed-header punctuation adds no runtime API.

## Rationale

- Retain the caller's single sealed syntax-improvement draw and bounded feature
  selection. Reasoning, dependencies, functions/scope, control flow,
  collections/text, modeling and diagnostics were considered; no redraw,
  deterministic rotation, math ban, quota or weaker compatibility rule is used.
- Reuse `has_indented_body` and `suite_body`, not a new whitespace grammar,
  speculative parse, token normalization, catch-all suite relaxation or rewind.
- Give explicit colons their original path first. Failed qualification must
  consume nothing and retain the original colon expectation and diagnostics.
- Keep independent optionality: an inline clause can retain its required colon
  while the other clause omits one before an indented suite.
- Preserve all 603 historical measured programs and all 27 earlier training
  files. Append only the eight already pre-executed accepted counterparts;
  remove only their qualifying exception-header colons.
- Already implemented exception behavior is the accepted baseline. No pending
  NUC, new throw/scope semantics, finally clause, filter or multi-catch is needed.

## Specification

- Consume the existing `Try` keyword. If the next token is `Colon`, use the
  original `suite()` parser, preserving every accepted body form.
- Otherwise qualify without consuming: the immediate token is `Newline` or
  `Indent`, and the first token after only `Newline`/`Semicolon` layout is
  `Indent`. On success call the existing `suite_body()`; on failure call the
  original colon-required `suite()`.
- Keep complete catch association after the try body, including the existing
  newline/semicolon handling and the required `Catch` token.
- Parse catch parameters exactly as before: one ordinary identifier, or an
  identifier inside parentheses, or the default name `error`. Do not skip new
  header layout or accept expressions, annotations or multiple names.
- After that complete header, apply the same explicit-colon priority and
  real-indentation qualification independently to the catch body.
- Keep the entire ordered body/catch AST, nested associations, statement depth,
  expression/operator/postfix budgets, canonical keys and top-level positions.
  The existing generator's key for a Try remains `try`; no new renderer or
  public representation is introduced.
- Blank lines and comments do not create a body; LF, CRLF and accepted tabs
  use existing lexer layout. A same-line semicolon is not a newline.
  Inline statements and bare braced suites do not qualify without a colon.
- All colon-bearing inline, braced, semicolon-separated and indented forms
  remain supported. Other conditional, loop, class and function headers retain
  their own accepted qualification rules; `suite()` is not relaxed globally.
- In the native REPL, a complete lexical bare `try` header starts the existing
  multiline buffer, including accepted layout and trailing comments. Its catch
  remains in that submission; a standalone `catch` starts no new buffer.
  Blank-line commit and EOF flush run the original source through the parser.
- Strings, templates, regex text, comment-only lines, identifier prefixes,
  assignments, extra header tokens and lexical errors do not qualify as bare
  `try` headers. Existing colon/arrow buffering and command handling are
  unchanged; malformed committed suites still print their actual errors.
- Keep the original savepoints, globals/locals, rollback, pending propagation
  and deletion tracking, dependency graph, class rules and instances, actual
  thrown values/errors, return flow, receivers, noncapture, snapshots and
  reasoning. Inherited runtime, source-column and host-stack limitations are
  neither repaired nor presented as new behavior.
- Trace values/default and parenthesized bindings to
  `Nucleoid catches thrown values with colon-free indented suites`.
- Trace dependency restoration and return `12` to
  `Nucleoid restores dependencies through colon-free exception suites`.
- Trace nesting to
  `Nucleoid preserves nested catch association without suite colons`;
  trace function returns to
  `Nucleoid preserves function returns through compact exception suites`.
- Trace rule rollback to
  `Nucleoid rolls back class rules with colon-free catch suites`.
  Those five spec entries preserve sixteen executed checks.
- The exact appended reference, README and examples counterparts preserve
  eleven more checks and the examples return `true`. The reference retains
  both inline colons and uses its two indented pairs for opposite independent
  omissions; no assertion, title, expected return or coverage is weakened.
- This is the dependency-restoration entry without its title comment:

```
source = 2
derived = source * 3
try
    source = 9
    throw "ABORT"
catch failure
    assert(failure, "ABORT")
assert(source, 2)
assert(derived, 6)
source = 4
assert(derived, 12)
derived
```

## Errors

- No new error kind, runtime error message or exception value is introduced.
  Invalid nonqualifying prefixes retain the original colon-required path.
- Exact `try` raises `SyntaxError("Expected ':' but found end of input")`
  at line 1, column 4. Exact `try\n` raises
  `SyntaxError("Expected ':' but found end of line")` at line 1, column 1.
- Exact `try;\n    pass\ncatch: pass` raises
  `SyntaxError("Expected ':' but found ';'")` at line 1, column 4.
  Exact `try pass\ncatch: pass` raises
  `SyntaxError("Expected ':' but found keyword 'pass'")` at line 1, column 5.
- Exact `try: pass\ncatch` raises
  `SyntaxError("Expected ':' but found end of input")` at line 2, column 6.
  Exact `try: pass\ncatch issue pass` raises
  `SyntaxError("Expected ':' but found keyword 'pass'")` at line 2, column 13.
- Exact `try: pass\ncatch (issue, other): pass` retains
  `SyntaxError("Expected ')' but found ','")` at line 2, column 13.
  Malformed bindings otherwise keep the existing
  `Expected a name but found <token>`/`Expected ')' but found <token>` diagnostics.
- Exact `try:\npass\ncatch: pass` retains
  `SyntaxError("Expected an indented block but found keyword 'pass'")`
  at line 2, column 1. A qualified try still requires its catch:
  missing or unrelated headers use `SyntaxError("Expected 'catch' after 'try'")`.
- Exact `try: pass\ncatch\n    value = (1 +)` raises
  `SyntaxError("Unexpected ')'")` at line 3, column 18. Exact
  `try\n    value = (1 +)\ncatch: pass` retains the inherited next-newline
  position at line 2, column 17. Both match their colon-bearing controls.
  Four-space-indented `value = @` raises
  `SyntaxError("Unexpected character '@'")` at column 13.
- Unsupported Unicode whitespace retains its existing lexical error.
  Resource errors remain `SyntaxError("Statements are nested too deeply")`,
  `SyntaxError("Expressions are nested too deeply")`,
  `SyntaxError("Expression has too many operands")` and
  `SyntaxError("Expression has too many parts")`.
- Ordinary missing reads retain `ReferenceError("NAME is not defined")`;
  catch bindings still receive the complete existing thrown value or error.
  Runtime positions keep the enclosing top-level statement convention.

## Reference Implementation

- The accepted parser changes only the two suite selections in private
  `src/lang/ast/parser.rs::try_statement`; the lexer, public AST, runtime,
  canonical generator, dependencies, versions, edition and MSRV are unchanged.
- R2 retains the frozen R1 parser, exporter, executable cases and training
  records exactly. It repairs the demonstrated missing top-level REPL surface
  in `src/main.rs` with a complete bare-`Try` token classifier sharing the
  existing named-arrow layout filtering. No source preprocessing, fake colon,
  parser-error heuristic, new command or unrelated buffering redesign is used.
- Ordinary classifier and `tests/indented_exception_cli.rs` regressions cover
  direct top-level entry, independent colons, bindings, accepted layout,
  blank-line/EOF submission, false headers, commands and explicit failures.
  Fresh direct native launches distinguish printed errors from the REPL's
  existing zero exit on EOF or `.exit`; an outer colon wrapper is not proof
  that the new root-level header works.
- The actual build splitter shares the existing complete ASCII Word boundary
  convention for `else`, `elif` and `catch`, retaining default/no-space and
  parenthesized catches without joining identifiers such as `catcher`.
  Grouping selects statements; it never validates headers.
- `build.rs` runs affected exception records as complete original programs
  through `common::runner`, preserving actual parser failures, assertion
  operands, AST coverage and explicit return metadata. Do not extract caught
  or local checks into unrelated literal expectations.
- Keep the accepted NUC45 original-source colon-assertion guard intact.
  Its independent validation runner does not duplicate effects in the runner
