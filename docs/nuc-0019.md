# NUC 19 -- Bare Single-Parameter Indented Block Definitions

```
NUC: 19
Title: Bare Single-Parameter Indented Block Definitions
Author: Copilot <223556219+Copilot@users.noreply.github.com>
Status: Accepted
Type: Standards Track
Category: Syntax enhancement
Created: 14-Oct-2026
Requires: 8, 18
```

## Abstract

- NUC 19 specifies optional parameter parentheses for one untyped ordinary identifier before an indented named block definition.
- `def double amount:` with an indented body is exactly `def double(amount):` with that same body.
- Methods and `init` share this spelling without changing tokens, public AST types, runtime semantics or canonical rendering.
- Every accepted parenthesized definition and NUC 18 bare named arrow remains available.

## Motivation

- A single untyped input does not need parameter delimiters when a colon and real indentation already delimit the suite.
- Extend NUC 18's narrow single-parameter shortcut to existing multistatement and branching block bodies.
- Keep shared relationships, explicit returns and reactive updates unchanged rather than introducing another execution mode.

## Rationale

- Inspect only the immediate ordinary identifier and its following arrow or qualifying colon after the required function name.
- Require lexer-supplied indentation before recognizing the colon shortcut; a newline alone does not qualify.
- Keep the accepted parameter-parenthesis diagnostic for typed, inline, missing-indent and other unsupported prefixes.
- Use lookahead only, then let the existing suite parser consume layout and statements.
- Keep parentheses for typed, multiple, nullary, multiline-parameter, inline and brace-suite signatures, and for all calls.
- Keep named block bodies distinct from anonymous arrows and named-arrow object expressions.
- Depend only on accepted [NUC 8](nuc-0008.md) and [NUC 18](nuc-0018.md); NUC 18 already depends on NUC 12.
- Do not add nullary sugar, return annotations, call-site omission, ordinary-identifier invocation or local closure capture.

## Specification

### Grammar and lookahead

- The [authoritative specification](../nucleoid.spec.md), especially `Bare single-parameter indented block definitions`, governs the prototype.
- Parse `def` and its required ordinary identifier name exactly as before.
- Preserve NUC 18's immediate `Identifier` followed by `Arrow` shortcut exactly.
- Extend the shortcut only when the next token is `Identifier`, `peek_at(1)` is `Colon`, and `peek_at(2)` is `Newline` or `Indent`.
- Starting at that body token, look past only `Newline` and `Semicolon`; require the first remaining token to be `Indent`.
- Do not consume separators or body tokens during this guard.
- Consume exactly one `Parameter { name, type_name: None }` for a qualifying prefix.
- For every other prefix, call `Parser::parameters()` unchanged, without consuming or skipping anything first.
- Use the existing named-arrow expression path or `Parser::suite()` unchanged for the actual body.
- No logical newline or semicolon may separate `def`, the required name, the bare parameter and colon.
- Blank/comment lines before the body and normal suite layout after the initial logical newline remain supported.
- A semicolon immediately after the colon on the header line does not qualify, even if a later line is indented.
- Methods and `init` already use `Parser::function_statement`; no separate class grammar is added.
- Bare typed, multiple, defaulted, destructured, nullary, anonymous-colon, inline and brace-suite definitions are not added.
- All parenthesized typed/untyped, empty, multiple, trailing-comma and multiline signatures and their indented/inline/braced suites remain valid.
- Calls, class parameter lists, strings, comments, templates, keywords, expression precedence and anonymous-function forms are unchanged.

### Runtime equivalence

- The parameter metadata and complete `FunctionBody::Block` are identical to the corresponding parenthesized definition.
- The body may contain multiple statements, nested scopes and multiple explicit returns using the existing block semantics.
- A block without `return`, or with a bare `return`, yields `null`; the last expression is not implicitly returned.
- Parameters keep local binding and shadowing; missing arguments bind `null`, and extra arguments retain accepted handling.
- Typed, multiple and empty parenthesized alternatives retain their existing behavior.
- Calls remain reactive to arguments, body dependencies and named redefinitions.
- Live references follow named replacement; `.value` freezes the definition, not its body's external reads.
- Methods keep their receiver, `this`/`self` aliasing and canonical graph keys.
- Constructors keep initializer adoption, instance returns and explicit/bare `super` behavior.
- Failed definitions and propagated updates keep caught errors, transaction rollback, graph edges and recovery.
- Existing noncapturing nested/local behavior remains unchanged, including inherited failures for parameter-dependent local reactivity.
- Parser statement/expression depth, operand/postfix chains and runtime limits are not bypassed or changed.
- Public `Token`, `Parameter`, `Function`, `FunctionBody`, runtime, generator and library APIs are unchanged.

## Errors

- No new error kind or runtime message is introduced.
- A nonqualifying header keeps the existing parenthesized parameter parser's error before consuming the unsupported prefix.
- The following exact diagnostics are exercised by focused regressions and trace to the normative boundary section and unchanged parser/runtime rules.

| Condition or input | Exact error |
| --- | --- |
| `def f amount:` at EOF, a newline without real indentation, or a comments-only body | `SyntaxError("Expected '(' but found identifier 'amount'")` |
| `def f amount: int:`, `def f amount: int => amount`, bare inline/brace suites, or a semicolon immediately after the colon | `SyntaxError("Expected '(' but found identifier 'amount'")` |
| Bare multiple/default/return-annotation prefixes, or a newline/semicolon between parameter and colon | `SyntaxError("Expected '(' but found identifier 'amount'")` |
| `def f:` with an indented body | `SyntaxError("Expected '(' but found ':'")` |
| Logical newline immediately after `def f` | `SyntaxError("Expected '(' but found end of line")` |
| Semicolon immediately after `def f` | `SyntaxError("Expected '(' but found ';'")` |
| `this` instead of the ordinary parameter identifier | `SyntaxError("Expected '(' but found keyword 'this'")` |
| `def f [amount]:` | `SyntaxError("Expected '(' but found '['")` |
| `def f {amount}:` | `SyntaxError("Expected '(' but found '{'")` |
| `def f $Amount:` | `SyntaxError("Expected '(' but found '$Amount'")` |
| A string instead of the parameter | `SyntaxError("Expected '(' but found a string")` |
| `def f 1:` | `SyntaxError("Expected '(' but found number 1")` |
| `def f ...amount:` | `SyntaxError("Expected '(' but found '.'")` |
| `def f(amount:):` | `SyntaxError("Expected a type but found ')'")` |
| `def f(amount = 1):` | `SyntaxError("Expected ')' but found '='")` |
| `def f() -> int:` | `SyntaxError("Expected ':' but found '-'")` |
| Indented `return amount +)` after a qualifying header | `SyntaxError("Unexpected ')'")` |
| Indented `return @` after a qualifying header | `SyntaxError("Unexpected character '@'")` |
| An undefined body dependency `missing` | `ReferenceError("missing is not defined")` |
| `this`/`self` without an instance receiver | `ReferenceError("this is not defined")` |
| Inherited noncapturing local/nested parameter failure | `ReferenceError("amount is not defined")` |
| A non-callable parameter shadows `operation` | `TypeError("operation is not a function")` |
| Expression or statement nesting exceeds the existing limit | `SyntaxError("Expressions are nested too deeply")` or `SyntaxError("Statements are nested too deeply")` |
| An operand or postfix chain exceeds the existing limit | `SyntaxError("Expression has too many operands")` or `SyntaxError("Expression has too many parts")` |

- The `amount` header boundaries above retain line 1, column 7; `def f:` retains line 1, column 6.
- A newline after `def f` retains line 1, column 5; its semicolon retains line 1, column 6.
- `def f(amount:):` retains line 1, column 15; the malformed indented `return amount +)` and `return @` retain line 2, columns 21 and 12 respectively.
- Runtime errors retain top-level statement positions; caught values omit positions.
- Inherited Windows debug CLI deep-parentheses/direct-nullary-recursion stack-overflow limitations are outside this revision; no broad CLI stack-safety claim is made.
