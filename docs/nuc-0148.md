## Abstract

- Two range operators build a list of consecutive integers.
  `START..<END` holds the integers from `START` up to, but not including,
  `END`, and `START..=END` holds the integers from `START` through `END`:

  ```
  first = 9
  last = 13
  hours = first..<last    # [9, 10, 11, 12]
  levels = 1..=5          # [1, 2, 3, 4, 5]
  ```

- A range is an ordinary list value, so list methods, membership tests,
  equality, indexing and JSON output treat it as they treat a list
  literal. It is computed from its bounds each time it is evaluated: a
  declaration such as `hours = first..<last` is a standing declaration
  that follows changes of `first` and `last`, and
  `$Shift.hours = $Shift.start..<$Shift.end` is a class-level rule for
  every shift. Both bounds must be integers. A range is empty when `START`
  is not below `END` (`..<`) or is above `END` (`..=`), and it holds at
  most 100,000 items.
- At the accepted revision `..<` and `..=` after an operand raise
  `SyntaxError("Expected a property but found '.'")` at the second dot, in
  statements, conditions, arguments, list items, object values and
  template interpolations alike. A template interpolation ignores the
  tokens after the expression it reads, so it accepts them where that
  expression ends before them, as after a pipeline stage
  (`` `${x |> why ..<3}` ``), and those programs keep their readings. Only
  programs that failed to parse change. A bare `a..b`, a three-dot
  `a...b` and a range without an operand stay errors.

## Motivation

- A world model often needs consecutive integers: the hours of a shift,
  the floors of a building, the rows and columns of a grid, the positions
  of a list's items. Accepted programs have no integer sequence. A list
  literal hard-codes its length, and a list that follows its bounds needs
  a detour through a repeated string:

  ```
  hours = "x".repeat(last - first).split("").reduce(lambda a, c: a.concat(a.length + first), [])
  ```

  That declaration takes 37 lexer tokens, against 7 for
  `hours = first..<last`. The coordinates of a `w` by `h` grid take 52
  tokens through the same detour and 31 as
  `cells = (0..<w * h).map(i -> [i % w, Math.floor(i / w)])`. Literal
  bounds save tokens too: `digits = 0..<10` takes 7 tokens against 23 for
  the written-out list, and `ok = level in 1..=5` takes 9 against 15.
- Callbacks receive no index, so a range of positions also pairs items
  with their indexes, as in `(0..<names.length).map(i -> ...)`.
- The two spellings come from Kotlin and Swift (`..<`, half-open) and Rust
  (`..=`, closed), and no language reads either of them differently. The
  bare `..` is half-open in Rust and C# but closed in Kotlin, Ruby and
  Haskell, so it stays an error rather than guess.
