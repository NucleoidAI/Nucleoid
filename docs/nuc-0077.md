## Abstract

- Lists and class instance lists gain the read-only queries `maxBy` and
  `minBy`. `RECEIVER.maxBy(selector)` returns the first item whose
  `selector(item)` is the largest, and `RECEIVER.minBy(selector)` the first
  item whose `selector(item)` is the smallest.
- The result is the item itself, unchanged: an object or instance stays the
  same object, and the selected key is not returned.
- Keys compare as `>` and `<` compare them: two strings as text, and every
  other pair as numbers, so dates compare by time. On a tie the item that
  comes first wins. An empty receiver gives undefined, which a declaration
  stores as `null`, and so does any key that cannot be compared with itself,
  such as undefined, NaN or an object.
- The selector is required and is called once per item, in order, with only
  the item, as [NUC 69](nuc-0069.md)'s `max` calls its selector. A missing
  selector, or one that is not a function, raises
  `TypeError("maxBy expects a function")` or
  `TypeError("minBy expects a function")`.
- `maxBy` and `minBy` follow [NUC 61](nuc-0061.md)'s shared query rules
  beside `sum`, `max`, `min`, `distinct`, `count` and `mode`. They accept
  every receiver the list queries accept, read the receiver before their
  arguments, never write it, and stay live in declarations and class-level
  rules.
- At the accepted revision these calls raise
  `TypeError("<receiver>.maxBy is not a function")` and its `minBy`
  counterpart. No syntax, keyword, token, error type or public Rust API is
  added. The authoritative contract is
  [List and population extreme items](../nucleoid.spec.md#list-and-population-extreme-items).
- **Outcome: Accepted.** The independent evaluation and the caller's
  integrated-tree checks passed all three hard criteria. The independent
  evaluator decided Accepted, and every required token comparison passed;
  no policy check failed.

## Motivation

- World models select objects by an extreme property: the leading bid, the
  nearest free charger of each robot, the latest event, the heaviest parcel,
  the cheapest open offer. The answer is an object, not a number, and it has
  to stay true while the model changes.
- [NUC 69](nuc-0069.md) gives the extreme value, `Bid.max(bid -> bid.amount)`,
  and both NUC 69 and [NUC 75](nuc-0075.md) list `maxBy` and `minBy` as not
  added. At the accepted revision the item takes a longer spelling, and each
  has a defect:
  - `top = Bid.reduce((a, b) -> b.amount > a.amount ? b : a)` is 24 lexer
    tokens where `top = Bid.maxBy(bid -> bid.amount)` is 12. It writes and
    runs the key twice per step, and a NaN key decides by position: in first
    place it wins against every later item, and later it is ignored.
  - `top = Bid.find(bid -> bid.amount == Bid.max(each -> each.amount))` is 23
    tokens. It runs `max` again for every item it tests, so it is quadratic,
    and `max` compares numbers only, so it cannot select by a name.
  - `top = Bid.find(b -> all c in Bid: b.amount >= c.amount)`, with a
    [NUC 62](nuc-0062.md) quantifier, is 21 tokens and compares items in
    pairs, every pair in the worst case.
  - The helper `def hi xs key => xs[xs.map(key).indexOf(xs.max(key))]` is 24
    tokens on its own. It runs the key twice per item, compares numbers only,
    and picks a wrong item when a key is unknown: the first item whose key is
    missing or `null` when a key is undefined, and the last item when a key
    is NaN.
- The duplication grows with the key. The class-level rule
  `$Robot.dock = Charger.minBy(charger -> Math.abs(charger.x - $Robot.x))` is
  23 tokens, and its `reduce` spelling is 44.
- Kotlin's `maxBy` and `minBy`, C#'s `MaxBy` and `MinBy`, lodash's `_.maxBy`
  and `_.minBy`, Ruby's `max_by` and `min_by`, and Python's `max(xs, key=f)`
  and `min(xs, key=f)` name the operation. All of them return the item and
  keep the first of equal keys. LLM-written code such as
  `orders.maxBy(o => o.total)` raises
  `TypeError("orders.maxBy is not a function")` at the accepted revision.

## Rationale

- **Category and mode.** The caller selected the Utility enhancement
  category by one uniform draw over the five eligible registry categories,
  index 2 with probability 1/5 and no redraw, in continuous mode, so the
  token non-regression gate applies. Runtime applicability does not apply to
  this category. Each new case is paired with the most compact accepted-syntax
  counterpart found, recorded in the evaluation baseline.
- **Two more shared queries.** `maxBy` and `minBy` are operations of the
  read-only list query that serves `map`, `filter`, `reduce`, `sum`, `max`,
  `min`, `distinct`, `count` and `mode`. Lists, list properties, call results
  such as `filter(...)`, `map(...)` and `slice(...)`, ranges, `.value`
  snapshots, selected versions, class instance lists and `Name.list()`
  therefore accept them through one implementation, with the receiver,
  argument and liveness rules they already share.
- **The item itself.** The query exists to name the object with the extreme
  property, so it returns that object unchanged, as every prior art above
  does. The key stays one query away: `xs.maxBy(f).k`, or `xs.max(f)` for a
  number.
- **Compared as the comparison operators compare.** The keys go to the
  function behind `>` and `<`: two strings compare as text, by code point, and
  every other pair as numbers with the numeric conversion of the comparisons.
  Dates compare by time, and `true`, `false`, `null`, empty lists and one-item
  lists count as numbers. This is the comparison of the accepted `reduce`
  spelling and of
  lodash's `_.maxBy`, by construction rather than by a second set of rules.
- Rejected: [NUC 69](nuc-0069.md)'s numeric conversion. Names, labels and
  timestamps written as strings would all convert to NaN, so `maxBy` could
  not select by them. `max` keeps converting because its result is a number.
- Rejected: the order of the default `sort`, by string forms, under which
  `10` would come before `9`; and a new order across kinds of values, which
  the language does not have.
- **Parity contracts.** When every key can be compared with itself,
  `xs.maxBy(f)` is the item that
  `xs.reduce((best, item) -> f(item) > f(best) ? item : best)` returns, with
  `f` called once per item, and `xs.minBy(f)` the item of the same `reduce`
  with `<`. When the keys are all strings, or none is a string, it is the
  item that `xs.find(x -> all y in xs: f(x) >= f(y))` finds, and undefined
  where that `find` finds none. For keys that are not strings and a receiver
  that is not empty, it is undefined exactly when `xs.max(f)` is undefined or
  NaN, and otherwise the first item whose key converts to `xs.max(f)`.
- **The first item wins a tie.** The scan keeps the first item and replaces
  it only with a later item whose key is strictly greater, or strictly
  smaller for `minBy`. Python's `max` and `min`, Kotlin, C#, Ruby and lodash
  all keep the first of equal keys, as [NUC 75](nuc-0075.md)'s `mode` keeps
  the first of equal counts. `0` and `-0` keys tie, so the first item wins
  without depending on the sign of the zero.
- Rejected: the last tied item, which no prior art returns.
- **A key that cannot be compared with itself makes the result undefined.**
  Such a key, one for which `key >= key` is `false`, is undefined, NaN, an
  object, an instance, a class, a function, a regular expression or a list
  that converts to NaN. No item can be shown to be the largest while one key
  is unknown or has no order, so the result is undefined, which a declaration
  stores as `null`. This carries [NUC 69](nuc-0069.md)'s rule that an
  undefined value stays unknown over to NaN and other keys without an order.
- Every item is still visited, so every selector read is a dependency. A
  declaration such as `top = Bid.maxBy(bid -> bid.amount)` waits for every
  amount to be defined and comparable, and re-evaluates when one changes.
- Rejected: skipping such keys, as lodash skips `null` and undefined. A
  missing amount would then silently give a different bid as the leader.
- Rejected: the plain scan with `>`, the `reduce` spelling, under which a NaN
  key wins when it comes first and is ignored when it comes later.
- Rejected: defining the result as the first item whose key is `>=` every
  key, the quantifier spelling. Checking it needs a comparison for every pair
  of items or a separate algorithm for every kind of key, and it differs from
  the scan only where strings and other keys mix.
- **Mixed strings and other keys.** A string that is not numeric is neither
  greater nor smaller than a number, so where such keys mix the kept item
  stays: `["b", 5].maxBy(k -> k)` is `"b"` and `[5, "b"].maxBy(k -> k)` is
  `5`. The result is deterministic and follows the scan.
- **An empty receiver gives undefined.** Nothing is the largest item of
  nothing. Undefined is also what the `reduce` spelling gives, and a
  declaration stores it as `null`, so `leader = Bid.maxBy(bid -> bid.amount)`
  reads `null` before the first bid and then re-evaluates.
- Rejected: raising an error, as Python's `max([])` and Kotlin's `maxBy` do.
  A live declaration over a population that starts empty would then fail when
  it is declared. Also rejected: a default value, as
  [NUC 69](nuc-0069.md) rejected one for `max`.
- **The selector is required.** `By` names the key, and without a selector
  `maxBy` would be a second `max` with another comparison. A missing first
  argument, or one that is not a function, including `null`, raises
  `TypeError("maxBy expects a function")` or
  `TypeError("minBy expects a function")` after the arguments are evaluated,
  even on an empty receiver, as [NUC 73](nuc-0073.md)'s `count` raises for a
  missing predicate.
- Rejected: property-name selectors such as `Bid.maxBy("amount")`, which
  lodash accepts and [NUC 69](nuc-0069.md) rejected for `max`.
- **The selector is called like `map`'s callback.** It runs once per item, in
  order, with only the item; further parameters stay `null`. A `null` key
  compares as `0`, as in `null > -1`, while a selector that reads a `null`
  binding or property settles a declaration to `null`, as the same callback
  does in `map` and `max`.
- **Extra arguments** are evaluated once, left to right, and ignored, as
  every list query does.
- **Instance lists.** On a class name, `Name.maxBy(...)` and `Name.minBy(...)`
  are population queries even when the class declares instance methods
  `maxBy` or `minBy`, as for `max` and `mode`. The methods stay reachable
  through each instance.
- **No noun form.** [NUC 75](nuc-0075.md)'s `NOUN of OPERAND` takes no
  argument, and `maxBy` needs its selector, so `maxBy of xs` keeps raising
  `SyntaxError("Unexpected keyword 'of'")`.
- **Bounded cost.** The receiver and the arguments are evaluated once per
  call, the selector once per item, and each key is compared once with itself
  and at most once with the kept key. Nothing is sorted, copied or expanded,
  so cost and
  rendered size stay linear in the receiver and the source. The call keeps its
  ordinary rendering in graph keys and `why`.
- **Not added.** A global `maxBy(...)` or `minBy(...)`, `maxBy of xs`,
  several keys or a tie-breaking argument, default values, property-name
  selectors, results that pair the item with its key, the index of the
  extreme item, and queries for the first or last `n` items.

## Specification

### Extreme items

- `RECEIVER.maxBy(selector)` returns the first item of the receiver whose
  `selector(item)` is the largest, and `RECEIVER.minBy(selector)` the first
  item whose `selector(item)` is the smallest. The result is the item itself,
  unchanged.
- The receiver is a list, however it is reached: a variable, a property, a
  call result such as `filter(...)`, `map(...)`, `slice(...)` or
  `concat(...)`, a range, a literal, a `.value` snapshot or a selected
  version. It may also be a class's instance list, named by the class or by a
  variable that holds the class, in population order; a range of one and
  `Name.list()` are lists.
- An empty receiver gives undefined, which a declaration stores as `null`.

```
readings = [{at: 9, c: 18}, {at: 12, c: 24}, {at: 15, c: 24}, {at: 18, c: 9}]
warmest = readings.maxBy(reading -> reading.c)
coldest = readings.minBy(reading -> reading.c)
assert: warmest.at, 12
assert: coldest.at, 18
assert: warmest == readings[1], true
readings.push({at: 21, c: 30})
assert: warmest.at, 21
readings = []
assert: warmest, null
```

```
class Bid(bidder, amount, open):
    this.bidder = bidder
    this.amount = amount
    this.open = open
best = Bid.maxBy(bid -> bid.amount)
assert: best, null
ada = Bid("ada", 120, true)
bo = Bid("bo", 90, false)
cy = Bid("cy", 150, true)
leading = Bid.filter(bid -> bid.open).minBy(bid -> bid.amount)
recent = Bid[-2:].maxBy(bid -> bid.amount)
assert: best, cy
assert: leading, ada
assert: recent, cy
bo.amount = 200
assert: best, bo
delete cy.amount
assert: best, null
```

### Comparison

- Keys compare as `>` and `<` compare them: two strings as text, by code
  point, and every other pair as numbers with the numeric conversion of the
  comparisons. Dates compare by time, and `true`, `false`, `null`, empty lists
  and one-item lists count as numbers: `["10", "9"].maxBy(code -> code)` is
  `"9"`, while `["10", "9"].max()` is `10`.
- The items are scanned in receiver order. The first item is kept, and a
  later item replaces the kept one only when its key is greater for `maxBy`,
  or smaller for `minBy`, so on a tie the item that comes first wins. A
  string that is not numeric is neither greater nor smaller than a number, so
  where such strings and other keys mix, the kept item stays.
- A key that cannot be compared with itself, one for which `key >= key` is
  `false`, makes the result undefined: undefined, NaN, objects, instances,
  classes, functions, regular expressions and lists that convert to NaN.
  Every item is still visited.
- When every key can be compared with itself, `xs.maxBy(f)` is the item that
  `xs.reduce((best, item) -> f(item) > f(best) ? item : best)` returns, and
  `xs.minBy(f)` the item that the same `reduce` with `<` returns.
- When the keys are all strings, or none is a string, `xs.maxBy(f)` is the
  item that `xs.find(x -> all y in xs: f(x) >= f(y))` finds, and undefined
  where it finds none; `xs.minBy(f)` corresponds to the same `find` with
  `<=`.
- For keys that are not strings and a receiver that is not empty,
  `xs.maxBy(f)` is undefined exactly when `xs.max(f)` is undefined or NaN,
  and otherwise it is the first item whose key converts to `xs.max(f)`;
  `minBy` and `min` correspond the same way.

```
class Job(name, due, kg):
    this.name = name
    this.due = due
    this.kg = kg
alpha = Job.minBy(job -> job.name)
soonest = Job.minBy(job -> job.due)
heaviest = Job.maxBy(job -> job.kg)
press = Job("press", new Date("2026-12-01"), 40)
coat = Job("Coat", new Date("2026-11-20"), "9")
weld = Job("weld", new Date("2026-11-28"), 40)
assert: alpha, coat
assert: soonest, coat
assert: heaviest, press
coat.kg = "75"
Job("Anvil", new Date("2026-12-24"), "100")
assert: alpha.name, "Anvil"
assert: heaviest, coat
press.kg = 0 / 0
assert: heaviest, null
```

### Selectors

- The selector is required. It is called once for every item, in order, with
  the item as its only argument; further parameters are `null`. The call
  order and the argument are those of `map`.
- A missing first argument, or one that is not a function, including `null`,
  raises `TypeError("maxBy expects a function")` or
  `TypeError("minBy expects a function")`, even on an empty receiver.
- Every supplied argument, including unused extras, is evaluated once, left
  to right, after the receiver and before the first selector call.
- A `null` key compares as `0`. Reads inside a selector follow the existing
  rules, so a selector that reads a `null` binding or property settles a
  declaration to `null`.
- A null or undefined receiver keeps the existing method-call route: the call
  yields undefined without evaluating its arguments.

```
seen = []
def weigh(parcel, position):
    seen.push(position ?? parcel.id)
    return parcel.kg
parcels = [{id: 1, kg: 4}, {id: 2, kg: 9}, {id: 3, kg: 2}]
def heaviest() => parcels.maxBy(weigh)
assert: heaviest().id, 2
assert: seen, [1, 2, 3]
depot = 5
def gap parcel => Math.abs(parcel.kg - depot)
closest = parcels.minBy(gap)
assert: closest.id, 1
depot = 10
assert: closest.id, 2
```

### Liveness and transactions

- `maxBy` and `minBy` never write their receiver. A declaration that uses one
  depends on the list or the population, on its argument expressions and on
  whatever the selector reads for every item, as for `map` and `max`.
- Pushing, popping, shifting or replacing a list, creating or deleting an
  instance, and changing a property that a selector reads re-evaluate the
  declaration.
- In a class-level rule, each instance evaluates its own extreme item, and
  `$Class` inside a selector or a filter is the instance the rule is
  evaluated for.
- Selector errors propagate through the existing transaction, so a failed
  standing re-evaluation rolls back the change that triggered it, including a
  list write or a new instance.

```
class Team(name, target):
    this.name = name
    this.target = target
class Player(team, name, goals):
    this.team = team
    this.name = name
    this.goals = goals
$Team.star = Player.filter(player -> player.team == $Team.name).maxBy(player -> player.goals)
$Team.fit = Player.minBy(player -> Math.abs(player.goals - $Team.target))
reds = Team("reds", 4)
blues = Team("blues", 10)
ana = Player("reds", "ana", 7)
Player("reds", "ben", 3)
cal = Player("blues", "cal", 5)
assert: reds.star, ana
assert: blues.fit, ana
cal.goals = 12
assert: blues.fit, cal
cal.team = "reds"
assert: reds.star, cal
assert: blues.star, null
```

```
def checked(value):
    if value > 100:
        throw "TOO_MANY"
    return value
orders = [{id: 1, qty: 30}, {id: 2, qty: 50}]
largest = orders.maxBy(order -> checked(order.qty))
failure = ""
try:
    orders.push({id: 3, qty: 500})
catch error:
    failure = error
assert: failure, "TOO_MANY"
assert: orders.length, 2
assert: largest.id, 2
```

### Cost

- The receiver and the arguments are evaluated once per call, and the
  selector once per item.
- Each key is compared once with itself and at most once with the kept key,
  in one pass; the receiver is neither sorted nor copied.
- A unit test calls the selector exactly 20,000 times for a 20,000-item list
  and population.

    a number `TypeError("number.minBy is not a function")`, a boolean
    `TypeError("boolean.maxBy is not a function")`, a date
    `TypeError("Date.minBy is not a function")`, a function
    `TypeError("function.maxBy is not a function")` and a regular expression
    `TypeError("minBy is not a function")`;
  - `Math.maxBy([1])` raises `TypeError("Math.maxBy is not a function")`, and
    `maxBy([1, 2])` without a definition raises
    `ReferenceError("maxBy is not defined")`;
  - `xs.maxBy(missing)` raises `ReferenceError("missing is not defined")`;
  - `maxBy of [1, 2]` raises `SyntaxError("Unexpected keyword 'of'")`;
  - variables, functions and parameters named `maxBy` or `minBy`, object
    properties such as `x = {minBy: 4}.minBy`, a function held in a property
    and called as `o.maxBy(4)`, and instance methods called on an instance,
    such as `bag.maxBy(1)`, keep their results;
  - the motivating spellings with `reduce`, `find`, `max` and the numeric
    helper keep their results.
- A program that caught the former error now receives a value: a `try`
  around `r = xs.maxBy(x -> x)` with `xs = [1, 2]` stores `2`.

## Reference Implementation

- `src/lang/ast/array.rs`: `list_query`, the read-only query shared by lists
  and class instance lists, sends `maxBy` and `minBy` to the private
  `Runtime::extreme_item`. It validates the selector with the existing
  `expect_function`, calls it once per item through `Runtime::invoke`, and
  keeps the first item, replacing it only with a later item whose key
  compares greater for `maxBy` or smaller for `minBy`; a key that cannot be
  compared with itself makes the result undefined. Keys are compared
  by `operator::compare`, the function behind `>` and `<`, which becomes
  `pub(crate)` so that both share one comparison. Lists reach the query
  through `call_list_method` and populations through `call_class_method`,
  unchanged, so the receiver and the arguments are evaluated once by the
  existing routes and the null-receiver route stays in front of it.
- `src/terminal/completion.rs`: the list members that lists and instance
  lists offer include `maxBy` and `minBy`, and a new completion unit test
  covers them on a list and on a class.
- `tests/list_extreme_items.rs` covers the appended document cases and their
  assertions, the parity contracts, every receiver kind and Compatibility
  row, the comparison of every kind of key, ties, the undefined result,
  selector validation and argument order, once-only evaluation, graph
  dependencies, class-level rules, unchanged forms and errors, rendering in
  `why`, rollback compared with a control runtime, and 20,000-item queries
  that call their selector exactly 20,000 times.
- `tests/value_assignment.rs`, `tests/destructuring.rs`,
  `tests/noun_queries.rs` and `tests/object_entry_loops.rs`: the whole-corpus
  case count changes from 884 to 895. Their checks are otherwise unchanged,
  because no appended case uses `:=`, a destructuring, a noun query or an
  entry loop.
- `tests/dataset.rs` counts 613 specification records and 1,267 synthesized
  records, with the new shard `dataset/nucleoid.synth.52.jsonl` pinned at
  eight.
- The root specification, executable reference, README, examples, the
  consolidated reference with its built-in table, error table and syntax
  summary, both NUC 0 indexes, the new synthesized shard, the regenerated
  specification export and the generated specification tests are
  synchronized in the isolated candidate. Every existing exported record and
  generated test is byte-identical.
- No dependency, MSRV, edition, project version or public Rust API changes:
  `extreme_item` is private and `compare` is crate-private. The new results
