# NUC 13 -- Compound Arithmetic Assignment

```
NUC: 13
Title: Compound Arithmetic Assignment
Author: Copilot <223556219+Copilot@users.noreply.github.com>
Status: Accepted
Type: Standards Track
Category: Syntax enhancement
Created: 12-Oct-2026
```

## Abstract

- Introduce `+=`, `-=`, `*=`, `/=`, and `%=` as short spellings of existing arithmetic assignments.
- Lower `target op= expression` to `target = target op (expression)` without adding an AST or runtime node kind.
- Preserve the expanded assignment's relationships, errors, return values, and canonical rendering.
- This revision passed independent evaluation against the accepted syntax without a per-case token increase or behavior failure.

## Motivation

- Self-referential arithmetic currently repeats the target and uses separate assignment and arithmetic tokens.
- Names, dotted property paths, local parameters, and method receivers benefit from the same compact spelling.
- A shorter spelling must not replace Nucleoid's dependency tracking with an imperative read-modify-write operation.
- Token acceptance belongs to the independent per-case evaluator, not to this proposal's preparation checks.

## Rationale

- Existing `Expr::Assign`, `Stmt::Assign`, and `Expr::Binary` already express the complete behavior.
- Parser lowering keeps arithmetic coercion, string addition, null propagation, graph keys, scope selection, and transactions on the existing paths.
- The entire right-hand expression becomes the binary operator's right operand; textual substitution without parentheses would change grouping.
- Assignment precedence and right associativity permit both `outer = inner += delta` and `a += b *= delta`.
- Plain-path targets make duplication bounded and predictable; calls, indexes, slices, and assignment expressions inside a target are deliberately unsupported.
- Duplicating arbitrary computed targets was rejected because nested compound targets could clone an exponentially growing AST.
- Single-evaluation receiver temporaries, indexed mutation, increment/decrement operators, logical compound assignment, and a new mutation mode are out of scope.
- The old `=` form remains available for every target it previously accepted, including computed property receivers.
- Adding variants to the public, exhaustive Rust `Token` enum is source-breaking for downstream exhaustive matches; the crate therefore changes from `1.0.0` to `2.0.0`.
- Runtime source compatibility is additive; the Rust API major-version boundary is separate from language compatibility.
- Dependencies, the Rust 1.85 minimum, public AST types, and unrelated public APIs are unchanged.

## Specification

### Operators and lowering

- Recognize each adjacent two-character compound operator as one token.
- Use the following existing binary operators in the lowered assignment.

| Proposed form | Expanded form | Existing operator |
| --- | --- | --- |
| `target += expression` | `target = target + (expression)` | `BinaryOp::Add` |
| `target -= expression` | `target = target - (expression)` | `BinaryOp::Subtract` |
| `target *= expression` | `target = target * (expression)` | `BinaryOp::Multiply` |
| `target /= expression` | `target = target / (expression)` | `BinaryOp::Divide` |
| `target %= expression` | `target = target % (expression)` | `BinaryOp::Modulo` |

- Parse the right operand with the existing full assignment-expression grammar, below pipelines, logical operators, comparisons, and arithmetic.
- `a += b *= 2` lowers to `a = a + (b = b * 2)`, not `(a = a + b) * 2`.
- An assignment used as a statement becomes the existing `Stmt::Assign`; an assignment inside an expression remains the existing `Expr::Assign`.
- Render only the expanded canonical AST; no compound spelling appears in graph keys or canonical assertion expressions.
- `Nucleoid keeps compound arithmetic assignments equivalent` in `nucleoid.spec.md` covers all five operators, grouping, string addition, an adjacent negative operand, and null propagation.

```
value = 20
value += 4
assert(value, 24)
value -= 6
assert(value, 18)
value *= 2 + 1
assert(value, 54)
value /= 3
assert(value, 18)
value %= 5
assert(value, 3)
```

### Targets and bounds

- A target is an identifier or a dotted member chain rooted in an identifier, `$Class`, `this`, or `self`.
- A `$Class`, `this`, or `self` root must have at least one property; the bare class or receiver is not a compound target.
- Parentheses may group a qualifying path without changing its AST.
- A computed target is rejected before its AST is cloned; this includes a call, index, slice, binary or logical expression, function, or assignment anywhere in the target's receiver chain.
- Nested compounds are allowed on the right, not inside a target; `(a += 1).amount += 2` is rejected.
- Validate dotted receiver links iteratively and allow at most 128 links in a compound target, including links across parenthesized groups.
- Existing per-chain parsing bounds remain unchanged; recursive expression and statement entry still share the existing 64-level nesting budget.
- Right-associative compound chains consume that budget just as ordinary assignments do; lowering moves the right operand and clones only the bounded target path once.
- These grammar and resource restrictions are normative in the opening text of `nucleoid.spec.md` and checked by the lexer/parser unit tests plus `tests/diagnostics.rs` and `tests/robustness.rs`; they add no unpaired executable document cases.

### Relationships and snapshots

- A standing assignment still records a relationship and tracks its right-hand dependencies.
- A variable or instance property's self-reference keeps the expanded form's current-value behavior; it is not a new dependency cycle.
- Re-evaluating a relationship reads the target's current value exactly as the expanded assignment would.
- `.value` on the right retains the existing isolated snapshot behavior.
- A class-level self-reference keeps its existing cycle check; `$Scale.factor *= 3` is not an imperative update.
- `Nucleoid keeps compound assignments reactive` covers re-evaluation and snapshots.
- `Nucleoid keeps compound property and local assignments equivalent` covers property self-reference, local parameter assignment, method receivers, class-level cycle detection, and rollback.
- Existing self-reference and propagation cases are rewritten only when their original AST is exactly the lowering's AST.

```
amount = 10
step = 2
amount += step
doubled = amount * 2
assert(amount, 12)
assert(doubled, 24)
step = 3
assert(amount, 15)
assert(doubled, 30)
amount += step.value
assert(amount, 18)
step = 5
assert(amount, 18)
assert(doubled, 36)
```

### Scope, expressions, and transactions

- Statements retain the existing distinction between local bindings and standing state assignments.
- `this` and `self` continue to lower to the same receiver node; compound syntax does not introduce a receiver binding.
- An assignment expression returns the expanded form's assigned value, including in single-return functions and nested right-hand assignments.
- A failed assignment and its triggered propagation roll back under the existing transaction machinery.
- A caught failure retains the existing assertion coverage and propagation-queue behavior.
- `Nucleoid returns compound assignment expressions` covers all five expression returns and right associativity.
- `Nucleoid rolls back failed compound assignments` covers a thrown standing-rule failure, a dependency cycle, state restoration, and an undefined self-reference.
- Existing `Nucleoid cancels propagation queued by a caught failure` and `Nucleoid preserves earlier queued work across nested caught failures` retain their assertions after equivalent compound rewrites.

```
def combined(a, b) => a += b *= 2
assert(combined(1, 3), 7)
```

### Lexical compatibility

- Longest matching recognizes `+=`, `-=`, `*=`, `/=`, and `%=` without consuming an adjacent unary sign.
- `amount *= -3` contains a compound multiplication token followed by the existing unary minus token.
- Whitespace between the two characters does not form a compound token; `amount + = 1` retains its existing syntax error.
- A slash after an operand still denotes division or division assignment.
- A slash in an operand position keeps the existing regular-expression lookahead, including an initial `=` in `/=/`, escaped slashes, character classes, and flags.
- A regular expression may follow any assignment operator; its pattern is not reinterpreted as compound syntax.
- Diagnostics describe the new tokens exactly as `'+='`, `'-='`, `'*='`, `'/='`, and `'%='`.
- Lexer tests verify single-token operators, adjacent signs, old equality and arrow tokens, division, regex disambiguation, and source positions.

## Errors

- No new arithmetic or transaction error is introduced; errors from the lowered assignment and its right operand retain their exact type and message.
- Invalid-target checks occur during parsing and cannot be caught by a program's `try`; runtime assignment failures remain catchable.
- The following feature-specific or inherited diagnostics are covered directly.

| Condition | Exact error | Trace |
| --- | --- | --- |
| A compound target is not a qualifying plain path | `SyntaxError("Invalid compound assignment target")` | Spec target restriction; parser target tests; `compound_assignment_diagnostics_name_exact_tokens_and_targets`; `malformed_compound_targets_do_not_change_state` |
| A compound path exceeds the total dotted-link bound | `SyntaxError("Expression has too many parts")` | Spec resource restriction; `compound_target_limits_include_parenthesized_member_chains` |
| Expression nesting, including a compound chain, exceeds the existing budget | `SyntaxError("Expressions are nested too deeply")` | Spec nesting restriction; `compound_assignment_chains_respect_existing_resource_limits` |
| An arithmetic chain exceeds the existing operand bound | `SyntaxError("Expression has too many operands")` | Spec existing operator-chain limits; `compound_assignment_chains_respect_existing_resource_limits` |
| A right operand is missing at end of input | `SyntaxError("Unexpected end of input")` | `compound_assignment_diagnostics_name_exact_tokens_and_targets` |
| A right operand is missing at end of line | `SyntaxError("Unexpected end of line")` | `compound_assignment_diagnostics_name_exact_tokens_and_targets` |
| A parenthesized right operand ends after a binary operator | `SyntaxError("Unexpected ')'")` | `compound_assignment_diagnostics_name_exact_tokens_and_targets` |
| A compound token occurs where an operand is required | `SyntaxError("Unexpected '+='")`, `SyntaxError("Unexpected '-='")`, `SyntaxError("Unexpected '*='")`, `SyntaxError("Unexpected '/='")`, `SyntaxError("Unexpected '%='")` | `compound_assignment_diagnostics_name_exact_tokens_and_targets` |
| The new relationship closes a cycle, including `$Scale.factor *= 3` | `TypeError("Circular Dependency")` | `Nucleoid rolls back failed compound assignments`; `Nucleoid keeps compound property and local assignments equivalent` |
| The target reads an undefined name | `ReferenceError("missing is not defined")` | `Nucleoid rolls back failed compound assignments` |
| A receiver is read without an instance | `ReferenceError("this is not defined")` | `Nucleoid rejects this and self outside an instance or as assignment targets`; `compound_runtime_errors_follow_the_expanded_assignment` |
| A reserved `value` property is assigned | `TypeError("Cannot use 'value' as a property")` | `Nucleoid rejects value as a property name`; `compound_runtime_errors_follow_the_expanded_assignment` |
| A property is assigned on a number | `TypeError("Cannot assign 'reading' on number")` | Existing typed assignment dispatch; `compound_runtime_errors_follow_the_expanded_assignment` |
| A standing rule rejects the assignment | The original thrown value, such as `"LIMIT"` | `Nucleoid rolls back failed compound assignments` |

- Undefined names and paths use the existing `ReferenceError("<name-or-path> is not defined")` format; the quoted `missing` and `this` messages above are concrete tested instances.
- Other malformed operands use the existing exact `Unexpected <token description>` or `Expected <token description> but found <token description>` diagnostics.
- Existing statement nesting, runtime depth, propagation, and right-operand errors are unchanged, including `SyntaxError("Statements are nested too deeply")`, `TypeError("Maximum expression depth exceeded")`, `TypeError("Maximum statement depth exceeded")`, and `TypeError("Propagation did not settle")`.
- Error positions follow the existing diagnostic API; a caught runtime error retains its position-free language value.

## Reference Implementation

- `src/lang/ast/lexer.rs` recognizes and describes the five public token variants and preserves operand-position regex scanning.
- `src/lang/ast/parser.rs` validates bounded plain paths and lowers compounds to existing typed assignment and binary nodes.
- Runtime evaluation, dependency tracking, AST types, and canonical generation need no new node or execution path.
- `Cargo.toml` and Cargo's regenerated lockfile use `2.0.0` for the exhaustive public lexer enum change, without dependency or minimum-Rust upgrades.
- Focused parser tests compare compound and expanded ASTs and canonical renderings in statement, expression, function, method, conditional, loop, assertion, and template contexts.
- Focused integration tests cover exact diagnostics, unchanged graph keys and returns, rollback safety, recursion limits, and nested-target cloning guards.
- The five new spec cases, one reference case, and two snippet cases are paired with accepted-syntax inputs in the caller's immutable baseline.
- Existing measured case identities, ordered canonical assertions, expected returns, and executed coverage are preserved.
- `docs/README.md`, `tests/reference.md`, `README.md`, `docs/examples.md`, affected synthesized sources, and regenerated dataset/Rust exports are synchronized in the candidate.
