# NUC 65 -- Hypothetical Suppose Blocks

```

Title: Hypothetical Suppose Blocks
Author: Claude <noreply@anthropic.com>
Status: Accepted
Type: Standards Track
Category: Reasoning enhancement
Created: 31-Oct-2026
Requires: 8, 13, 14, 17, 18, 45, 57, 59, 62
```

## Abstract

- Adds `suppose` blocks, the hypotheticals planned as stage 6 of Draft
  [NUC 11](nuc-0011.md), without its `diff` selection, as a standalone
  proposal.
- `suppose PREMISE:` followed by a suite runs the premise statement and then
  the suite in a hypothetical world. Rules propagate there as usual. When the
  block ends, normally, by an error or a thrown value, or by `return`,
  everything it did is rolled back.
- `suppose:` followed by a suite has no premise. `TARGET = suppose PREMISE:`
  and `TARGET = suppose:` assign the value of the block's last expression
  statement as a snapshot, with no dependency. An assigned block that has no
  value raises `TypeError("suppose has no value")` before it runs.
- Every value that leaves a block is plain data. Objects, instances and
  reasoning steps become plain copies that keep the values they had in the
  hypothetical world, so nothing that leaves is a live reference into the
  discarded world.
- No keyword or lexer token is added. A block is recognized only where the
  accepted parser rejects the input, and `suppose` keeps every accepted
  reading as a name. The authoritative contract is the
  [hypotheticals](../nucleoid.spec.md#hypotheticals) section.

## Motivation

- A world model is useful when it can answer questions it was not built for:
  what happens to the alarm if the reading rises, how many accounts are rich
  if one more opens, what the fees total under a different fee rule. An LLM
  that maintains such a model needs to ask these questions without changing
  the model it is asking about.
- Accepted Nucleoid can only answer them by abusing error handling: change the
  model inside a `try` body, `throw` the answer, and bind it in the `catch`,
  as in `try: reading = 95; throw alarm catch: peak = error`. The spelling
  hides the intent behind an artificial failure, costs five tokens more than
  `peak = suppose reading = 95: alarm`, and grows with every hypothetical.
- The workaround is also wrong in ways a model cannot see:
  - a value thrown out of the `try` keeps references into the discarded
    world, so a reasoning selection loses every `holds` value and an object
    created inside reads as empty;
  - local bindings written inside the `try` body, such as function
    parameters, are not rolled back;
  - inside a function that runs while other changes propagate, the `try` body
    does not see the propagation of its own changes, so the hypothetical
    reads stale derived values;
  - the reads inside the `try` body become dependencies of the declaration
    that runs it, so a snapshot silently turns into a live relationship.
- Testing a change before making it is the most common question an LLM asks
  of a world model it maintains. Draft NUC 11 already proposes `suppose` for
  it as stage 6, and stage 6 needs no other unimplemented part of NUC 11
  except `diff`, so it can be accepted on its own.

## Rationale

- **Category and mode.** The caller selected the Reasoning enhancement
  category by one uniform draw over the four eligible registry categories,
  index 3 with probability 1/4 and no redraw, in continuous mode, so the token
  non-regression gate applies. A hypothetical is reasoning about the model:
  it asks what the rules would derive from different facts. Each new case is
  paired with the most compact accepted-syntax counterpart found, recorded in
  the evaluation baseline.
- **A transaction that always rolls back.** NUC 11 describes a hypothetical as
  "a transaction that always rolls back". The block reuses the savepoint that
  a caught failure already uses, `Transaction::mark` and `rollback_to`, so a
  hypothetical world is exactly as consistent as the real one, and rolling it
  back restores every write, instance, declaration, graph edge, reasoning
  observer, structural subscription, state version and queued propagation.
  The block also restores local bindings, which a caught failure does not.
- **Its own propagation.** While a statement re-runs during propagation, new
  work is queued and drained later, so a `try` body never sees its own
  changes propagate there. A block gets a fresh propagation queue that keeps
  the set of running statements, drains its own changes before it reads its
  value, and is restored afterwards. A statement that runs a block therefore
  sees the same hypothetical answer whether it runs at the top level or during
  propagation, and it cannot wake itself.
- **One-shot, like `for`.** A block runs when the statement holding it runs,
  and its reads add no dependency or structural subscription to that
  statement. The assigned form stores the value as `TARGET = LITERAL` does, so
  the declaration never runs the block again. Rejected: a standing
  relationship that re-runs the hypothetical when its inputs change. It would
  need its own dependency tracking across a discarded world, its answer would
  depend on when propagation reaches it, and a class-level rule would run one
  hypothetical per instance on every change. Live hypotheticals can be
  proposed later without changing these programs.
- **Plain data at the boundary.** Every value that leaves a block, its value,
  a thrown value and a returned value, is converted before the rollback and
  rebuilt after it. Objects are copied, because an object reference names a
  slot in the world, and the hypothetical world's version of that slot is
  gone. The copies keep shared references and cycles, so a list holding the
  same object twice still does.
  - A copy belongs to no class. A copy that stayed an instance would join the
    population, run class-level rules and answer to methods in the real world,
    which is exactly the live behavior the boundary removes.
  - A class value names a class. When the class still exists after the
    rollback, the name keeps meaning it. When the class was declared inside the
    block, there is nothing left to name, so the value becomes `null`, as a
    reference to a deleted name settles to `null` in its dependents.
  - A function value holds no world state: its body resolves names when it
    runs. It stays callable after the rollback, even when its name was
    declared inside the block and is gone.
- **The value of the last expression statement.** NUC 11 defines the value as
  "the value of its last expression statement". Assignments, assertions,
  `delete`, `if`, `for` and other statements do not end a block with a value,
  because an assignment inside the block is a change to the hypothetical world,
  not an answer. A `suppose` block without a target that has a value counts as
  an expression, so `suppose a = 1: suppose b = 2: c` nests answers.
- **No value is an error only when one is needed.** NUC 11's
  `TypeError("suppose has no value")` applies to an assigned block. It is
  raised before the block runs, because whether a block has a value is known
  from its source, and running a hypothetical whose answer cannot be stored
  would only run its assertions for nothing. An unassigned block has the value
  `null` instead, so a block that only asserts or prints is valid.
- **Returns and throws leave after the rollback.** `return` inside a block
  returns from the enclosing function with the converted value, which spells a
  hypothetical answer as `suppose x = 5: return y` without a temporary name. A
  thrown value or an error is raised to the enclosing statement. `try` itself
  is unchanged, so a `try` that catches a throw restores the state from before
  its own body, which removes the plain copies made for the thrown value along
  with everything else its body did. Rejected: making `catch` rebuild them,
  which changes `try` for every program.
- **Recognition where the accepted parser fails.** At the accepted revision,
  `suppose` followed by a statement is two juxtaposed statements, and a colon
  after a complete premise is `SyntaxError("Unexpected ':'")`. A block starts
  only where the accepted parser ended an expression at the name `suppose`, so
  every accepted program keeps its reading:
  - `suppose reading = 95` followed by an indented block or by `{ ... }` stays
    two statements, and with `suppose = 1` it changes `reading`;
  - `suppose x: int`, `suppose: int` and `x = suppose y: int` stay typed
    declarations, and `suppose assert: a, b` stays a colon-led assertion,
    because the statement parser accepts those colons;
  - a premise whose last token before the colon is `lambda`, as in
    `suppose f = lambda: 1`, stays `suppose` followed by a lambda.
  Rejected: a reserved keyword, which would break programs that name a
  variable, function or property `suppose`.
- **A premise parsed like an `if` header.** The premise is an expression or an
  assignment in the clause context, so conditional expressions
  ([NUC 59](nuc-0059.md)) and quantifiers ([NUC 62](nuc-0062.md)) pair their
  own colons, and compound assignments ([NUC 13](nuc-0013.md)) work as
  premises. Each attempt is cached by token position and nesting depth, as
  Python-style conditions are, so juxtapositions nested in function bodies are
  not parsed again and again: at the deepest nesting the parser accepts, 20
  levels, an uncached prototype took 10.9 seconds to parse what the cached one
  parses in milliseconds.
- **The header-less form.** `suppose:` is a syntax error at the accepted
  revision except before a type name, so it is free. It lets a hypothetical
  start with a compound statement, such as a `for` loop over every instance,
  and it is how blocks render canonically. It costs the same two tokens as the
  premise form.
- **Folded rendering.** The premise is the first statement of the block, so
  `suppose reading = 95: alarm` and `suppose: reading = 95; alarm` are the
  same block, and graph keys render both as `suppose{reading=95;alarm}`.
- **Specification export.** The exporter in `build.rs` turns specification
  entries into tests one top-level statement at a time and rewrites the
  assertions inside an indented statement. That rewrite would evaluate every
  assertion inside a block at its first assertion. Entries that mention the
  name `suppose` are exported as one program, as entries with `try` or `catch`
  already are. Every existing generated test and JSONL line is unchanged.
- **Not added.** `diff`, `require` and constraints, `retract`, `why not`,
  live hypotheticals, `return suppose ...`, compound or chained assigned forms,
  and any change to `try`, `catch` or transactions.

### Departures from Draft NUC 11

- NUC 11 adds `diff`, a selection of what changed inside the block. It is not
  added: `diff` outside a block stays an ordinary name, so `suppose a = 2: diff`
  raises `ReferenceError("diff is not defined")`.
- NUC 11 freezes a selection that leaves a block and makes chaining it raise
  `TypeError("Cannot chain a frozen selection")`, and `retract` over it raise
  `TypeError("Cannot retract a frozen selection")`. Here a selection leaves as
  a plain list of plain step objects. Neither error is added: like any list
  held by a variable, `trace |> why` explains the variable `trace`.
- NUC 11 freezes only selections. Here every value that leaves a block is
  converted: objects, instances, lists and thrown and returned values too,
  because each can name a slot of the discarded world.
- NUC 11 makes reasoning keywords lose to variables of the same name. Here
  recognition depends only on the tokens: a variable named `suppose` does not
  disable blocks, and `suppose suppose = 3: x` supposes a new value for it.
- NUC 11 checks constraints inside a block. `require` is not implemented, so
  this proposal checks nothing beyond the existing rules.
- NUC 11's header is always a premise. Here a header-less `suppose:` is added
  and the premise may be any expression or assignment.
- NUC 11 does not say what an unassigned block evaluates to, whether reads
  inside a block become dependencies, whether locals are restored, how a
  `return` leaves, or how a block runs during propagation. This proposal
  specifies each.
- NUC 11 itself is not edited and remains Draft.

### Counterparts

- Every new case is compared with the most compact accepted-syntax program
  found that reaches the same canonical assertions in the same order and the
  same expected return. Each hypothetical becomes a `try` body that ends with
  an undefined name, which fails more cheaply than `throw 0`, or with
  `throw VALUE`, and a `catch` that takes the default `error` binding. The
  catch body absorbs the statement after it instead of `pass`, a snapshot
  asserted only once is asserted inside the `try`, and nested hypotheticals
  nest their `try` statements on one line.
- Both sides share every other line and use the most compact incidental
  spellings: `assert:` statements ([NUC 45](nuc-0045.md)), lambdas for
  two-parameter callbacks ([NUC 57](nuc-0057.md)), one-line class bodies,
  object shorthand ([NUC 17](nuc-0017.md)) and bare named arrows
  ([NUC 18](nuc-0018.md)).
- Every hypothetical in a case is observed by a later assertion, so a
  counterpart cannot drop a rollback. The rule behind a hypothetical answer
  changes later in several cases, so a formula that computes the answer by
  hand is not behavior-equivalent.

## Specification

### Syntax

```
suppose_statement := [target "="] "suppose" (premise ":" | ":") suite
premise           := expression or assignment, in the context of an if header
```

- `suppose` is an ordinary identifier. A statement is a block when its
  expression is exactly the name `suppose`, or a plain `=` assignment whose
  value is exactly the name `suppose`, and what follows is either `:` or one
  premise immediately followed by `:`. The suite is that of `if`: an indented
  block, or statements on the same line separated by `;`.
- These spellings keep their accepted readings:
  - the name followed by a statement with no colon, including an indented
    block or `{ ... }` after it;
  - a typed declaration or a colon-led assertion after the name, as in
    `suppose x: int`, `suppose: int`, `x = suppose y: int` and
    `suppose assert: a, b`;
  - a premise whose last token before the colon is `lambda`.
- The premise may contain conditional expressions, quantifiers, `??`, `|>`,
  calls, arrows and compound assignments. A statement keyword such as `if`,
  `for`, `def`, `class` or `return` cannot start a premise, so
  `suppose if x: y` keeps meaning `suppose` followed by an `if` statement; use
  `suppose:` with an indented body to start a block with one.
- Only statements separated by `;` belong to a same-line suite:
  `suppose a = 1: b c` is a block holding `b`, followed by the statement `c`.
- Blocks are statements, so they appear wherever a statement does: at the top
  level, in suites, braced blocks, function, method and constructor bodies,
  and class bodies. `(suppose ...)`, `[suppose: ...]`, call arguments,
  `return suppose ...`, `x += suppose ...` and `a = b = suppose ...` are not
  blocks and keep their accepted `SyntaxError`.
- `parse_expression`, which reads expressions only, still reads the name
  `suppose`.

```
reading = 40
alarm = reading > 90
peak = suppose reading = 95: alarm
suppose:
    reading = 99
    assert: alarm, true
assert: peak, true
```

### Semantics

- The premise, then the suite, run in the current scope on a transaction
  savepoint. Rules propagate as they do outside the block, and the block's own
  propagation completes inside it, even while other changes propagate; the
  statement being re-evaluated does not run itself again.
- When the block ends, normally, by an error or a thrown value, or by
  `return`, everything it did is rolled back: writes to variables, properties
  and objects, created and deleted instances, class, function and class-level
  rule declarations, graph nodes and dependency edges, reasoning observers and
  their structural subscriptions, state versions, queued propagation, and
  local bindings such as parameters and loop variables. Assertions that ran
  inside stay counted and their failures stay recorded.
- A block adds no dependency and no structural subscription to the
  declaration, block or call that runs it.
- The block's value is the value of its last statement when that statement
  is an expression statement other than an `assert` call, or a block without
  a target that has a value. A statement-level `delete`, an assignment and
  every other statement leave the block without a value.
- Without a target, the statement's value is the block's value, or `null`
  when the block has none. A program, or a native REPL input, that ends with
  one returns or prints it.
- `TARGET = suppose ...` runs the block, then assigns its value as
  `TARGET = LITERAL` does, where LITERAL is the value's literal: a list of
  literals, an object reference, a function, `Date(<milliseconds>)` for a date
  or the class's name for a class. The declaration has no dependency and never
  runs the block again. The target is resolved after the rollback, so a name,
  a local, a property path, `this.x` and `$Class.property` behave as in
  `TARGET = LITERAL`, including their errors.
- An assigned block without a value raises
  `TypeError("suppose has no value")` when the statement runs, before the
  block runs; nothing inside it runs.
- `return` inside a block rolls the block back, then leaves the enclosing
  function, method or program with the converted value.
- An error or a thrown value inside a block rolls the block back, then is
  raised to the enclosing statement. A thrown value is converted like the
  block's value. A `try` that catches it restores the state from before its
  own body, which removes those copies again: in the catch, scalars, lists and
  functions in the thrown value are intact, and an object in it reads every
  property as undefined, as an object created in a `try` body does.
- Blocks nest. An inner block is rolled back before the outer one, and its
  value leaves into the outer hypothetical world.

```
threshold = 90
reading = 40
alarm = reading > threshold
peak = suppose reading = 95: alarm
assert: peak, true
assert: alarm, false
threshold = 99
assert: peak, true
```

### Values that leave a block

- The block's value, a thrown value and a returned value are converted to
  plain data when they leave:
  - null, booleans, numbers, strings, dates, regular expressions and functions
    leave unchanged;
  - a list leaves with each item converted;
  - every object the value reaches is copied into a new plain object holding
    its converted properties as they were when the block ended. Copies keep
    shared references and cycles within one value. A copy belongs to no
    class: it is not an instance, joins no population, has no methods and is
    skipped by `for`;
  - an object reference whose object no longer existed when the block ended is
    copied as an empty plain object;
  - a class value leaves unchanged when a class or built-in namespace of that
    name exists after the rollback, and as `null` otherwise.
- A reasoning selection is a list of step objects, so it leaves as plain
  steps that keep `node`, `holds`, `rule`, `state` and `from`, and it no longer
  re-derives.
- A class declared inside a block is rolled back with it:
  - `kind = suppose: class Temp; Temp` stores `null`, and `kind.length` reads
    `null`;
  - `Temp.length` and `Temp()` after the block raise
    `ReferenceError("Temp is not defined")`;
  - `suppose: class Temp; Temp` as the last statement of a program returns
    `null`.
- A function defined inside a block leaves as itself:
  - `twice = suppose: def double(x) => x * 2; double` stores a function, and
    `twice(4)` is `8`;
  - `double(4)` after the block raises `ReferenceError("double is not defined")`;
  - the function's body resolves names when it runs, so a function that reads
    a name declared only inside the block raises
    `ReferenceError("<name> is not defined")` when called, and one that reads
    a name the block changed reads its restored value.

```
a = 1
b = a * 2
trace = suppose a = 5: why b
a = 7
assert: trace[0].holds, 10
assert: trace[1].holds, 5
```

### Contexts

- A block runs each time the statement holding it runs: once at the top
  level, on each call of a function or method, on each iteration of a `for`
  body, in a constructor for each instance, and whenever an enclosing
  standing `if` branch or block runs again.
- A block never makes the block or conditional around it a class-level rule,
  as a `for` or `try` statement does not. Inside a block or conditional that
  is a class-level rule, it runs once per instance, and `$Class` reads that
  instance.
- `$Class.property = suppose ...` outside a class-level rule runs the block
  once and declares a class-level rule whose value is that snapshot for every
  instance, now and later.

### Canonical rendering

- Graph keys render a block with its premise folded into the body:
  `suppose{reading=95;alarm}` and `peak=suppose{reading=95;alarm}`. Inside
  default-bearing declarations a block renders as `suppose:` or `peak=suppose:`
  with an indented body. Both read back as the same block.

### Native REPL and terminal workspace

- The native REPL already buffers a line whose last token is `:` until a
  blank line, so `suppose reading = 95:`, `peak = suppose reading = 95:` and
  `suppose:` wait for their body, while `suppose reading = 95: alarm` runs at
  once and prints the block's value. No buffering code changes; unit tests and
  an end-to-end REPL test cover it.
- In the terminal workspace, Ctrl-J indents after such a header through the
  same header scan, and `suppose` is a completion word.

### Compatibility

- The lexer and its token stream are unchanged; no keyword is reserved.
- Accepted programs keep their parsing, positions, diagnostics and behavior.
  An accepted program never has a premise or the name `suppose` followed
  directly by `:` outside the preserved spellings above, because the accepted
  parser rejected both with `SyntaxError("Unexpected ':'")`.
- These are the only observable changes:
  - sources with a block, which were syntax errors, now run or fail
    differently, as listed under Errors;
  - the public `Stmt` enum gains `Stmt::Suppose { target, body }`, the public
    `nuc` module gains the `suppose` module with the `Suppose` node, and the
    public `Nuc` enum gains `Nuc::Suppose`. Neither enum is
    `#[non_exhaustive]`, so exhaustive downstream matches stop compiling. This
    needs human SemVer review; no project version is changed;
  - the terminal workspace offers `suppose` as a completion word.
- `try`, `catch`, transactions, functions, class-level rules and every
  existing diagnostic are unchanged.

## Errors

- One message is added; no error type is added.

| Condition | Error |
| --- | --- |
| An assigned block whose last statement is not an expression statement or a valued block, checked before it runs | `TypeError("suppose has no value")`, positioned at the start of the running top-level statement |

| A value thrown inside the block | That value, converted to plain data, after the rollback |

## Reference Implementation

- `src/lang/ast/mod.rs` adds `Stmt::Suppose { target, body }`, where the
  premise is the first body statement.
- `src/lang/ast/parser.rs` recognizes a block after the statement parser has
  read the expression `suppose` or `TARGET = suppose`: a following colon
  starts a header-less block, and otherwise `suppose_premise` tries a clause
  expression and keeps it only before a colon that does not follow `lambda`,
  outside the declaration and assertion spellings. Each attempt is cached by
  token position and nesting depth. The suite is the existing `suite`.
- `src/nuc/suppose.rs` adds the `Suppose` node. `Suppose::run` checks the
  missing-value error, runs `Runtime::suppose`, and assigns an assigned
  block's value through the ordinary assignment statement with
  `literal::constant`. `Runtime::suppose` takes a savepoint and a copy of the
  scope, runs the body in an isolated tracking frame on a nested propagation
  queue from `Stack::nested`, converts the escaping value, rolls back and
  rebuilds the value as plain objects. `src/nuc/mod.rs` adds `Nuc::Suppose`.
- `src/lang/ast/literal.rs` adds `constant`, the literal of any value.
  `src/stack.rs` adds `Stack::nested`, which keeps only the running set.
- `src/lang/ast/generator.rs` renders the folded block in graph keys and in
  the suite form inside default-bearing declarations.
- `build.rs` exports specification entries that mention the name `suppose` as
  one program.
- `src/main.rs`, `src/terminal/editor.rs` and `src/terminal/completion.rs`
  add tests for header buffering and indentation and the `suppose` completion
  word.
- `tests/common/assertions.rs` visits a block's body and target when it
  collects protected assertions.
- `tests/suppose.rs` covers the appended document cases and their assertion
  counts, the AST of every form, rendering and its round trip, every preserved
  reading, `parse_expression`, the parser cache at the deepest nesting, the
  rollback of each kind of effect against a runtime that rolls back the same
  statements with a caught failure, value conversion, classes and functions
  declared inside, throws and errors, the missing-value error, unassigned
  values, `return`, local bindings, dependency isolation, propagation while
  propagating, contexts, assignment targets, out-of-scope spellings, exact
  diagnostics, the native REPL and the whole-program export of the eight
  specification entries.
- The root specification, executable reference, README, examples, the
  consolidated reference with its error table and syntax summary, both NUC 0
  indexes, a new canonical `dataset/nucleoid.synth.44.jsonl` with seven
  records, the regenerated specification export and generated specification
  tests, and the dataset record counts are synchronized in the isolated
  candidate.
- The required Rust improvement pass ran before the candidate was frozen and
  changed no behavior:
  - `Suppose::run` is one match on the target and the flow that
    `Runtime::suppose` returns: only a normal flow with a target is assigned,
    and every other flow passes through unchanged;
  - `has_value` and `Runtime::suppose` are private to `src/nuc/suppose.rs`;
  - both arms of `suppose_statement` use a new `names_suppose` helper;
  - the parser unit test
    `suppose_premises_consume_nothing_unless_a_colon_follows_and_reuse_outcomes`
    checks that a premise is kept only before its colon, that a failed attempt
    consumes nothing and restores the nesting depth and expression context,
    that each attempt is cached under its token position and depth and reused,
    and that declaration, assertion and end-of-statement spellings are refused
    without an attempt.
- No dependency, MSRV, edition or project version changes.
- Preparation checks against accepted revision
  `74e28beeed31c25f84de3c3de9dd0c69fd652a66`, run again after the improvement
