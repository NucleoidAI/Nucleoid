# NUC 116 -- Size and Emptiness Method Aliases

```

Author: Can Mingir <canmingir@gmail.com>
Status: Accepted
Type: Standards Track
Category: Language compatibility
Created: 17-Nov-2026
```

## Abstract

- Lists, class populations and strings gain the size and emptiness methods
  that Java, Kotlin, C++ and Rust spell, as aliases of the accepted
  `length`:
  - `RECEIVER.size()` and `RECEIVER.len()` give `RECEIVER.length`;
  - `RECEIVER.isEmpty()` and `RECEIVER.is_empty()` give
    `RECEIVER.length == 0`, and `RECEIVER.isNotEmpty()` gives
    `RECEIVER.length > 0`;
  - strings also accept Java's `TEXT.length()`, as lists and populations
    already do.
- Each alias behaves exactly as the accepted `RECEIVER.length()` call does
  for lists and populations: its arguments are evaluated and ignored, a
  declaration that holds it stays live as the receiver changes, and a class
  with no instances has size `0`. A string's size counts its characters, as
  `TEXT.length` does, so `"Zoë".len()` is `3`.
- At the accepted revision each of these calls raises
  `TypeError("<receiver>.<name> is not a function")`. Only those calls
  change, along with the programs that caught that error. On every other
  receiver the names keep the reading that `length()` has there: numbers,
  booleans, functions, dates and regular expressions keep their
  `TypeError`, objects and instances keep their methods, callable
  properties and undefined members, a `null` or undefined receiver stays
  undefined, and a class declared as `Math`, `Number`, `String` or `Date`
  keeps reaching that namespace's static methods. Reads without a call,
  such as `xs.size`, stay undefined.
- `length` stays the canonical spelling. No token, keyword, syntax-tree
  node, error type or message format, dependency or public item is added.
- The authoritative contract is
  [Size and emptiness method aliases](../nucleoid.spec.md#size-and-emptiness-method-aliases).

## Motivation

- Programs and models written by people and LLMs that know Java, Kotlin,
  C++ or Rust ask a collection for its size and emptiness with methods:
  `list.size()` and `list.isEmpty()` in Java, `isEmpty()` and
  `isNotEmpty()` in Kotlin, `v.size()` in C++, `v.len()` and `v.is_empty()`
  in Rust, and `text.length()` in Java. In Nucleoid every one of them
  raises `TypeError("<receiver>.<name> is not a function")`, so a world
  model that guards a rule with `queue.isEmpty()` or reports
  `orders.size()` fails before it runs, although the accepted spellings
  `queue.length == 0` and `orders.length` say the same thing.
- A world model is often guarded by emptiness: a queue that is idle when it
  holds no job, a shelf to restock when it holds no item, a sensor that is
  silent until it reads a value. These rules are standing, so they must
  follow every later push and pop, which the accepted `length` already
  does and the aliases inherit.
- The aliases advance the language-superset aspiration of the Language
  compatibility category. The accepted `this`/`self`, `=>`/`->`, `append`,
  `find`, `contains`, `lower`, `upper`, `strip`, `substr` and NUC 110's
  `startswith`, `endswith` and `join` follow the same pattern: an
  equivalent familiar spelling beside the canonical one, with no change to
  any accepted program.
- Prior art: Java's `Collection.size()`, `Collection.isEmpty()` and
  `String.length()`, Kotlin's `isEmpty()` and `isNotEmpty()`, C++'s
  `size()`, and Rust's `len()` and `is_empty()`.

## Rationale

- **Category and mode.** The allocating continuous cycle drew Language
  compatibility with one tool-backed uniform draw over the five categories
  that NUC 1's registry marks eligible for automatic selection, index 4
  with probability 1/5 and no redraw, and recorded the requested change in
  the allocation commit `7bc9f013`, which this revision pins. Token
  comparison is therefore skipped as `language_compatibility`. The skip is
  categorical; it is neither a measured comparison nor a passing token
  gate. Runtime applicability does not apply to this category.
- **No counterparts.** Because comparison is skipped, the new cases have no
  accepted-syntax counterparts. They execute their assertions and explicit
  returns with full coverage, and every pre-existing case is unchanged.
- **Optional evidence.** No hint was supplied. Advisory usefulness is
  unscored (`missing_rubric`), not zero. Strategy learning is
  `not_configured`, so this revision is unattributed, with no policy,
  selection receipt, trial or reward.
- **Only former errors.** At the accepted revision every call of the five
  names on a list, population or string receiver, and every `length()` call
  on a string, raises `TypeError("<receiver>.<name> is not a function")` at
  the start of the running statement, in plain and JSON output alike,
  unless an argument raises first. No accepted test, document case, dataset
  record or ARC dataset calls them, and no test pins that error.
- **One table for every receiver.** The names and their meanings live in
  one crate-private function, `size_query`, which the list queries and the
  string methods both consult after their other arms, with the receiver's
  own length: the list's item count, the population's instance count or
  the string's character count. `isEmpty` is `length == 0` and
  `isNotEmpty` is `length > 0` of that same count, so the aliases cannot
  drift from `length` or from each other. Rejected: rewriting the names at
  parse time, which would render `length` where the source wrote `size()`,
  and separate arms per receiver, which could disagree.
- **The receivers of `length()`.** Lists and populations already answer
  `length()`, through the list queries that every list receiver and every
  class value reach, so the aliases join exactly those receivers: a list
  however it is reached, and a class named by its name, by a variable or
  parameter that holds it, or by `$Name` outside a class-level rule. A
  string gains `length()` together with the aliases, through the string
  methods. Every other receiver keeps its route, and with it its result:
  where `length()` raises, the aliases raise the same error with their own
  name, and where it reads a member, they read theirs.
- **Statics and built-in names.** A class declared as `Math`, `Number`,
  `String` or `Date` reaches that namespace's static methods before its
  instances, so `Math.size()` keeps raising
  `TypeError("Math.size is not a function")`, as `Math.length()` does,
  although `Math.length` reads its instance count. `Boolean`, `Class`,
  `Object`, `List`, `Function`, `JSON` and `RegExp` without a declared
  class of that name keep `ReferenceError("<name> is not defined")`, as
  their `length()` does; `Class.length` keeps counting the declared
  classes.
- **Population first on a class name.** As `Name.length()` already counts
  the instances when the class declares an instance method `length`,
  `Name.size()` counts them when it declares `size`, which raised
  `TypeError("Name.size is not a function")` at the accepted revision.
  Instances keep calling their methods, as
  [NUC 114](nuc-0114.md) settled for `product`.
- **Calls only.** Reading `xs.size` or `s.isEmpty` without a call stays
  undefined, and assigning them keeps its accepted `TypeError`. A property
  alias would change accepted outputs, since those reads give `undefined`
  rather than an error, and it would read like an object's own property of
  the same name, as in `{size: 3}`.
- **Arguments.** The receiver is read first and then every argument once,
  left to right, as for every call, and the values are ignored, as
  `length()` ignores them. An argument's error therefore propagates before
  the alias runs, and a `null` or undefined receiver stays undefined
  without evaluating the arguments, as the accepted null-safe reading does.
- **Live and rendered as written.** A declaration or class-level rule that
  calls an alias depends on what its receiver reads, the same nodes the
  accepted spelling depends on. Statements, `why`, `affects`, `--graph` and
  graph keys render the call as every call is rendered, with the name the
  source wrote; nothing renders `length` in its place.
- **Source-language differences stay documented, not emulated.**
  - Kotlin reads `list.size` and Swift `array.isEmpty` as properties;
    Nucleoid adds calls only, for the reasons above.
  - Java's `isEmpty()` on maps, optionals and other objects is not added:
    objects and instances keep their routing, so `o.isEmpty()` after
    `o = {}` stays undefined.
  - C++'s `empty()` is not added: it reads as a command to empty the
    container, and `xs.empty()` keeps its `TypeError`.
  - Python's `len(xs)` is not added: it is a global function rather than a
    method alias, and `len` is a common name of variables and parameters.
  - Swift's and C#'s `count` and `Count` are not added, because
    `xs.count(predicate)` is the accepted predicate count.
  - Every receiver counts characters, Unicode scalar values, as `length`
    does, where Java counts UTF-16 code units and C++ and Rust count bytes:
    `"Zoë".len()` is `3` where Rust gives `4`.
- **Completion.** The terminal workspace offers the JavaScript names of
  string and list members, and none of the accepted aliases, as
  [NUC 110](nuc-0110.md) kept it. This proposal follows that precedent and
  adds no completion entry.
- **The public string method.** `nucleoid::builtins::string_method` is the
  public function behind every string method, so it now accepts `length`,
  `size`, `len`, `isEmpty`, `is_empty` and `isNotEmpty` where it returned
  the `TypeError`. No public item is added or removed; the widened set of
  names is the change to report for semantic-versioning review.
- **No `Requires`.** `length`, the list queries, the populations and the
  string methods are base built-ins that no NUC introduced; NUC 110 and
  NUC 114 are followed as precedents, not depended on.
- **Not added.** Property aliases, `count`, `empty()`, `len(xs)`,
  `isBlank`, `isNullOrEmpty`, aliases on objects, instances or other
  receivers, static forms such as `String.size`, noun forms such as
  `size of xs`, completion entries and any change to `length`.

## Specification

- The normative contract is
  [Size and emptiness method aliases](../nucleoid.spec.md#size-and-emptiness-method-aliases).

### Calls

- `RECEIVER.size(...)`, `RECEIVER.len(...)`, `RECEIVER.isEmpty(...)`,
  `RECEIVER.is_empty(...)` and `RECEIVER.isNotEmpty(...)` are aliases when
  `RECEIVER` evaluates to a list, to a declared class whose instances the
  list queries reach, or to a string. On a string `TEXT.length(...)` joins
  them, as lists and populations already answer `length(...)`.
- Receivers are reached however the language reaches them: literals,
  names, properties, call and query results, indexes and slices, `.value`
  snapshots, state versions, templates, conditional expressions, a class
  through a variable or a parameter, and `$Name` outside a class-level rule
  or conditional.
- On every other receiver the names keep the readings of
  [Compatibility](#compatibility).

### Sizes

- `size()`, `len()` and, on a string, `length()` give `RECEIVER.length`:
  the number of items of a list, the number of instances of a class, `0`
  for a class without instances, and the number of characters of a string.

```
queue = ["ana", "bo"]
waiting = queue.size()
served = queue.len()
assert([waiting, served], [2, 2])
queue.push("cy")
assert([waiting, served, queue.length], [3, 3, 3])
class Order(item):
    this.item = item
orders = Order.size()
assert([orders, Order.len()], [0, 0])
Order("tea")
Order("cake")
assert([orders, Order.len(), Order.length], [2, 2, 2])
name = "Zoë"
letters = name.size()
assert([letters, name.len(), name.length(), name.length], [3, 3, 3, 3])
name = "Ada Lovelace"
assert([letters, "".size(), [].len()], [12, 0, 0])
queue.shift()
[waiting, served]
```

- This returns `[2,2]`: both declarations follow the push and the shift,
  `orders` follows the new instances, and `letters` follows the write of
  `name`.

### Emptiness

- `isEmpty()` and `is_empty()` give `RECEIVER.length == 0`, and
  `isNotEmpty()` gives `RECEIVER.length > 0`, of the same count.

```
jobs = []
idle = jobs.isEmpty()
busy = jobs.isNotEmpty()
assert([idle, busy, jobs.is_empty()], [true, false, true])
jobs.push("print", "scan")
assert([idle, busy], [false, true])
jobs.pop()
jobs.pop()
assert([idle, busy], [true, false])
class Sensor(name):
    this.name = name
    this.readings = []
$Sensor.silent = $Sensor.readings.is_empty()
$Sensor.alarm = $Sensor.readings.isNotEmpty() && $Sensor.readings.at(-1) > 40
door = Sensor("door")
oven = Sensor("oven")
assert([door.silent, oven.silent, oven.alarm], [true, true, false])
oven.readings.push(35, 52)
assert([oven.silent, oven.alarm, door.silent], [false, true, true])
oven.readings.pop()
assert([oven.silent, oven.alarm], [false, false])
assert([Sensor.isEmpty(), Sensor.isNotEmpty(), "".isEmpty(), "on".is_empty()], [false, true, true, false])
```

- `idle` and `busy` follow the pushes and pops of `jobs`, and each sensor's
  class-level rules follow its own readings; `isNotEmpty()` guards
  `at(-1)`, which would read an empty list's missing last item.

### Evaluation

- The receiver is read first and then every supplied argument once, left to
  right, including unused extras, as for every call; the values are
  ignored. A missing name among them raises
  `ReferenceError("<name> is not defined")` before the alias runs:
  `xs.size(missing)` raises it, as `xs.length(missing)` does.
- The receiver's items are read before the arguments run, as for
  `length()`, so an argument that changes the receiver does not change the
  answer: after `Item(1)` and `Item(2)`, `Item.size(Item(3))` is `2`, as
  `Item.length(Item(3))` is, and `Item.size()` is `3` afterwards; after
  `xs = [1]`, `xs.size(xs.push(2))` is `1`.
- A `null` or undefined receiver keeps the accepted route: the call is
  undefined and the arguments are not evaluated, so after `u = null`,
  `u.size(missing)` is undefined.

### Liveness and class-level rules

- A declaration that calls an alias depends on what its receiver reads:
  pushes, pops, shifts, sorts and replacements of a list, writes of a
  string, writes of the property that holds either, and new and deleted
  instances of a population re-evaluate it. A declaration whose receiver is
  `null` or undefined waits, as the accepted spelling does, and takes the
  alias's value once the receiver is written.
- In a class-level rule or conditional each instance evaluates its own
  alias over its own properties. There `$Name` is the instance, so
  `$Name.size()` keeps calling the instance's method or giving undefined,
  while `Name.size()` is the population.
- This program is the specification entry
  `Nucleoid rolls back failed updates through size and emptiness aliases`,
  which also exercises [Transactions](#transactions):

```
stock = ["bolt", "nut"]
low = stock.size() < 3
failure = ""
try:
    stock = 7
catch error:
    failure = error
assert(failure, TypeError("number.size is not a function"))
assert([stock, low], [["bolt", "nut"], true])
try:
    stock.push("gear")
    assert([stock.len(), low], [3, false])
    throw "UNDO"
catch error:
    assert(error, "UNDO")
assert([stock.len(), low], [2, true])
class Bin(items):
    this.items = items
$Bin.empty = $Bin.items.isEmpty()
bin = Bin(["pin"])
try:
    bin.items = 0
catch error:
    failure = error
assert(failure, TypeError("number.isEmpty is not a function"))
assert([bin.items, bin.empty], [["pin"], false])
label = "ok"
shown = label.length()
try:
    label = true
catch error:
    failure = error
assert([failure, label, shown], [TypeError("boolean.length is not a function"), "ok", 2])
bin.items.pop()
bin.empty
```

- This returns `true`.

### Rendering and graph keys

- Statements, `why`, `affects`, `--graph` and graph and block keys show the
  call in the canonical rendering of every call, with its name as written:
  after `n = queue.size()`, `(why n)[0].rule` is `"n = queue.size()"`, and
  the block key of `if xs.isEmpty():` is `if(xs.isEmpty())`.
- The dependencies are those of the accepted spelling: `(why n)[0].from`
  is `["queue"]` after `n = queue.size()`, as after `n = queue.length`, and
  `c = Item.len()` depends on `$Item`, as `c = Item.length` does.

### Transactions

- Errors of an alias propagate through the existing transaction, so a failed
  standing re-evaluation rolls back the change that triggered it: a list
  replaced by a number, raising `TypeError("number.size is not a function")`,
  a property written a number under a class-level rule, raising
  `TypeError("number.isEmpty is not a function")`, and a string replaced by
  a boolean under `length()`, raising
  `TypeError("boolean.length is not a function")`, as the entry above
  shows. A failed statement or transaction restores declarations that call
  aliases, their values and their dependencies.

### Cost

- Each alias runs one match on its name after the receiver's other method
  names, and then reads the receiver's length: a list's item count, a
  population's instance list, which `length()` builds too, or a string's
  character count, which `TEXT.length` counts too. A string method that is
  not a size name, such as `toUpperCase`, passes one more match on its name
  and counts nothing.
- **Measured**, not projected, on the final tree, through the command line
  on release builds, rustc 1.97.1: the median of five runs of each program
  with `--json`, including process start, on `nucleoid-final.exe`, the
  release build of the final tree, and on the accepted revision's release
  build for the accepted spellings, one process at a time with nothing else
  running. Unless a row says otherwise, each program makes 100,000 calls
  from `items.map(x -> ...)`, where `items` is
  `"x".repeat(100000).split("")`, which alone takes 30.5 ms; the list holds
  three items and the class three instances. Times are in milliseconds.

- In the `length()` column the emptiness rows are `length() == 0` and
  `length() > 0`, and in the `length` column `length == 0` and
  `length > 0`. Strings have no accepted `length()`.
- Each alias takes 0.96 to 1.03 times the `length()` spelling on the same
  build, so it costs what the accepted method costs. Against the `length`
  property it pays the cost of a method call: 1 to 9 ms per 100,000 calls
  on a list; 0.99 to 1.08 times the property on one-letter strings, and
  0.96 on the long string; and on a population the instance list that
  every population method builds, 12 to 13 ms per 100,000 calls with three
  instances.
- That instance list grows with the population: with 1,000 instances
  `Item.size()` takes 359 ms and the accepted `Item.length()` 373 ms for
  10,000 calls, about 33 µs a call, where the `Item.length` property takes
  26 ms. The alias adds no cost of its own there; a declaration that reads
  a large population's size often reads it fastest through the property.
  Any faster path for the population's size would have to keep reading the
  instances before the arguments, as [Evaluation](#evaluation) states.
- A standing declaration that calls an alias re-runs once per push, as its
  spelling does; the 10,000 pushes take 1.5 to 1.7 s with every spelling.
- The final build's accepted spellings take 0.97 to 1.04 times the
  accepted revision's, apart from two medians that vary between runs: the
  unrelated `toUpperCase` at 1.06 and the standing `e = xs.length == 0` at
  1.08. Runs of each build interleaved one by one put them at 1.005 (21
  runs each, 68.4 and 68.7 ms) and 1.005 (11 runs each, 1,538.9 and
  1,546.8 ms), the string `length` property at 0.99 and the program that
  only builds `items` at 1.00, so the further match on the name of a
  string method that is not a size name costs nothing measurable.

### Compatibility

- Parsing, the syntax tree, canonical rendering and graph keys are
  unchanged; the six names stay ordinary method names.
- Only inputs that were errors at the accepted revision change: calls of
  the five names on list, population and string receivers and of
  `length()` on strings, each of which raised
  `TypeError("<receiver>.<name> is not a function")` at the start of the
  running statement, and the programs that caught that error. Calls whose
  arguments raise first keep that error. "The items" are
  `class Item(v):` with the body `this.v = v`, then `Item(1)` and
  `Item(2)`.
