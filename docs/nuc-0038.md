# NUC 38 -- Reactive Inverse Interpolation

```

Type: Standards Track
```

## Abstract

- Add only unshadowed static `Math.inverseLerp(start, end, value)`, an
  unclamped intrinsic numeric normalization.
- Convert the first three inputs intrinsically, then compute numerator
  subtraction, denominator subtraction and division as separate ordered
  ordinary floating-point operations.
- Preserve accepted syntax, reactive reads, argument effects, class rules,
  frames, receivers, error positions and transactional recovery.
- Independent evaluation accepted the frozen candidate: eight cases use
  fewer lexer tokens, 539 are unchanged, and none increase.

## Motivation

- Name a live position within a range without repeating the start input in
  `(value - start) / (end - start)`.
- Complement accepted `Math.lerp` reconstruction without hiding extrapolation
  or imposing clamping on descending or out-of-range measurements.
- Retain independent reconstruction controls, every assertion and both real
  rollback catches rather than weakening demonstrations to abbreviate them.

## Rationale

- Ordinary subtraction followed by subtraction and division specifies the
  exact accepted normalization, including nonfinite and overflow behavior.
- Clamping, smoothing, range validation, factoring, endpoint shortcuts,
  fused operations and scaling to avoid span overflow are different contracts.
- Equal endpoints do not justify a special return: ordinary zero-over-zero
  gives NaN and nonzero-over-zero gives signed infinity.
- Descending ranges are valid; outputs outside `[0, 1]` are intentional.
- Compare expected NaNs by classification, not payload; compare every other
  result, including zero, by bits against independent accepted binary controls.
- Reuse the existing Math supplied-Undefined gate and first-input conversion,
  without adding a namespace, callable representation or production helper.
- Intrinsic conversion must never resolve, invoke or track shadowable Number
  or Math method bindings.
- Evaluate every supplied expression once, left to right, including ignored
  extras and expressions following an Undefined.
- Depend only on already accepted arithmetic, conversion, calls and reactive
  behavior; combine no pending proposal.

## Specification

### Static numeric contract

- The authoritative
  [Reactive inverse interpolation section](../nucleoid.spec.md#reactive-inverse-interpolation)
  defines the accepted contract and takes precedence over this proposal.
- The only added unshadowed static signature is
  `Math.inverseLerp(start, end, value)`.
- Evaluate every supplied expression once, left to right, through the
  unchanged call machinery before numeric dispatch.
- If any supplied value is Undefined, including an ignored extra, return
  Undefined through Math's existing gate before conversion.
- Reuse the dispatcher's existing first-input `Value::to_number` conversion
  for start; intrinsically convert positions one and two to end and value,
  in that order. Each missing input supplies numeric NaN, not Undefined.
- Numbers retain their values, literal null converts to zero, booleans to
  zero/one, trimmed strings and empty/singleton lists keep existing numeric
  conversion, and dates contribute milliseconds.
- Other nonnumeric conversions yield numeric NaN, not new type errors.
- Compute `numerator = value - start`.
- Compute `denominator = end - start`.
- Return numeric `numerator / denominator`.
- Perform those separate ordinary `f64` operations in exactly that order.
- Do not clamp, smooth, validate or reorder ranges, factor, use FMA, raise
  precision, scale to avoid overflow, or shortcut equal endpoints or zero width.
- Descending ranges and results below zero or above one remain ordinary arithmetic.
- Equal finite endpoints give zero-over-zero NaN or nonzero-over-zero signed
  infinity, rather than a range error or a special midpoint.
- Nonfinite inputs, span overflow, cancellation, underflow, subnormals and
  signed zeros retain the exact ordered accepted composition.
- In particular, `Math.inverseLerp(-Number.MAX_VALUE, Number.MAX_VALUE, 0)`
  yields zero, not `0.5`; overflowing the span is not avoided by rescaling.
- Expected NaNs compare by classification; every non-NaN result, including
  zero, matches independent accepted binary subtraction/division controls by
  bits. No portable NaN-payload or zero-sign convention is introduced.
- Extra resulting values are neither numerically converted nor used.

### Evaluation and compatibility

- Preserve all supplied expressions' reads, effects, dependencies and strict
  failures, including extras and expressions after an undefined property.
- Supplied Undefined preserves deferred assignments and recovery when
  missing properties become defined.
- Intrinsic literal-null conversion does not override inherited live
  assignment or parameter-null deferral.
- Preserve positions, caught values, graph subscriptions, transactions,
  rollback, property deletion and subsequent reactive recovery.
- State/local Math bindings still shadow the static namespace; ordinary
  `.Math` properties and methods retain their existing lookup.
- Reading `Math.inverseLerp` as a value remains unsupported/Undefined, not a
  first-class callable reference or alias.
- Intrinsic conversion neither invokes nor tracks shadowable Number or
  Math methods; do not recursively invoke public Math dispatch.
- Typed wrappers, call frames, receivers, aliases, scopes and per-instance
  class rules use unchanged machinery.
- New intrinsic RHS ASTs and immediate dependency graphs may intentionally
  differ from emulation; do not require whole-new-program AST/graph identity.
- Protect non-RHS source/ASTs, ordered canonical assertions, independent
  controls, observable values, transitive reads/effects/errors, explicit
  returns and actual executed assertion coverage.
- Every existing Math arm, helper, constant, conversion and error remains
  unchanged, especially lerp, clamp, saturate, smoothstep, smootherstep and fract.
- The arithmetic normalization spelling and every accepted syntax form,
  including NUC37 comma-free named arrows, remain fully available.
- Add no parser, lexer, AST, generator, CLI implementation, API/representation,
  namespace, dependency, version, MSRV, edition or resource-bound change.
- Do not repair inherited noncapture, parameter-dependent-local, Windows debug
  stack or old whole-suite Gitless discovery limitations.

## Errors

- Introduce no numeric, coercion, range-validation or arity errors.
- NaNs, missing numeric inputs, equal ranges and nonfinite results are not errors.
- Argument/application failures retain inherited kinds, exact messages,
  statement positions, caught values and transactional recovery.
- Never skip an expression because an earlier value is Undefined.

| Condition | Exact inherited error |
| --- | --- |
| Strict unknown argument `missing`, including extras or after an undefined property | `ReferenceError("missing is not defined")` |
| Unsupported static `Math.random()` argument | `TypeError("Math.random is not supported")` |
| Unchanged unknown static method `unknown` | `TypeError("Math.unknown is not a function")` |
| Calling through numeric state `Math = 7` | `TypeError("number.inverseLerp is not a function")` |
| Literal EOF after `Math.inverseLerp(` | `SyntaxError("Unexpected end of input")`, line 1, column 18 |
| Literal EOF after `Math.inverseLerp(` and a newline | `SyntaxError("Unexpected end of input")`, line 2, column 1 |

- Runtime failures retain the start of their top-level statement; catch values
  omit the position. User throws, including `"ROLLBACK"`, retain their values.
- Unknown/random Math calls still pass through the existing supplied-Undefined
  gate; shadowed receivers retain ordinary method errors.
