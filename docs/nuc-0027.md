## Abstract

- A named expression-body arrow may optionally omit parentheses around a comma-separated list of two or more untyped ordinary identifier parameters.
- `def add left, right => left + right` is exactly `def add(left, right) => left + right`, including methods and `init`.
- Reuse accepted [NUC 12](nuc-0012.md)'s named return-block lowering and extend accepted [NUC 18](nuc-0018.md)'s untyped arrow shorthand without changing existing syntax or runtime behavior.

## Motivation

- Multi-input calculations, higher-order helpers and short methods can express their existing parameter list without its parentheses.
- Keep every parenthesized alternative valid; a shorter spelling is optional, not a replacement or a new calling convention.
- Select one syntax improvement, as supplied by the coordinating caller; add no runtime feature or pending dependency.

## Rationale

- Require the complete identifier/comma sequence to end immediately in `=>`, so an unsupported prefix is never partially consumed.
- Require at least two untyped ordinary identifiers; the existing single-parameter typed and untyped guards remain unchanged.
- Do not extend bare block headers, typed/mixed lists, defaults, destructuring, rest parameters, return annotations or calls.
- Do not skip logical newlines, semicolons or comment-induced logical breaks; parenthesized multiline lists retain their existing grammar.
- Reuse the existing parameter parser, types and expression-body path rather than cloning an AST, inventing lexer tokens or adding runtime dispatch.
- Retain the flat parameter parser's existing resource behavior; an operator-chain limit is not a parameter-count limit.
- Keep all accepted dependencies and canonical rendering unchanged; historical NUC18 exclusions describe that proposal's own scope and are not edited.

## Specification

### Grammar and lowering

- The authoritative [bare multiple-parameter named arrows](../nucleoid.spec.md#bare-multiple-parameter-named-arrows) section governs this revision.
- Parse `def` and the required ordinary definition name exactly as before.
- Look ahead without consuming any tokens for `Identifier Comma Identifier (Comma Identifier)* Arrow`.
- Each comma must be followed immediately by another ordinary identifier token; the complete list must be followed immediately by `Arrow`.
- Allow ordinary whitespace between tokens on the same logical header line, but skip no logical newline, semicolon, indentation token or comment-induced logical break.
- Perform lookahead without allocating parameter names or cloning an AST; its scan is linear in the candidate list.
- If the complete list qualifies, consume its parameters in order through the existing parameter parser, preserving `Parameter { name, type_name: None }`.
- Reuse the existing named-arrow expression path, producing the same named `FunctionBody::Block` containing `Stmt::Return(Some(expression))` as the parenthesized form.
- If the list does not qualify, leave it untouched for the existing single-parameter guards or parenthesized parameter parser, preserving unsupported-prefix diagnostics and positions.
- Methods and `init` use the same function-statement parser, so they receive exactly the same optional spelling.
- Skip no separator before the first body expression; a parenthesis starting on that logical line may still span physical lines.
- Named-arrow leading braces remain object expressions, not statement suites; lists, templates and returned anonymous functions keep their existing expression grammar and noncapturing scope.
- Keep precedence, assignment-expression returns, missing/null/extra argument binding, local shadowing, receiver handling, initializer adoption and `super` unchanged.
- Keep reactive inputs, live callable aliases, `.value` definition snapshots, redefinition, graph dependencies, transactions, error recovery and canonical rendering identical to the parenthesized counterpart.
- Introduce no parameter-count cap, lexer/public AST/runtime type, runtime/generator change, dependency, MSRV or version change; existing expression nesting and chain limits remain in force.

### Compatibility and exclusions

- Preserve all parenthesized arrows and blocks, including empty, typed/mixed, trailing-comma and multiline parameter lists.
- Preserve NUC18/20's single-parameter untyped/typed arrows and NUC19/24's single-parameter untyped/typed indented blocks.
- Preserve class parameter lists, anonymous arrows, calls, ordinary-identifier references and all word/keyword meanings.
- Do not add bare multiple-parameter indented, inline or braced block headers.
- Do not add typed/mixed bare multiple parameters, defaults, destructuring, rest parameters, trailing bare commas or return annotations.
- Preserve every measured case identity, assertion order, canonical assertion, expected return and executed assertion coverage.
- Add only the five supplied spec cases and the supplied reference, README and examples cases, paired with pre-executed accepted-syntax sources in the caller's immutable baseline.
- Rewrite only eligible named multi-untyped-parameter arrow headers in those cases and existing executable documents; leave single parameters, typed/block definitions, calls, anonymous arrows, strings, comments, templates and assertions unchanged.
- Keep relevant canonical synthesized examples and generated normative JSONL/Rust exports synchronized; retain representative parenthesized alternatives in the reference and Rust compatibility tests.

- This complete example is the new forms entry without its title comment.

```nuc
def add left, right => left + right
def scaled left, right, factor => (left + right) * factor
def pair left, right => [left, right]
def coordinates x, y => {x, y}
assert(add(2, 3), 5)
assert(scaled(2, 3, 4), 20)
assert(pair("left", "right"), ["left", "right"])
point = coordinates(2, 3)
assert(point.x, 2)
assert(point.y, 3)
```

## Errors

- Introduce no new error kind or runtime message; unsupported tokenizable prefixes use the unchanged parenthesized parser before any prefix consumption.
- The following exact errors and positions follow the normative boundary section; arbitrary body expressions retain their existing diagnostics.

| Exact input or condition | Exact error | Position |
| --- | --- | --- |
| `def f left, right` | `SyntaxError("Expected '(' but found identifier 'left'")` | line 1, column 7 |
| `def f left, right, => left` or a missing parameter after a comma | `SyntaxError("Expected '(' but found identifier 'left'")` | line 1, column 7 |
| `def f left, right: int => left` or `def f left: int, right => left` | `SyntaxError("Expected '(' but found identifier 'left'")` | line 1, column 7 |
| Bare multiple-parameter blocks, defaults, destructuring, rest, return annotations, or logical breaks after the first `left` | `SyntaxError("Expected '(' but found identifier 'left'")` | line 1, column 7 |
| `def f this, right => right` | `SyntaxError("Expected '(' but found keyword 'this'")` | line 1, column 7 |
| Logical newline immediately after `def f` | `SyntaxError("Expected '(' but found end of line")` | line 1, column 5 |
| Semicolon immediately after `def f` | `SyntaxError("Expected '(' but found ';'")` | line 1, column 6 |
| `def f(left, right:) => left` | `SyntaxError("Expected a type but found ')'")` | line 1, column 21 |
| `def f left, right =>` | `SyntaxError("Unexpected end of input")` | line 1, column 21 |
| That exact header followed by a final newline | `SyntaxError("Unexpected end of line")` | line 2, column 1 |
| `def f left, right => (left +)` | `SyntaxError("Unexpected ')'")` | line 1, column 30 |
| `def f left, right => { return left }` | `SyntaxError("Expected a key but found keyword 'return'")` | line 1, column 31 |
| `def f left, right => { left = 1 }` | `SyntaxError("Expected ':' but found '='")` | line 1, column 29 |
| An unparenthesized multiline object body introduces indentation | `SyntaxError("Expected a key but found an indented block")` | line 2, column 5 |
| `def f left, right => @` | `SyntaxError("Unexpected character '@'")` | line 1, column 22 |
| An evaluated body or object field reads undefined `missing` | `ReferenceError("missing is not defined")` | existing top-level statement position |
| A returned anonymous function reads uncaptured parameter `left` | `ReferenceError("left is not defined")` | existing top-level statement position |
| `this` or `self` without an instance receiver | `ReferenceError("this is not defined")` | existing top-level statement position |
| A non-callable parameter shadows `operation` | `TypeError("operation is not a function")` | existing top-level statement position |
| Excessive body expression nesting | `SyntaxError("Expressions are nested too deeply")` | existing expression position |
| Excessive body operator chain | `SyntaxError("Expression has too many operands")` | existing expression position |
| Excessive body postfix chain | `SyntaxError("Expression has too many parts")` | existing expression position |

- Lexical failures precede parsing; caught runtime values keep their existing messages without source positions.
- Header-delimiter removal naturally shifts later columns by one character relative to the explicit form; errors in unsupported prefixes retain their exact prior positions.
- No broad stack-safety, closure-capture or inherited propagation repair is proposed.

- [`tests/bare_named_arrows.rs`](../tests/bare_named_arrows.rs) replaces only the newly supported negative prefix with positive exact-equivalence checks, preserving all other unsupported-prefix assertions.

- Relevant `synth-21` records retain their stable IDs, descriptions, assertions and expected results; unchanged parenthesized training records remain valid legacy examples.
