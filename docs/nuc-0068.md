```

Author: Claude <noreply@anthropic.com>

Type: Standards Track

Created: 31-Oct-2026
Requires: 8, 18, 41, 45, 57, 59, 60, 61, 66
```

## Abstract

- Lists and class instance lists gain the read-only query `sum`.
  `RECEIVER.sum()` returns the numeric total of the items and
  `RECEIVER.sum(selector)` the total of `selector(item)`, added left to right
  from `0`. An empty receiver gives `0`.
- Each added value is converted to a number with the conversion of `-`, `*`
  and the Math helpers: `true` counts `1`, `null` and `""` count `0`, and
  `"3"` counts `3`. An undefined value makes the total undefined, which a
  declaration stores as `null`, as `+` and the Math helpers do.
- For a list of numbers, `xs.sum()` is exactly
  `xs.reduce((total, x) => total + x, 0)`: the same order and the same
  rounding.
- The selector is called once for every item, in order, with only the item,
  as `map` calls its callback. A supplied selector that is not a function
  raises `TypeError("sum expects a function")`.
- `sum` follows [NUC 61](nuc-0061.md)'s shared query rules. It accepts every
  receiver the list queries accept, reads the receiver before its arguments,
  never writes it, and stays live in declarations and class-level rules like
  `map` and `reduce`.
- At the accepted revision, these calls raise
  `TypeError("<receiver>.sum is not a function")`. No syntax, keyword, error
  type or public Rust API is added. The authoritative contract is
  [List and population sums](../nucleoid.spec.md#list-and-population-sums).

## Motivation

- World models keep totals: the revenue of open orders, the load of the
  devices in a room, the value of stock, the points of a team. Each is a sum
  over a list or over a class's instances, and it has to stay true while the
  model changes.
- The accepted spelling is an accumulator `reduce`. The specification spells
  six totals this way, such as
  `total = Account.reduce(lambda sum, account: sum + account.balance, 0)`;
  the executable reference and the examples add five more, including the
  aggregation rule
  `$Category.revenue = Product.filter(p => p.category == $Category).reduce((sum, p) => sum + p.price, 0)`.
- The accumulator restates the same three parts every time: a running name,
  `+` and the initial `0`. `total = Account.sum(account -> account.balance)`
  is 12 lexer tokens where the accepted line is 19,
  `total = items.sum()` is 7 where
  `total = items.reduce(lambda sum, item: sum + item, 0)` is 17, and the
  aggregation rule drops from 33 tokens to 25.
- The accumulator is easy to get subtly wrong. Without the initial `0`, an
  empty list totals `null` and `[true]` totals `true`. With string items,
  `+` concatenates: `["2", "3"].reduce((s, x) => s + x, 0)` is `"023"`.
- Python's `sum`, Kotlin's `sum` and `sumOf`, C#'s `Sum`, Ruby's `sum` and
  Java streams' `sum` name the operation. JavaScript has none, and LLM-written
  code such as `orders.sum(o => o.total)` raises
  `TypeError("orders.sum is not a function")` at the accepted revision.

## Rationale

- **Category and mode.** The caller selected the Utility enhancement
  category by one uniform draw over the four eligible registry categories,
  index 2 with probability 1/4 and no redraw, in continuous mode, so the
  token non-regression gate applies. Each new case is paired with the most
  compact accepted-syntax counterpart found, recorded in the evaluation
  baseline.
- **One shared query.** `sum` is one more operation of the read-only list
  query that serves `map`, `filter`, `reduce` and NUC 61's queries. Lists,
  list properties, call results such as `filter(...)` and `map(...)`, ranges,
  selected versions, class instance lists and `Name.list()` therefore accept
  it through one implementation, with the receiver, argument and liveness
  rules they already share.
- **A numeric total.** Each value is converted with the numeric conversion
  that `-`, `*`, `**` and the Math helpers use. For numbers this changes
  nothing, so `sum` and the accumulator `reduce` agree; for booleans, `null`,
  dates and lists the accumulator's `+` gives the same numbers too.
- Rejected: the rules of `+`, under which one string item turns the total
  into concatenated text. A query named `sum` that can return `"023"` is not
  a numeric total, and `Math.max("2", "3")` already reads strings as numbers.
- Rejected: raising an error for a non-numeric item, as Python does.
  Nucleoid's arithmetic never raises for the kind of a value; an object or a
  non-numeric string gives NaN, as in `order * 2`.
- **Undefined stays unknown.** An undefined item or selector result makes the
  total undefined, which a declaration stores as `null`. This is the rule of
  `+` and of the Math helpers' undefined gate, so `Order.sum(o -> o.discount)`
  waits for every discount to be defined, as `subtotal + order.discount`
  does. Rejected: counting undefined as NaN, which would make a missing
  property look like a computed but meaningless total.
- **Left to right from zero.** The total is `0 + v1 + v2 + ...` in 64-bit
  floating point, so `[0.1, 0.2, 0.3].sum()` is `0.6000000000000001`, exactly
  as the accumulator `reduce` gives, and a list of negative zeros sums to
  `0`. Rejected: compensated summation, as in Python 3.12's float `sum` or
  `math.fsum`. No accepted spelling reproduces it, and `sum` and `reduce`
  would disagree in the last digits.
- **The selector is called like `map`'s callback.** It runs once per item, in
  order, with only the item; further parameters stay `null`. Every item is
  visited even after the total has become NaN or undefined, so every item's
  reads are dependencies, as in `map` and `reduce`. Rejected: JavaScript's
  `(item, index, list)` arguments, which no accepted list query passes.
- **No artificial null read.** `sum()` reads items, not bindings, so a `null`
  item counts `0` and does not settle a declaration to `null`. Accepted
  [NUC 41](nuc-0041.md)'s `flatMap` adds no read to emulate the map and
  reduce composition either. A selector's own reads follow the existing
  rules: `Order.sum(order -> order.total)` over a `null` total settles a
  declaration to `null`, as the same callback does in `map` and `reduce`.
- The accumulator spelling differs for `null` items: its callback reads each
  item through a parameter, so `t = [1, null].reduce((s, x) => s + x, 0)`
  stores `null`, while `t = [1, null].sum()` stores `1` and
  `t = [1, null].sum(x -> x)` stores `null`. As expressions all three are
  `1`.
- **A supplied selector must be a function.** Any other first argument,
  including `null`, raises `TypeError("sum expects a function")` after the
  arguments are evaluated, even on an empty receiver, as `map`, `filter`,
  `find`, `flatMap` and `reduce` raise for their callbacks.
- Rejected: the rule of `sort`, which ignores a comparator that is not a
  function. A stray value such as lodash's property name
  (`sumBy(orders, "total")`) is far more likely a mistake than a request for
  the item total. Property-name selectors are also left out, as in NUC 61.
- **Extra arguments** are evaluated once, left to right, and ignored, as
  every list query does. Rejected: Python's `start` argument. `+ start`
  states it, and `xs.sum(5)` stays an error rather than a silent total.
- **Instance lists.** On a class name, `Name.sum(...)` is the population
  query even when the class declares an instance method `sum`, as NUC 61 made
  `Name.list()` and `Name.all()` population queries. The method stays
  reachable through each instance, `bag.sum()`, and `Bag.sum(b -> b.sum())`
  totals it.
- **Bounded cost.** The receiver and the arguments are evaluated once per
  call, the selector once per item, and the call keeps its ordinary rendering
  in graph keys and `why`. Nothing is copied or expanded, so cost and
  rendered size stay linear in the receiver and the source.
- **Not added.** A global `sum(...)`, `Math.sum`, averages, products, minimum
  and maximum over lists, string joining, start values, property-name
  selectors and compensated summation.

## Specification

### Sums

- `RECEIVER.sum()` returns the total of the receiver's items, and
  `RECEIVER.sum(selector)` the total of `selector(item)` for every item. The
  values are converted to numbers and added left to right, starting from
  `0`, in 64-bit floating point. An empty receiver gives `0`.
- The receiver is a list, however it is reached: a variable, a property, a
  call result such as `filter(...)`, `map(...)`, `slice(...)` or
  `concat(...)`, a range, a literal, a `.value` snapshot or a selected
  version. It may also be a class's instance list, named by the class or by a
  variable that holds the class, in population order; a range of one and
  `Name.list()` are lists.
- The result is a number, or undefined when any added value is undefined.

```
moves = [4, -6, 10]
net = moves.sum()
travelled = moves.sum(move -> Math.abs(move))
assert: net, 8
assert: travelled, 20
moves.push(-5)
assert: net, 3
moves = []
assert: net, 0
assert: travelled, 0
cart = {items: [0.1, 0.2]}
paid = cart.items.sum()
cart.items.push(0.3)
assert: paid, 0.6000000000000001
```

```
class Order(total, rush):
    this.total = total
    this.rush = rush
first = Order(20, false)
second = Order(45, true)
revenue = Order.sum(order -> order.total)
rushed = Order.filter(order -> order.rush).sum(order -> order.total)
recent = Order[-2:].sum(order -> order.total)
third = Order(30, true)
assert: revenue, 95
assert: rushed, 75
assert: recent, 75
class Refund(amount): this.amount = amount
refunds = Refund.sum(refund -> refund.amount)
assert: refunds, 0
```

### Conversion

- Each added value, an item or a selector result, is converted with the
  numeric conversion of `-`, `*` and the Math helpers: a number is itself;
  `null`, `false`, an empty or whitespace-only string and an empty list are
  `0`; `true` is `1`; a numeric string, after trimming, is its number; a
  one-item list is its item's number; a date is its time in milliseconds;
  objects, instances, classes, functions, regular expressions, other strings
  and longer lists are NaN.
- NaN and infinities add as 64-bit floating point: a NaN value makes the
  total NaN, and `Infinity` plus `-Infinity` is NaN.
- An undefined value makes the total undefined, which a declaration stores as
  `null`. Every item is still visited.
- `sum()` reads items, not bindings: a `null` item counts `0` without
  settling a declaration to `null`. Reads inside a selector follow the
  existing rules, so a selector that reads a `null` binding or property
  settles a declaration to `null`, as it would in `map` or `reduce`.

```
flags = [true, false, true]
count = flags.sum()
entries = [2, "3", " 4 ", "", null, [5], []]
total = entries.sum()
assert: count, 2
assert: total, 14
entries.push("x")
assert: Number.isNaN(total), true
class Item(price): this.price = price
pen = Item(3)
spent = Item.sum(item -> item.price)
gift = Item(null)
assert: spent, null
gift.price = 5
assert: spent, 8
```

### Selectors

- A selector is called once for every item, in order, with the item as its
  only argument; further parameters are `null`. The call order and the
  argument are those of `map`.
- A supplied first argument that is not a function, including `null`, raises
  `TypeError("sum expects a function")`, even on an empty receiver.
- Every supplied argument, including unused extras, is evaluated once, left
  to right, after the receiver and before the first selector call.
- A null or undefined receiver keeps the existing method-call route: the call
  yields undefined without evaluating its arguments.

```
seen = []
def weigh(item, position):
    seen.push(position ?? item)
    return item * item
items = [3, 1, 2]
weighed := items.sum(weigh)
assert: weighed, 14
assert: seen, [3, 1, 2]
floor = 2
def price item => Math.max(item, floor)
cost = items.sum(price)
floor = 3
assert: cost, 9
```

### Liveness and transactions

- `sum` never writes its receiver. A declaration that uses it depends on the
  list or the population, on its argument expressions and on whatever the
  selector reads, as for `map` and `reduce`.
- Pushing, popping or replacing a list, creating or deleting an instance, and
  changing a property that a selector reads re-evaluate the declaration.
- In a class-level rule, each instance evaluates its own sum, and `$Class`
  inside a selector is the instance the rule is evaluated for.
- Selector errors propagate through the existing transaction, so a failed
  standing re-evaluation rolls back the change that triggered it, including
  a list write or a new instance.

```
class Order(name): this.name = name
class Line(order, price, qty):
    this.order = order
    this.price = price
    this.qty = qty
$Line.cost = $Line.price * $Line.qty
$Order.total = Line.filter(line -> line.order == $Order).sum(line -> line.cost)
north = Order("north")
south = Order("south")
Line(north, 2, 3)
pen = Line(south, 4, 2)
grand = Order.sum(order -> order.total)
assert: grand, 14
pen.qty = 5
assert: south.total, 20
assert: grand, 26
```

## Errors

- No error type or message format is added. The selector error reuses the
  message format of the other list queries.

| Condition | Error |
| --- | --- |
| A supplied first argument that is not a function, including `null`, even on an empty receiver | `TypeError("sum expects a function")` |
| A supplied argument, including an unused extra, reads an undefined name | `ReferenceError("<name> is not defined")`, raised before the selector is validated |
| The selector raises an error or throws a value | That error or thrown value, unchanged; the triggering change rolls back |
| `sum` on a string, number, boolean, date, function or regular expression | Its accepted `TypeError`, unchanged |

- Calls that raised `TypeError("<receiver>.sum is not a function")` on lists
  and instance lists now return totals; with a non-function first argument
  they raise `TypeError("sum expects a function")` instead.
