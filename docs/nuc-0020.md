## Abstract

- A named arrow definition or method may optionally omit parentheses around one ordinary identifier and its existing single-identifier type annotation.
- `def double amount: int => amount * 2` is exactly `def double(amount: int) => amount * 2`.
- Preserve the existing parameter name, `Some(annotation)` metadata and named return-block lowering; add no type resolution, runtime constraint, token, AST or API.

## Motivation

- A single typed named-arrow parameter already has an unambiguous name, colon, annotation and arrow.
- Remove redundant parameter delimiters without changing the declaration, body, calls or binding.
- Keep the accepted parenthesized alternative and all other accepted signatures available.

## Rationale

- Extend accepted [NUC 18](nuc-0018.md), with its transitive accepted [NUC 12](nuc-0012.md) named-arrow lowering, by exactly one immediate token prefix.
- Reuse the existing single-parameter parser rather than maintain a second annotation grammar.
- Treat an annotation as the same stored identifier metadata, not a variable to resolve or a new runtime type constraint.
- Keep NUC18 untyped arrows and the accepted NUC19 untyped indented-colon guard unchanged.
- Require only Accepted NUC18; preserve baseline syntax without combining pending proposals or adopting rejected NUC15 omissions.
- Keep parentheses for typed blocks, empty or multiple parameter lists, other parameter/type forms and calls.
- Keep canonical name-based function rendering and explicit-return body rendering rather than introduce a new generator spelling.

## Specification

### Immediate grammar and lowering

- The authoritative [`Bare typed single-parameter named arrows` section](../nucleoid.spec.md#bare-typed-single-parameter-named-arrows) governs the implemented syntax.
- Parse `def` and its required name exactly as before.
- Recognize only immediate `Identifier(parameter)`, `Colon`, `Identifier(annotation)`, `Arrow` tokens after that name.
- Consume the name and optional annotation through the same single-parameter parser used by parenthesized parameter lists.
- Produce exactly `Parameter { name: parameter, type_name: Some(annotation) }`.
- Keep the existing named `FunctionBody::Block` containing one `Stmt::Return(Some(expression))`.
- Reuse the existing expression parser, precedence, body handling and class method/initializer path unchanged.
- If the immediate typed-arrow guard fails, retain the existing untyped-arrow, untyped-indented-block or mandatory-parenthesis paths without consuming the unsupported prefix.
- The new guard never skips a logical newline, semicolon or comment-induced logical break between the required name, parameter, colon, annotation and arrow.
- Preserve the existing first-body-expression rule: an expression beginning with `(` on the header line may continue over physical lines.
- Preserve all parenthesized signatures, including typed/untyped, nullary/multiple, trailing-comma and multiline forms, and class/anonymous parameter lists.
- Typed bare blocks, inline or braced suites, multiple/nullary/defaulted/destructured parameters, dotted/union/generic/keyword annotation forms, return annotations and logical header breaks are not added.
- Calls retain parentheses; ordinary identifiers do not become automatically invoked functions.
- Named-arrow leading braces remain object expressions, while a returned anonymous arrow retains its own expression/block grammar.

### Runtime and canonical equivalence

- An undeclared ordinary annotation such as `ArbitraryType` remains metadata and does not become a dependency or resolved variable.
- Missing/null, extra and string arguments keep the existing binding behavior; annotations introduce no new type enforcement.
- Parameters retain local shadowing and assignment-expression behavior without rebinding the outer name.
- Argument and external-input reactivity, named redefinition, live callable references and `.value` definition snapshots are unchanged.
- Definition snapshots retain dependencies subsequently read by the old body rather than freeze external input values.
- Methods retain the same receiver; `this` and `self` still name the same instance.
- Expression-bodied `init` retains initializer adoption; construction returns the instance, not the expression result.
- Parent construction and explicit or bare `super` retain their accepted paths.
- Failed definitions/redefinitions preserve caught errors, transaction rollback, dependency edges and subsequent recovery.
- Object/template reads remain strict; returned anonymous functions gain no capture of outer parameters.
- Inherited parameter-dependent local/nested noncapturing propagation failures are not repaired or bypassed.
- Keep public tokens, `Parameter`, `Function`, `FunctionBody`, runtime/generator representations, API, precedence and all existing bounds unchanged.

## Errors

- Introduce no new error kind or runtime message.
- Unsupported tokenizable typed prefixes retain the mandatory-parenthesis error before consumption; lexical errors still precede parsing.
- Lexical `|` is rejected as `SyntaxError("Unexpected character '|'")`; table pipes below are Markdown-escaped, not part of the error message.
- The exact exercised errors below follow the normative typed-arrow boundary section and unchanged expression/runtime rules.

## Reference Implementation

- The integrated implementation changes only named-header lookahead and factors the existing single-parameter parser in [`src/lang/ast/parser.rs`](../src/lang/ast/parser.rs).
- The annotation grammar, parenthesized list handling, NUC19 suite guard and named-arrow body lowering retain their existing consumption and diagnostics.
- No runtime, generator, public type/API, dependency, version or MSRV implementation change is required.
- [`tests/bare_typed_named_arrows.rs`](../tests/bare_typed_named_arrows.rs) protects metadata, complete ASTs, canonical body/source rendering, former negative inputs and exact boundaries/positions.
