# NUC 61 -- Instance List Ranges and Common List Queries

```

Title: Instance List Ranges and Common List Queries
Author: Claude <noreply@anthropic.com>
Status: Accepted
Type: Standards Track
Category: Utility enhancement
Created: 30-Oct-2026
Requires: 8
```

## Abstract

- A class's instance list takes the range syntax of lists. `Name[start:end]`,
  `Name[:]`, `Name[-3:]` and `Name[:2]` return its instances in population
  order with the bound rules of list slices, exactly as
  `Name.slice(start, end)` does. At the accepted revision these ranges yield
  undefined, shown as `null`.
- `Name.list()` and `Name.all()` return every instance of a class as a list,
  with the result and dependency of `Name[:]`. Plain lists keep raising
  `TypeError("<list>.list is not a function")` and its `.all` counterpart.
- Lists and instance lists gain JavaScript's `at`, `lastIndexOf`,
  `findIndex`, `findLast` and `findLastIndex`, adapted to Nucleoid's
  conventions: callbacks receive only the item, searches return `null` or
  `-1` when nothing matches, and `at` returns bracket indexing's missing value
  outside the receiver.
- The existing but undocumented `includes`, `indexOf` and `concat` are
  specified as the accepted runtime implements them, and `slice` is presented
  with the family. None of their results change.
- All of these are read-only and live. A declaration that uses one depends on
  the list or population, on its arguments and on what its callback reads, and
  keeps the existing transaction and rollback behavior.
- No syntax, keyword, error type or public Rust API is added. The
  authoritative contract is
  [Instance list ranges and list queries](../nucleoid.spec.md#instance-list-ranges-and-list-queries).

## Motivation

- The user asked: "Support #2 like and also add javascript slice and related
  common functions and Obj.list() and Obj.all() for listing all instances".
  Asked which related functions to include, the user chose the read-only set:
  specify the undocumented `includes`, `indexOf` and `concat`, and add `at`,
  `lastIndexOf`, `findIndex`, `findLast` and `findLastIndex`, working on plain
  lists and instance lists and staying live like `filter`, with `reverse` left
  as it is. This is a request for concrete features, prepared in
  single-proposal mode.
- `Name` is the list of a class's instances and `typeof Name` is `List`, but
  a range on it yields undefined. With users `a` and `b`, `User[:]` and
  `User[1:]` are `null` at the accepted revision, while `[1, 2, 3][:]` is
  `[1,2,3]` and `User.slice(1)` is `[b]`.
- No member names "every instance" as a list. `User.list()` and `User.all()`
  raise `TypeError("User.list is not a function")` and
  `TypeError("User.all is not a function")`, so programs write
  `User.slice()` or `User.filter(user => true)`.
- JavaScript programs, including LLM-written ones, reach for `items.at(-1)`,
  `findIndex`, `findLast`, `findLastIndex` and `lastIndexOf`. Each raises
  `TypeError("<receiver>.<name> is not a function")` at the accepted revision.
  Kotlin, C# and Java offer the same last-match and last-position queries.
- Bracket indexing does not replace `at`: `[1, 2, 3][-5]` reads `1`, and
  `User[-1]` reads the first instance, not the last.
- `includes`, `indexOf` and `concat` already work on lists and instance lists,
  but no reference documents them. Their deep equality, ignored `fromIndex`
  and argument handling are observable behavior without a contract.

## Rationale

- **Category.** Standard built-in collection helpers are a Utility
  enhancement, like accepted [NUC 41](nuc-0041.md)'s `flatMap`,
  [NUC 58](nuc-0058.md)'s `sort` and Draft [NUC 10](nuc-0010.md)'s indexing
  and slicing. The user's explicit request fixed the category; there was no
  random draw.
- **Single-proposal mode.** Token comparison is skipped. No accepted case is
  rewritten: ten specification entries, one reference entry, one README
  snippet and one examples snippet are appended.
- **Ranges reuse list slicing.** A range on a declared class reads the
  population as the list of its instance references, then applies the
  unchanged list slice. `Name[start:end]` therefore equals
  `Name.slice(start, end)` for every bound, including omitted, negative,
  fractional, non-numeric and out-of-range bounds.
- The population is read before the bounds, as `Name.slice()` reads it before
  its arguments. Both use one population read, which also records the
  dependency on the population.
- Rejected: making the bare name `Name` evaluate to a list value. That would
  change its rendering, `typeof`, comparisons and the dispatch of every query,
  and the bare-name value is outside this request.
- Bracket indexing is unchanged. Changing `Name[-1]` or the clamping of
  `[1, 2, 3][-5]` would change accepted results that the request does not
  touch; `at` provides JavaScript's index rules instead.
- **`list()` and `all()` belong to instance lists.** Both return the
  population as a list. A plain list is already a list, and `items.all()`
  would read as Python's boolean `all()`, so plain lists keep raising their
  accepted `TypeError`.
- Supplied arguments are evaluated once, left to right, and ignored, as every
  read-only list query does with arguments it does not use. Rejected: an
  arity error, which no list query raises.
- **Specified, not changed.** The accepted `includes`, `indexOf` and `concat`
  compare with the deep equality of `assert`, ignore a `fromIndex`, spread
  list arguments one level and append other values. This NUC records those
  results. JavaScript differs in four places: it compares objects by
  identity, its `includes` finds NaN, `indexOf(value, fromIndex)` starts at
  `fromIndex`, and `concat` spreads array-likes.
- Rejected: adopting any of those four. Each would reinterpret accepted calls,
  such as `[1, 2, 1].indexOf(1, 1)`, which returns `0`, and would give
  `includes` an equality rule of its own.
- Instances carry distinct `id` properties, so deep equality never confuses
  two instances, and `Name.indexOf(instance)` is that instance's position in
  the population.
- A comparison reads the objects it compares without subscribing to their
  properties. Rejected: subscribing to every compared property, which would
  add dependencies to accepted declarations and would still miss properties
  added later. The behavior is recorded as a limitation.
- An instance list passed to `concat` is one value: `[1].concat(User)` is
  `[1, User]`. Rejected: spreading it, which changes an accepted result;
  `Name.list()` and `Name[:]` are the spreadable lists.
- **`at` agrees with bracket indexing.** Inside the receiver, `at(i)` returns
  the item that `xs[i]` and `Name[i]` return. Outside it, `at` returns what
  bracket indexing returns there: undefined for a list, which operators
  propagate and a declaration stores as `null`, and `null` for an instance
  list. So `"top " + xs.at(9)` behaves like `"top " + xs[9]`.
- Rejected: always `null`, as `find` returns, which would make `xs.at(9)` and
  `xs[9]` disagree; always undefined, as in JavaScript, which would make
  `Name.at(9)` and `Name[9]` disagree.
- The index follows JavaScript's conversion: number conversion, NaN as `0`,
  truncation toward zero, a negative index from the end, and no clamping.
  Rejected: bracket indexing's index rules, which clamp a negative index past
  the start to the first item.
- **Searches follow `find`.** `findIndex`, `findLast` and `findLastIndex`
  validate the callback like `find`, even on an empty receiver, and stop at
  the first accepted item. They pass only the item, as `find`, `map` and
  `flatMap` do; additional callback parameters stay `null`.
- Rejected: JavaScript's `(item, index, list)` arguments, which no accepted
  list query passes.
- `findLast` and `findLastIndex` visit from the last item back, as in
  JavaScript. Unvisited items add no dependency, which is sound: an unvisited
  item cannot change the result unless a visited item changes first.
- `find` shares one search helper with the three new searches, so their visit
  order and validation cannot drift. Its results, call order and error are
  unchanged.
- **`lastIndexOf` follows `indexOf`.** One compared argument, deep equality,
  the last match or `-1`. A `fromIndex` is ignored, as `indexOf` ignores it.
- **Not added.** Mutators such as `unshift` and `splice`, string methods,
  property projection, implicit `it` callbacks, the global `Class` list, the
  bare-name `Name` value and its rendering, and changes to `reverse`, `shift`
  or the aliases `contains`, `any` and `append`.

## Specification

### Instance list ranges

- `Name[start:end]` on a declared class `Name` returns its instances in
  population order with the bound rules of list slices: either bound may be
  omitted, a negative bound counts from the end, a bound is converted to a
  number and clamped to the population, and a start at or after the end gives
  `[]`.
- `Name[:]` lists every instance; `Name[start:end]` equals
  `Name.slice(start, end)`. The population is read once, before the bounds are
  evaluated.
- A range depends on the population and on what its bounds read, unless a
  bound is frozen with `.value`. Creating or deleting an instance re-evaluates
  it.
- A class-level rule validates the references in both bounds when it is
  declared, as for list slices, and each instance evaluates its own bounds.
- Bracket indexing is unchanged. A range on anything other than a list, a
  string or a declared class, such as `Math[:]` or the global `Class[:]`,
  still yields undefined.

```
class User(name):
    this.name = name
ada = User("Ada")
bob = User("Bob")
cy = User("Cy")
assert(User[:], [ada, bob, cy])
assert(User[1:], [bob, cy])
assert(User[-2:], [bob, cy])
assert(User[1:-1], [bob])
assert(User[1:], User.slice(1))
class Empty
assert(Empty[:], [])
```

```
class Task(title):
    this.title = title
first = Task("plan")
second = Task("build")
count = 1
recent = Task[-2:]
opening = Task[:count]
pinned = Task[:count.value]
third = Task("ship")
assert(recent, [second, third])
count = 2
assert(opening, [first, second])
assert(pinned, [first])
```

```
class Player(name):
    this.name = name
class Team(size):
    this.size = size
$Team.roster = Player[0:$Team.size]
ana = Player("Ana")
ben = Player("Ben")
red = Team(1)
assert(red.roster, [ana])
red.size = 2
assert(red.roster, [ana, ben])
```

### Listing every instance

- `Name.list()` and `Name.all()` return every instance in population order,
  with the result and dependency of `Name[:]` and `Name.slice()`.
- Supplied arguments are evaluated once, left to right, and ignored.
- Plain lists have neither method. An instance's own method or property named
  `list` or `all` keeps its dispatch.

```
class Member(name):
    this.name = name
ana = Member("Ana")
ben = Member("Ben")
everyone = Member.list()
roster = Member.all()
assert(everyone, [ana, ben])
assert(roster, everyone)
cal = Member("Cal")
assert(everyone, [ana, ben, cal])
```

### Shared query rules

- Every query below snapshots its receiver before its arguments, evaluates
  every supplied argument once, left to right, including unused extras, and
  never writes the receiver.
- A declaration that uses a query depends on the list or population, on its
  argument expressions and on whatever its callback reads.
- A null or undefined receiver keeps the existing method-call route: the call
  yields undefined without evaluating its arguments.
- Callback errors propagate through the existing transaction. A failed
  standing re-evaluation rolls back the change that triggered it, including a
  new instance.

### Comparisons: includes, indexOf and lastIndexOf

- `includes(value)`, `indexOf(value)` and `lastIndexOf(value)` compare items
  with the deep equality of `assert`. Lists and objects match on their
  contents, `null` and undefined match each other, so `null` matches an
  omitted value, and NaN matches nothing.
- Every instance holds its own `id`, so distinct instances never match each
  other.
- `includes` returns whether an item matches. `indexOf` and `lastIndexOf`
  return the first and the last matching position, or `-1`.
- Only the first argument is compared; a JavaScript `fromIndex` is evaluated
  and ignored.
- A comparison reads the objects it compares without subscribing to their
  properties: a declaration follows its list or population and its argument,
  not a property of a compared object.

```
tags = ["red", "blue", "red"]
assert(tags.includes("blue"), true)
assert(tags.indexOf("red"), 0)
assert(tags.lastIndexOf("red"), 2)
assert(tags.lastIndexOf("green"), -1)
assert(tags.indexOf("red", 1), 0)
assert([[1, 2], { x: 1 }].includes({ x: 1 }), true)
assert([Number.NaN].includes(Number.NaN), false)
class Seat(row):
    this.row = row
front = Seat(1)
twin = Seat(1)
assert(Seat.indexOf(twin), 1)
```

### Positions: at

- `at(index)` converts the index to a number, reads NaN, including an omitted
  index, as `0`, truncates it toward zero and counts a negative index from the
  end, as in JavaScript. It returns the item at that position.
- Outside the receiver it returns what bracket indexing returns there:
  undefined for a list, which a declaration stores as `null`, and `null` for
  an instance list. A negative index before the start is outside the receiver
  too; `at` never clamps an index into the receiver.

```
scores = [10, 20, 30]
assert(scores.at(-1), 30)
assert(scores.at(1.9), 20)
assert(scores.at(), 10)
assert(scores.at(-4), null)
assert(typeof scores.at(3), "undefined")
last = scores.at(-1)
scores.push(40)
assert(last, 40)
class Lap(time):
    this.time = time
one = Lap(61)
two = Lap(58)
assert(Lap.at(-1), two)
assert(typeof Lap.at(2), "null")
```

### Searches: findIndex, findLast and findLastIndex

- `findIndex(callback)` returns the position of the first item the callback
  accepts, or `-1`.
- `findLast(callback)` and `findLastIndex(callback)` visit items from last to
  first and return the first accepted item or its position, or `null` and
  `-1`, as `find` returns `null`.
- The callback receives only the item and is not called after an item is
  accepted, so unvisited items add no dependency.
- A missing or non-function callback raises
  `TypeError("<name> expects a function")`, even on an empty receiver.

```
visits = []
def big(value):
    visits.push(value)
    return value > 15
readings = [10, 20, 30, 5]
assert(readings.findIndex(big), 1)
assert(visits, [10, 20])
visits = []
assert(readings.findLast(big), 30)
assert(visits, [5, 30])
assert(readings.findLastIndex(value => value > 99), -1)
assert([].findLast(value => true), null)
```

```
class Order(total, rush):
    this.total = total
    this.rush = rush
first = Order(20, false)
second = Order(45, true)
third = Order(30, false)
lastRush = Order.findLast(order => order.rush)
assert(lastRush, second)
third.rush = true
assert(lastRush, third)
```

### Concatenation and slices

- `concat(...values)` returns a new list of the receiver's items followed by
  each argument: a list contributes its items one level deep, and any other
  value contributes itself.
- An instance list named by its class is one value, not spread;
  `Guest.concat(Host.list())` appends the instances of `Host`.
- `slice(start, end)` keeps its accepted behavior and the bound rules of
  ranges.

```
base = [1, 2]
more = base.concat(3, [4, [5]])
assert(more, [1, 2, 3, 4, [5]])
base.push(9)
assert(more, [1, 2, 9, 3, 4, [5]])
class Guest
amy = Guest()
class Host
cara = Host()
dan = Host()
assert(Guest.concat(Host.list()), [amy, cara, dan])
assert(Guest.concat(Host).length, 2)
```

## Errors

- No new error type or message format is added. The new searches reuse the
  message format of `find`.

| Condition | Error |
| --- | --- |
| A missing or non-function `findIndex`, `findLast` or `findLastIndex` callback, even on an empty receiver | `TypeError("<name> expects a function")` |
| `list()` or `all()` on a plain list | `TypeError("<list>.list is not a function")` or `TypeError("<list>.all is not a function")`, unchanged |
| A supplied argument, including an unused extra, reads an undefined name | `ReferenceError("<name> is not defined")`, raised before the callback is validated |
| A callback raises an error or throws a value | That error or thrown value, unchanged; the triggering change rolls back |
| A class-level rule's range bound reads an undefined name | `ReferenceError("<name> is not defined")` when the rule is declared |

- Calls that raised `TypeError("<receiver>.<name> is not a function")` for
  `at`, `lastIndexOf`, `findIndex`, `findLast` and `findLastIndex` on lists
  and instance lists, and for `list` and `all` on instance lists, now return
  results.

## Reference Implementation

- `src/lang/ast/array.rs`:
  - `ListSource` is a crate-private enum, `List` or `Population`, passed to
    `list_query`. It gates `list` and `all` to instance lists and gives `at`
    its missing value: undefined for a list, `null` for a population.
  - `population` reads a declared class's instances in population order and
    tracks the class node. `evaluate_slice` uses it to turn a class receiver
    into a list before the bounds are evaluated, then slices the result with
    the free `slice` function, as for every other receiver.
  - `slice_items` holds the bound rules of list slices. The free `slice`
    function, which list and instance-list ranges use, and the `slice` query
    both call it, so `Name[start:end]` equals `Name.slice(start, end)` by
    construction. Their results are unchanged.
  - `list_query` gains `at`, `lastIndexOf`, `findIndex`, `findLast`,
    `findLastIndex`, `list` and `all`. `find` and the three searches share
    `find_position`, which visits items first to last or last to first and
    stops at the first accepted one. `relative_index` holds `at`'s index
    conversion, and `position_number` the `-1` convention shared with
    `indexOf`.
- `src/lang/ast/call.rs`: `call_class_method` reads the population through
  `population` instead of cloning the class data, and passes
  `ListSource::Population`.
- `src/terminal/completion.rs`: the terminal workspace completes the new list
  members, and a class name its instance-list members, including `list` and
  `all`. A unit test covers both and the absence of `list` and `all` on plain
  lists.
- `tests/list_queries.rs` covers the appended document cases and their
  assertion counts, every bound pair against list slices and `slice`, the
  population read before arguments, graph dependencies of ranges, listings,
  class rules and searches, unchanged forms and errors, `at` index
  conversion, search visit order, callback validation and argument order,
  null receivers, comparisons without subscriptions, and rollback compared
  with a control runtime.
- The required Rust improvement pass changed only `src/lang/ast/array.rs`. It
  extracted `slice_items` from the identical bound computations of the free
  `slice` function and the `slice` query, without changing behavior.
- The root specification, executable reference, README, examples, the
  consolidated reference with its error table and syntax summary, both NUC 0
  indexes, a new canonical `dataset/nucleoid.synth.41.jsonl` with seven
  records, the regenerated specification export and generated specification
  tests, and the dataset record counts are synchronized in the isolated
  candidate.
- No dependency, MSRV, edition or project version changes, and no public Rust
  API changes: `ListSource`, `population` and `list_query` are crate-private.
  The new results in the Compatibility table are observable language changes
  for human SemVer review.
