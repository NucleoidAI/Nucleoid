```

Type: Standards Track

Created: 25-Oct-2026
```

## Abstract

- Let the existing For execution route accept a String source.
- Snapshot one String value per Unicode scalar, in source order, before
  executing any body; an empty String executes zero bodies.
- Preserve the existing Class/List branches, one-shot imperative bodies,
  accepted syntax, temporary scopes, receivers, control flow and transactions.

## Motivation

- Traverse text directly for observable imperative effects without an
  otherwise discarded `text.split("").map(...)` result.
- Reuse all existing explicit `of`/`in` and named-source implicit-`it` forms,
  rather than adding a helper, grammar or general iterator protocol.
- Distinguish scalar traversal from byte, UTF-16 and grapheme traversal while
  retaining exact supplementary and combining characters.

## Rationale

- The caller's single uniform live-registry draw selected index `1`,
  `Runtime features`; preserve that confirmed selection without a redraw.
- Extending core For execution is a bounded runtime capability, not a new
  built-in utility or syntax enhancement.
- Rust `str::chars()` matches the accepted empty-separator String split,
  scalar indexing and scalar length semantics without normalization.
- Build the complete snapshot before any body, using the existing source-once
  evaluation and For machinery rather than a callback or lazy iterator.
- Do not broaden List traversal: primitive entries, including Strings, remain
  intentionally skipped. A loop over `text.split("")` is not a behavioral
  counterpart; the supplied accepted programs use split/map effects instead.
- Those map results are discarded. Do not claim that a returned map array,
  callback AST or graph source is identical to a normally completed For's
  `null`; protect final observations, controls and explicit expected returns.
- Depend only on already accepted For execution, String scalar operations,
  calls, scopes and transactions; combine no pending proposals.

## Specification

### Execution contract

- The authoritative [String iteration section](../nucleoid.spec.md#string-iteration)
  and its six executable entries define the implemented contract.
- Evaluate the existing source expression exactly once, before introducing
  the iteration binding, and dispatch on the resulting concrete Value.
- For a String, fully collect one `Value::String` for each `char`, in order,
  before the first body. Keep supplementary characters whole and combining
  marks, zero-width joiners and embedded NUL as their own scalars.
- Empty Strings execute no body. Do not trim, normalize, coerce, invoke a
  callable source or interpret bytes, UTF-16 units or grapheme clusters.
- Existing `for variable of expression` and `for variable in expression`
  retain arbitrary source expressions and inline, braced or indented suites.
- Existing `for NAME:` still requires one ordinary identifier and a genuine
  indented suite, and binds local `it`. No shorthand expression source,
  relaxed header guard, new token, AST or generator behavior is added.
- Each item uses the existing pushed temporary scope and imperative mode.
  Nested/local/global iteration bindings shadow and restore normally;
  enclosing `this` and `self` retain their receiver.
- Body or later source mutations do not change the current snapshot.
  Completed loops are not standing declarations and never replay on updates.
  A subsequent For statement takes a new snapshot.
- Explicit and bare returns propagate through the existing Flow route.
  Normally completed and empty loops yield `null`; body expressions do not
  become implicit returns and no result collection is added.
- Thrown values and strict errors use existing scope/mode cleanup,
  enclosing top-level statement positions, transaction rollback and recovery.
- Class sources retain the same ordered instance snapshot. List sources
  retain only references registered with a class, preserving duplicates and
  skipping primitives, null, unregistered objects, plain `Object()` instances
  and literal objects. Leave both branches semantically unchanged.
- All other noniterable kinds and callable values retain their existing
  error route; no automatic invocation or general iterable support is added.

## Errors

- Introduce no new error kind or message; String values cease to be
  noniterable only when used directly as the For source.
- Empty String traversal is not an error. Primitive String items in a List
  remain skipped, not recursively traversed or converted.
- Non-String invalid sources, source evaluation and body failures retain
  their exact existing kinds, messages, positions, caught values and rollback.

| Condition | Exact inherited error |
| --- | --- |
| Noniterable source named `broken`, including null, numbers, booleans, ordinary objects and callables | `TypeError("broken is not iterable")` |
| Strict missing source or body read named `missing` | `ReferenceError("missing is not defined")` |
| Body reads `this` or `self` without an enclosing receiver | `ReferenceError("this is not defined")` |
| Nonqualifying shorthand `for values:` at EOF or without a genuine indented body | `SyntaxError("Expected 'of' in for statement")` |
| Unsupported parenthesized shorthand `for (values):` | `SyntaxError("Expected a name but found '('")` |

- The named invalid-source and missing-read runtime errors use the enclosing
  top-level For statement position; after a preceding statement, line 2,
  column 1 remains line 2, column 1.
- The listed invalid `for values:` forms retain line 1, column 11;
  `for (values):` retains line 1, column 6. Existing lexical/body errors and
  all other grammar diagnostics remain unchanged.
- User throws propagate their exact values, including
  `"STOP_STRING_ITERATION"` in the normative rollback entry; ordinary
  transactional machinery restores prior effects and permits recovery.
