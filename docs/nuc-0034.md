# NUC 34 -- Colon-Free Indented Else Suites

```
NUC: 34
Title: Colon-Free Indented Else Suites
Author: Copilot <223556219+Copilot@users.noreply.github.com>
Status: Accepted
Type: Standards Track
Created: 15-Oct-2026
```

## Abstract

- Optionally omit the colon after a final `else` only before a genuine
  indented suite, exactly equivalent to `else:` with the same body.
- Preserve the complete existing `Stmt::If` and alternate `Stmt::Block`,
  canonical rendering, runtime behavior and every accepted spelling.
- Keep all condition headers and every other suite header unchanged.

## Motivation

- A final alternative has no condition whose end needs a colon delimiter;
  existing indentation can identify its body without repeating that punctuation.
- Retain explicit colons wherever existing inline or braced bodies need them.
- Implement the caller's bounded syntax improvement and single category draw
  `0`, without redrawing or combining pending proposals.

## Rationale

- Reuse the accepted `has_indented_body` qualification rather than recognizing
  indentation textually, skipping header separators or adding a lexer token.
- Extract the existing private suite body once; all colon-bearing callers still
  require their colon before entering that identical parser.
- Limit the optional spelling to the final branch of `if_statement`.
  `else if` recursively uses the unchanged condition-and-colon path.
- Do not add speculative parsing, error recovery, broad catches, new block
  semantics, implicit returns, or a global colon-optional `suite`.
- Leave the CLI unchanged: an initial colon-bearing conditional header already
  buffers its later `else` and body until blank-line commit or stdin EOF.
- Preserve legacy alternatives in the executable specification and regression
  fixtures, not just in prose. The root specification remains authoritative.

## Specification

### Grammar and lowering

- Normative detail is in
  [colon-free indented else suites](../nucleoid.spec.md#colon-free-indented-else-suites).
- After consuming the existing final `Else` token, inspect without consuming.
  The immediate next token must be `Newline` or `Indent`.
- Look through only existing `Newline`/`Semicolon` tokens; the first other token
  must be `Indent`. Both conditions must hold to omit the colon.
- On success, enter the shared existing suite-body parser. Consume its ordinary
  newline/semicolon layout and required indent, parse its complete statement
  sequence, and retain its existing optional final dedent and EOF handling.
- On failure, enter unchanged `suite`, including its required `Colon` and
  existing diagnostic at the untouched parser position.
- An immediate semicolon after `else` cannot qualify, even if a later line is
  indented. Semicolon-only lines after the initial newline, leading/trailing
  body separators, blank/comment lines, real LF/CRLF and accepted tab
  indentation retain the existing layout rules.
- Preserve the full alternate as `Some(Box::new(Stmt::Block(body)))`.
  Nested and mixed inline/braced/indented conditionals retain their existing
  dangling-else association, branch order and condition evaluation.
- Every `if` and `else if` header keeps its required colon. `for`, named
  definitions, classes, try/catch and anonymous forms retain their accepted
  grammars, including already accepted bodyless and named-arrow alternatives.
- Colon-bearing indented, inline, semicolon-separated and braced final
  alternatives remain valid. No literal or comment containing `else:` is a
  header delimiter or a rewrite target.
- No keyword, token, public enum/AST/API, dependency, version, MSRV or edition
  change is introduced. Canonical source and graph generation are unchanged;
  the implementation does not teach a generator to emit colon-free alternatives.

### Behavior and compatibility

- Preserve standing variable/property relationships, class-level rules,
  per-instance independence, later input changes, graph keys and graph edges.
- Preserve short-circuiting, deferred reads, branch evaluation, local scope,
  caller frames/receivers, explicit returns and thrown/caught values.
- Preserve transaction rollback, queue recovery, inherited diagnostics and
  parser/runtime resource bounds. `MAX_NESTING = 64` and `MAX_CHAIN = 128`
  are unchanged; this revision does not repair a Windows host-stack boundary.
- Source files and the native REPL use the same parser. Normal multiline input,
  blank-line commit, EOF without a final newline, diagnostics and recovery use
  the existing CLI path without a new continuation heuristic.
- Inline colon-bearing alternatives and strings, regexes, templates or comments
  containing `else:` keep the existing interaction. No general interactive
  delimiter or comment-buffering repair is proposed.
- Execute unchanged accepted-syntax cases from the pinned revision and the
  eight accepted v2 extra sources alongside shortened candidate forms.
  Full AST/canonical equality is required, not merely equal final values.

## Errors

- Introduce no new error kind or message. A nonqualifying new prefix uses the
  old colon expectation; qualifying bodies propagate existing lexer, statement
  and expression errors unchanged, without retries or fabricated positions.
- Exact `if false: pass\nelse` gives
  `SyntaxError("Expected ':' but found end of input")` at line 2, column 5.
- Exact `if false: pass\nelse\n` gives
  `SyntaxError("Expected ':' but found end of line")` at line 2, column 1.
  Comments-only bodies and an unindented `pass` give that same error/position.
- Exact `if false: pass\nelse;\n    pass` gives
  `SyntaxError("Expected ':' but found ';'")` at line 2, column 5.
- Exact `if false: pass\nelse pass` gives
  `SyntaxError("Expected ':' but found keyword 'pass'")` at line 2, column 6;
  `else { pass }` instead gives `"Expected ':' but found '{'"` there.
- Exact `if false: pass\nelse:\npass` preserves
  `SyntaxError("Expected an indented block but found keyword 'pass'")`
  at line 3, column 1.
- Exact `if false: pass\nelse\n    value = (1 +)` gives
  `SyntaxError("Unexpected ')'")` at line 3, column 18.
  Replacing the body with four-space-indented `value = @` gives
  `SyntaxError("Unexpected character '@'")` at line 3, column 13.
- Exact `if true\n    pass` still gives
  `SyntaxError("Expected ':' but found end of line")` at line 1, column 4.
  Exact `if false: pass\nelse if true\n    pass` gives the same message at
  line 2, column 9. Other nonqualifying headers keep their inherited errors.
- Existing resource messages remain
  `SyntaxError("Statements are nested too deeply")`,
  `SyntaxError("Expressions are nested too deeply")`,
  `SyntaxError("Expression has too many operands")` and
  `SyntaxError("Expression has too many parts")`.
- Runtime errors remain unchanged. For example, exact
  `if false: pass\nelse\n    missing` gives
  `ReferenceError("missing is not defined")` at the enclosing top-level
  statement's line 1, column 1; caught values retain their existing rendering.

## Reference Implementation

- Parser support in the accepted implementation changes only the private
  suite-body extraction and final-else dispatch in `src/lang/ast/parser.rs`.
- The normative-test exporter in `build.rs` keeps a top-level bare `else`,
  including a trailing comment, attached to its conditional instead of
  exporting it as a separate runtime invocation. Its generated tests cover
  these boundaries; the AST/graph source generator is unchanged.
- `tests/indented_else_suites.rs` pairs complete AST/canonical/graph/runtime
  behavior, layout boundaries, mixed branch association, protected fixtures,
  exact diagnostics, frames, rollback, bounds and native CLI entry paths.
- New ordinary tests use embedded sources and normative documents, tolerate future
  appended cases, and need no Git history or session artifacts. Training JSONL
  is not added to the default runtime loop.
- Synchronize executable source documents and affected reference prose, maintain
  eligible synthesized programs directly as canonical JSONL, and regenerate
  normative JSONL/Rust exports with the existing update flags.
- A session-only development helper verifies all training ASTs, canonical
  rendering and nonprogram metadata against the immutable accepted snapshot.

  before the separate fresh independent evaluation.
- Independent evaluation accepted the frozen candidate; the caller integrated
  it unchanged before recording this outcome metadata.
