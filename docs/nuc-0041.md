# NUC 41 -- Reactive Flat Mapping

```

Title: Reactive Flat Mapping
Author: Copilot <223556219+Copilot@users.noreply.github.com>
Status: Accepted
Type: Standards Track
Created: 16-Oct-2026
Requires: 8, 12
```

## Abstract

- Add one read-only `flatMap(callback)` query to ordinary lists and class
  populations, using the same invocation machinery as `map`.
- Each callback result contributes either its immediate list items or one
  non-list value, preserving order, duplicates and identities.
- The implemented contract is the normative root
  [Reactive flat mapping specification](../nucleoid.spec.md#reactive-flat-mapping).

## Motivation

- A related record can contribute no result, one result or many results:
  team memberships, batches of tasks, itinerary legs and reasoning fan-out
  need an ordered projection rather than a one-to-one map.
- The caller's single tool-backed draw selected **runtime feature** (`1`);
  this proposal does not redraw or substitute a syntax change.
- Recent accepted NUCs emphasize numeric helpers and function headers.
  Existing `map`, `filter`, `find`, `some`, `every`, `reduce` and `concat`
  leave one-level flat mapping absent.
- Broaden collections, reactive reasoning and data-modeling expressiveness
  with one shared query, without another namespace or grammar family.
  This user value and modest API cost, not implementation convenience or
  token savings, motivate the selection.

## Rationale

- Reuse `Runtime::list_query` so ordinary lists and class populations share
  one implementation instead of diverging methods.
- Keep exactly `map`'s one-item argument and callable invocation semantics;
  do not add an index, implicit receiver binding or closure capture.
- Flatten only the callback's immediate returned list. Recursive flattening,
  a depth option, aliases, new syntax, public Rust types, dependencies and
  arbitrary new caps are outside this revision.
- Move returned list items into the result without reconstructing objects
  or functions; retained references preserve identity and duplicates.
- Preserve actual evaluation rather than simulating an explicit reducer:
  a reducer can read a null intermediate, whereas returning null alone need
  not make that read. Do not manufacture reads or repair inherited behavior.
- Keep accepted `map`/`reduce`/`concat`, user functions/properties named
  `flatMap`, and every existing syntax form available unchanged.
- Require only already accepted NUCs 8 and 12; no pending built-ins proposal
  is a prerequisite.

## Specification

### Ordered projection

- `receiver.flatMap(callback)` snapshots a list or class population using
  the existing method-call route.
- Invoke the function once per snapshotted item in receiver order.
- A returned `Value::List` contributes its items exactly one level deep.
  Any other value contributes one item; an empty returned list contributes
  none, and a string remains a single value.
- Preserve order, duplicates, deeper nested lists, and object/function
  identities. The query itself never writes its receiver; callback effects
  remain ordinary language effects.
- The root entry `Nucleoid flat maps lists by one level` specifies the
  result shape and read-only input behavior.

```
numbers = [1, 2, 3]
def expand(value) => [value, value * 10]
expanded = numbers.flatMap(expand)
assert(expanded, [1, 10, 2, 20, 3, 30])
assert(numbers, [1, 2, 3])
```

### Calls, validation and timing

- Snapshot the receiver before evaluating arguments, as for `map`.
- Evaluate every supplied argument expression once, left to right,
  including unused extras, before callback validation or invocation.
  A later supplied-argument failure therefore precedes callback validation.
- Require the first supplied value to be a function even for an empty
  receiver. Validate an omitted callback with the same exact type error.
- Pass precisely the snapshotted item, not its position or receiver.
  Additional declared parameters retain the existing missing-argument
  `null` binding; ordinary function scopes and noncapture are unchanged.
- A null or undefined receiver retains the existing method-call route,
  including not evaluating its arguments.
- The root contract's call/timing bullets and focused integration
  regressions specify these boundaries; no parser or AST changes are made.

### Reads, dependencies and snapshots

- Callback results retain null and undefined values without an artificial
  read or conversion. Actual reads of null bindings, properties or parameters
  still set assignment null tracking; a complete assignment may settle to
  null for that reason.
- Missing properties and deleted names retain actual existing deferred
  handling. An undefined item nested in a returned list is not automatically
  an undefined complete result.
- Track callback/member reads through the existing graph and replace
  obsolete read dependencies on re-evaluation.
- Receiver mutation, population changes, member updates and live named
  callable redefinition refresh dependent queries.
- `.value` snapshots keep their existing meaning. Freezing a function
  freezes its definition, not the state read from its body.
- Root entries `Nucleoid keeps flat mapped lists reactive`,
  `Nucleoid flat maps class populations` and
  `Nucleoid preserves flat mapping callable snapshots` provide the
  executable relationships.

```
numbers = [1, 2]
factor = 2
def expand(value) => [value, value * factor]
expanded = numbers.flatMap(expand)
assert(expanded, [1, 2, 2, 4])
factor = 3
assert(expanded, [1, 3, 2, 6])
numbers.push(4)
assert(expanded, [1, 3, 2, 6, 4, 12])
```

### Errors, rollback and compatibility

- Callback and argument failures propagate through existing transactions,
  restoring effects, relationships, subscriptions and queued propagation.
  Subsequent valid updates remain usable.
- The root entry `Nucleoid rolls back flat mapping callback failures`
  covers failed redefinition and recovery.
- The class-population entry preserves the actual caught
  `TypeError("Cannot delete object 'batch2'")`, unchanged population and
  recovery by emptying its items; this feature does not repair object deletion.
- Ordinary object and instance methods, callable properties and global/local
  bindings named `flatMap` retain their own dispatch. Native list queries do
  not become first-class bound properties.
- Keep all historical executable programs unchanged. The eight new cases
  replace only the paired accepted map/reduce/concat operations; titles,
  definitions, side effects, comments, assertions, returns and coverage stay.
- Compare protected behavior and non-rewritten source, not unconditional
  whole-AST or canonical graph-source equality for intentionally different
  runtime-call right-hand sides. Null-read-sensitive arbitrary compositions
  are not claimed equivalent.
- Existing expression/statement depth and propagation limits remain; no new
  resource policy or unrelated runtime repair is introduced.

## Errors

| Condition | Error |
| --- | --- |
| Missing or non-function callback, including on an empty list or population | `TypeError("flatMap expects a function")` |
| A supplied expression or callback reads a strictly unknown name | `ReferenceError("<name> is not defined")` |
| A callback throws a value | The same thrown value, unchanged |

- Receiver/member routing, syntax, depth, propagation and transaction errors
  retain their existing exact types, messages and positions.
- Validation does not swallow earlier receiver or supplied-argument failures.
- A null/undefined receiver follows existing deferred routing rather than
  producing a new callback error.

## Reference Implementation

- The accepted implementation adds the single native branch in
  [`Runtime::list_query`](../src/lang/ast/array.rs); existing list and class
  method routes snapshot receivers and evaluate supplied expressions.
- Use existing typed `Value::Function` validation and `Runtime::invoke`,
  then extend the result for `Value::List` or push any other value.
- Keep lexer, parser, AST, call dispatch, public Rust API, Cargo manifests,
  dependencies, project version, MSRV and edition unchanged.
- Normative tracing is to the root contract and its five named entries above;
  [`tests/reference.md`](../tests/reference.md), the README and
  [`examples`](examples.md#reactive-flat-mapping) add live related-record
  and identity demonstrations.
- [`tests/flat_map.rs`](../tests/flat_map.rs) embeds all eight exact accepted
  counterparts and checks candidate forms alongside unchanged controls,
  actual assertion coverage, reads, dependencies, timing, identity, rollback,
  custom names and native CLI bytes.
- Maintain new synthesized training examples as a small regular
  `dataset/nucleoid.synth.22.jsonl` shard. Existing training bytes and
  historical fingerprint checks are not rewritten; training remains
  non-normative.
- Regenerate specification JSONL and Rust exports only from source documents.
  The proposer froze its Draft without acceptance measurements or a verdict;
  the following outcome records the separate independent evaluation.
