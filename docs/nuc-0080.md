## Abstract

- Lists and class instance lists gain the read-only query `average`.
  `RECEIVER.average()` returns the arithmetic mean of the items and
  `RECEIVER.average(selector)` the mean of `selector(item)`.
- The result is exactly `RECEIVER.sum(...) / RECEIVER.length` with the same
  arguments: the total of [NUC 68](nuc-0068.md)'s `sum`, with its numeric
  conversion, left-to-right addition and undefined gate, divided by the
  number of items with the division of `/`. A list of numbers averages bit
  for bit to `xs.sum() / xs.length`, so `[0.1, 0.2, 0.3].average()` is
  `0.20000000000000004`.
- An empty receiver gives `0 / 0`, which is NaN, as Kotlin's `average()`
  does. An undefined value makes the result undefined, which a declaration
  stores as `null`.
- The selector is called once for every item, in order, with only the item,
  as `sum` calls its selector. A supplied first argument that is not a
  function raises `TypeError("average expects a function")`, even on an
  empty receiver.
- `average` follows [NUC 61](nuc-0061.md)'s shared query rules beside `sum`.
  It accepts every receiver `sum` accepts, reads the receiver before its
  arguments, never writes it, and stays live in declarations and class-level
  rules.
- At the accepted revision these calls raise
  `TypeError("<receiver>.average is not a function")`. No syntax, keyword,
  token, error type or public Rust API is added, and `average` is not a noun
  query, so `average of xs` keeps raising
  `SyntaxError("Unexpected keyword 'of'")`. The authoritative contract is
  [List and population averages](../nucleoid.spec.md#list-and-population-averages).
- **Outcome: Accepted.** The independent evaluation and the caller's
  integrated-tree checks passed all three hard criteria, and the independent
  evaluator decided Accepted. The required token comparison ran in
  continuous mode: 11 cases use fewer tokens, 915 the same and none more. No
  policy check failed.

## Motivation

- World models keep averages: the mean temperature of each room, the average
  order value, the rating of a product from its reviews, the typical speed of
  a fleet. Each is a mean over a list or over a class's instances, and it has
  to stay true while the model changes.
- [NUC 68](nuc-0068.md) and [NUC 69](nuc-0069.md) list averages under "Not
  added". At the accepted revision a mean is a total divided by a count, and
  the spelling names its receiver twice: `mean = sum of temps / temps.length`
  is 9 lexer tokens and `mean = temps.sum() / temps.length` is 11, where
  `mean = temps.average()` is 7. Over a population,
  `typical = Order.sum(.total) / Order.length` is 13 tokens where
  `typical = Order.average(.total)` is 9.
- The repetition grows with the receiver. The class-level rule
  `$Room.mean = Sensor.filter(sensor -> sensor.room == $Room).sum(sensor -> sensor.temp) / Sensor.count(sensor -> sensor.room == $Room)`
  is 38 tokens and states its filter twice;
  `$Room.mean = Sensor.filter(sensor -> sensor.room == $Room).average(sensor -> sensor.temp)`
  is 25.
- A divided total is easy to get subtly wrong, because the count must be of
  the same items as the total. The shortest accepted spelling of a filtered
  mean divides by the wrong count:
  `rushed = Order.filter(.rush).sum(.total) / Order.length` is 19 tokens and
  divides the rush total by every order. The correct
  `rushed = Order.filter(.rush).sum(.total) / Order.count(.rush)` is 23 tokens
  and repeats the filter. `rushed = Order.filter(.rush).average(.total)` is 15
  and names the items once.
- Kotlin's `average()`, C#'s `Average`, Java streams' `average()`, SQL's
  `AVG`, lodash's `_.mean` and `_.meanBy` and Python's `statistics.mean` name
  the operation. JavaScript has none, and LLM-written code such as
  `orders.average(o => o.total)` raises
  `TypeError("orders.average is not a function")` at the accepted revision.

## Rationale

- **Category and mode.** The caller selected the Utility enhancement category
  by one tool-backed uniform draw over the five categories that NUC 1's
  registry marks eligible for automatic selection, index 2 with probability
  1/5 and no redraw. This is a continuous cycle, so the token
  non-regression gate is required. Runtime applicability does not apply to
  this category.
- **Optional evidence.** No hint was supplied. Advisory usefulness is
  unscored, not zero. Strategy learning is `not_configured`, so this revision
  is unattributed, with no policy, selection receipt, trial or reward.
- **One more shared query.** `average` is an operation of the read-only list
  query that serves `map`, `filter`, `reduce`, `sum`, `max`, `min` and NUC
  61's queries. Lists, list properties, call results such as `filter(...)`,
  `map(...)` and `slice(...)`, ranges, `.value` snapshots, selected versions,
  class instance lists and `Name.list()` therefore accept it through one
  implementation, with the receiver, argument and liveness rules they
  already share.
- **Defined by `sum` and `/`.** The mean is the total of `sum` divided by the
  number of items with the function behind `/`. The conversion, the order and
  rounding of the additions, the undefined gate, NaN and infinities are
  therefore those of `xs.sum() / xs.length` by construction, not a second
  set of rules that could drift.
- Rejected: a separately computed mean, such as Python's `statistics.mean`,
  which computes exactly with fractions and rounds once, or a running mean
  `m += (x - m) / n`, which avoids overflow. Neither agrees with
  `xs.sum() / xs.length` in the last digits, no accepted spelling reproduces
  them, and `[1e308, 1e308]` would average to `1e308` rather than to the
  `Infinity` that the accepted division gives. Compensated summation is
  rejected for the reasons NUC 68 gives.
- **Every item counts.** The divisor is the receiver's length, so items that
  convert to `0` or NaN count too: `[2, null].average()` is `1` and
  `["", 4].average()` is `2`, as `sum` counts those items `0`.
- Rejected: skipping `null` or non-numeric items, as SQL's `AVG` skips
  `NULL`. The divisor would then differ from `length` while the total still
  counts those items, and a `null` reading would silently change which items
  the mean is over.
- **An empty receiver gives NaN.** `0 / 0` is NaN, the value of the accepted
  spelling, and Kotlin's `average()` and lodash's `_.mean([])` give NaN too.
  The result stays a number, so a declaration over a population that starts
  empty has a value rather than failing the statement that declares it, and
  `Number.isNaN` tells it apart from `null`.
- Rejected: raising an error, as Python's `statistics.mean([])` and C#'s
  `Average` do, which would fail a live declaration over an empty class when
  it is declared, as NUC 69 argued for `max`. Also rejected: `null`, as SQL's
  `AVG` returns, which a declaration would store as a missing value and
  which arithmetic would read as `0`.
- **Undefined stays unknown.** An undefined item or selector result makes the
  total undefined, and `/` gives undefined when an operand is undefined, so
  the mean is undefined and a declaration stores `null`.
  `pace = Trip.average(speed)` waits for every trip's speed to be defined, as
  `Trip.sum(speed) / Trip.length` does.
- **No artificial null read.** `average()` reads items, not bindings, so a
  `null` item counts `0` without settling a declaration to `null`, as in
  `sum`. A selector's own reads follow the existing rules:
  `Line.average(line -> line.price * line.qty)` over a `null` price settles a
  declaration to `null`, as the same selector does in `sum`.
- **The selector is called like `map`'s callback.** It runs once per item, in
  order, with only the item; further parameters stay `null`. Every item is
  visited even after the total has become NaN or undefined, so every item's
  reads are dependencies, as in `sum`.
- **A supplied selector must be a function.** Any other first argument,
  including `null`, raises `TypeError("average expects a function")` after
  the arguments are evaluated, even on an empty receiver, as `sum` raises
  `TypeError("sum expects a function")`.
- Rejected: a number argument as a weight or a default, as in
  `numpy.average(xs, weights)`. `xs.average(5)` stays an error rather than a
  silent weighted mean or a fallback.
- **Extra arguments** are evaluated once, left to right, and ignored, as every
  list query does.
- **Instance lists.** On a class name, `Name.average(...)` is the population
  query even when the class declares an instance method `average`, as NUC 68
  made `Name.sum(...)`. The method stays reachable through each instance,
  `bag.average()`, and `Bag.average(each -> each.average())` averages it.
- **The method call only.** `average` is not added to
  [NUC 75](nuc-0075.md)'s noun queries, so `average of xs` keeps its accepted
  `SyntaxError("Unexpected keyword 'of'")`, which `tests/noun_queries.rs`
  pins. Rejected: a global `average(...)`, `Math.average`, and `mean` or `avg`
  aliases. They would add names beside the list query, while `average` and
  `mean` are common names of user functions and bindings, which keep their
  meaning.
- **Bounded cost.** The receiver and the arguments are evaluated once per
  call, the selector once per item, and the division once. The call keeps its
  ordinary rendering in graph keys and `why`. Nothing is copied or expanded,
  so cost and rendered size stay linear in the receiver and the source.
- **Not added.** `average of xs`, a global `average(...)`, `Math.average`,
  `mean` and `avg` aliases, medians, weighted, geometric and harmonic means,
  compensated or overflow-safe means, property-name selectors such as
  `xs.average("total")` and default values for empty receivers.

## Specification

### Averages

- `RECEIVER.average()` returns the mean of the receiver's items, and
  `RECEIVER.average(selector)` the mean of `selector(item)` for every item.
  The result is `RECEIVER.sum(...) / RECEIVER.length` with the same
  arguments: the values are converted to numbers and added left to right,
  starting from `0`, and the total is divided by the number of items, in
  64-bit floating point.
- The receiver is a list, however it is reached: a variable, a property, a
  call result such as `filter(...)`, `map(...)`, `slice(...)` or
  `concat(...)`, a range, a literal, a `.value` snapshot or a selected
  version. It may also be a class's instance list, named by the class or by a
  variable that holds the class, in population order; a range of one and
  `Name.list()` are lists.
- An empty receiver gives NaN, the value of `0 / 0`. The result is a number,
  or undefined when any added value is undefined.

```
temps = [18, 24, 9]
mean = temps.average()
gap = temps.average(temp -> Math.abs(temp - 20))
assert: [mean, gap, (why mean)[0].from], [17, 5.666666666666667, ["temps"]]
temps.push(29)
assert: [mean, gap], [20, 6.5]
temps = []
assert: [Number.isNaN(mean), Number.isNaN(gap)], [true, true]
cart = {items: [0.1, 0.2]}
paid = cart.items.average()
cart.items.push(0.3)
assert: paid, 0.20000000000000004
```

```
class Trip(km, hours):
    this.km = km
    this.hours = hours
def speed trip => trip.km / trip.hours
first = Trip(120, 2)
second = Trip(45, 1)
pace = Trip.average(speed)
far = Trip.filter(trip -> trip.km > 100).average(speed)
recent = Trip[-2:].average(trip -> trip.hours * 60)
assert: [pace, far, recent], [52.5, 60, 90]
third = Trip(300, 4)
assert: [pace, far, recent], [60, 67.5, 150]
class Refund(cents): this.cents = cents
refunds = Refund.average(refund -> refund.cents / 100)
assert: Number.isNaN(refunds), true
```

### Conversion and special values

- Each added value, an item or a selector result, is converted with the
  numeric conversion of `-`, `*`, the Math helpers and `sum`: a number is
  itself; `null`, `false`, an empty or whitespace-only string and an empty
  list are `0`; `true` is `1`; a numeric string, after trimming, is its
  number; a one-item list is its item's number; a date is its time in
  milliseconds; objects, instances, classes, functions, regular expressions,
  other strings and longer lists are NaN.
- Every item counts toward the divisor, including items that convert to `0`
  or NaN: `[2, null].average()` is `1`.
- NaN and infinities follow 64-bit floating point: a NaN value makes the mean
  NaN, `Infinity` plus `-Infinity` is NaN, and a total that overflows stays
  `Infinity` after the division, so `[1e308, 1e308].average()` is `Infinity`,
  as `xs.sum() / xs.length` is.
- An undefined value makes the mean undefined, which a declaration stores as
  `null`. Every item is still visited.
- `average()` reads items, not bindings: a `null` item counts `0` without
  settling a declaration to `null`. Reads inside a selector follow the
  existing rules, so a selector that reads a `null` binding or property
  settles a declaration to `null`.

```
flags = [true, false, true, true]
share = flags.average()
entries = [2, "3", " 4 ", "", null, [5], []]
mean = entries.average()
assert: [share, mean], [0.75, 2]
entries.push("x")
assert: Number.isNaN(mean), true
class Line(price, qty):
    this.price = price
    this.qty = qty
pen = Line(3, 2)
book = Line(12, 1)
typical = Line.average(line -> line.price * line.qty)
gift = Line(null, 1)
assert: typical, null
gift.price = 6
assert: typical, 8
```

### Selectors

- A selector is called once for every item, in order, with the item as its
  only argument; further parameters are `null`. The call order and the
  argument are those of `map` and `sum`.
- A supplied first argument that is not a function, including `null`, raises
  `TypeError("average expects a function")`, even on an empty receiver.
- Every supplied argument, including unused extras, is evaluated once, left
  to right, after the receiver and before the first selector call.
- A null or undefined receiver keeps the existing method-call route: the call
  yields undefined without evaluating its arguments.

```
seen = []
def weigh(item, position):
    seen.push(position ?? item)
    return item * item
items = [3, 1, 2]
def spread() => items.average(weigh)
assert: [spread(), seen], [4.666666666666667, [3, 1, 2]]
floor = 2
def price item => Math.max(item, floor)
cost = items.average(price)
assert: cost, 2.3333333333333335
floor = 3
items.push(5)
assert: [cost, seen], [3.5, [3, 1, 2]]
missing = null
skipped = missing.average(weigh(9))
assert: [skipped, seen], [null, [3, 1, 2]]
```

### Liveness and transactions

- `average` never writes its receiver. A declaration that uses it depends on
  the list or the population, on its argument expressions and on whatever the
  selector reads, as for `sum`.
- Pushing, popping or replacing a list, creating or deleting an instance, and
  changing a property that a selector reads re-evaluate the declaration.
- In a class-level rule, each instance evaluates its own average, and
  `$Class` inside a filter or a selector is the instance the rule is
  evaluated for.
- Selector errors propagate through the existing transaction, so a failed
  standing re-evaluation rolls back the change that triggered it, including
  a list write or a new instance. A `suppose` block sees the hypothetical
  mean and restores the accepted one when it ends.

```
class Room(name): this.name = name
class Sensor(room, temp):
    this.room = room
    this.temp = temp
$Room.mean = Sensor.filter(sensor -> sensor.room == $Room).average(sensor -> sensor.temp)
$Room.warm = $Room.mean > 21
lab = Room("lab")
hall = Room("hall")
Sensor(lab, 20)
probe = Sensor(lab, 25)
Sensor(hall, 18)
assert: [lab.mean, lab.warm, hall.mean], [22.5, true, 18]
probe.room = hall
assert: [lab.mean, hall.mean], [20, 21.5]
attic = Room("attic")
assert: [Number.isNaN(attic.mean), attic.warm], [true, false]
```

### Rendering

- The call keeps its ordinary rendering. `mean = temps.average()` renders as
  `mean = temps.average()` in `why`, and `why` lists the receiver in the
  declaration's `from` list. A lambda selector renders as `function()`, as in
  `typical = Order.average(function())`, and a property selector as written,
  as in `picked = Order.average(.amount)`.
- Graph and block keys use the same form: `if temps.average() > 20:` is the
  standing condition `if(temps.average()>20)`.
- Errors that quote an expression quote the call: `temps.average()(1)` raises
  `TypeError("temps.average() is not a function")`,
  `all t in temps.average(): t` raises
  `TypeError("temps.average() is not a collection")`, and
  `why temps.average()` keeps raising
  `TypeError("Cannot explain temps.average()")`.
- The accepted spelling of the same mean renders differently, as
  `mean = sum of temps/temps.length`, so the two are different graph keys, as
  `sum of xs` and `xs.sum()` are.

- No error type or message format is added. The selector error reuses the
  message format of the other list queries.

## Reference Implementation

- `src/lang/ast/array.rs`: `list_query`, the read-only query shared by lists
  and class instance lists, sends `average` to `aggregate_items` beside
  `sum`. After the existing `optional_selector` validates the selector with
  the message format `<query> expects a function`, `aggregate_items` sends
  `sum` to the existing `Runtime::sum_items` and `average` to the new private
  `Runtime::average_items`. That method counts the items with
  `number::from_usize`, totals them with `sum_items` and divides the total by

  front of it.

  `RECEIVER.sum(...) / RECEIVER.length`" when the receiver is read once. A

  number of items" used elsewhere is exact, and no case or test depends on
  the difference.
