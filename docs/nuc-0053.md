## Abstract

- Automatically retain the values of variable and object-property storage
  slots, exposing read-only postfix `@0`, `@1`, ... selectors.
- Provide contextual literal aliases `@first`, `@last` and `@previous`,
  without changing ordinary dot fields, list indexes, or the Value model.
- Prototype one explicit user feature on accepted revision
  `8f6b18ba6195401f31352432e4ae8f6615e35094`; no pending NUC 52 work is a
  dependency or part of this revision.

## Motivation

- State changes, including reactive changes, should be inspectable without
  manually maintaining parallel lists and push operations.
- A history should belong to the actual storage owner, persist across runs,
  and roll back with state rather than leaking failed writes.
- This is an explicit user feature, not a random category draw; the confirmed
  `Runtime features` classification describes storage, scope and transactions.

## Rationale

- The user's final `@` spelling supersedes earlier dot-history suggestions:
  `student1.name@0`, `@1`, `@2`, `@first`, `@last`, and `@previous`.
- Zero is the first version. Negative selectors, including `@-1` and `@-2`,
  are rejected rather than overloaded as newest-relative addressing.
- `.first`, `.last` and `.previous` are existing real fields. Preserve those
  meanings, `.value` snapshots, and all existing list indexing/slicing.
- Use normal Value semantics: lists copy by value and objects retain identity.
  Deep snapshots, deep freezing, wrappers, serializers with new shapes, hidden
  object properties and a second dynamic value representation are rejected.
- Keep all retained entries for the slot lifetime, not an arbitrary window.
  Memory grows with actual changes; reading a history is not a mutation.
- Preserve the existing division between State transactions and Scope locals;
  this feature does not turn parameter/local writes into state declarations.

## Specification

- The candidate normative contract is
  [Read-only state versions](../nucleoid.spec.md#read-only-state-versions).
  The six appended specification entries trace the following behavior:

| Entry | Implemented behavior |
| --- | --- |
| `Nucleoid reads zero based and named versions of instance properties` | Numeric/alias selection, ordinary result composition and explicit return |
| `Nucleoid tracks reactive variable versions without duplicate states` | Live readers, actual reactive changes, equal writes and missing versions |
| `Nucleoid reads versions through nulls and deferred indices` | Old values through current Null, deferred recovery and previous Null |
| `Nucleoid isolates local and parameter version histories between calls` | Innermost parameter storage, local assignment expressions and call isolation |
| `Nucleoid preserves list values object identity and ordinary fields in versions` | List value copies, object identity and collision-free fields |
| `Nucleoid restores version histories on rollback and resets deleted bindings` | Caught rollback, retention, deletion, redefinition and live recovery |

### Syntax and resolution

- Add a postfix Version expression at ordinary member/index/call precedence.
  A numeric selector is an unsigned decimal digit literal fitting `usize`;
  no float conversion or rounding of indexes is permitted.
- Accept `@first` as index zero, `@last` as the newest retained entry and
  `@previous` as the entry before newest. The words are not new keywords and
  are not dynamically evaluated expressions.
- Resolve a bare variable to the same innermost Scope binding as an ordinary
  read, otherwise to its actual State variable slot.
- Resolve a member or computed property to its evaluated ObjectId and property
  name. Evaluate a side-effecting receiver/key once in ordinary left-to-right
  order. Aliases do not create separate property histories.
- A namespace, list element, slice, arbitrary temporary, `this` itself or
  `.value` pseudo-property is not a new storage slot. A function/class Value
  actually stored in a variable has an ordinary variable history.
- A missing slot or unavailable index returns Undefined, using the existing
  deferred-Null assignment behavior and retaining dependencies for recovery.
  Never fabricate a successful history from just the current Value.
- Only the selected historical result contributes nullishness; a valid old
  value remains usable while the current slot contains Null or Undefined.
- Result Values support ordinary member, index, slice, method/function-call
  and `.value` snapshot composition, including returned object identity.

### Recording, lifetime and transactions

- Record the initial stored Value at index zero; append on actual
  `Value::same_value` changes only. This includes reactive assignments,
  constructor writes, initial object-property maps, class-rule receivers and
  mutable-list write-backs.
- Repeated NaNs do not append, signed zeros differ, lists compare recursively
  by contents and object references compare by identity. Equal writes, reads,
  graph bookkeeping, restoration and synthetic placeholders add no versions.
- Retain State history across successful `Runtime::run` commits independently
  of the cleared transaction log. Successful writes are readable immediately.
- Retain each property by concrete ObjectId/property slot, including computed
  property reads and changes of the variable selecting its owner.
- Delete its history when a variable/property is actually deleted, its object
  is removed, or State/Runtime is cleared. A new binding/property lifetime
  begins at zero. Replacing a named object preserves surviving identity/slots
  and resets only properties that actually disappear.
- Failed runs and try savepoints undo State history appends/removals/resets
  with the corresponding State writes. Store append length checkpoints;
  move removed histories into the undo log instead of cloning their full
  retained contents on each write. Nested delete/recreate rollback is atomic.
- Parameters, local assignment expressions, loop binders, constructor locals,
  catch bindings and cloned scopes retain existing innermost binding and
  frame lifetimes. Scope locals remain non-transactional, as before: a caught
  local write and its local history stay together rather than disagreeing.
  A failed invocation's dead frame retains nothing in State.

### Read-only boundaries and compatibility

- Direct assignment, compound assignment or deletion of a selected slot fails
  explicitly; mutable-list write-back into a selected history also fails.
  Read-only list queries remain available, and an ordinary copied binding
  can be mutated without modifying the retained list.
- Read-only slots do not deep-freeze object identities: a real property of
  a returned historical object can be read, assigned, deleted or mutated by
  ordinary supported property operations. Resolve version-derived list
  property destinations once before arguments so write-back does not replay
  a side-effecting receiver/key.
- Preserve ordinary call/receiver routing, source diagnostics, one-shot
  expression execution, graph propagation/cycle checks, snapshot freezing,
  negative list indexing/slicing and all previously accepted forms.
- Existing expression, postfix-chain and statement-depth limits still apply;
  no new dependency, MSRV, release metadata or language version is changed.

## Errors

- `SyntaxError("Expected a non-negative integer, 'first', 'last', or 'previous' after '@'")`
  for a missing, signed, decimal/fractional, exponent, out-of-range numeric,
  expression, unknown or malformed selector.
- `TypeError("State versions require a variable or object property")` for a
  non-slot or namespace history reference; missing slots instead defer.
- `TypeError("State versions are read-only")` for assignment, compound
  assignment, deletion or mutable-list write-back targeting a version.
- Existing unsupported compound computed/call targets retain
  `SyntaxError("Invalid compound assignment target")`; new plain historical
  object paths may address their real properties, not the version slot.
- Existing nesting, chain, source-position, snapshot and propagation errors
  retain their exact messages; this revision adds no separate exception type.
