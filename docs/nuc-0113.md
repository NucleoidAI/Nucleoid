# NUC 113 -- Implicit Receivers in Method Bodies

```

Title: Implicit Receivers in Method Bodies
Author: Can Mingir <canmingir@gmail.com>
Status: Accepted
Type: Standards Track
Category: Syntax enhancement
Created: 17-Nov-2026
Requires: 79, 93, 102, 107
```

## Abstract

- In the code of a class body, a `.` that begins an operand and is directly
  followed by a property name reads that property of the instance the code
  runs on, its receiver `this`. So `def area() => .w * .h` is
  `def area() => this.w * this.h`, and `return .total - .paid` in a
  method's indented body is `return this.total - this.paid`.
- It completes [NUC 102](nuc-0102.md)'s implicit receivers, which read the
  assigned object inside the value of a property assignment, for the rest
  of a class's code: the methods it declares with `def` or `function` in
  every parameter form, the Python-style `self` methods of
  [NUC 107](nuc-0107.md) included, its `def init` and `def __init__`
  constructors and the statements of its own body, which make up its
  constructor, in subclasses too, with expression and indented bodies and
  every statement, expression and template interpolation in them.
- A read builds `this.NAME`, the tree of the member access written out, so
  values, dependencies, live updates, rendering, `why`, `affects`, rollback
  and errors are those of the written-out spelling.
- Every accepted reading keeps its meaning:
  - A property assignment keeps NUC 102's receiver, and the innermost one
    decides, so `other.p = .q` in a method reads `other.q`.
  - A whole argument `.name` stays a [NUC 79](nuc-0079.md) selector, and a
    dot that begins a call argument, a statement or an assignment target
    keeps its accepted reading or error, as do `is` values and a dot after a
    name.
  - Lambdas, arrows, `function` expressions, operator sections, nested
    declarations and the elements and conditions of comprehensions keep
    their accepted errors, since `this` is not defined in them.
  - Functions outside classes, object functions and class-level rules are
    unchanged, so `def f() => .a` keeps `SyntaxError("Unexpected '.'")`.
- Reads happen only in NUC 102's final parse, after every accepted parse
  has failed, so only inputs that were syntax errors at the accepted
  revision change. The probes of the juxtaposed `while` and `suppose`
  headers of [NUC 93](nuc-0093.md) read the instance too, so such a header
  splits as its written-out spelling does.
- No token, keyword, syntax-tree node, error type or message, option or
  public item is added, and no version changes. The authoritative contract
  is [Implicit receivers in method bodies](../nucleoid.spec.md#implicit-receivers-in-method-bodies).

## Motivation

- Methods read the properties of their own instance more than anything
  else. In the four executable documents, 53 lines that give a method's
  value, an arrow body or a `return` value in a class body, read the
  instance, 59 times in all: 28 lines through `this.`, as in
  `return this.count` and `def combine left right => this.base + left + right`,
  and 25 through `self.`, as in `def free(self) => self.capacity - self.level`.
  - The count runs over the 1,151 cases of the four documents, duplicates
    included. A line is in a class body when the nearest line above it
    that begins, after its indentation, with `class ` is indented less
    than it and than every nonblank line between them. Its value is what
    follows the first `=>` or `->` of a line that begins with the word
    `def` or `function`, or what follows the word `return` that begins a
    line. A value that begins with `this.NAME =` or `self.NAME =`, an
    assignment rather than `==`, is left out. A line counts when its value
    holds the word `this` or `self` followed by `.` and a letter or
    underscore. Each such occurrence is a read, and a line with a `this.`
    read is a `this.` line, the others `self.` lines.
- NUC 102 gave class-level rules and property values the short receiver
  form, so `$Rect.area = .w * .h` and `this.area = .w * .h` read the
  receiver's properties, but a method that computes the same value still
  spells every read out: at the accepted revision `def area() => .w * .h`
  raises `SyntaxError("Unexpected '.'")` at the `w` while the program is
  parsed.
- Each read outside a template saves one lexer token, `this.w` and
  `self.w` being three and `.w` two, so a world model's methods read as its
  rules already do: `def area() => .w * .h` is 10 tokens against 12 for its
  written-out spelling.
- Prior art: Ruby's and CoffeeScript's `@name`, the implicit `this` of
  Kotlin, Swift, Java and C#, and Visual Basic's `With` blocks, whose
  `.Name` reads a member of the object in context.

## Rationale

- **Category and selection.** The caller made one tool-backed uniform draw
  over the five categories that NUC 1's registry marks eligible for
  automatic selection and selected Syntax enhancement, index 0, with
  probability 1/5 and no redraw, and allocated this Draft in the pushed
  commit `e1506250` on 17-Nov-2026. Within the category, the caller chose
  NUC 102's leading-dot reads, extended from property values to the code of
  a class's methods and constructors, after setting aside `??=`, operators
  over selectors, `class P(.x)`, bare tuples `a, b = 1, 2`, list spread and
  chained comparisons for protected readings or pinned tests. No NUC
  proposes it: NUC 102 reaches methods only through property assignments
  such as `self.w = .h`. Token comparison is required in this continuous
  cycle, and runtime applicability does not apply to this category.
- **Optional evidence.** No hint was supplied. Advisory usefulness is
  unscored, not zero, because no rubric was frozen. Strategy learning is
  `not_configured`, so this revision is unattributed, with no policy,
  selection receipt, trial or reward.
- **Only former errors.** At the accepted revision a class body's code has
  no receiver, so a `.` where an operand begins in it reaches the operand
  parser, which raises `SyntaxError("Unexpected '.'")` at the name after
  it. A method with a `self` parameter reports the error of the parse
  without receiver parameters instead,
  `SyntaxError("Expected a parameter but found keyword 'this'")`, because
  NUC 107's parse with them runs after it and keeps the first error, and a
  tentative statement that falls back at the dot reports its own error,
  such as `SyntaxError("Unexpected ','")` for `a, b = .pair`.
- **The instance of a class body.** A class body is the one place where
  `this` always names one object, the instance its code runs on, and NUC 102
  already reads it in values such as `this.area = .w * .h`. So the class
  body gives its code the receiver `this`, and a read there is a property of
  it. Rejected:
  - a sigil such as Ruby's `@name`, a new token where `@` already begins
    state versions and NUC 96's at-variables;
  - reads in functions outside classes, where no receiver is defined:
    `def f() => .a` keeps its accepted error, which
    `tests/implicit_receivers.rs` pins;
  - implicit targets such as `.count += 1`, another feature that NUC 102
    also rejected;
  - a spelling flag or option, which the user removed from the language.
- **The innermost receiver.** A property assignment names its receiver on
  its own line, so its value keeps every rule of NUC 102: in a method,
  `other.p = .q` reads `other.q`, and `this.p = (x = .a)` keeps its error
  rather than reaching past the variable assignment. Elsewhere in a class
  body no target names another object, so the values of variables, of
  compound and `:=` assignments to names, of label arguments and of
  destructuring declarations read the instance:
  `total = .price * .qty` reads `this.price * this.qty`. A computed,
  indexed or versioned target, such as `xs[0].p`, `xs[0]` or `o.p@first`,
  gives no receiver, as in NUC 102, and does not fall back to `this`,
  which a reader of `xs[0].p = .a` could take for `xs[0].a`.
- **Nested functions keep their errors.** At the accepted revision `this`
  is not defined in the lambdas, arrows, `function` expressions, operator
  sections and nested declarations of a method, nor in the elements and
  conditions of comprehensions, which lower to lambdas:
  `def twice() => [1, 2].map(i -> i * this.w)` raises
  `ReferenceError("this is not defined")` when it runs. A read there could
  only build that error, so these dots keep their accepted syntax errors,
  and a later proposal that defines `this` in nested functions remains free
  to give them a meaning. The source of a comprehension and the condition
  of a quantifier are evaluated in the method, so they read. A property
  value keeps NUC 102's lexical receiver inside its functions, and a class
  declared inside a function gives its own body the instance again.
- **Comprehension elements.** A list's first item is parsed before the
  `for` that makes it a comprehension's element. So when the code holds the
  instance and the list holds a `for` at its own bracket depth, the first
  item is parsed without the instance. A list with such a `for` parses only
  as a comprehension, so no list that parses is affected: any other list
  with it fails at that `for` either way. Rejected: parsing the element a
  second time after seeing the `for`, which would meet the outcomes that the
  parser caches for Python-style conditions, `while` headers and `suppose`
  premises by position and depth, computed with the instance.
- **Kept readings.** NUC 102's kept readings keep their meaning in a class
  body: a call argument that begins with `.` is a NUC 79 selector or its
  accepted error, so one rule decides what a leading dot means in an
  argument wherever the call stands; `is` values read no receiver; a dot
  that begins a statement or an assignment target keeps its error; and a
  dot after a token that is not in operand position, such as a name, stays
  member access.
- **One final parse.** The reads join NUC 102's final parse instead of
  adding a pass, so every input that an accepted pass parses gets that
  pass's result before they can apply, and compatibility holds by
  construction. The final parse already runs for every failing input that
  holds a receiver dot, so methods add no parse.
- **Probes read the instance.** NUC 93's juxtaposed `while` and `suppose`
  headers decide their separation through probes that NUC 102 left without
  reads, which is the defect F1 that NUC 102's evaluation records. For
  method reads the probes take the instance and read it, so
  `while 1 + .n is a: b` in a method runs as the separate statements of
  `while 1 + this.n is a: b`, as its written-out spelling does. They still
  read no property receiver: NUC 102's F1 inputs parse at the accepted
  revision, so reading there would change accepted programs, and they keep
  their accepted trees.
- **No document cases.** The four executable documents gain no case or
  `nuc` code block.
  `tests/implicit_receivers.rs::only_the_appended_cases_read_receivers_and_they_run_every_assertion`
  checks every case of the four documents with `holds_receiver_read`
  against a fixed whitelist of NUC 102's titles, so a case with a method
  read would fail it, and widening that whitelist would weaken an existing
  test, as [NUC 101](nuc-0101.md)'s rejection records. The behavior is
  specified instead in prose sections of the specification and the
  language reference, with plain fences, whose programs
  `tests/method_receivers.rs` runs and checks; in that focused suite; and
  in the synthesized shard `dataset/nucleoid.synth.77.jsonl`.
  `tests/docs.rs` and every other suite still pass.
- **The token gate measures no savings.** With no new document case, the
  gate compares the 1,151 accepted cases with themselves, every one the
  same. The savings are measured separately in [Cost](#cost).
- **Requires.** NUC 102 for the receivers, reads and final parse that this
  extends; NUC 79 for the selectors that whole arguments keep; NUC 93 for
  the juxtaposed headers whose probes now read the instance; and NUC 107
  for the `self` methods it covers.
- **Bounds.** A read builds one member expression over `Expr::This`, and
  counts toward the chain bound as `(this).NAME` does, as NUC 102's reads
  count. The comprehension lookahead scans at most to the list's closing
  bracket and runs only in code that holds the instance. No recursion is
  added outside the accepted nesting guards.

## Specification

- The normative contract is
  [Implicit receivers in method bodies](../nucleoid.spec.md#implicit-receivers-in-method-bodies).

### Where the instance is the receiver

- The receiver is `this` in the code of a class body, in the final parse of
  [NUC 102](nuc-0102.md), wherever no property value already gives a
  receiver:
  - the methods declared directly in the body with `def` or `function`, in
    every accepted parameter form: parenthesized, bare (NUC 18, NUC 27),
    comma-free, typed, defaulted, rest, and Python-style `self` or `this`
    (NUC 107);
  - `def init` and `def __init__` constructors, with or without a `self`
    parameter;
  - the statements of the class's own indented or same-line body, which
    make up its constructor;
  - the bodies of classes that name a parent with `extends` or a colon.
- Expression bodies (`=> expr`, also indented) and indented bodies read in
  every statement and expression they hold, including `if`, `for`, `while`,
  `try` and `suppose` headers and bodies, `return`, `throw` and `delete`,
  and template interpolations.
- A `def` written on the same line as a class header, as in
  `class C: def f() => .x`, is a statement of the constructor that declares
  a local function, as at the accepted revision, so it is a nested
  declaration and keeps its error.

### Reads

- A `.` token that begins an operand, after a token in operand position or
  at the start of an interpolation, as NUC 102 defines it, and is directly
  followed by an identifier or keyword `NAME`, reads `this.NAME`. A keyword
  reads its canonical spelling, as after any `.`: `.self` reads `this.this`
  and `.None` reads `this.null`.
- The read continues with every postfix suffix that member access takes:
  members, versions, subscripts, slices and calls.

```
class Item(this.price, this.qty):
    def total() => .price * .qty
    def label() => `${.qty} x ${.price} = ${.total()}`
    def discounted(rate) => .total() * (1 - rate)
i = Item(4, 3)
assert([i.total(), i.label()], [12, "3 x 4 = 12"])
line = i.total()
i.qty = 5
assert(line, 20)
assert(i.discounted(0.5), 10)
i.label()
```

- This program, the first of the specification section, returns
  `"5 x 4 = 20"`.

### The innermost receiver

- The value of an assignment to a property path keeps the receiver of
  NUC 102: the path without its last property, or none for a computed or
  versioned target. Inside that value NUC 102's rules apply unchanged, so
  a variable assignment nested in it gives no receiver.
- The value of an assignment to a name, with `=`, `:=` or a compound
  operator, of a label argument and of a destructuring declaration keeps
  the instance.
- An assignment to another target, such as `xs[0] = .w` or `$C = .w`,
  gives no receiver.

| Source in a method | Builds the tree of |
| --- | --- |
| `this.w = .h` | `this.w = this.h` |
| `other.p = .q + .r` | `other.p = other.q + other.r` |
| `x = .w * 2` | `x = this.w * 2` |
| `x += .w` | `x = x + this.w` |
| `a, b = .pair` | `a = this.pair[0]` and `b = this.pair[1]` |
| `x = (o.p = .a) + .b` | `x = (o.p = o.a) + this.b` |
| `x = P(n = .w)` | `x = P(n = this.w)` |
| `this.xs = [1].map(i -> i * .w)` | `this.xs = [1].map(i -> i * this.w)`, NUC 102's lexical read |

### Nested functions

- The bodies of lambdas, arrows, `function` expressions, operator sections
  and nested `def` and `function` declarations, and the element and
  condition of a comprehension, have no instance receiver, so their dots
  keep their accepted errors. Their property values keep NUC 102's
  receivers.
- The source of a comprehension and the collection and condition of a
  quantifier are evaluated in the method and keep the instance.
- The first item of a list is parsed without the instance when the code
  holds it and a `for` keyword stands at the list's own depth before its
  closing bracket.
- A class declared in a nested function, or anywhere without a receiver,
  gives its body the instance; a class declared inside a property value
  keeps that value's receiver.

### Kept readings

- These dots keep their accepted readings and errors in a class body:
  - the first token of a call argument, which is a NUC 79 selector when the
    argument is exactly a property path, as in `[this].map(.w)` and
    `Inner(.w)`, and otherwise its accepted error, as in `f(.w + 1)`; and
    the first tokens of the two arguments of an `assert:` statement;
  - every dot in the value of an `is` assignment;
  - a dot that begins a statement, including the first statement of a
    same-line suite such as `if c: .w`, or the target of an assignment;
  - a dot after a token that is not in operand position, which is member
    access where the accepted grammar reads one: `x .a`, and
    `while .n > 0:`, which keeps its accepted `SyntaxError("Unexpected ':'")`.
- Outside class bodies nothing changes: functions declared outside a class,
  object functions such as `o.f = function() { return .w }`, which read `o`,
  and class-level rules such as `$Rect.area = .w * .h`.
- Juxtaposition still splits statements, and each part reads where it
  stands: in a class body `def f() => 1 is not .w` is the method
  `def f() => 1` followed by the constructor statements `is` and
  `not this.w`, as its written-out spelling is.

### Lowering and rendering

| Source in a class body | Builds the tree of |
| --- | --- |
| `def area() => .w * .h` | `def area() => this.w * this.h` |
| `def f(self, k) => .w * k` | `def f(k) => this.w * k` |
| `return .items[0].name` | `return this.items[0].name` |
| `def f() => .area() * 2` | `def f() => this.area() * 2` |
| `if .w > .h:` | `if this.w > this.h:` |
| `` def f() => `${.w}x${.h}` `` | `` def f() => `${this.w}x${this.h}` `` |
| `def f() => [x * 2 for x in .xs]` | `def f() => [x * 2 for x in this.xs]` |
| `def f() => all x in .xs: x > .w` | `def f() => all x in this.xs: x > this.w` |
| `def f() => new .Kind(1)` | `def f() => new this.Kind(1)` |
| `while 1 + .n is a: b` | `while`, `1 + this.n`, `is` and `a: b`, as NUC 93 splits it |

- Statement rendering, `why` and `affects` steps, `--graph` output and
  graph and block keys are those of the written-out spelling.

### Parse passes and probes

- The reads belong to NUC 102's final parse, which runs only after every
  accepted pass has failed, and to the interpolations and probes of that
  parse. Every input first runs the accepted passes, with no reads.
- The probes that decide NUC 93's separation of a `while` header or a
  `suppose` premise run with the parse's instance receiver: they read the
  instance and no property receiver, and a dot that begins an assignment
  target keeps its error there, as in the parse. A probe of an accepted
  pass reads nothing.
- When the final parse fails too, the input reports whichever of the
  accepted error and the final parse's error lies further into the source,
  the accepted one on a tie, as NUC 102 specifies.

### Cost

- **Parses.** An input without a read takes its accepted path unchanged. A
  program with reads fails every accepted pass at its first read and parses
  once more in NUC 102's final parse: at most five parses, and three when it
  holds neither `for` nor a template, as for NUC 102's reads. A `self`
  method or an operator section adds the run of NUC 107 or NUC 109 that the
  accepted revision already adds for it.
- **The lookahead.** In code that holds the instance, the first item of
  each list costs one scan of the list's tokens up to its closing bracket,
  so lists nested `d` deep scan at most `d` times the tokens, with `d` at
  most 64. Nothing else is added.
- **Measured.** Release builds of the accepted and the candidate libraries
  with debug assertions and overflow checks, linked in one process. Each
  cell is the median over three runs of the median of nine calls, five for
  1,000 lines, of `Runtime::check` / `Runtime::run`, in microseconds;
  "written" is the spelling with `this.`. The method lines are
  `def mI() => .w * .h + I`, the statements `xI = .w + I` in one indented
  method, and the lists stand in a class whose other method holds a
  comprehension, so that the lookahead runs.

- Programs without reads take their accepted paths: over the 1,139
  distinct cases of the four documents, `Runtime::check` took 30.73 ms on
  the accepted library and 29.35 ms on the candidate, and `Runtime::run`
  262.04 ms and 262.27 ms. The five cases with the largest ratios, timed
  again with 41 calls, are within 9% of the accepted library, either way.
- A program with reads costs about what its written-out spelling costs at
  the accepted revision. It costs less at scale, because its accepted
  passes stop at the first read and it has one token less for each read,
  and up to 1.3 times as much where the accepted passes parse every level
  before failing at the innermost read, as in nested parentheses, as
  NUC 102's nested reads do. A long list in a source with `for` costs the
  written-out spelling two complete parses, a list-literal pass that fails
  at the `for` and a comprehension pass, and the reads one, so they cost
  half. The growth of that list shape from 100 to 1,000 lists, about 80
  times, is the accepted parser's own, in both spellings and on both
  libraries.
- **Token savings.** The token gate measures none, since no case is paired.
  Measured separately with the lexer, the five documented programs use 682
  tokens against 704 written out, 22 fewer, and the 12 shard records 864
  against 890, 26 fewer. A read inside a template interpolation saves
  nothing, since a template is one token.

### Compatibility

- Only inputs that were syntax errors at the accepted revision change.
  Every input that an accepted pass parses keeps its tree, positions,
  rendering, result, errors, JSON, graph and REPL behavior, and every
  accepted `parse_expression` result keeps its tree, because that pass
  returns it before the final parse can run.
- An input that the accepted revision parses only in the final parse, with
  NUC 102 reads, keeps its tree too. There the instance changes a reading
  only at a dot that had no receiver, which raised an error at the accepted
  revision; every dot that NUC 102 reads keeps its property receiver,
  which is innermost. The probes read only instances, so NUC 102's F1
  inputs, such as
  `o.f = function() { while 1 + .x is a: b` followed by `return 1 }`, keep
  their accepted trees and results.
- The changed inputs raised:
  - `SyntaxError("Unexpected '.'")` at the name after a dot that now reads;
  - for a method with a `self` parameter, the error of the parse without
    receiver parameters, such as
    `SyntaxError("Expected a parameter but found keyword 'this'")`;
  - for a tentative statement that fell back at the dot, its own error,
    such as `SyntaxError("Unexpected ','")` for `a, b = .pair` or
    `SyntaxError("Unexpected '='")` for `{a} = .o`, or the error of the
    statements it fell back to, such as `SyntaxError("Expected ']' but found ','")`
    for `while [1, .w]:`.
  They now parse, or report another error further into the source.
- The near misses keep their accepted readings: `while .n > 0:`,
  `x is .w` and `this.b is .a`, where the dot follows a name, so the last
  two run as juxtaposed statements; `y is 2 * .w`, whose `is` value reads
  nothing; `String(.w + 1)`, `[this].map(.w)` and
  `Inner(.w)`, whose dot begins an argument; `.w = 9`, `.xs.push(1)`,
  `if c: .w` and `suppose this.w = 5: .w * 2`, whose dot begins a
  statement; `(.w = 1)`, whose dot begins a target; `def f(x) => x .a`, `.5`
  and `{...{a: 2}}`; and `` `${any x in .xs: x > .w}` ``, whose
  interpolation ignores the tokens after `any`, as at the accepted
  revision.
- **Exports.** No document case is added, so `dataset/nucleoid.spec.jsonl`
  and `tests/nucleoid.spec.rs` are unchanged, and the four documents keep
  their 1,151 cases byte for byte.
- **Tests.** The only edits to existing tests are the count pins of
  `tests/dataset.rs`, which add `SYNTH_77_RECORDS` at 12 and move
  `SYNTH_RECORDS` from 1,479 to 1,491. The 23 `cases` pins stay 1,151, and
  no other existing assertion, pinned diagnostic or case byte changes.
- **Public API.** No public item is added or removed. `parse`,
  `parse_program` and `parse_expression` return the new trees for the
  changed inputs. No version number is changed.

- **State:** Implemented and Accepted; the frozen candidate, after the

  - `Dots` gains `Instances`, the mode of the final parse's probes, which
    read the instance and no property receiver, and `Dots::probed` gives a
    probe its mode: `Accepted` for a probe of an accepted pass, `Instances`
    otherwise.
  - `Receiver` gains `Instance`, the receiver of a class body's code, which
    `receiver_read` builds as `Expr::Member` over `Expr::This`.

    other target NUC 102's receiver of its target, in the final parse and

    value.

    reads and no receiver is set; `holds_instance` and `without_instance`
    leave it out of nested functions and leave every other receiver alone.

    through `without_instance`, and NUC 102's `without_receiver` stays
    private to the module.

    in the probes too: it returns early only in an accepted pass or for a
    target that does not begin with a dot.
  - `receiver/tests.rs`, 67 lines, holds three unit tests: the modes of
    `Dots::probed`, and probes that the real probe constructor,
    `Parser::accepted`, builds from a parser in the final parse's mode,
    which read the instance, read no property receiver and keep the error
    of a target that begins with a read.
- `parser/class.rs`: `class_body` parses the class's contents
  `with_instance`.
- `parser/primary.rs`: `function_literal`, `arrow_body` and `lambda` parse

### Records
