## Abstract

- Add only unshadowed static `Math.exp10(value)` as the exact accepted
  `Math.pow(10, value)` numeric operation with one fixed base and one live
  exponent. Reuse the same `10.0_f64.powf(first)` kernel and existing
  Math evaluation, conversion, supplied-Undefined, omission and extra-argument
  boundaries.
- Preserve every accepted Math method, constant, ordinary/member route,
  diagnostic, dependency, class rule and transaction. Do not substitute
  native decimal exponentiation, exponential/logarithmic algebra, integer
  shortcuts, rescaling or another floating-point evaluation order.
- The caller's single unbiased live-registry draw selected Utility
  enhancement, index 2 among five eligible categories, probability 20%.
  Continuous evaluation requires per-case lexer-token comparison alongside
  immutable accepted-source replay and every hard criterion.
- Accepted under automatic acceptance: the fresh independent policy decision
  is Accepted and every hard criterion passes, including the caller's
  current-main-based integration checks. The one synchronous Rust improvement
  pass required no source changes. Required token comparison ran: the new
  paired case uses 163 to 161 tokens and all 1,340 historical cases are equal.

## Motivation

- Decimal scales occur in logarithmic measurements and magnitude
  relationships. A fixed-base helper names `Math.pow(10, exponent)` without
  repeating its constant base, as accepted NUC 56 names base-two powers.
- The intended benefit is a smaller numeric utility expression, not a new
  power algorithm, broader foreign-language compatibility, improved accuracy
  or a measured speed claim.
- Standing decimal scales must retain live exponent and ignored-argument
  dependencies, once-only effect order, missing-value recovery and rollback.

## Rationale

- Reuse the accepted Math dispatcher, its supplied-Undefined gate, intrinsic
  conversion and the existing powf kernel. Add one unary dispatch arm beside
  `exp2`; neither resolve a shadowable `Math.pow` nor construct a second
  runtime call.
- Keep the floating-point operation exactly `10.0_f64.powf(first)`.
  Native decimal exponentiation, exponential/logarithmic identities,
  integer shortcuts, rescaling and altered arithmetic order are excluded.
- Do not extend member reads, add a first-class function, introduce an
  alias or alter argument, scope, graph, transaction or parsing machinery.
- The one new measured case has an accepted-runtime-executed
  `Math.pow(10, power)` counterpart. Only its standing scale RHS changes;
  its fractional pow assertion remains an independent accepted control.

## Specification

- Add only unshadowed static `Math.exp10(value)`, computing the same numeric
  operation as accepted `Math.pow(10, value)`.
- Before conversion, return Undefined when any supplied top-level argument
  is Undefined, including ignored extras. Omission is numeric NaN, not an
  explicitly supplied Undefined.
- Intrinsically convert only the first supplied value with the existing
  `Value::to_number`, then compute `10.0_f64.powf(first)`. Preserve the
  accepted pow kernel unchanged. Non-NaN results match by bits; NaNs retain
  the accepted classification without a new payload guarantee.
- Both zero signs as exponents yield one. Finite and fractional exponents,
  overflow, subnormal rounding and positive-zero underflow match accepted
  powf. Positive infinity yields positive infinity; negative infinity yields
  positive zero; numeric NaN yields numeric NaN.
- Literal null converts to zero. Booleans, strings, empty and singleton
  lists, dates and nonnumeric values keep their existing intrinsic
  conversions. Do not change live-null or parameter-null deferral.
- Evaluate every supplied expression exactly once left to right per call,
  before gating, including ignored extras and expressions after Undefined.
  Extras retain reads, dependencies, effects and strict errors without
  numeric conversion.
- Standing assignments, independent class rules, wrappers, receivers,
  call frames, scopes, subscriptions, deletion/recovery, savepoints and
  transaction rollback use the unchanged runtime machinery.
- The fixed base and intrinsic conversion consult neither Math constants
  nor shadowable Number. Local/state Math bindings and ordinary `.Math`
  members retain ordinary lookup.
- Native `Math.exp10` value reads remain Undefined, not a stored callable.
  No sibling helper, constant, accepted spelling, public Rust type/API,
  dependency, version or resource limit changes.
- The root specification's
  [reactive base ten contract](../nucleoid.spec.md#reactive-base-ten-exponentiation)
  and appended case `Nucleoid keeps base ten exponentiation reactive` trace
  these claims. The case keeps its twelve ordered assertions and explicit
  return `1000`.

## Errors

- Add no arity, coercion, numeric or range error. Nonnumeric conversion
  yields numeric NaN through the accepted conversion.
- Strict unknown argument reads retain
  `ReferenceError("<name> is not defined")`, including extras and expressions
  after Undefined. Existing evaluation order determines which error occurs.
- Unknown native helpers retain
  `TypeError("Math.<name> is not a function")`, and `Math.random()` retains
  `TypeError("Math.random is not supported")`, after the unchanged gate.
- Ordinary numeric `Math = 7` retains
  `TypeError("number.exp10 is not a function")`. Other ordinary receiver
  errors, positions, caught values and rollback remain unchanged.
- Only the previously unsupported unshadowed static call's
  `TypeError("Math.exp10 is not a function")` becomes the documented numeric
  result when no supplied argument is Undefined.
