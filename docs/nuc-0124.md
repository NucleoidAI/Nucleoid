## Abstract

- Lists and class instance lists gain the read-only query `quantile`.
  `RECEIVER.quantile(q)` returns the `q` quantile of the receiver's items,
  for a number `q` from `0` to `1`, and `RECEIVER.quantile(q, selector)`
  that of `selector(item)` for every item: `0` gives the smallest value,
  `0.5` the median and `1` the largest.
- It interpolates linearly between the two closest ranks of the sorted
  values, the default method of NumPy's `quantile` and pandas' `quantile`,
  R's type 7 and Excel's `PERCENTILE.INC`. The rank is `h = (n - 1) * q` for
  `n` values: a whole rank gives its value, two equal neighbours give their
  value, and any other rank between two values gives
  `(1 - t) * s[lo] + t * s[lo + 1]` for the sorted values `s`, the whole part
  `lo` and the fraction `t` of the rank, in 64-bit floating point, as R
  computes type 7. For a list of finite numbers, `xs.quantile(q)` is
  therefore exactly what the accepted spelling
  `(1 - h % 1) * s[h] + h % 1 * s[Math.ceil(h)]` gives with
  `s = xs.sortBy(v -> v)` and `h = (s.length - 1) * q` wherever the rank is
  whole or its two neighbours differ, apart from the sign of a zero.
- A single value gives that value, and an empty receiver gives NaN. A value
  that converts to NaN makes the result NaN, and an undefined value makes it
  undefined, which a declaration stores as `null`.
- The rank is required: anything but a number from `0` to `1` raises
  `TypeError("quantile expects a number from 0 to 1")`, and a supplied
  selector that is not a function raises
  `TypeError("quantile expects a function")`, both even on an empty
  receiver.
- It follows [NUC 84](nuc-0084.md)'s `median`, beside
  [NUC 68](nuc-0068.md)'s `sum`, [NUC 80](nuc-0080.md)'s `average` and
  [NUC 123](nuc-0123.md)'s `variance`: the same receivers, numeric
  conversion, selector rules, NaN and undefined results, and liveness
  under [NUC 61](nuc-0061.md)'s shared query rules. NUC 84 left quantiles
  out, and `xs.median(0.9)` stays an error.
- At the accepted revision these calls are run-time errors,
  `TypeError("<receiver>.quantile is not a function")`. Only inputs that
  were errors change. No syntax, keyword, token or error type is added,
  and bindings, properties and methods named `quantile` keep their
  accepted results.
- The authoritative contract is
  [List and population quantiles](../nucleoid.spec.md#list-and-population-quantiles).

## Motivation

- World models describe their populations by more than a center. A model
  that asks how high the top tenth of its readings reach, where the
  quartiles of its prices fall, or which deliveries are slower than nine
  in ten, needs a quantile. Lists and class populations already have their
  sums, extremes, averages, medians, modes, variances and standard
  deviations, but not their quantiles.
- Written out, a quantile sorts a copy of the values, computes the rank
  and interpolates between two indexed values: `s = xs.sortBy(x -> x)`,
  `h = (s.length - 1) * q`, and then `s[Math.floor(h)]` and
  `s[Math.ceil(h)]` weighed by `h - Math.floor(h)`. That repeats the
  receiver, is easy to get one rank wrong, and must not sort the receiver
  itself: `xs.sort()` sorts a list in place, by text without a comparator.
  `quantile(q)` names the statistic once, as `median()` does.
- The accepted spellings are long. `p90 = times.quantile(0.9)` is 8 lexer
  tokens; the accepted spelling written inline,
  `p90 = (1 - (times.length - 1) * 0.9 % 1) * times.sortBy(v -> v)[(times.length - 1) * 0.9] + (times.length - 1) * 0.9 % 1 * times.sortBy(v -> v)[Math.ceil((times.length - 1) * 0.9)]`,
  is 74, and 51 with helper lines for the sorted copy and the rank. Over a
  population, `slow = Trip.quantile(0.9, trip -> trip.minutes)` is 14 tokens
  where the spelling with helper lines is 57. In a class-level rule over a
  filtered population,
  `$Room.high = Sensor.filter(sensor -> sensor.room == $Room).quantile(0.9, sensor -> sensor.temp)`
  is 27 tokens, while the inline spelling states the filter five times in
  154.
- NumPy's `quantile` and `percentile`, pandas' `Series.quantile`, R's
  `quantile`, Excel's `PERCENTILE.INC` and `QUARTILE.INC` and SQL's
  `PERCENTILE_CONT` name the operation. JavaScript has none, and LLM-written
  code such as `times.quantile(0.9)` raises
  `TypeError("times.quantile is not a function")` at the accepted revision.

## Rationale

- **Category and mode.** The caller drew Utility enhancement with one
  tool-backed uniform draw over the five categories that NUC 1's registry
  marks eligible for automatic selection: index 2, with probability 1/5, at
  08:23:26 on 19-Nov-2026, and no redraw. This is a continuous cycle, so the
  token non-regression gate is required. Runtime applicability does not
  apply to this category.
- **Selection.** Within the category the caller chose the next member of the
  list and population aggregate family, after NUC 68's sums, 69's extremes,
  71's distinct values, 73's counts, 75's modes, 77's extreme items, 80's
  averages, 84's medians, 114's products and 123's variances and standard
  deviations. NUC 84 named quantiles and percentiles among what it did not
  add and kept `xs.median(0.9)` an error, and no NUC proposes a quantile.
- **Optional evidence.** No hint was supplied. Advisory usefulness is
  unscored, not zero, because no rubric was frozen. Strategy learning is
  `not_configured`, so this revision is unattributed, with no policy,
  selection receipt, trial or reward.
- **One more query.** `quantile` joins `Runtime::list_query` beside the
  aggregates, so lists however they are reached and class instance lists
  accept it through the route and the receiver, argument and liveness rules
  they already share. Rejected: a list-only method, which would leave
  `Reading.quantile(...)` raising where `Reading.median(...)` runs.
- **Linear interpolation between the closest ranks.** With `n` sorted values
  `s`, the rank of `q` is `h = (n - 1) * q`, so `0` is the first value and `1`
  the last, and every rank between two values weighs them by how close it
  lies to each. This is Hyndman and Fan's type 7, the default of NumPy, pandas
  and R and the method of Excel's `PERCENTILE.INC` and SQL's
  `PERCENTILE_CONT`. Its ranks spread the whole range from `0` to `1` evenly
  over the sorted values, without clamping, so `0` and `1` are the extremes
  and `0.5` is the median. Rejected: the other types, among them the nearest
  rank, the inverse of the empirical distribution and Excel's exclusive
  `PERCENTILE.EXC`, and NumPy's `method` choices, `lower`, `higher`,
  `nearest` and `midpoint`; one method keeps the query to one argument for
  the rank, and a method argument can be proposed later without changing
  this one.
- **The weights.** A rank between two different values gives
  `(1 - t) * s[lo] + t * s[lo + 1]` for its whole part `lo` and fraction `t`,
  in 64-bit floating point, as R computes it. Wherever the rank is whole or
  its two neighbours differ, this is exactly the accepted spelling
  `(1 - h % 1) * s[h] + h % 1 * s[Math.ceil(h)]` for finite numbers, so a
  model can check a quantile with accepted Nucleoid. Rejected:
  `s[lo] + t * (s[lo + 1] - s[lo])`, the computation of `Math.lerp`, and
  NumPy's, which uses it below the midpoint and `b - (b - a) * (1 - t)` from
  it. They round differently in the last bit for some values: for the north
  route of the examples case, after its 50-minute trip, the 0.9 quantile is
  `41` and `Math.lerp` gives `41.00000000000001`.
- **Equal neighbours give their value.** When the two neighbours are equal,
  `s[lo] == s[lo + 1]`, the result is their value, as R's type 7 computation
  gives, since R weighs the neighbours only where `x[hi] != x[lo]`. A
  quantile therefore never lands outside two equal neighbours:
  `[3, 3].quantile(0.01)` is `3`, where weighing them gives
  `(1 - 0.01) * 3 + 0.01 * 3`, `2.9999999999999996`, as the accepted spelling
  does. Rejected: weighing equal neighbours too, which lands one unit in the
  last place off for some ranks.
- **Signed zeros.** Equality is `==`, so `-0` and `0` are equal neighbours,
  and the result takes the sign of the lower neighbour in the sorted order,
  which keeps the receiver order of equal values: `[-0, 0].quantile(0.5)` is
  `-0` and `[0, -0].quantile(0.5)` is `0`. The accepted spelling gives `0` for
  both, and at the rank `-0` it also turns a `-0` value into `0`, because its
  weight `-0 % 1` is `-0` and `-0 * -0` is `0`.
- **A whole rank gives its value.** When `t` is `0` the result is `s[lo]`
  itself, with no arithmetic, so neither the value at the rank nor its
  neighbour passes through `0 * Infinity`, which is NaN: `[1, x].quantile(0)`
  is `1` and `[1, x].quantile(1)` is `x` for any number `x`, `Infinity`
  included, and `-0` keeps its sign. The accepted spelling computes
  `1 * s[h] + 0 * s[Math.ceil(h)]` there, so the two differ only for an
  infinite value at a whole rank: for `s = [1, Infinity]` it gives `1` at `0`
  and NaN at `1`, where the query gives `Infinity`.
- **A single value gives that value, an empty receiver NaN.** One value has
  rank `0` for every `q`. An empty receiver has no rank, and NaN is what
  `median` and `average` give for it, so the result stays a number, a
  declaration over a population that starts empty has a value rather than
  failing, and `Number.isNaN` tells it apart from `null`. The accepted
  spelling reads an element that an empty list does not have and gives
  undefined, which a declaration stores as `null`. Rejected: raising an
  error, as NumPy's `quantile` of an empty array does, which would fail a
  live declaration over an empty class, and `null`.
- **NaN and infinities.** A value that converts to NaN makes the result NaN,
  as it makes the median NaN: a NaN has no place in the order. Rejected:
  skipping NaN values, as pandas does, which would silently change which
  values the quantile is over. Infinities take their places in the order, and
  the interpolation follows 64-bit floating point, so `-Infinity` and
  `Infinity` at the two closest ranks give NaN, and `Infinity` beside a finite
  value at a rank between them gives `Infinity`.
- **Undefined stays unknown.** An undefined item or selector result makes the
  result undefined, which a declaration stores as `null`, as it makes `sum`,
  `average` and `median` undefined, so a declaration waits for every value.
  Every item is still visited, so every item's reads are dependencies. An
  undefined value wins over a NaN value, whatever their order, as in
  `median`.
- **The conversion of `sum`.** Each value is converted once with the numeric
  conversion of `-`, `*`, the Math helpers, `sum`, `average` and `median`:
  `null`, `false`, empty strings and empty lists are `0`, `true` is `1`,
  numeric strings and one-item lists are their number, a date is its time in
  milliseconds, and objects, other strings and longer lists are NaN. The
  values are ordered as numbers, with `median`'s stable sort, so
  `["10", "9"].quantile(0)` is `9`, where `sortBy(v -> v)` orders the same
  strings as text. `sortBy(v -> v)` gives undefined for a list that holds
  NaN, an object or a list of more than one item, so there the accepted
  spelling is undefined where the query is NaN.
- **No artificial null read.** The query reads items, not bindings, so a
  `null` item counts `0` without settling a declaration to `null`, as in
  `sum` and `median`. The accepted spelling reads each item through its
  callback's parameter, so a declaration that sorts a list holding `null`
  with `sortBy(v -> v)` stores `null`. A selector's own reads follow the
  existing rules.
- **The rank is required and is a number from `0` to `1`.** The query has no
  meaning without a rank, so a missing rank raises. Anything but a number
  from `0` to `1`, both included, raises
  `TypeError("quantile expects a number from 0 to 1")`, even on an empty
  receiver: NaN, a number outside the range, a numeric string, a boolean,
  `null`, undefined, a list, an object or a function. `-0` is a number in
  the range and gives the smallest value. Rejected: a default rank, which
  would make `xs.quantile()` a second spelling of the median; converting the
  rank, which would read `"0.9"` and `true` as ranks; clamping a rank outside
  the range, which would hide a percentile written as `90`; and a list of
  ranks, as NumPy accepts, which would return a list where every other
  aggregate returns a number.
- **The rank comes first.** `RECEIVER.quantile(q, selector)` puts the rank
  where NumPy's `quantile(a, q)` and pandas' `quantile(q)` put it, and the
  selector second, where the other aggregates take theirs first. The rank is
  checked before the selector, so `xs.quantile(2, "total")` reports the rank.
  Rejected: the selector first, as in `xs.quantile(f, 0.9)`, which would make
  the one-argument call ambiguous between a rank and a selector.
- **The selector is called like `median`'s.** It runs once per item, in
  order, with only the item; further parameters stay `null`. A supplied
  second argument that is not a function, including `null`, raises
  `TypeError("quantile expects a function")` after the arguments are
  evaluated, even on an empty receiver, as `median` raises
  `TypeError("median expects a function")`. Rejected: property-name selectors
  such as `Order.quantile(0.5, "total")`.
- **Extra arguments** are evaluated once, left to right, and ignored, as
  every list query does.
- **Instance lists.** On a class name, `Name.quantile(...)` is the population
  query even when the class declares an instance method `quantile`, as NUC 84
  made `Name.median(...)`. For a class `Team` that declares
  `def quantile(q): return q * 10`, `Team.quantile(0.5)` raised
  `TypeError("Team.quantile is not a function")` at the accepted revision,
  while its instance `red` answers `red.quantile(0.5)` with `5`, as it still
  does.
- **The method call only.** `quantile` is not added to
  [NUC 75](nuc-0075.md)'s noun queries, so `quantile of xs` keeps raising
  `SyntaxError("Unexpected keyword 'of'")`. Rejected: a global `quantile(...)`
  function, `Math.quantile`, and the names `percentile`, with ranks from `0`
  to `100`, and `quantiles`, which returns cut points in Python's
  `statistics` module. They would add names beside the list query, while
  `quantile` is a common name of user functions and bindings, which keep
  their meaning.
- **The receiver is never written.** Unlike `sort`, which writes a writable
  receiver back, the query sorts a private list of the converted numbers.
- **Bounded cost.** The receiver and the arguments are evaluated once per
  call and the selector once per item. Each value is converted once, and one
  list of numbers is sorted, in O(n log n) time and O(n) extra space, without
  recursion. The accepted spelling sorts its copy once per use of it.
- **Rendered as written.** The call keeps its ordinary rendering:
  `p90 = times.quantile(0.9)` explains as `p90 = times.quantile(0.9)`, a
  lambda selector renders as `function()`, and a query and its accepted
  spelling are different statements and graph keys.
- **The relation to `median`.** For an odd count the `0.5` quantile is the
  middle value, as the median is. For an even count it is
  `0.5 * a + 0.5 * b` of the two middle values, or `a` when they are equal,
  where `median` computes `(a + b) / 2`. Halving is exact apart from
  overflow and subnormal values, and equal middle values give `a`, which is
  `(a + a) / 2` unless that sum overflows. So the two agree unless the sum
  `a + b` overflows, as for `[1e308, 1.5e308]` and `[1e308, 1e308]`, whose
  medians are `Infinity` and whose `0.5` quantiles are `1.25e308` and
  `1e308`; unless halving rounds a subnormal value, as for
  `[5e-324, 1e-323]`, whose median is `1e-323` and whose `0.5` quantile is
  `5e-324`; and unless the middle values are `-0` and `0` in that order, where
  the median is `0` and the quantile `-0`. `median` keeps every result it
  has.
- **Pre-existing defects stay.** A callback in a function body cannot read
  the function's parameters, at both revisions: with
  `def scaled(xs, k) => xs.quantile(0.5, x -> x * k)`, `scaled([1, 3], 3)`
  raised `TypeError("xs.quantile is not a function")` and raises
  `ReferenceError("k is not defined")` under this NUC, as the same body with
  `median` or `map` does at both revisions. This proposal neither fixes nor
  pins the defect, and its cases stay clear of it.
- **Requires.** [NUC 61](nuc-0061.md), whose shared list query, population
  receivers, ranges, `list()`, argument order and null-receiver route the
  query joins; [NUC 68](nuc-0068.md), whose numeric conversion, undefined rule
  and item-only selector calls it uses; and [NUC 84](nuc-0084.md), whose
  stable numeric sort of a private list, selector validation, collected
  values and undefined-before-NaN rule it follows. Those already require
  everything else these rules rest on.
- **Not added.** Other interpolation methods and a method argument, lists of
  ranks, percentiles from `0` to `100`, `quantiles(n)` cut points, weighted
  and grouped quantiles, an inverse quantile or percentile rank, a default
  rank, noun forms such as `quantile of xs`, a global function,
  `Math.quantile`, aliases, property-name selectors, NaN-skipping quantiles,
  and any change to what `median` or the other queries return.

### Counterparts

- Every new case is compared with the most compact accepted-syntax program
  found that reaches the same canonical assertions in the same order and the
  same expected return. Each differs from its case only where a query is
  written, plus a helper line or a helper function where that makes the
  whole program shorter; every other line is the case's own. They are
  recorded in `extra-baselines.json`, which the accepted runtime executed
  with every assertion run.
- Every query reads a receiver, a rank or a selector input that changes
  after the query is declared: pushed and shifted items, new instances, a
  changed property, a changed rank, a changed variable that a selector reads,
  and a rolled-back push and instance. No assertion calls a query, so both
  sides keep the same canonical assertions.
- A counterpart may pass only because of the case's values, such as a
  neighbour read `s[h + 1]` that breaks at a whole rank the case never
  reaches, or a text sort that orders the case's values correctly. That makes
  the comparison stricter, so the search admitted such spellings whenever
  they pass every asserted value and expected return of the case. The
  recorded counterparts use five of them, each fair for its case and none
  equivalent in general:
  - **The in-place `sort()`** of the ranks, reference and examples
    counterparts orders by text, which orders these values as numbers only
    because each list's values have the same number of digits: the scores
    `60` to `95`, the rain `15` to `30`, the laps `4` to `9` and the trip
    times `22` to `52`. It writes the sorted list back into `scores`, `rain`
    and each route's `times`, whose order no assertion reads, and the south
    route's `pop()` then removes `52`, its largest and, in the original order
    too, its last time. In general `[10, 9].sort()` keeps `[10, 9]`, and the
    receiver changes order.
  - **The rank `L * q - q`** of six counterparts rounds twice where
    `(L - 1) * q` rounds once, so its rank can differ in the last bit; for
    the asserted values of these cases the results round alike. In the lists
    case `6 * 0.2 - 0.2` is `1.0000000000000002` rather than the whole rank
    `1`, which is why that counterpart writes `(s.length - 1) * 0.2`.
  - **The neighbour `s[h + 1]`** of every counterpart reads past the end at a
    whole rank on the last value, as at the rank `1`, and gives undefined;
    no case reaches a whole rank on its last value, and elsewhere `h + 1` is
    `Math.ceil(h)` or the weight is `0`.
  - **`Math.lerp(a, b, t)`** of six counterparts computes
    `a + (b - a) * t`, which rounds differently from `(1 - t) * a + t * b`
    for some values, as the examples case shows; for the asserted values of
    the other six cases the two round alike.
  - **`qt(...) + bonus`** of the ranks counterpart adds the shift after
    interpolating, which equals interpolating the shifted values when both
    are exact, as for the case's halves and quarters, but can round
    differently in general, and calls no selector.
- The rollback counterpart sorts with `levels.sortBy(checked)` and
  `Tank.map(.level).sortBy(checked)`, which validate and sort at once
  because `checked` returns its argument, as its definition guarantees.
- The equivalence claims, the Rust reference comparison and the
  differential use the bit-exact spelling and the amended rule, never these
  case-specific spellings.
- The search measured these spellings at every query site:
  - the sorted copy: `R.sortBy(v -> v)`, the section `R.sortBy(* 1)`,
    `R.sort()` in place, `R[:].sort()`, `R[:].sort((a, b) -> a - b)` and the
    comprehension `[x for x in R].sort()`; for a selector, `R.map(f)` and the
    property selector `R.map(.p)` with each sort, `[x.p for x in R].sort()`,
    the items sorted by the selector, `R.sortBy(.p)` and `R.sortBy(f)`, read
    with `.p`, and, where the case defines a named function that returns its
    argument, `R.sortBy(checked)` and `R.map(.p).sortBy(checked)`, which
    validate and sort at once;
  - the rank: `(L - 1) * q` and `L * q - q`, with `L` the length of the
    receiver or of the sorted copy, written inline or held in a helper line;
  - the weights and neighbours: `h % 1` and `h - Math.floor(h)`, the elements
    at `h`, at `h + 1` and at `Math.ceil(h)`, combined as
    `(1 - t) * a + t * b`, `a + t * (b - a)` and `Math.lerp(a, b, t)`, and,
    for whole ranks only, `s[h]` alone and the mean of `s[h : h + 2]`;
  - inline spellings, helper lines that hold the sorted copy, the rank or
    both, an inline function call `((s, h) -> ...)(sorted, rank)`, helper
    functions of the receiver and the rank (`qt(r, q)`), of a sorted list and
    the rank (`qs(s, q)` and `qh(s, h)`), of the rank over the receiver
    (`q -> ...`) and of the rank index over a sorted helper line
    (`h -> ...`), in the shortest headers measured, `def f a b =>` and
    `f = a ->`;
  - for the shifted selector `score -> score + bonus`, the shift applied
    after the quantile of the unshifted values. `+` has no section, so
    `scores.map(+ bonus)` raises `TypeError("map expects a function")`.
- The search ran every alternative at every site with the other sites at the
  bit-exact inline spelling, 40,620 programs, of which 23,944 pass. It then
  counted every combination of passing alternatives across the sites of a
  case, sharing helper lines and helper functions where both sites use the
  same one, about 23.8 million combinations, and ran all 410 within four
  tokens of the smallest; every count it predicted matched the lexer, and all
  410 pass. The recorded counterpart is the smallest passing program of each
  case.
- Four limits of the accepted revision shape the helpers. Parameter defaults
  must be scalar literals, so `(r, q, h = (r.length - 1) * q) -> ...` raises
  `SyntaxError("Expected a scalar literal parameter default")`. A receiver
  read inside a call's parentheses reads as a property selector, so
  `Math.lerp(.s[.h], ...)` does not parse and `qt(.times, 0.9)` passes a
  function. A list cannot be assigned through an index, so `xs[1] = 40` and
  `south.times[3] = 34` raise `SyntaxError("Cannot assign to ...")`. And a
  sort inside a helper sorts only the helper's parameter, which is why
  `r.sort()` there leaves the caller's list in its order.

## Specification

- The normative contract is
  [List and population quantiles](../nucleoid.spec.md#list-and-population-quantiles).

### Calls

- `RECEIVER.quantile(RANK)`, `RECEIVER.quantile(RANK, SELECTOR)` and
  `RECEIVER.quantile(RANK, SELECTOR, ...)` are list queries when `RECEIVER`
  evaluates to a list, however it is reached: a variable, a property, an
  index, a slice, a call result such as `filter(...)`, `map(...)`,
  `sortBy(...)`, `slice(...)` or `concat(...)`, a literal, a `.value`
  snapshot or a selected version. The receiver may also be a class's
  instance list, named by the class, by a variable that holds the class or by
  `$Name`, in population order; a range such as `Reading[-3:]` and
  `Name.list()` are lists.
- The receiver is read once, before the arguments. Every supplied argument
  is then evaluated once, left to right; the first is the rank, the second
  the selector, and the others are ignored.
- A `null` or undefined receiver keeps the accepted method route: the
  arguments are not evaluated and the call is undefined, so a declaration
  holding it stores `null`.
- On a class name the call is the population query even when the class
  declares an instance method `quantile`; `instance.quantile(...)` keeps
  calling the method.

### Quantiles

- The values are the receiver's items, or `selector(item)` for every item,
  each converted to a number once, and sorted ascending in a private list
  `s` by a stable sort, so equal values keep their receiver order.
- With `n` values, the rank is `h = (n - 1) * q`, its whole part is `lo` and
  its fraction is `t = h - lo`, all in 64-bit floating point. When `t` is `0`
  the result is `s[lo]` itself, and so it is when the two neighbours are
  equal, `s[lo] == s[lo + 1]`; otherwise it is
  `(1 - t) * s[lo] + t * s[lo + 1]`, rounded as each operation rounds. This
  is R's type 7 computation.
- For a list of finite numbers the result is exactly what
  `(1 - h % 1) * s[h] + h % 1 * s[Math.ceil(h)]` gives with
  `s = xs.sortBy(v -> v)` and `h = (s.length - 1) * q`, bit for bit,
  wherever the rank is whole or its two neighbours differ, except that the
  spelling turns a `-0` at the rank `-0` into `0`. With a selector `f` that
  has no side effects and gives finite numbers, it is what the same spelling
  gives with `s = xs.map(f).sortBy(v -> v)`. Where the two differ, for equal
  neighbours, for signed zeros, for an infinite value at a whole rank, for
  empty receivers, NaN and `null` items in a declaration, for strings and
  for the number of selector calls, [Rationale](#rationale) says so.

```
waits = [12, 3, 45, 7, 30, 18]
slow = waits.quantile(0.9)
quick = waits.quantile(0.2)
assert([slow, quick, waits], [37.5, 7, [12, 3, 45, 7, 30, 18]])
waits.push(50)
assert([slow, quick], [47, 8])
waits.shift()
assert([slow, quick], [47.5, 7])
```

- With six values the rank of `0.9` is `4.5`, halfway between `30` and `45`,
  and the rank of `0.2` is `1`, a whole rank, so `quick` is the second
  smallest value, `7`. The push gives seven values, with ranks of about `5.4`
  and `1.2`, and the shift six again. `waits` keeps its order.

### Ranks

- The rank is the first argument and is required. It must be a number from
  `0` to `1`, both included; `-0` is such a number and gives the smallest
  value.
- Anything else raises `TypeError("quantile expects a number from 0 to 1")`,
  even on an empty receiver, after the arguments are evaluated and before
  the selector is checked: a missing rank, NaN, a number below `0` or above
  `1`, `Infinity`, a numeric string, a boolean, `null`, undefined, a list, an
  object or a function.
- A rank held in a variable is read like any argument, so a declaration
  follows it, and a change that makes it invalid raises the rank error in the
  re-evaluation and rolls back.

```
scores = [70, 85, 90, 60, 75, 80]
rank = 0.9
top = scores.quantile(rank)
bonus = 5
curved = scores.quantile(0.75, score -> score + bonus)
assert([top, curved], [87.5, 88.75])
rank = 0.2
assert([top, curved], [70, 88.75])
bonus = 10
assert([top, curved], [70, 93.75])
scores.push(95)
assert([top, curved], [71, 97.5])
```

- `top` follows its rank, and `curved`, the upper quartile of the curved
  scores, follows `bonus`, which its selector reads; both follow the push.

### Relation to median

- With an odd number of values, `xs.quantile(0.5)` is the middle value, the
  value `xs.median()` gives.
- With an even number, `xs.quantile(0.5)` is `0.5 * a + 0.5 * b` of the two
  middle values `a` and `b`, or `a` when they are equal, and `xs.median()` is
  `(a + b) / 2`. They agree unless `a + b` overflows, halving rounds a
  subnormal value, or the middle values are `-0` and `0` in that order:
  `[1e308, 1.5e308].median()` and `[1e308, 1e308].median()` are `Infinity`
  where the `0.5` quantiles are `1.25e308` and `1e308`,
  `[5e-324, 1e-323].median()` is `1e-323` where the quantile is `5e-324`, and
  `[-0, 0].median()` is `0` where the quantile is `-0`.
  `[0.1, 0.7]` gives `0.39999999999999997` either way, and
  `[5e-324, 5e-324]` and `[0, -0]` give the same value and sign either way.

### Conversion and special values

- Each value, an item or a selector result, is converted with the numeric
  conversion of `sum`: a number is itself; `null`, `false`, an empty or
  whitespace-only string and an empty list are `0`; `true` is `1`; a numeric
  string, after trimming, is its number; a one-item list is its item's
  number; a date is its time in milliseconds; objects, instances, classes,
  functions, regular expressions, other strings and longer lists are NaN.
- A single value gives that value for every rank. An empty receiver gives
  NaN. A NaN value makes the result NaN.
- Infinities take their places in the order. A whole rank returns the value
  at it unchanged. Between two ranks the interpolation follows 64-bit
  floating point: `Infinity` beside a finite value gives `Infinity`, and
  `-Infinity` beside `Infinity` gives NaN.
- An undefined value makes the result undefined, which a declaration stores
  as `null`; every item is still visited, and an undefined value wins over
  NaN.
- The query reads items, not bindings: a `null` item counts `0` without
  settling a declaration to `null`. Reads inside a selector follow the
  existing rules, so a selector that reads a `null` binding or property
  settles a declaration to `null`, as it would in `map`, `sum` or `median`.

### Selectors

- The selector is the optional second argument. It is called once for every
  item, in order, with the item as its only argument; further parameters are
  `null`. The call order and the argument are those of `map`, `sum`,
  `average` and `median`.
- A supplied second argument that is not a function, including `null`, raises
  `TypeError("quantile expects a function")`, even on an empty receiver,
  after the rank is checked.
- Every supplied argument, including unused extras, is evaluated once, left
  to right, after the receiver and before the first selector call.

```
class Parcel(weight):
    this.weight = weight
Parcel(4)
Parcel(9)
heavy = Parcel(15)
Parcel(6)
Parcel(2)
lower = Parcel.quantile(0.25, parcel -> parcel.weight)
upper = Parcel.quantile(0.75, parcel -> parcel.weight)
assert([lower, upper], [4, 9])
Parcel(11)
assert([lower, upper], [4.5, 10.5])
heavy.weight = 1
assert([lower, upper], [2.5, 8.25])
```

- The quartiles of five weights fall on whole ranks; a sixth parcel moves
  both between two weights, and a lighter heavy parcel changes the order.

### Liveness and class-level rules

- The query never writes its receiver. A declaration that uses it depends on
  the list or the population, on its argument expressions, the rank
  included, and on whatever the selector reads for every item, as for `sum`
  and `median`.
- Pushing, popping, shifting or replacing a list, creating or deleting an
  instance, and changing a property, a rank or a variable that a selector
  reads re-evaluate the declaration.
- In a class-level rule, each instance evaluates its own query, and `$Class`
  inside a filter or a selector is the instance the rule is evaluated for.

```
class Route(name, times):
    this.name = name
    this.times = times
$Route.slow = $Route.times.quantile(0.9)
$Route.late = $Route.slow > 40
north = Route("north", [22, 25, 31, 28, 35, 24])
south = Route("south", [30, 41, 38, 33, 36, 52])
assert([north.late, south.slow, south.late], [false, 46.5, true])
north.times.push(50)
south.times.pop()
[north.slow, north.late, south.slow, south.late]
```

- This is the `docs/examples.md` case, which returns
  `[41, true, 39.8, false]`: every route keeps the 0.9 quantile of its own
  trip times, and a rule derived from it follows every trip.

### Transactions

- Selector errors and invalid ranks propagate through the existing
  transaction, so a failed standing re-evaluation rolls back the change that
  triggered it, including a list write or a new instance, and a rolled-back
  transaction restores the results of its declarations. `suppose` sees the
  hypothetical quantile and restores the accepted one when it ends.

```
def checked(level):
    if level < 0:
        throw "NEGATIVE_LEVEL"
    return level
levels = [3, 5, 10, 8]
high = levels.quantile(0.75, checked)
failure = ""
try:
    levels.push(-1)
catch error:
    failure = error
assert([failure, levels, high], ["NEGATIVE_LEVEL", [3, 5, 10, 8], 8.5])
try:
    levels.push(6)
    assert(high, 8)
    throw "UNDO"
catch error:
    assert(error, "UNDO")
assert([levels, high], [[3, 5, 10, 8], 8.5])
class Tank(level): this.level = level
Tank(4)
Tank(8)
Tank(6)
low = Tank.quantile(0.25, tank -> checked(tank.level))
failure = ""
try:
    Tank(-2)
catch error:
    failure = error
assert([failure, Tank.length, low], ["NEGATIVE_LEVEL", 3, 5])
Tank(12)
low
```

- This returns `5.5`: the failed push, the undone push and the failed new
  tank leave the levels, the tanks and both results as they were.

### Rendering and graph keys

- Statements, `why`, `affects` and graph and block keys show the call as
  written, with function arguments rendered as `function()`: the rule that
  `why p90` reports is `p90 = times.quantile(0.9)`, and `why` lists the
  receiver in the declaration's `from` list. A query and its accepted
  spelling are different statements and keys.
- Errors that quote an expression quote the call: `xs.quantile(0.5)(1)`
  raises `TypeError("xs.quantile(0.5) is not a function")`, and a quantifier
  over `xs.quantile(0.5)` raises
  `TypeError("xs.quantile(0.5) is not a collection")`, as they do for
  `median`.
