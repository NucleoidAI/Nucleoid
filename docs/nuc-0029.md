## Abstract

- A named arrow definition may optionally omit parentheses around two or more ordinary identifier parameters with the existing optional ordinary-identifier annotations.
- `def add left: int, right: int => left + right` is exactly `def add(left: int, right: int) => left + right`, including methods and `init`.
- Mixed headers such as `def scaled left: number, right, factor: number => (left + right) * factor` preserve the same names, annotation metadata, order and behavior as their parenthesized counterparts.
- At least one annotation distinguishes this addition from accepted NUC27's entirely untyped lists; preserve every accepted spelling and introduce no runtime feature.

## Motivation

- Multi-input named arrows can use existing annotations without two parameter delimiter tokens.
- Keep the optional syntax consistent with accepted NUC20's single typed arrow and NUC27's untyped multiple-parameter arrow.
- Prepare exactly the caller-selected syntax improvement, retaining its original category draw and depending only on already accepted NUCs.

## Rationale

- Recognize only a complete immediate header; malformed prefixes must not be partially consumed or acquire new diagnostics.
- Reuse accepted NUC28's complete-list lookahead and the existing parameter parser rather than duplicate parameter grammar or change public types.
- Track whether any annotation occurred during the shared scan so only entirely untyped lists may end in NUC28's block colon.
- Keep single typed/untyped arrow and block guards unchanged, including the distinction between a suite colon and annotation metadata.
- Exclude typed/mixed multiple bare blocks, logical header breaks, trailing bare commas, defaults, destructuring, rest, return annotations and richer type grammar.
- Preserve uncapped flat parameter lists without applying expression operator-chain bounds to parameters.
- Preserve representative parenthesized alternatives in the current reference and tests; qualify current exclusions without revising earlier proposal documents.

## Specification

### Grammar and lowering

- The authoritative [bare typed multiple-parameter named arrows](../nucleoid.spec.md#bare-typed-multiple-parameter-named-arrows) section governs this isolated candidate.
- Parse `def` and its required ordinary definition name exactly as before.
- Recognize `Identifier (Colon Identifier)? (Comma Identifier (Colon Identifier)?)+ Arrow` without consuming tokens, allocating names or skipping any logical `Newline`, `Semicolon`, `Indent`, `Dedent` or comment-induced break.
- Require at least two ordinary parameter identifiers; each comma immediately needs another parameter, and the final arrow immediately follows the complete list.
- Accept only the existing `Colon Identifier` annotation metadata; arbitrary undeclared ordinary annotation names remain legal without lookup, graph dependency or runtime enforcement.
- The newly added forms have at least one annotation in any position; entirely untyped lists remain NUC27 behavior.
- Once the complete lookahead succeeds, reuse `parameter()` to preserve ordered `Parameter { name, type_name }` values, including every `Some(annotation)` and `None`.
- Reuse the existing named arrow path to produce the same named `FunctionBody::Block` containing `Stmt::Return(Some(expression))`, with identical complete AST and canonical rendering.
- The shared scan may return a block colon only for an entirely untyped list, leaving NUC28's real-indent guard and suite parser exact; annotations never authorize a typed/mixed multiple block.
- Failed lookahead consumes nothing before the unchanged single guards or parenthesized parameter parser.

### Behavior and compatibility

- Methods and `init` share the same parser and retain receiver identity, `this`/`self`, initializer adoption and explicit/bare `super`.
- Expression precedence, assignment returns, objects, lists, templates and returned anonymous functions retain their existing grammar and noncapturing behavior.
- Braces after a named arrow remain object expressions, not statement blocks; a returned anonymous function retains its own body grammar.
- No separator is skipped before the first expression; an expression opening a parenthesis on that logical line may continue over physical lines.
- Missing/null/extra/string arguments, parameter shadowing and local assignments retain the accepted bindings, without type checking.
- A null callable parameter retains deferred `null`; a non-callable parameter still shadows an outer function and raises the existing error.
- Reactive arguments and body inputs, live callable aliases, `.value` definition snapshots, redefinition, graph keys/dependencies, reasoning, transactions, caught values and rollback are unchanged.
- Preserve parenthesized typed/untyped/mixed, empty/multiple, trailing-comma/multiline and arrow/indented/inline/braced alternatives.
- Preserve NUC18/20 single typed/untyped arrows, NUC19/24 single typed/untyped blocks and NUC27/28 entirely untyped multiple arrows/indented blocks, including no implicit block return.
- Calls, anonymous functions, class parameters, ordinary identifier references and keyword meanings retain their grammar.
- Add no typed/mixed multiple bare indented/inline/braced blocks, trailing bare commas, defaults, destructuring, rest, return annotations, multiline/broken bare headers or richer annotation syntax.
- Introduce no lexer, public AST, runtime, generator, API, dependency, MSRV, project-version or resource-bound change; inherited noncapturing/scope/propagation failures are not repaired.
- Flat all-typed and mixed lists remain uncapped, including lists through 1,024 parameters; the 128-link expression chain bound is not a parameter-count cap.
- Append only the eight caller-supplied pre-executed counterparts: five spec entries and one each for executable reference, README and examples.
- Preserve the 467 historical identities and order, every ordered canonical assertion, expected return and executed assertion; rewrite only eligible typed/mixed multiple named-arrow headers.
- Keep current reference boundaries, relevant canonical synthesized records and generated normative JSONL/Rust exports synchronized, without new records, mirrors or changes to protected training fields and ARC annotations.

## Errors

- Introduce no new error kind or message; unsupported tokenizable prefixes fall through without consumption.
- All conditions below trace to the normative typed multiple-parameter arrow boundary section; lexical errors still precede parsing.

| Exact input or condition | Exact error | Position |
| --- | --- | --- |
| `def f left: int, right`, `def f left: int, right, => left` or `def f left: int, right: => left` | `SyntaxError("Expected '(' but found identifier 'left'")` | line 1, column 7 |
| Typed/mixed multiple bare indented/inline/braced blocks, missing types/parameters, unsupported type/parameter forms, return annotations or logical header breaks | `SyntaxError("Expected '(' but found identifier 'left'")` for a prefix beginning `def f left` | line 1, column 7 |
| `def f this: int, right => right` | `SyntaxError("Expected '(' but found keyword 'this'")` | line 1, column 7 |
| Logical newline immediately after `def f` | `SyntaxError("Expected '(' but found end of line")` | line 1, column 5 |
| Semicolon immediately after `def f` | `SyntaxError("Expected '(' but found ';'")` | line 1, column 6 |
| Four-space-indented `def reading left: int, right, => left` after `class Gauge:` and a newline | `SyntaxError("Expected '(' but found identifier 'left'")` | line 2, column 17 |
| Exact `def f left: int, right =>` at end of input | `SyntaxError("Unexpected end of input")` | line 1, column 26 |
| Same header with a final newline | `SyntaxError("Unexpected end of line")` | line 2, column 1 |
| Same header with body ` (left +)` | `SyntaxError("Unexpected ')'")` | line 1, column 35 |
| Same header with body ` { return left }` | `SyntaxError("Expected a key but found keyword 'return'")` | line 1, column 36 |
| Same header with body ` { left = 1 }` | `SyntaxError("Expected ':' but found '='")` | line 1, column 34 |
| Same header with an unparenthesized indented multiline object body | `SyntaxError("Expected a key but found an indented block")` | line 2, column 5 |
| `def f left: int, right => @` | `SyntaxError("Unexpected character '@'")` | line 1, column 27 |
| `def f left: int \| str, right => left` | `SyntaxError("Unexpected character '\|'")` | line 1, column 17 |
| `def f left: int?, right => left` | `SyntaxError("Unexpected character '?'")` | line 1, column 16 |
| `def f(left: int, right:) => left` | `SyntaxError("Expected a type but found ')'")` | line 1, column 26 |
| Evaluated body or object field reads undefined `missing` | `ReferenceError("missing is not defined")` | existing top-level statement position |
| Returned anonymous function reads uncaptured `left` | `ReferenceError("left is not defined")` | existing top-level statement position |
| `this` or `self` without an instance receiver | `ReferenceError("this is not defined")` | existing top-level statement position |
| Non-callable `operation` parameter shadows an outer function | `TypeError("operation is not a function")` | existing top-level statement position |
| Excessive body expression nesting | `SyntaxError("Expressions are nested too deeply")` | existing expression position |
| Excessive body operator chain | `SyntaxError("Expression has too many operands")` | existing expression position |
| Excessive body postfix chain | `SyntaxError("Expression has too many parts")` | existing expression position |

- Caught error values omit positions as before; removing parentheses may shift later columns on the same physical line, not unsupported-prefix or body-line positions.
- In the binding case, `invoke(null, 3)` deliberately remains deferred `null`; `invoke(7, 3)` executes the protected TypeError catch.

## Reference Implementation

- The prototype changes only the private shared complete-list scanner in [`src/lang/ast/parser.rs`](../src/lang/ast/parser.rs).
- Scan optional existing annotations without consuming tokens or allocating; permit an arrow after at least two parameters, but permit the block colon only when no annotation occurred.
- Reuse the unchanged parameter parser, named return-block lowering and suite parser; all single guards, lexer, public AST, runtime and generator remain unchanged.
- The 16 portable ordinary tests in [`tests/bare_typed_multiple_named_arrows.rs`](../tests/bare_typed_multiple_named_arrows.rs) cover complete AST/metadata/canonical equivalence, annotation positions, boundaries, exact errors/positions, bindings/null/non-callables, methods/init/receivers/super, objects/templates/noncapture, live aliases/snapshots/graphs, redefinition/rollback, CLI recovery and flat lists through 1,024 with inherited limits.
- Two additional audits are explicitly `#[ignore]` because default CI may have no historical Git objects: one compares complete historical measured ASTs and the eight appended counterparts; the other checks all 1,081 synthesized records' ASTs and protected fields/order plus unchanged ARC annotations.
- With Git and accepted revision `c40b64bc6338b84ce3d76019c6e0ee1e13900da1` available, run `cargo +stable-x86_64-pc-windows-gnu test --locked --target x86_64-pc-windows-gnu --test bare_typed_multiple_named_arrows -- --ignored`; selected audits fail on missing prerequisites rather than silently skipping.
- Existing suites retain unsupported-prefix assertions using still-invalid trailing-comma variants, alongside positive checks for newly valid counterparts.
- Keep only the eight supplied measured additions, regenerate normative exports from source and preserve all training IDs, descriptions, assertions, returns and ARC annotations.
