## Abstract

- Specifies variables: declaration, dependency, re-evaluation, freezing, deletion, rollback.
- An assignment is a statement that keeps holding, not a computation that runs once.
- `c = a + b` records that `c` is the sum of `a` and `b`, and the runtime maintains it as they change.

## Motivation

- Imperative assignment makes the programmer re-run computations by hand and track every downstream use.
- Statement order becomes load-bearing, and a missed update is a silent bug.
- Recording the relationship rather than only its result keeps derived values current by construction.
- Editing one statement does not require auditing its dependents, which is what makes Nucleoid tractable for a language model to write and revise.

## Rationale

- **Declarative by default.** The dependent form is the common case; a keyword to opt in would cost more syntax than it saves. `.value` is the opt-out.
- **Self-reference reads the value.** `radius = radius + 10` could be rejected as circular, but every other language reads it imperatively, and rejecting it would make an ordinary idiom an error.
- **A null dependency yields null, not an error.** This lets a rule be written before its data exists, so statement order stays free.

## Specification

### Declaration and assignment

- A variable is created by assigning to it; no keyword is required.
- An assignment evaluates to the assigned value.
- A variable used as an expression statement returns its current value.
- A declaration with a type but no value is rejected; there is no relationship to record.
- One statement per line, or several on a line separated by `;`.

```
normal = "NORMAL"; low = "LOW"; empty = "EMPTY"
```

- Three statements, applied in order, exactly as if written on three lines.

```
i = 1
```

```
k = 1
k
```

returns `1`.

```
a: int
```

raises `ReferenceError("Missing definition")`.

### Dependency

- Naming a variable on the right-hand side establishes a dependency on it.
- When a dependency changes, the dependent is re-evaluated.
- A bare reference is a dependency like any other.
- Dependencies are transitive.

```
a = 1
b = 2
c = a + b
```

- `c` is `3`.
- After `a = 2`, `c` is `4`, without being reassigned.

```
a = 1
b = a
```

- `b` is `1`.
- After `a = 2`, `b` is `2`.

### Re-assignment replaces the relationship

- Assigning again discards the previous dependencies and records the new ones.

```
a = 1
b = 2
c = a + 3
c = b + 3
```

- `c` is `5` and now depends on `b`, not `a`.
- After `b = 4`, `c` is `7`.
- Assigning to `a` no longer affects `c`.

### Self-reference

- A variable on both sides of its own assignment is read on the right as the current value.
- This is not a cycle.

```
radius = 10
radius = radius + 10
```

- `radius` is `20`.

### The value property

- `.value` takes the value at the time the statement runs.
- No dependency is recorded on the reference it is applied to.
- It is the means of depending on a number without depending on its source, and of breaking what would otherwise be a cycle.

```
goldenRatio = 1.618
altitude = 10
width = goldenRatio.value * altitude
```

- `width` is `16.18`.
- After `goldenRatio = 1.62`, `width` is unchanged; no dependency was recorded.
- After `altitude = 100`, `width` is `161.8`; that dependency is live, and the frozen `1.618` is still used.

### Null and undefined dependencies

- If any dependency is `null`, the result is `null`.
- Reading something not yet defined also yields `null`, and re-evaluates if it later becomes available.
- This is what allows a rule to be written ahead of its data.

```
a = 1
c = null

{
    b = null
    c = b / a
}
```

- `c` is `null`.

### Deletion

- `delete` removes a variable from the state.
- It returns whether anything was removed.
- Using a deleted variable raises a reference error.
- Deleting a variable that still has dependents leaves those dependents in place with the value `null`.

```
t = 1
q = t + 1
delete q
```

- `q` no longer exists; using it raises `ReferenceError("q is not defined")`.
- After `t = 2`, `q` is unaffected; the relationship went with the variable.

### Transactions

- Statements run in a transaction.
- If a statement, or any statement it triggers, raises, the whole transaction rolls back.
- The state is left exactly as it was.

```
a = 5

if a > 5:
    throw 'INVALID_VALUE'
```

- Assigning `a = 6` raises `'INVALID_VALUE'`.
- Afterwards `a` is still `5`; the assignment and the rule it triggered either both take effect or neither does.

## Errors

| Condition | Error |
| --- | --- |
| Reading a variable that is not defined | `ReferenceError("<name> is not defined")` |
| Declaring a variable with no value | `ReferenceError("Missing definition")` |
| An assignment that would close a dependency cycle | `TypeError("Circular Dependency")` |
| Using `value` as a property name | `TypeError("Cannot use 'value' as a property")` |

- A cycle is detected when the new relationship would make a variable depend on itself through one or more steps.

```
number1 = 10
number2 = number1 * 10
```

- Assigning `number1 = number2 * 10` raises `TypeError("Circular Dependency")`, and the state is unchanged.
- Contrast with self-reference: `number1 = number1 * 10` is not a cycle, because a variable's own occurrence on the right is read as a value.
