# NUC 5 -- Class-Level Rules

```
NUC: 5
Title: Class-Level Rules
Author: Can Mingir <canmingir@gmail.com>
Status: Draft
Type: Standards Track
Created: 31-Jul-2026
Requires: 1, 2, 3, 4
```

## Abstract

- Specifies rules written against a type rather than an instance, using the `$` prefix.
- A class-level rule holds for every instance of the type, whenever it was created.
- Rules may be declared before or after the instances they govern.

## Motivation

- "All humans are mortal" is a statement about a type, not about a list of people.
- Writing the same derived property on every instance by hand does not scale and goes stale as instances are added.
- A rule attached to the type is applied once and holds for the whole population, including instances that do not exist yet.

## Rationale

- **`$Name` addresses the type; `Name` addresses its instances.** The sigil keeps a rule about the type distinct from a query over the list.
- **Declaration order does not matter.** A rule written before any instance exists must still apply to instances created later, and a rule written afterwards must apply retroactively. Anything else would make the order of statements load-bearing.
- **Later rules win.** When two rules assign the same property, the last one received is the one that holds, matching how re-assignment works for variables.
- **An instance assignment overrides the rule for that instance only.** Otherwise a type-level default could not be specialised.

## Specification

### Class-level assignment

- `$Name.property = ...` states a rule for every instance of `Name`.
- The rule applies to instances created before and after it.

```
class Human(name: str):
    this.name = name

$Human.mortal = true

human1 = Human("Socrates")
```

- `human1.mortal` is `true`.

- A rule may read other properties of the same type.

```
class Employee:
    pass

$Employee.username = "E" + $Employee.id
```

- Re-assigning the rule replaces it, for existing instances too.
- Rules may chain: one class-level property may read another.
- A rule may read a variable, and updates when that variable changes.

### Before and after instantiation

- A rule declared first applies as soon as its inputs exist.
- A rule declared later applies immediately to every existing instance.

```
class Review:
    pass

$Review.rate = $Review.sum / 10

review1 = Review()
```

- `review1.rate` is `null`.
- After `review1.sum = 42`, it is `4.2`.

### Class-level conditionals

- `if`, `else if`, and `else` may be written over `$Name`.
- Each instance is evaluated independently.
- Instances whose inputs are missing are left untouched.

```
class Grade:
    pass

if $Grade.score > 89:
    $Grade.letter = "A"
else if $Grade.score > 79:
    $Grade.letter = "B"
else:
    $Grade.letter = "C"
```

- An instance with score `95` has letter `"A"`; `85` has `"B"`; `60` has `"C"`.
- Changing an instance's score re-evaluates only that instance.
- Conditions may combine with `and` and `or`.
- A condition may compare against a date variable, or test a regular expression.

### Order of rules

- Class-level statements are applied in the order received.
- When several assign the same property, the last matching one wins.

```
class Alert:
    pass

if $Alert.level > 1:
    $Alert.tone = "LOW"

if $Alert.level > 2:
    $Alert.tone = "HIGH"

if $Alert.level > 1:
    $Alert.tone = "FINAL"
```

- An alert with level `5` has tone `"FINAL"`.
- An alert with level `0` has tone `null`.

### Overriding

- Assigning the property on one instance overrides the rule for that instance.
- Other instances keep the rule's value.

```
class Node:
    pass

$Node.status = "IDLE"

node1 = Node()
node2 = Node()
node1.status = "ACTIVE"
```

- `node1.status` is `"ACTIVE"`, `node2.status` is `"IDLE"`.

### Inheritance

- A rule on a supertype applies to subtype instances.
- A rule on the subtype overrides the supertype's for that subtype.

```
class Payment:
    pass

$Payment.method = "CARD"

class Wire: Payment
    pass

$Wire.method = "TRANSFER"
```

- `payment1.method` is `"CARD"`, `wire1.method` is `"TRANSFER"`.

### Chains across types

- A rule may read through a reference into another type.
- Changes at any link propagate to every instance governed by the rule.

```
$Store.label = $Store.city.country.code + "-" + $Store.city.name
```

- With `country1.code` `"US"`, `store1.label` is `"US-NY"`.
- After `country1.code = "CA"`, it is `"CA-NY"`.

- A rule may assign an instance, which is then shared by every instance of the type.
- A rule may aggregate another type's list.

```
$Category.revenue = Product.filter(p => p.category == $Category).reduce((sum, p) => sum + p.price, 0)
```

- The aggregate updates as products are added or their prices change.

### Class-level rules in blocks

- A block may compute locals and assign a class-level property from them.
- The rule tracks the locals' dependencies.
- A block that reads a specific instance may not declare a class-level rule.

```
class Stock:
    pass

{
    change = $Stock.before * 4 / 100
    $Stock.after = $Stock.before + change
}
```

- With `before` `57.25`, `after` is `59.54`.
- With `before` `59.5`, `after` is `61.88`.

### The value property at class level

- `.value` freezes a reading inside a class-level rule as elsewhere.

```
count = 0

{
    $Device.code = "A" + count.value
    count = count + 1
}
```

- `device1.code` is `"A0"` and does not follow `count`.

## Errors

| Condition | Error |
| --- | --- |
| Declaring a rule on an undeclared type | `ReferenceError("<Name> is not defined")` |
| Writing through an undefined class-level reference | `ReferenceError("<Name>.<property> is not defined")` |
| A rule that would close a dependency cycle | `TypeError("Circular Dependency")` |
| Using `value` as a class-level property name | `TypeError("Cannot use 'value' as a property")` |
| Declaring a class-level rule in a non-class block | `SyntaxError("Cannot define class declaration in non-class block")` |

- If a rule throws for an existing instance, the whole assignment is rolled back and no instance keeps the property; see [NUC 9](nuc-0009.md).
