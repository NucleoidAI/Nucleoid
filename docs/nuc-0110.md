## Abstract

- Adds Python's names for three accepted string operations, as methods of
  string receivers that give the accepted methods' exact results:
  - `TEXT.startswith(prefix)` is `TEXT.startsWith(prefix)`, so
    `"report.csv".startswith("report")` is `true`;
  - `TEXT.endswith(suffix)` is `TEXT.endsWith(suffix)`, so
    `"report.csv".endswith(".csv")` is `true`;
  - `SEPARATOR.join(ITEMS)`, with the separator as the receiver, as Python
    writes it, is `ITEMS.join(SEPARATOR)` when `ITEMS` is a list or a
    class's instances, so `", ".join(["ada", "bo"])` is `"ada, bo"`.
- They join the runtime's accepted cross-language aliases of string and
  list methods: `find` for `indexOf`, `contains` for `includes`, `lower`
  and `upper` for `toLowerCase` and `toUpperCase`, `strip` for `trim`,
  `substr` for `substring` and `append` for `push`.
- Only calls on a string receiver that raised
  `TypeError("<receiver>.<name> is not a function")` change, along with
  the programs that caught that error. A `join` whose argument is neither a
  list nor a class's instances keeps raising it. Every other method,
  receiver, property read and accepted result is unchanged. No token,
  keyword, syntax-tree node, error type or message format, dependency or
  public item is added.
- Each alias inherits the semantics of its accepted method, including where
  they differ from Python. `join` converts its items as the list method
  does, so `"-".join(["a", 1, null])` is `"a-1-null"`, where Python raises
  `TypeError`.
- The authoritative contract is
  [Python string method aliases](../nucleoid.spec.md#python-string-method-aliases).

## Motivation

- Python is among the languages that LLMs write most fluently, and a world
  model built in Nucleoid often classifies records by their names or file
  types and renders lists as text. Nucleoid already accepts Python's names
  for several string and list methods, but three of the most common Python
  string idioms fail at run time. At the accepted revision:
  - `file.endswith(".csv")`, with `file = "report.csv"`, raises
    `TypeError("report.csv.endswith is not a function")`;
  - `name.startswith("A")`, with `name = "Ada"`, raises
    `TypeError("Ada.startswith is not a function")`;
  - `", ".join(names)` raises `TypeError(", .join is not a function")`.
- The accepted spellings are `file.endsWith(".csv")`,
  `name.startsWith("A")` and `names.join(", ")`. A model that writes Python
  has to remember that these three names differ, and `join` also swaps the
  receiver and the argument, which makes it the easiest of the three to get
  wrong.
- The aliases follow the existing ones:
  - they are methods of strings only, so lists, objects, class populations
    and every other receiver keep their accepted readings;
  - they are reached only through calls, as every built-in method is, so
    reading `text.startswith` without a call stays `undefined`, as reading
    `text.startsWith` does;
  - a standing declaration such as `label = ", ".join(names)` follows later
    writes of `names`, as `label = names.join(", ")` does.
- Prior art: Python's `str.startswith`, `str.endswith` and `str.join`, and
  Nucleoid's accepted aliases above, which already answer Python's
  `str.find`, `str.lower`, `str.upper`, `str.strip` and `list.append`.

## Rationale

- **Confirmed category and mode.** The allocating continuous cycle drew
  Language compatibility with one tool-backed uniform draw over the five
  categories that NUC 1's registry marks eligible for automatic selection,
  index 4 with probability 1/5 and no redraw, and recorded the requested
  change in the allocation commit `6b0edc20`, which this revision pins.
  Token comparison is therefore skipped as `language_compatibility`. That
  skip is categorical; it is neither a measured comparison nor a passing
  token gate. Runtime applicability does not apply to this category.
- **No counterparts.** Because comparison is skipped, the new cases have no
  accepted-syntax counterparts. They execute their assertions and explicit
  returns with full coverage, and every pre-existing case is unchanged.
- **Optional evidence.** No hint was supplied. Advisory usefulness is
  unscored (`missing_rubric`), not zero. Strategy learning is
  `not_configured`, so this revision is unattributed, with no policy,
  selection receipt, trial or reward.
- **Only former errors.** At the accepted revision every call of the three
  names on a string receiver raises
  `TypeError("<receiver>.<name> is not a function")` at the start of the
  running statement, in plain and JSON output alike. No accepted test,
  document case, dataset record or ARC dataset calls them, and none pins
  that error.
- **The accepted arms.** `startswith` and `endswith` are two more names of
  the arms that compute `startsWith` and `endsWith` among the string
  methods, as `find`, `contains`, `lower`, `upper`, `strip` and `substr`
  are names of theirs. They share the first argument's conversion to text,
  the evaluation of every argument and the result by construction.
  Rejected: rewriting the names at parse time, which would render
  `startsWith` where the source wrote `startswith`, and a second
  implementation, which could drift from the accepted one.
- **The separator as the receiver.** Python's `str.join` takes the
  separator as its receiver and the items as its argument. On a string
  receiver whose first argument is a list or a class's instances, the alias
  hands those items and the receiver, as the one separator, to the same
  list query `join` that `ITEMS.join(SEPARATOR)` reaches, so the rendering
  of every item, the empty result and the separator are those of the list
  method. Rejected: a string-level join with its own rendering of items.
- **Lists and instances only.** A population counts when
  `ITEMS.join(SEPARATOR)` would join its instances: a declared class, named
  by the class, by a variable or parameter that holds it, or by `$Name`
  outside a class-level rule or conditional. A class declared as `Math`,
  `Number`, `String` or `Date` does not count, because `Math.join(", ")`
  reaches `Math`'s static methods and raises
  `TypeError("Math.join is not a function")` rather than joining the
  instances.
- **Every other argument keeps the accepted error.** A string, a number, a
  boolean, an object or instance, `null`, an undefined value, a function, a
  built-in namespace, such a class or a missing argument keeps
  `TypeError("<receiver>.join is not a function")`. This adds no error type
  or message, and it leaves Python's iteration of a string's characters and
  of a dictionary's keys out of scope. Rejected: joining the characters of a
  string argument, which Python does but no accepted method does.
- **The null-safe reading belongs to receivers.** A `null` or undefined
  receiver keeps its accepted undefined result without evaluating the
  arguments. The separator is the receiver of the alias, so a `null` or
  undefined list argument keeps the error instead: after `o = {}`,
  `", ".join(o.items)` raises where `o.items.join(", ")` is undefined, and
  inside a class-level rule `", ".join($Order.items)` raises for an
  instance without `items`. A declaration that should wait for its list
  keeps the accepted spelling.
- **Written order of evaluation.** The receiver is read first and then every
  argument once, left to right, as for every call. `SEPARATOR.join(ITEMS)`
  therefore evaluates the separator before the items, where
  `ITEMS.join(SEPARATOR)` evaluates the items first; the two differ only
  when both have side effects.
- **Live as written.** A declaration or class-level rule that calls an alias
  depends on what its receiver and arguments read, as the accepted spelling
  does. Its dependencies are the accepted spelling's, in the order the call
  reads them, so `why` and `affects` list the separator of `sep.join(names)`
  before `names`.
- **Rendered as written.** Statements, `why`, `affects`, `--graph` and graph
  and block keys show the call as the source wrote it. An alias and its
  accepted spelling are different statements and keys, as the accepted
  aliases are.
- **Differences from Python stay documented, not emulated.** The aliases
  are the accepted methods under Python's names, so Python's further
  arguments and conversions do not arrive with them:
  - `startswith` and `endswith` ignore Python's start and end positions:
    `"abc".startswith("b", 1)` is `false`, where Python gives `True`;
  - they take no tuple of choices; a list converts to its text, so
    `"a.csv".endswith([".csv", ".tsv"])` tests the suffix `".csv,.tsv"` and
    is `false`;
  - `join` writes items that are not strings in their string form, where
    Python raises `TypeError`;
  - `join` over a string raises, where Python joins its characters;
  - the accepted `replace` replaces the first occurrence only, where
    Python's `str.replace` replaces every one, and `replaceAll` is the
    accepted spelling of Python's;
  - the accepted `split()` without a separator returns the whole string in
    a list, `["a b"]` for `"a b"`, where Python's `split()` splits on
    whitespace.
- **Completion.** The terminal workspace offers the JavaScript names of
  string and list members, and none of the accepted Python aliases. This
  proposal follows that precedent and adds no completion entry.
- **The public string method.** `nucleoid::builtins::string_method` is the
  public function behind every string method, so it accepts `startswith`
  and `endswith` where it returned the `TypeError`. A string receiver's
  `join` needs the runtime to read a population, so the runtime dispatches
  it, and `string_method(", ", "join", ...)` keeps its accepted error. No
  public item is added or removed; the widened set of names is the change
  to report for semantic-versioning review.
- **No `Requires`.** `startsWith`, `endsWith`, the list and population
  `join` and the accepted aliases are base built-ins that no NUC introduced.
  The routing rules that [NUC 42](nuc-0042.md) states for string methods are
  followed, not depended on.
- **Not added.** Python's positions and tuples, `join` over strings,
  dictionaries and other iterables, a whitespace `split()`, Python's other
  string methods such as `lstrip`, `rstrip`, `title`, `count` and
  `isdigit`, static forms such as `String.join`, aliases on lists or other
  receivers, completion entries and any change to `startsWith`, `endsWith`,
  `join`, `replace` or `split`.

## Specification

- The normative contract is
  [Python string method aliases](../nucleoid.spec.md#python-string-method-aliases).

### Calls

- `RECEIVER.startswith(...)`, `RECEIVER.endswith(...)` and
  `RECEIVER.join(...)` are aliases when `RECEIVER` evaluates to a string:
  a literal, a name, a property, a call result, a template, an index, a
  `.value` snapshot or a string read from a state version.
- On every other receiver the three names keep their accepted readings.

### Prefixes and suffixes

- `TEXT.startswith(prefix)` is `TEXT.startsWith(prefix)` and
  `TEXT.endswith(suffix)` is `TEXT.endsWith(suffix)`. The first argument
  converts to its string form, so `null` tests `"null"`, a number its
  digits, a list its comma-joined items, and a missing argument
  `"undefined"`. Matching is exact and case-sensitive, and an empty prefix
  or suffix matches. Further arguments are evaluated and ignored.

```
files = ["report.csv", "notes.txt", "draft_report.csv"]
tables = files.filter(file -> file.endswith(".csv"))
drafts = files.filter(file -> file.startswith("draft_"))
assert(tables, ["report.csv", "draft_report.csv"])
assert(drafts, ["draft_report.csv"])
assert(tables, files.filter(file -> file.endsWith(".csv")))
assert(["Ada".startswith("A"), "Ada".startswith("a"), "Ada".endswith("")], [true, false, true])
assert("draft_report.csv".startswith("report", 6), false)
files.push("draft_plan.txt", "data.CSV")
assert(drafts, ["draft_report.csv", "draft_plan.txt"])
assert(tables, ["report.csv", "draft_report.csv"])
files.shift()
tables
```

- This returns `["draft_report.csv"]`: both filters stay live, and
  `"data.CSV"` is not a CSV file to a case-sensitive suffix.

### Joins

- `SEPARATOR.join(ITEMS)`, on a string receiver, returns exactly what
  `ITEMS.join(SEPARATOR)` returns when `ITEMS` evaluates to:
  - a list, however it is reached, including a slice, a call result, a
    `.value` snapshot and a list read from a state version;
  - a declared class whose instances `ITEMS.join(SEPARATOR)` joins, named
    by the class, by a variable or parameter that holds it, or by `$Name`
    outside a class-level rule or conditional, in population order.
- Each item takes its ordinary string form, and an empty list or population
  gives `""`. Further arguments are evaluated and ignored.

| `ITEMS`, the first argument | `", ".join(ITEMS)` |
| --- | --- |
| `["ada", "bo"]` | `"ada, bo"` |
| `[]` | `""` |
| `["a", 1, null, true, [1, 2]]` | `"a, 1, null, true, 1,2"` |
| `Tag`, with instances `red` and `blue` | `"[object red], [object blue]"`, as `Tag.join(", ")` |
| `Tag.map(tag -> tag.n)`, with `n` of `"a"` and `"b"` | `"a, b"` |
| A string, number, boolean, object, instance, `null`, undefined value, function, built-in namespace or none | `TypeError(", .join is not a function")`, as at the accepted revision |
| A class declared as `Math`, `Number`, `String` or `Date` | The same `TypeError`, where `Math.join(", ")` raises `TypeError("Math.join is not a function")` |

```
class Tag(name):
    this.name = name
names = ["ada", "bo"]
sep = ", "
label = sep.join(names)
shown = " | ".join(Tag.map(tag -> tag.name))
assert([label, shown], ["ada, bo", ""])
red = Tag("red")
blue = Tag("blue")
assert(shown, "red | blue")
assert([label, "/".join(Tag)], [names.join(sep), Tag.join("/")])
assert("-".join(["a", 1, null, true, []]), "a-1-null-true-")
names.push("cy")
sep = " / "
assert(label, "ada / bo / cy")
"".join(names)
```

- This returns `"adabocy"`: `label` follows a push to its list and a write
  of its separator, and `shown` follows new instances.

### Evaluation

- The receiver is read first and then every supplied argument once, left to
  right, including unused extras, as for every call. A missing name among
  them raises `ReferenceError("<name> is not defined")` before the alias
  runs.
- `SEPARATOR.join(ITEMS)` evaluates the separator before the items. With
  side effects in both, the effects run in that written order: after
  helpers `sepf()` and `itemsf()` that log their names and return `"-"` and
  `["x", "y"]`, `[sepf().join(itemsf()), log]` is
  `["x-y", ["separator", "items"]]`, where
  `[itemsf().join(sepf()), log]` is `["x-y", ["items", "separator"]]`.
- A `null` or undefined receiver keeps the accepted route: the call is
  undefined and the arguments are not evaluated.

### Liveness and class-level rules

- A declaration that calls an alias depends on what its receiver and its
  arguments read: pushes, pops, shifts and replacements of a list, writes of
  a separator held in a name or a property, and new, changed and deleted
  instances of a population re-evaluate it.
- In a class-level rule each instance evaluates its own alias, and the rule
  follows that instance's properties. This program is the specification
  entry `Nucleoid rolls back failed updates through Python string methods`,
  which also exercises [Transactions](#transactions):

```
class File(name):
    this.name = name
$File.table = $File.name.endswith(".csv")
report = File("report.csv")
notes = File("notes.txt")
assert([report.table, notes.table], [true, false])
notes.name = "notes.csv"
assert(notes.table, true)
failure = ""
try:
    report.name = 7
catch error:
    failure = error
assert(failure, TypeError("number.endswith is not a function"))
assert([report.name, report.table], ["report.csv", true])
names = ["ada", "bo"]
label = ", ".join(names)
try:
    names = "ada"
catch error:
    failure = error
assert(failure, TypeError(", .join is not a function"))
assert([names, label], [["ada", "bo"], "ada, bo"])
try:
    names.push("cy")
    report.name = "report.txt"
    assert([label, report.table], ["ada, bo, cy", false])
    throw "UNDO"
catch error:
    assert(error, "UNDO")
[label, report.table]
```

- This returns `["ada, bo",true]`.
- Inside a class-level rule or a class-level conditional, `$Name` is the
  instance, an object, so `", ".join($Tag)` there keeps the accepted
  `TypeError`, and `$Tag.join(", ")` there keeps calling the instance's own
  `join`, or giving undefined.

### Rendering and graph keys

- Statements, `why`, `affects`, `--graph` and graph and block keys show the
  call as written: after `label = sep.join(names)`, `(why label)[0].rule`
  is `"label = sep.join(names)"`.
- The dependencies are those of the accepted spelling, in the order the call
  reads them: `(why label)[0].from` is `["sep", "names"]` and the steps of
  `why label` are `label`, `sep` and `names`, where
  `label = names.join(sep)` gives `["names", "sep"]` and `label`, `names`,
  `sep`. A literal separator reads nothing, so `label = ", ".join(names)`
  and `label = names.join(", ")` both depend on `names` alone.

### Transactions

- Errors of an alias propagate through the existing transaction, so a failed
  standing re-evaluation rolls back the change that triggered it: a
  property write that makes a file's name a number, raising
  `TypeError("number.endswith is not a function")`, and a list replaced by a
  string, raising `TypeError(", .join is not a function")`, as the entry
  above shows. A failed statement or transaction restores declarations that
  call aliases, their values and their dependencies.

### Cost

- An affix alias runs the arm of its accepted method, and a string's `join`
  runs the list query of its accepted spelling once, so every call costs
  what its accepted spelling costs: one pass over the receiver's text, or
  one pass over the items.
- **Measured**, not projected, through the command line on release builds,
  rustc 1.97.1: the median of five runs of each program with `--json`,
  including process start, on `nucleoid-final.exe`, the release build of
  the final tree, for the alias and its accepted spelling, and on the
  accepted revision's binary for the accepted spelling. `items` is
  `"x".repeat(100000).split("")`, 100,000 one-letter strings, which takes
  30.5 ms on the final binary and 31.0 ms on the accepted one before the
  measured work.

| Program | Alias | Accepted spelling | Accepted spelling at the accepted revision | Alias over spelling |
| --- | ---: | ---: | ---: | ---: |
| `items.map(x -> x.startswith("x")).length`, 100,000 calls | 77.7 ms | 76.4 ms | 75.1 ms | 1.02 |
| `items.map(x -> x.endswith("x")).length`, 100,000 calls | 74.2 ms | 76.1 ms | 75.5 ms | 0.97 |
| `items.map(x -> "-".join([x, x])).length`, 100,000 calls | 101.3 ms | 110.7 ms | 107.1 ms | 0.92 |
| `",".join(items).length`, one join of 100,000 items | 35.0 ms | 34.4 ms | 34.0 ms | 1.02 |
| A standing `label = ",".join(xs)` under 10,000 pushes of `xs` from a `while` loop | 14,079 ms | 14,040 ms | 13,985 ms | 1.00 |

- Each alias takes 0.92 to 1.02 times its accepted spelling's time, and the
  final binary's accepted spellings take 1.00 to 1.03 times the accepted
  revision's. The join call is the one that runs faster as an alias,
  because `[x, x].join("-")` renders its receiver's source text for a
  possible error message on every call, which `"-".join([x, x])` does not.
- The standing join re-joins once per push: the 10,000 pushes alone take
  10.8 s on the final binary and 10.9 s at the accepted revision, as their
  accepted cost, and the join adds 3.3 s with the alias and 3.2 s with the
  accepted spelling.
- The build before the improvement pass gave figures within 6 percent of
  these, with each alias at 0.93 to 1.02 times its accepted spelling.

### Compatibility

- Parsing, the syntax tree, canonical rendering and graph keys are
  unchanged; the three names stay ordinary method names.
- Only inputs that raised `TypeError("<receiver>.<name> is not a function")`
  at the accepted revision change: calls of `startswith` and `endswith` on
  strings, and calls of `join` on strings whose first argument is a list or
  a class's instances. Every accepted error was raised at the start of the
  running statement. "The tags" are `class Tag(n):` with the body
  `this.n = n`, then `red = Tag("a")` and `blue = Tag("b")`.
