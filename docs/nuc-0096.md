# NUC 96 -- At Variables

```
NUC: 96
Title: At Variables
Author: Can Mingir <canmingir@gmail.com>
Status: Accepted
Type: Standards Track
Category: Syntax enhancement
Created: 09-Nov-2026
Requires: 53, 86, 93, 94, 95
```

## Abstract

- `@name`, an `@` directly followed by a name, reads the variable `name`
  where an operand begins inside the value of an `is` assignment of
  [NUC 93](nuc-0093.md) or inside the right operand of an `is` or `is not`
  comparison of [NUC 86](nuc-0086.md). It reads the name exactly as `(name)`
  and the `=` spelling do: its value when something defines it, and
  `ReferenceError("<name> is not defined")` when nothing does. It is never a
  word.
- So after `a is 1`, `b is @a + 2` makes `b` follow `a` and be `3`, and
  `b is @c + 3` raises `ReferenceError("c is not defined")` at line 1,
  column 1 while nothing defines `c`, as `b = c + 3` does.
- Where a bare name would be a word, `@name` asks for the variable instead:
  `x is @A`, `x is @A if c else B`, `[@A, B]`, `{k: @A}`, `Light(color=@A)`
  and `if $Obj.color is @C:`. Where a bare name is already a reference, as in
  `@a + 2`, the mark is accepted and changes nothing.
- The regions reach as far as the item positions of [NUC 95](nuc-0095.md),
  outside function, arrow and lambda bodies, comprehension elements and
  filters, template interpolations, inner assignment values and assignment
  targets. Everywhere else a leading `@` keeps its accepted error and
  position, and an `@` after an operand keeps its meaning as the version
  selector of [NUC 53](nuc-0053.md).
- No token, keyword, syntax-tree variant, error message, option or flag is
  added. `@name` builds the syntax tree of `(name)`, so it renders,
  evaluates and records dependencies as `(name)` does. The authoritative
  contract is [At variables](../nucleoid.spec.md#at-variables).
- Backward compatible: at the accepted revision an `@` where an operand
  begins is always a syntax error, so only inputs that fail to parse there
  change. `target is @first`, `@last`, `@previous` and `@` with digits keep
  their accepted reading as `target` followed by `is@first`.
- Accepted: the user requested this feature directly, and the frozen
  candidate meets every hard criterion of the automatic acceptance rule, so
  the user-requested basis applies. The independent evaluator's overall
  decision is also Accepted. Token comparison was skipped as
  `single_proposal`, the rule for a single-proposal request, not a failed
  check; see [Evaluation](#evaluation).

## Motivation

- The user asked, in their words: "if @ used at beginning of word in is
  keyword, it should be consider as variable like:"

```
a is 1
b is @a + 2
```

- "however if variable not define it should throw reference error as
  usual":

```
b is @c + 3
```

- Words, the bare names of NUC 86, NUC 93, NUC 94 and NUC 95, read a name's
  value when something defines it and its own text otherwise. That lets a
  world model state words without quotes, but a misspelt or missing variable
  silently becomes text. Grouping parentheses, `(a)`, already ask for a
  reference, yet they read as grouping, not as a statement that `a` must be
  a variable.
- At the accepted revision the user's spelling fails to parse.
  `b is @a + 2` raises
  `SyntaxError("Expected a non-negative integer, 'first', 'last', or 'previous' after '@'")`
  at line 2, column 7 after `a is 1`, because `b is @a` reads as the
  statement `b` followed by a version of the name `is`; `x is [@A, B]` and
  `if x is @C:` raise `SyntaxError("Unexpected character '@'")` at the `@`.
- With at variables, one value can hold both: `colors is [@RED, GREEN]`
  stores `["red", "GREEN"]` after `RED = "red"`, and raises
  `ReferenceError("RED is not defined")` while nothing defines `RED`, where
  `colors is [RED, GREEN]` would store `["RED", "GREEN"]`.

## Rationale

- **Category and mode.** The user requested this concrete feature, so there
  was no random draw. It extends the word syntax of NUC 86, NUC 93, NUC 94
  and NUC 95, so its category is Syntax enhancement, theirs. It runs in
  single-proposal mode, which skips token comparison. Runtime applicability
  does not apply. No hint was supplied.
- **The name.** The form is the at sign marking a variable read, so "at
  variables", as "item words" names a word by its position. Rejected:
  "variable words", since `@name` is never a word, and "explicit
  references", which says nothing about the spelling.
- **The mark.** `@` is the user's choice. After an operand it already means
  "the version of", and where an operand begins every `@` is a syntax error
  at the accepted revision, so a prefix `@` can mean something new without
  changing any program that parses. Only an adjacent name counts: a space,
  tab, comment or line break after `@` keeps the accepted reading, as in
  `@ a` and `@/* c */a`, because `b is @ first` already parses, as `b` and
  `is@first`, and because the mark should read as part of the name it
  marks.
- **Reach.** In an `is` value, the mark is accepted wherever an operand
  begins, through every construct where NUC 95's item positions can lie:
  conditions and branches, operands, receivers, arguments, named-argument
  values, items, dictionary values, subscripts, quantifiers, comprehension
  sources, stage arguments, spread sources and grouping parentheses. The
  user's own example, `@a + 2`, is an operand of `+`, not a word position,
  so the mark cannot be limited to word positions. In a comparison, the
  region is the whole right operand, NUC 86's word position, as in
  `if $Obj.color is @C:`; it exists wherever such a comparison stands,
  including inside the function bodies and comprehension filters that the
  `is` value excludes.
- **Excluded parts.** Function, arrow and lambda bodies run later and hold
  their own statements; template interpolations are parsed separately; the
  value of an inner assignment is the value of `=`; a comprehension's
  element and filter become the bodies of the functions it lowers to; and a
  target is written, not read. A bare name there is never a word, so the
  mark would have nothing to say, and these are exactly the parts that hold
  no item position under NUC 95.
- **The left operand of a comparison.** Outside an `is` value it is not a
  region: the left operand is never a word, and the user asked for the word
  side. Inside an `is` value it is an operand of the value like any other,
  so `x is (@a is b)` reads `a`. Rejected: accepting `@` in every enclosed
  expression, which would make the mark a general prefix with no word to
  distinguish it from.
- **`@first`, `@last` and `@previous`.** These are ordinary identifiers
  except in a selector after an operand, so in prefix position they name the
  variables `first`, `last` and `previous`. At the start of a statement's
  `is` value, `target is @first` already parses as `target` followed by
  `is@first`, a version of a variable named `is`, so it keeps that reading;
  `target is (@first)` reads the variable. Digits
  after `@` are a version index token, never a name, so `@0` is never a
  variable.
- **No syntax-tree variant.** `@name` parses to `Expr::Identifier(name)` and
  spans two tokens, which NUC 93's one-token rule never makes a word. That
  is exactly what `(name)` builds, so dependency collection, `.value`
  freezing, cycle checks, static class-rule validation, rendering, graph
  keys, `why`, `affects` and the protected-assertion walker need no change.
  A comparison `x is @C` is the `==` comparison `x == C`, as `x is (C)` is.
- **Rendering.** A value with at variables renders as its parenthesized
  spelling and reads back as the same statement: `b is @a` renders as
  `b=a`, the rendering of `b is (a)` and `b = a`, and `b is c ? @a : B` as
  `b is c?(a):B`. Rejected: rendering `b is @a` as `b is (a)`, which needs a
  marker the tree does not have and would change the accepted rendering of
  `b is (a)`.
- **Targets and comprehension elements.** The parser reads the left side of
  an assignment operator before it sees the operator, and the first item of
  a list before it sees `for`. It records every `@` it accepts and, when the
  expression turns out to be a target or an element, rejects the first one
  in it with the error the accepted grammar reports there:
  `SyntaxError("Unexpected character '@'")` at that `@`, or, for a target
  that begins an `is` value, as in `x is @y = 1`, the selector error at `y`
  of the accepted reading `x` followed by `is@y = 1`.
- **Header colons.** A `while` or `suppose` header does not own a colon
  directly after the word `lambda`, which could begin `lambda x:`. After
  `@lambda` the name is a variable read, so the header owns the colon, as it
  does after `(lambda)`; `while x is lambda:` is unchanged.
- **REPL continuation.** It stays lexical. A colon-free `if` header waits
  for its indented body, and an `elif`, `else if` or direct `else`
  alternative indents its next line, when `@` and an adjacent name follow
  the comparison word `is`, or `is not`, after an operand, as in
  `if x is @C`. Any other `@` keeps the accepted rule that a valid version
  selector must follow, so `if x@a`, `if is @a` and `if (@a)` are still
  submitted at once; a colon header needs no change. Rejected: accepting
  `@` wherever an operand begins in a header, which would buffer headers
  such as `if (@a)` that the parser rejects outside a comparison.
- **Host stack.** Debug builds nest a fixed number of levels on the host
  stack, and every frame on the nesting path counts. `primary` now returns
  the result of `at_variable` instead of building its error in place, and
  the operator tail of `assignment_expression` moved into `assignment`, so
  both frames shrink and no shape overflows sooner; see Reference
  Implementation.
- **Not added.** `@name` at statement starts, in `=`, `:=` and `return`
  values, in conditions without an `is` comparison, in left operands
  outside `is` values, in keys, label names and parameters; `@` before a
  keyword, `$Class`, literal or `(`; a space after `@`; an option, a flag, a
  REPL command or a terminal toggle.
- **Settled choices.** These eight points were reviewed before evaluation
  and kept as specified:
  - the left operand of a comparison outside an `is` value is not a region,
    so `(@a is x)` keeps its accepted error;
  - prefix `@first`, `@last` and `@previous` read those variables, except
    `target is @first` right after a statement's `is`, which keeps its
    accepted reading, while `target is (@first)` reads the variable;
  - `b is @a` renders as `b=a`, since it is the tree of `b is (a)`;
  - rejected targets and elements raise the exact accepted errors, with
    `x is @y = 1` failing at `y`;
  - a comparison's right operand accepts `@name` wherever the comparison
    stands, including inside the parts that an `is` value excludes;
  - `if x is Light(color=@C):` keeps its accepted error, as its named
    argument is an inner assignment;
  - in the REPL, a colon-free `if x is @C` header waits for its body;
  - `while` and `suppose` headers own the colon after `@lambda`.
- **Optional evidence.** Advisory usefulness is unscored (`missing_rubric`),
  not zero. Strategy learning is `not_configured`; this revision is
  unattributed, without a policy, selection receipt, trial or reward.

## Specification

- The normative contract is
  [At variables](../nucleoid.spec.md#at-variables).

### Form

- `@name` is the token `@` with a name token directly after it: the name
  starts in the column after `@` on the same line, so no space, tab,
  comment or line break separates them. A name is an identifier token.
  Keywords such as `true`, `null`, `None`, `this`, `self`, `not`, `if`,
  `in`, `of` and `typeof`, `$Class` references, numbers, strings, `(` and
  another `@` are not names.

### Regions

- The value of an `is` assignment is a region wherever NUC 95's item
  positions can lie: the whole value and, at any depth, conditions,
  branches, operands, receivers, arguments, named-argument values, list
  items, dictionary values, subscripts, slice bounds, quantifier
  collections and conditions, comprehension sources, pipeline stage
  arguments, spread sources and grouping parentheses.
- The right operand of an `is` or `is not` comparison is a region, in every
  position where NUC 86 reads `is` as a comparison.
- Neither region reaches into a function, arrow or lambda body, the element
  or filter condition of a list comprehension, a template interpolation,
  the value of an assignment operator inside the region, or the target of
  an assignment operator. Outside an `is` value, a `name=value` argument is
  such an assignment, as NUC 95 describes, so `if x is Light(color=@C):`
  keeps the accepted error. A comparison inside one of these parts has its
  own right operand, and a block body's own `is` assignments have their own
  values.
- Inside a region, `@name` may stand wherever an operand begins.

### Reading

- `@name` reads `name` as an identifier is read, as `(name)` reads it: the
  local, variable, class, function or built-in global of that name,
  recording a dependency on it, and
  `ReferenceError("<name> is not defined")` when nothing defines it, raised
  at the start of its statement as for `=`. Static class-rule validation
  requires the name to be defined.
- It is never a word. In a word position it is the reference that `(name)`
  is: `x is @A if c else B` reads `A` as `x is (A) if c else B` does, and
  `if state is @OPEN:` compares with `==`.
- Postfix operations follow it as they follow any name: `@a.b`, `@a[0]`,
  `@a(1)`, `@Light(color=RED)`, whose named arguments are item positions as
  for `Light(color=RED)`, and `@a@first`, the version `first` of `a`.
- `first`, `last` and `previous` after a prefix `@` are names. After a
  complete operand, `@` is the version selector of NUC 53, unchanged.
- A statement `target is @first`, `@last`, `@previous` or `@` with digits
  keeps its accepted reading: the statement `target` followed by a version
  of the name `is`.
- A `while` or `suppose` header owns a colon after `@lambda`.

```
a is 1
b is @a + 2
assert(b, 3)
a = 5
assert(b, 7)
```

```
RED = "red"
colors is [@RED, GREEN]
assert(colors, ["red", "GREEN"])
light is "GREEN"
GO = "GREEN"
state is GO if light is @GO else STOP
assert(state, "GREEN")
```

### Outside the regions

- A leading `@` outside both regions raises
  `SyntaxError("Unexpected character '@'")` at the `@`, as at the accepted
  revision: `b = @a`, `return @a`, `f(@a)`, `x == @a`, `(@a is x)`, a
  statement that starts with `@a`, `x is () => @a`, `x is y = @a` and
  `x is [v for v in xs if @a]`.
- An assignment target or comprehension element inside a region that holds
  `@name` raises the error of the accepted reading at the same place:
  `SyntaxError("Unexpected character '@'")` at its first `@`, or, when the
  target begins an `is` value,
  `SyntaxError("Expected a non-negative integer, 'first', 'last', or 'previous' after '@'")`
  at the name.
- An `@` that a space, tab, comment or line break separates from the name,
  or that a non-name follows, keeps its accepted reading everywhere.

### Rendering

| Statement | Rendering |
| --- | --- |
| `b is @a` | `b=a` |
| `b is @a + 2` | `b=a+2` |
| `b is c ? @a : B` | `b is c?(a):B` |
| `b is [@A, B]` | `b is [(A),B]` |
| `b is {k: @A, j: B}` | `b is {"k":(A),"j":B}` |
| `b is Light(color=@A, size=B)` | `b is Light(color=(A),size=B)` |
| `{ total is [@a, B] }` | the block key `block(total is [(a),B])` |

- Every rendering is that of the parenthesized spelling and reads back as
  the same statement.

## Backward Compatibility

- **Only failing inputs change.** At the accepted revision, `primary` raises
  `SyntaxError("Unexpected character '@'")` for every `@` where an operand
  begins, and a statement `target is @name` reads as `target` followed by a
  version of `is`, which fails for every name but `first`, `last` and
  `previous`. Every input that holds `@name` in a region therefore fails to
  parse at the accepted revision, and only such inputs change.
- **What stays.** `target is @first`, `@last`, `@previous` and `@` with
  digits; every postfix selector; every `@` outside the regions, in the
  excluded parts, in targets and comprehension elements, or separated from
  its name; every program without such an `@`. Each keeps its parse, tree,
  positions, rendering, result, errors, JSON, graph and REPL behavior.
- **REPL.** A colon-free `if` header with `@` and a name after an `is`
  comparison word now waits for its indented body, and the same condition
  after `elif`, `else if` or a direct `else` indents the next line. At the
  accepted revision such a header was submitted alone and failed at the
  `@`; every other line is buffered, indented or submitted as before,
  including `if x@a`, `if is @a` and `if (@a)`.
- **Tests.** No existing test is edited. Existing test files only gain the
  continuation and terminal tests listed in Specification.
- **Public API.** No public item changes. The parser gains private state and
  a private module, and `Items` gains a private variant. No version number
  is changed.

## Errors

- No error type or message is added.

| Exact source | Error |
| --- | --- |
| `b is @c + 3` | `ReferenceError("c is not defined")`, line 1, column 1 |
| `colors is [@RED, GREEN]` | `ReferenceError("RED is not defined")`, line 1, column 1 |
| `b = @c` | `SyntaxError("Unexpected character '@'")`, line 1, column 5 |
| `x is y = @a` | `SyntaxError("Unexpected character '@'")`, line 1, column 10 |
| `x is [@y] = 1` | `SyntaxError("Unexpected character '@'")`, line 1, column 7 |
| `x is [@a for v in xs]` | `SyntaxError("Unexpected character '@'")`, line 1, column 7 |
| `x is @y = 1` | `SyntaxError("Expected a non-negative integer, 'first', 'last', or 'previous' after '@'")`, line 1, column 7 |
| `x is [@ a]` | `SyntaxError("Unexpected character '@'")`, line 1, column 7 |

- Each syntax error is the accepted revision's, at the same place.
- An input with `@name` in a region that fails for another reason reports
  that failure, as `(name)` would, where the accepted revision reported the
  `@`: `x is [@a b] = 1` raises
  `SyntaxError("Expected ']' but found identifier 'b'")` at line 1,
  column 10, and `x is @a => 1` raises `SyntaxError("Unexpected '=>'")` at
  line 1, column 12, since `@a` is not a parameter.

## Reference Implementation

- No token, keyword, `Expr`, `Stmt` or `UnaryOp` variant, option, flag or
  public item is added.
- `src/lang/ast/parser/at_variable.rs` is a new private module. `at_variable`
  reads `@name` when the item mode is not `Plain` and the name is adjacent,
  records the `@` with its `Rejection` kind, and otherwise raises the
  accepted `SyntaxError("Unexpected character '@'")`. `starts_at_variable`
  lets an `is` statement begin with `@name`, except before the names that
  `VersionSelector::from_name` knows, `first`, `last` and `previous`.
  `record_value_start` marks an `@` that begins an `is` value, and
  `enter_variables` opens a comparison's right operand.
  `at_variable_since` and `reject_at_variable` find and reject an `@`
  recorded inside a target or element, with the selector error for an `@`
  that began an `is` value.
- `src/lang/ast/lexer.rs` holds the selector error once, as the
  crate-private `EXPECTED_VERSION_SELECTOR`, which the lexer, postfix
  selectors and the at-variable rejection raise. `src/lang/ast/mod.rs` adds
  the crate-private `VersionSelector::from_name`, through which
  `parser/postfix.rs` reads selector names.
- `src/lang/ast/parser/is_assignment.rs` gives `Items` the mode
  `Variables`, for a comparison's right operand outside an `is` value,
  where `@name` is read but no item is a word, with a memo of Python-style
  conditions of its own; `src/lang/ast/parser/tests.rs` reads the accepted
  memo by its `(position, depth)` key, so the memos stay separate. `precedence.rs` parses the right operand of `is`
  and `is not` through `compared`. `primary.rs` hands `@` to `at_variable`
  and passes a list's start to `comprehension`. `expression.rs` records the
  start of every `assignment_expression` and moves its operator tail into
  `assignment`, which rejects at variables in targets. `comprehension.rs`
  rejects them in elements, and `statement.rs` lets a `while` or `suppose`
  header own a colon after `@lambda`. `parser.rs` holds the new state.
- `src/continuation.rs` accepts, in a colon-free condition header, an `@`
  and an adjacent name directly after an `is` comparison word or `is not`.
- `tests/at_variables.rs`, `tests/at_variables_cli.rs` and the continuation
  and terminal unit tests cover the claims above.
- The root specification, with its version, comparison and `is`-assignment
  sections, the consolidated reference with its syntax summary, the README
  and both NUC 0 indexes are synchronized. The specification change is
  prose, and the exports are unchanged.
- `docs/nucleoid.g4` adds the `atVariable` rule as the first alternative of
  `primary` with its contract, extends the `is`-assignment head, the
  comparison and parse-pass contracts and the `while` and `suppose` notes,
  and adds its lowerings and source files.

### Measured cost

- Measured before the caller's Rust improvement pass, on the debug command
  lines of the accepted revision and of the candidate, both built with
  `CARGO_INCREMENTAL=0` and `CARGO_PROFILE_DEV_DEBUG=false`.
- Debug stack frames, read from the stack reservation in each function's
  prologue in the emitted debug assembly. `primary` shrinks from 3,536 to
  3,472 bytes and `assignment_expression` from 560 to 480; nesting passes
  through both at every level. `assignment` grows from 1,216 to 1,328 bytes
  and `comprehension` from 2,368 to 2,416, but nesting reaches them only
  through assignment values and comprehensions, which pass through the two
  smaller frames as well. `clause_before_colon` shrinks from 464 to 400.
  The parser state grows by a memo and a map, 72 bytes, which adds 288
  bytes once to a template interpolation's frame; templates do not nest.
  `equality`, `relational`, `unary`, `postfix`, `subscript`,
  `conditional_with`, `python_condition`, `is_assignment` and `statement`
  are unchanged.
- An earlier draft kept the operator tail in `assignment_expression` and
  checked targets through `?`. Its frame grew to 576 bytes, and statement
  nesting through subscripts overflowed one level sooner than the accepted
  command line in three of four rounds, at 53 rather than 54; the final
  layout replaced it.
- The final command lines ran 45 nesting shapes at every depth from 15 to
  70 after the statement heads `x is `, `x = ` and none, and 5 header
  shapes after `while `, `suppose ` and `if `, three rounds each. The shapes
  are the 29 of NUC 95, comparisons through `is`, `is not` and `==` on
  either side, sums, assignments inside parentheses and lists, a template
  at the bottom of nested lists and parentheses, Python-style conditions,
  and five `@` shapes, which are compared with their `@`-free twins on the
  accepted command line.

### Findings

- **Low, the comparison region.** It exists only where `is` is read as a
  comparison. So `y = c is @a`, `x is c is @a` and
  `x is any v in xs: v is @a` still raise the selector error, because the
  accepted reading of each is a statement followed by `is@a`. The
  specification words this correctly, but it may surprise users.
- **Low, documented, selector names.** `target is @first`, and likewise
  `@last` and `@previous`, keep the accepted juxtaposed reading, so
  `x is @first + 1` and `x is 1 + @first` behave differently.
  `x is (@first)` reads the variable.
- **Info.** Some inputs that already failed to parse now report another
  error, for example `x is @a => 1` gives `Unexpected '=>'` at line 1,
  column 12: 2,032 generated and 4 corpus inputs. This is documented, and
  allowed for inputs that failed before.
- **Info.** In the REPL, a colon-free `if x is @C` waits for its body like
  any colon-free header, so an unindented next line joins the failing
  submission. `if x is 3` behaves the same way at both revisions.
