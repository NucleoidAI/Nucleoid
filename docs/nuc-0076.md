## Abstract

- Adds optional `//` line comments and non-nesting `/* ... */` block comments
  alongside accepted `#` comments.
- Requires explicit activation with CLI `--c-style-comments` or Rust
  `Runtime::with_options(SyntaxOptions { c_style_comments: true })`.
- Preserves the default parser, slash/regex interpretation, runtime results
  and diagnostics, including accepted inputs that fail during execution.
- Retains logical newlines, original character positions and indentation
  without counting comment text as indentation or joining neighboring tokens.
- Adds no dependencies, version changes, ARC behavior or implicit mode switch.

## Motivation

- Users bringing C, JavaScript and similar source forms expect both comment
  delimiters; accepted Nucleoid already supports hash comments.
- Activating them unconditionally would reinterpret accepted regex literals
  and arithmetic, not merely turn existing syntax errors into valid programs.
- An explicit source option makes the familiar forms available without
  changing existing programs or requiring a global language-mode change.

## Rationale

- **User choice.** The caller presented the accepted-syntax collision and the
  user selected `cli_runtime`: an opt-in CLI flag and runtime option.
  No separate hint was supplied or set aside.
- **Confirmed category.** Language compatibility describes optional familiar
  source forms that preserve the accepted default language. This is an
  explicit user-requested feature, not an automatic category draw.
- **Preserved mode.** `NUC_PROPOSAL_MODE=single`; token comparison is skipped
  as `single_proposal`, not measured, passed or assigned zero counts.
  Immutable accepted-corpus, behavior, integrity, compatibility and development
  checks remain required.
- **Runtime applicability.** Not applicable: this is not Runtime features.
  No runtime-applicability override is used.
- **Accepted collisions.** At accepted revision
  `521c2fe2f9cada2932f6f399c3c8a72c160aba34`, `//` is an empty regex;
  `// comment` parses and raises `ReferenceError: comment is not defined`;
  `/* comment */` parses and fails regex compilation; `1 // 2 /` divides
  one by a regex and returns NaN. None may silently become a default comment.
- **Explicit delimiter priority.** Only enabled runtimes give comment
  openers priority over slash/regex recognition. This intentionally reserves
  those ambiguous forms in that mode.
- **Reuse.** Extend the accepted Logos scanner and layout pass; do not strip
  or concatenate source before lexing. Share scanning with enabled template
  interpolation boundary detection and retain the accepted default boundary
  algorithm.
- **Typed API.** One small `SyntaxOptions` value, defaulting to false, is shared
  by runtime, compilation, program parsing, expression parsing and tokenization.
  It is per runtime, immutable after construction and preserved by `clear`.
- **Not added.** Nested blocks, documentation-comment nodes, comment retention
  in generated source, new token kinds, automatic detection, global settings,
  a separate source `eval` API and unrelated parser fixes are out of scope.
- **Optional evidence.** Advisory usefulness is unscored (`missing_rubric`),
  not zero. Strategy learning is `not_configured`; this revision is
  unattributed, without policy, selection receipt, trial, reward or assessment.

## Specification

- The normative candidate contract is
  [Opt-in C-style comments](../nucleoid.spec.md#opt-in-c-style-comments).

### Activation and API

- `Runtime::new()`, `Runtime::default()` and every existing no-options lexer,
  parser, compilation and static syntax-check function retain default behavior.
- Export `SyntaxOptions` from the crate root and lexer module, deriving
  `Debug`, `Clone`, `Copy`, `Default`, `PartialEq` and `Eq`; its concrete public
  field is `c_style_comments: bool`, initially false.
- `Runtime::with_options(options)` selects the syntax for all `run` calls,
  expression evaluation and template interpolations; `options()` returns it.
  Clearing state does not reset syntax.
- `Runtime::check_with_options(source, options)` checks the same syntax without
  running it; static `Runtime::check(source)` remains the default checker.
- Provide matching `tokenize_with_options`, `parse_program_with_options`,
  `parse_with_options`, `parse_expression_with_options` and
  `statement::compile_with_options` entry points. Existing signatures do not
  change; options are explicit at every standalone parsing boundary.
- `nucleoid --c-style-comments [file]` creates an enabled runtime for file,
  plain/piped REPL and full-screen terminal execution. The flag is off by
  default and changes neither result formatting nor assertion/error reporting.

### Lexical behavior and layout

- In enabled mode, outside literals, `//` discards everything up to but not
  including LF, or to end of input. The LF in CRLF remains a layout newline.
- `/*` discards through the first following `*/`. Openers, hash characters,
  quotes and slash characters inside that block are inert; blocks do not nest.
- Accepted `#` comments remain available in either mode.
- Comments separate tokens: `left/**/right` remains two identifiers, and
  `+/**/=` does not become `+=`.
- Every LF inside a block still reaches the layout pass. Parentheses and
  brackets suppress those logical breaks as before; in enabled mode a break
  within them does not turn a following division slash into a regex opener.
- Only actual whitespace outside comments contributes indentation; comment
  text and whitespace within it have zero indentation width. Comment-only
  lines cannot create a suite. Tabs keep the accepted width of four.
- Positions always refer to original source: one-based lines and character
  columns, with tabs counted as one character for diagnostic columns.
  CRLF, Unicode comment text and following token locations are retained.
- Preserve ordinary division, `/=`, nonambiguous regex literals, escaped regex
  slashes and character classes. Enabled source may use `/(?:)/` for
  empty-matching behavior; its pattern text is `(?:)`, not the empty string.
  This proposal does not add a `RegExp` constructor.
- Quoted strings and template literal text are not scanned for comments.
  An interpolation is source code and inherits the selected syntax, including
  comment-aware brace boundaries. Braces inside its strings, regexes or
  comments do not close it. Existing outer template quoting limits remain.
- In enabled mode, interpolation diagnostics are mapped back to the original
  template's source positions. Default interpolation behavior and diagnostics
  remain unchanged.

### Interactive input

- Plain/piped continuation recognizes real header tokens with the selected
  syntax; punctuation inside comments cannot manufacture a header.
- An open block comment buffers subsequent physical lines, including blank
  lines and command-looking text, until it closes. Closing a header comment
  preserves suite continuation. Ctrl-C cancels pending input as before.
- EOF executes pending input and reports an unclosed block once. REPL errors
  remain visible without changing the existing REPL exit-status convention.
- Full-screen submission uses the configured runtime; Ctrl-J indentation uses
  the same syntax and does not treat an open block's contents as headers.
- `clear` and `.clear` retain the selected option; no interactive mode toggle
  or new REPL command is introduced.

## Errors

- An unclosed enabled block raises `ErrorKind::Syntax` with exact message
  `Unterminated block comment`, positioned at its opening slash, including
  inside template interpolations.
- Display is exactly `SyntaxError: Unterminated block comment (line L, column C)`,
  with the original one-based position substituted for `L` and `C`.
- Tokenization/program compilation fails before any program statement runs;
  already committed state is unchanged.
- Existing non-comment syntax, runtime and regex errors retain their contracts
  in default mode; enabled programs otherwise use the ordinary errors.

- Prototype in `src/lang/ast/lexer.rs`, `parser.rs`, `statement.rs`,
  `runtime.rs`, `lib.rs`, `main.rs` and terminal indentation/submission helpers.
- `tests/c_style_comments.rs` groups default collision contracts, all comment
  forms, non-nesting, layout/positions, token separation, unterminated blocks,
  literals/templates and explicit API option propagation.
- `tests/c_style_comments_cli.rs` covers file activation, default failures,
  plain/redirected continuation, LF/CRLF, tabs, blank lines, EOF and clear.
  A terminal unit case exercises configured Ctrl-J, submission and diagnostics.
- New assertion-bearing programs check both canonical assertion count and
  executed assertion count; other cases assert explicit values or diagnostics.
- Keep all default-mode executable documents and synthesized record programs
  unchanged. Their configuration-free case schemas cannot activate this
  option; enabled examples live in the focused library/CLI cases and Rust API
  documentation rather than silently changing the corpus execution mode.
- Regenerate specification exports with the prescribed commands after the
  normative prose update; no executable source or export bytes need change.
