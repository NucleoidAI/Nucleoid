# NUC 131 -- Reversal Method Aliases

```

Status: Accepted
Type: Standards Track
Category: Language compatibility
Created: 21-Nov-2026
Requires: 61, 125
```

## Abstract

- Lists and class instance lists gain `reversed()`, as Kotlin and Swift
  spell it, and `toReversed()`, as JavaScript spells it since ES2023, as
  exact aliases of the accepted read-only `reverse()`: `[1, 2, 3].reversed()`
  and `[1, 2, 3].toReversed()` give `[3, 2, 1]`, `Truck.reversed()` gives the
  instances in reverse population order, the latest created first, and the
  receiver is never written.
- Strings gain `reversed()`, as Kotlin spells it, and `reverse()`, as Ruby
  spells it, as exact aliases of the accepted character reversal
  `TEXT[::-1]` of [NUC 125](nuc-0125.md): `"café".reversed()` gives
  `"éfac"`, reversing Unicode scalar values.
- Like the aliases of [NUC 116](nuc-0116.md) to [NUC 118](nuc-0118.md), they
  read what their accepted spellings read and stay live, and further
  arguments are evaluated and ignored. The equivalence holds per evaluation
  of the receiver: when a later write turns a held receiver into another
  kind of value, the call reads its name on that value, as every method name
  is read.
- At the accepted revision each of these calls raises
  `TypeError("<receiver>.<name> is not a function")`, unless an argument
  raises first. Only those calls change, along with the programs that
  caught that error and the standing `reverse()` calls whose list receiver a
  later write replaced with a string, which raised
  `TypeError("<text>.reverse is not a function")` at that write.
  `reverse()` on lists and populations, a string's `toReversed()`,
  functions, properties, methods and variables named `reversed`,
  `toReversed` or `reverse`, and every other receiver keep their readings.
- No token, keyword, syntax-tree node, error type or message format,
  dependency or public item is added.
- The authoritative contract is
  [Reversal method aliases](../nucleoid.spec.md#reversal-method-aliases).

## Motivation

- People and language models coming from Kotlin, Swift and JavaScript write
  `xs.reversed()` or `xs.toReversed()` for a reversed copy, and from Kotlin
  and Ruby `"abc".reversed()` or `"abc".reverse()`. Each raises a
  `TypeError` at the accepted revision, although the behavior already
  exists: `reverse()` on lists and class populations, and `[::-1]` on
  strings.
- Nucleoid's `reverse()` already returns a new list and leaves its receiver
  unchanged, unlike JavaScript's in-place `Array.prototype.reverse`, so the
  copying names `reversed` and `toReversed` describe it exactly. Accepting
  them moves Nucleoid toward the superset of familiar forms that its goals
  name, without changing any accepted reading.
- World models read ordered histories backward: an undo history newest
  first, the stops of a route on the way home, the latest readings first, a
  class's instances from the latest created, and a word against its own
  reversal to tell a palindrome. These readings are standing, so they must
  follow every push, new instance and write, which `reverse()` and `[::-1]`
  already do and the aliases inherit.
- The aliases advance the language-superset aspiration of the Language
  compatibility category, as the accepted `this`/`self`, `=>`/`->`,
  `append`, `contains`, `lower`, `upper`, `strip`, NUC 110's `startswith`,
  `endswith` and `join`, NUC 116's size and emptiness methods, NUC 117's
  `first` and `last` and NUC 118's case conversions do: an equivalent
  familiar spelling beside the canonical one, with no change to any
  accepted program.
- Kotlin's `Iterable.reversed()` and `String.reversed()`, Swift's
  `Sequence.reversed()`, Java 21's `SequencedCollection.reversed()`,
  JavaScript's `Array.prototype.toReversed()` and Ruby's `String#reverse`
  and `Array#reverse` are the prior art.
- Sorting copies stay out of scope. The accepted `sort()` orders by
  JavaScript string comparison, so `[10, 9, 1, 2].sort()` gives
  `[1, 10, 2, 9]`, while Kotlin's and Swift's `sorted()` order numbers by
  value; a `sorted()` alias would mislead.

## Rationale

- **Category and mode.** The allocating continuous cycle drew Language
  compatibility with one tool-backed uniform draw over the five categories
  that NUC 1's registry marks eligible for automatic selection, index 4
  with probability 1/5 and no redraw, at 21:17:07 on 21-Nov-2026, and
  recorded the requested change in the allocation commit `2ae49a2e`, which
  this revision pins. Token comparison is therefore skipped as
  `language_compatibility`. The skip is categorical; it is neither a
  measured comparison nor a passing token gate. Runtime applicability does
  not apply to this category.
- **Selection.** Among the open Language compatibility candidates the cycle
  surveyed, all of them former errors, were Kotlin's `!in`, Rust's
  `starts_with` and `ends_with`, `none(pred)` and these reversal aliases.
  The cycle chose the aliases: `reversed()` and `toReversed()` are the
  familiar names of the reversed copy that `reverse()` already returns, and
  Kotlin's `reversed()` and Ruby's `reverse` reverse strings, which `[::-1]`
  already does.
- **No counterparts.** Because comparison is skipped, the new cases have no
  accepted-syntax counterparts. They execute their assertions and explicit
  returns with full coverage, and every pre-existing case is unchanged.
- **Optional evidence.** No hint was supplied. Advisory usefulness is
  unscored (`missing_rubric`), not zero. Strategy learning is
  `not_configured`, so this revision is unattributed, with no policy,
  selection receipt, trial or reward.
- **Only former errors.** At the accepted revision every call of `reversed`
  or `toReversed` on a list or class population, and of `reversed` or
  `reverse` on a string, raises
  `TypeError("<receiver>.<name> is not a function")` at the start of the
  running statement, in plain and JSON output alike, unless an argument
  raises first, and a `try` catches it. No accepted test, document case,
  dataset record or ARC dataset calls them, and no test pins that error.
  No accepted document case calls `reverse()`; the tests that pin it,
  `values.reverse()` and `User.reverse()` in `tests/list_queries.rs`,
  `items@first.reverse()` in `tests/state_versions.rs` and the sealed
  `split("").reverse().join()` counterparts of `tests/stepped_slices.rs`,
  all call it on lists or populations and keep their results.
- **One arm each.** The list aliases join the accepted `reverse` arm of
  `list_query`, which lists and populations share, so they return
  `reverse()`'s result by construction. The string aliases form one arm of
  `string_transform` that collects the receiver's characters, its Unicode
  scalar values, in reverse order: exactly the characters, in exactly the
  order, that `[::-1]`'s backward walk with stride 1 and no bounds collects.
  Rejected: rewriting the calls at parse time into `reverse()` or a stepped
  slice, which would render the accepted spelling where the source wrote the
  alias in statements, `why`, `affects`, `--graph` and graph keys; a second
  implementation of the list reversal, which could drift from the accepted
  one; calling the stepped-slice evaluation from the string methods, which
  would make the built-in string methods depend on the syntax tree's
  evaluation and first collect every character into a vector, which
  `chars().rev()` does not need; and a table of alias names consulted before
  the dispatch, which would add a lookup to every method call.
- **`reverse` on strings.** Ruby's `String#reverse` shares its name with the
  accepted list `reverse()`, and Kotlin's `reversed()` serves both lists and
  strings, so the two names read alike on every receiver that has a
  reversal. A string's `reverse()` raised the `TypeError`, so giving it the
  reversal changes only former errors. JavaScript strings have no reversal
  method and `toReversed()` is an array method only, so a string's
  `toReversed()` keeps its error: no source language reads it as a string
  reversal.
- **Lists, populations and strings only.** Numbers, booleans, functions,
  dates, regular expressions, objects, instances and the built-in
  namespaces keep their accepted readings, and with them their errors and
  their members.
- **Calls only.** Reading `xs.reversed` or `text.reverse` without a call
  stays undefined, as reading `xs.reverse` does, and assigning them keeps
  the accepted `TypeError`. A property alias would change accepted outputs,
  since those reads give undefined.
- **Arguments.** The receiver is read first and then every argument once,
  left to right, as for every call, because the list and string routes
  evaluate the arguments before any method runs. The accepted `reverse()`
  ignores its arguments, and so do the aliases.
- **Population before methods.** On a class name, `Name.reversed()` and
  `Name.toReversed()` are population queries, as `Name.reverse()` and the
  aliases of NUC 116 and NUC 117 are, even when the class declares an
  instance method of that name; instances keep calling their methods, and
  inside a class-level rule `$Name` is the instance.
- **Per evaluation of the receiver.** The aliases are methods of lists,
  populations and strings, not rewrites of the call, so the receiver decides
  the reading each time a call is evaluated. `reversed` names both
  reversals, so a standing `reversed()` follows a receiver that a later
  write turns from a list into a string, or back, and reverses either.
  `reverse()`, the accepted list spelling, now does the same, because
  `reverse` is also a string alias: a standing `ys = xs.reverse()` whose list
  receiver a later write replaced with a string raised
  `TypeError("<text>.reverse is not a function")` at that write, which
  rolled back, and now holds the reversed string. `toReversed()` stays a
  list method, so it raises there. Against `[::-1]` on a string receiver,
  the string aliases differ only where the receiver becomes another kind of
  value: a number, boolean, date or function raises that receiver's
  `TypeError`, as every method call does, where `[::-1]` gives undefined,
  and an object reads its member of the alias's name. Every such program
  raised the alias's `TypeError` at the accepted revision. Rejected:
  reversing the text of a non-string receiver, which would give values
  methods they do not have, and raising the spelling's error instead, which
  would add a second message for one call.
- **Live and rendered as written.** While the receiver is a list, a
  population or a string, a declaration or class-level rule that calls an
  alias depends on what its spelling depends on: its receiver's reads.
  Statements, `why`, `affects`, `--graph` and graph keys render the call as
  every call is rendered, with the name the source wrote.
- **Source-language differences stay documented, not emulated.**
  - JavaScript's `Array.prototype.reverse()` reverses its array in place and
    returns it, and Python's `list.reverse()` reverses in place and returns
    `None`; Nucleoid's accepted `reverse()` copies, which is why the copying
    names describe it. No in-place reversal is added: it would write its
    receiver, which no list query does.
  - Swift's `reversed()` returns a lazy `ReversedCollection` view, and Java
    21's `reversed()` a view that writes through to its list; the aliases
    return a new list, which a declaration keeps live.
  - Swift reverses a string's grapheme clusters, keeping a letter with its
    combining marks and an emoji sequence whole. Kotlin and JavaScript
    strings are sequences of UTF-16 code units: Kotlin's `reversed()` on the
    JVM keeps each surrogate pair together, while JavaScript's usual
    `s.split("").reverse().join("")` splits it. The aliases reverse Unicode
    scalar values, as `[::-1]` does: an emoji beyond the Basic Multilingual
    Plane stays whole, while a combining mark, the parts of a ZWJ sequence
    and the two regional indicators of a flag change order.
  - Kotlin's `CharSequence.reversed()` returns a `CharSequence`, while its
    `String.reversed()` returns a string, as the aliases do on strings.
  - Ruby's in-place `reverse!` and Kotlin's in-place `MutableList.reverse()`
    are not added, nor is Kotlin's `asReversed()`, a live reversed view of a
    list.
  - Python's built-in `reversed(xs)` is not added: a new global name would
    change the accepted `x is NAME` comparisons, which read an undefined
    bare word as its own text.
  - Kotlin's `reversedArray()`, C#'s `Reverse()` and Java's static
    `Collections.reverse(list)`, which reverses in place, are not added.
- **Completion.** The terminal workspace offers canonical member names, and
  neither `reverse` nor any accepted alias, as [NUC 110](nuc-0110.md) and
  [NUC 116](nuc-0116.md) to [NUC 118](nuc-0118.md) kept it. This proposal
  follows that precedent and adds no completion entry.
- **Public API.** No public item is added or removed.
  `nucleoid::builtins::string_method`, the public function behind every
  string method, keeps its signature and accepts `reverse` and `reversed`
  where it returned the `TypeError`, as it accepted the names of NUC 110,
  NUC 116 and NUC 118. The widened set of names is the change to report for
  semantic-versioning review.
- **`Requires`.** [NUC 61](nuc-0061.md) specifies the list queries that
  lists and class populations share, among them the accepted `reverse()`,
  and [NUC 125](nuc-0125.md) the character reversal `[::-1]`. NUC 116 to
  NUC 118 are followed as precedents, not depended on.
- **Not added.** Property aliases; in-place reversals; reversed views;
  `toReversed()` on strings; static or global forms such as
  `String.reversed()`, `Math.reversed()` and `reversed(xs)`; noun forms
  such as `reversed of xs`, a pinned `SyntaxError`; `sorted()` and
  `toSorted()`; completion entries; and any change to `reverse()` on lists
  and populations or to `[::-1]`.

## Specification

- The normative contract is
  [Reversal method aliases](../nucleoid.spec.md#reversal-method-aliases).

### Calls

- `RECEIVER.reversed(...)` and `RECEIVER.toReversed(...)` are
  `RECEIVER.reverse(...)` whenever `RECEIVER` evaluates to a list or a class
  population.
- `TEXT.reversed(...)` and `TEXT.reverse(...)` are `TEXT[::-1]` whenever
  `TEXT` evaluates to a string, after their arguments are evaluated and
  ignored.
- Lists are reached however the language reaches them: literals, names,
  properties and instance properties, indexes and slices, call and query
  results such as `map`, `filter`, `concat`, `split` and `reverse`,
  conditional expressions, `.value` snapshots and lists read from a state
  version. Populations are named by the class, by a variable or parameter
  that holds it, or by `$Name` outside class-level rules and conditionals;
  their ranges such as `Name[1:]`, `Name.list()` and queries such as
  `Name.filter(...)` are lists. Strings are reached as lists are, and also
  as templates, concatenations, `String(...)` and `typeof` results.
- On every other receiver the names keep the readings of
  [Compatibility](#compatibility).

### Reversal

- The accepted `reverse()`, on a list or a class population, returns a new
  list of the same items in reverse order and leaves its receiver as it is:
  after `xs = [1, 2, 3]`, `[xs.reverse(), xs]` is `[[3, 2, 1], [1, 2, 3]]`.
  On a class it gives the instances in reverse population order, the latest
  created first, and a class without instances gives `[]`. The items are the
  receiver's own: an object in the reversed list is the receiver's object,
  and a nested list keeps its own order. The aliases share all of this. This
  program is the specification entry
  `Nucleoid reverses lists with reversed and toReversed`:

```
history = ["open", "type", "save"]
undo = history.reversed()
latest = history.toReversed()[0]
assert([undo, latest, history], [["save", "type", "open"], "save", ["open", "type", "save"]])
history.push("close")
assert([undo, latest], [["close", "save", "type", "open"], "close"])
history.pop()
history.shift()
assert([undo, latest], [["save", "type"], "save"])
assert([[].reversed(), [[1, 2], 3].toReversed()], [[], [3, [1, 2]]])
undo
```

- This returns `["save","type"]`: both declarations follow the push, the
  pop and the shift, and `history` keeps its order.
- A population reverses in reverse creation order and follows new
  instances, and a class-level rule reverses each instance's own list. This
  program is the specification entry
  `Nucleoid reverses class populations in reverse creation order`:

```
class Stop(name):
    this.name = name
Stop("Depot")
Stop("Mill")
Stop("Harbor")
home = Stop.reversed()
names = Stop.toReversed().map(stop -> stop.name)
assert(names, ["Harbor", "Mill", "Depot"])
Stop("Lighthouse")
assert([home.length, home[0].name, names], [4, "Lighthouse", ["Lighthouse", "Harbor", "Mill", "Depot"]])
class Train(cars):
    this.cars = cars
$Train.fromRear = $Train.cars.reversed()
local = Train(["engine", "coach"])
local.cars.push("caboose")
local.fromRear
```

- This returns `["caboose","coach","engine"]`.
- The string aliases reverse the characters, Unicode scalar values, exactly
  as `[::-1]` does:

| `TEXT` | `TEXT.reversed()` and `TEXT.reverse()` |
| --- | --- |
| `"stressed"` | `"desserts"` |
| `"café"` | `"éfac"` |
| `"añejo"` | `"ojeña"` |
| `"a😀b"` | `"b😀a"`, the emoji whole |
| `"日本語"` | `"語本日"` |
| `"racecar"` | `"racecar"` |
| `""` | `""` |
| `e`, a combining acute accent U+0301, `x` | `x`, U+0301, `e`: the accent now follows the `x` |
| the flag 🇫🇷, U+1F1EB and U+1F1F7 | U+1F1F7 and U+1F1EB, the flag 🇷🇫 |

- A string's `length` counts the same characters before and after. This
  program is the specification entry
  `Nucleoid reverses strings by character with reversed and reverse`:

```
word = "crème"
mirror = word.reversed()
assert(mirror, "emèrc")
word = "café"
assert([mirror, word.reverse()], ["éfac", "éfac"])
assert(["a😀b".reversed(), "".reverse(), "stressed".reversed()], ["b😀a", "", "desserts"])
class Word(text):
    this.text = text
$Word.palindrome = $Word.text.toLowerCase().reversed() == $Word.text.toLowerCase()
anna = Word("Anna")
kayaks = Word("kayaks")
assert([anna.palindrome, kayaks.palindrome], [true, false])
kayaks.text = "Kayak"
kayaks.palindrome
```

- This returns `true`.

### Evaluation

- The receiver is read first, a population's instances included, and then
  every supplied argument once, left to right, including unused extras, as
  for every call. A missing name among them raises
  `ReferenceError("<name> is not defined")` before the alias runs:
  `[1, 2].reversed(missing)` raises it, as `[1, 2].reverse(missing)` does,
  and `"abc".reverse(missing)` raises it too. A failed statement rolls back
  the effects of the arguments before it.
- A `null` or undefined receiver keeps the accepted route: the call is
  undefined and the arguments are not evaluated, so after `u = null`,
  `u.reversed(missing)` is undefined.

### Liveness and class-level rules

- While its receiver is a list, a population or a string, a declaration
  that calls an alias depends on what its spelling depends on: pushes, pops,
  shifts, sorts and replacements of a list's name or property, new and
  deleted instances of a population, writes of a string's name, property or
  instance property, and the operands of a template re-evaluate it.
  `(why undo)[0].from` is `["history"]` after `undo = history.reversed()`,
  as after `undo = history.reverse()`, `(why home)[0].from` is `["$Stop"]`
  after `home = Stop.reversed()`, and `(why m)[0].from` is `["word"]` after
  `m = word.reversed()`, as after `m = word[::-1]`. The nodes, sources,
  values and states of the `why` and `affects` steps are the spelling's;
  only their rules name the call as written.
- In a class-level rule or conditional each instance evaluates its own
  alias over its own properties, and a write of the property re-evaluates
  that instance's rule.

### Per evaluation

- An alias equals its spelling while its receiver evaluates to a list, a
  population or a string. When a later write replaces a held receiver with
  another kind of value, the re-evaluated call reads its name on that
  value, as [Calls](#calls) says for every other receiver. After
  `xs = [1, 2]` and `ys = xs.NAME()`:

| Later write | `reversed()` | `toReversed()` | `reverse()` |
| --- | --- | --- | --- |
| `xs = [3, 4, 5]` | `ys` is `[5,4,3]` | The same | The same |
| `xs = "abc"` | `ys` is `"cba"` | `TypeError("abc.toReversed is not a function")` at the write, which rolls back | `ys` is `"cba"`; at the accepted revision `TypeError("abc.reverse is not a function")`, which rolled back |
| `xs = 5` | `TypeError("number.reversed is not a function")`, which rolls back | `TypeError("number.toReversed is not a function")`, which rolls back | `TypeError("number.reverse is not a function")`, which rolls back |
| `xs = false`, `xs = Date(0)` or `xs = x -> x` | The `boolean`, `Date` or `function` error of the name, which rolls back | The same | The same |
| An object whose member of the name is a function | It runs: `ys` is its result | The same | The same |
| `xs = {other: 1}` | `ys` is `null`, read from `xs` and the object's `reversed` | `null`, from `xs` and `toReversed` | `null`, from `xs` and `reverse` |
| `xs = null` | `ys` is `null` | The same | The same |

- After `s = "ab"` and `t = s.NAME()`, against `t = s[::-1]`:

| Later write | `reversed()` | `reverse()` | `[::-1]` |
| --- | --- | --- | --- |
| `s = "xyz"` | `t` is `"zyx"` | The same | The same |
| `s = [1, 2]` | `t` is `[2,1]` | The same | The same |
| `s = 5` | `TypeError("number.reversed is not a function")`, which rolls back | `TypeError("number.reverse is not a function")`, which rolls back | `t` is `null` |
| `s = true`, `s = Date(0)` or `s = x -> x` | The `boolean`, `Date` or `function` error of the name, which rolls back | The same | `t` is `null` |
| `s = {reversed: () => "own"}` | `t` is `"own"` | `t` is `null` | `t` is `null` |
| `s = {reverse: () => "mine"}` | `t` is `null` | `t` is `"mine"` | `t` is `null` |
| `s = {other: 1}` | `t` is `null` | The same | The same |
| `s = null` | `t` is `null` | The same | The same |

- In both tables, every program whose declaration calls `reversed()` or
  `toReversed()`, or calls `reverse()` on a string, raised that alias's
  `TypeError` at the declaration at the accepted revision. The `reverse()`
  column of the first table keeps its accepted results apart from the
  `xs = "abc"` row, whose write raised
  `TypeError("abc.reverse is not a function")` and rolled back, and the
  `[::-1]` column of the second is unchanged. So none of these differences
  changes an accepted result that was not an error.

### Transactions

- Errors of an alias's readers propagate through the existing transaction,
  so a failed standing re-evaluation rolls back the change that triggered
  it, and a failed statement or transaction restores declarations that call
  aliases, their values and their dependencies. This program is the
  specification entry
  `Nucleoid rolls back failed updates through reversal aliases`:

```
def latest(log):
    if log.length > 3:
        throw "FULL"
    return log
entries = ["boot", "sync"]
recent = latest(entries.reversed())
failure = ""
try:
    entries.push("scan", "send")
catch error:
    failure = error
assert([failure, entries, recent], ["FULL", ["boot", "sync"], ["sync", "boot"]])
try:
    entries.push("scan")
    assert(recent, ["scan", "sync", "boot"])
    throw "UNDO"
catch error:
    assert(error, "UNDO")
assert([entries, recent], [["boot", "sync"], ["sync", "boot"]])
def short(text):
    if text.length > 4:
        throw "LONG"
    return text
class Tag(label):
    this.label = label
$Tag.code = short($Tag.label.reversed())
tag = Tag("AB12")
try:
    tag.label = "ABC123"
catch error:
    failure = error
assert([failure, tag.label, tag.code], ["LONG", "AB12", "21BA"])
tag.label = "XY9"
tag.code
```

- This returns `"9YX"`. A property written a number under
  `$Tag.mirror = $Tag.label.reversed()` raises
  `TypeError("number.reversed is not a function")` and rolls back too.

### Rendering and graph keys

- Statements, `why`, `affects`, `--graph` and graph and block keys show the
  call in the canonical rendering of every call, with its name as written:
  after `undo = history.reversed()`, `(why undo)[0].rule` is
  `"undo = history.reversed()"`, where the spelling's is
  `"undo = history.reverse()"`, and `$Train.rear = $Train.cars.toReversed()`
  renders as `$Train.rear=$Train.cars.toReversed()`. A class-level `if`
  whose condition calls an alias names it in the block key that `--graph`
  prints.
- `--graph` lists `undo [variable]` reading `history` and
  `mirror [variable]` reading `word`, as for the spellings.

### Cost

- Each list alias is one more name in the pattern of the accepted
  `reverse` arm, so a call runs exactly the code of `reverse()`:
  `list_query` receives the items the receiver read, reverses that copy in
  place and returns it. Each string alias collects the receiver's
  characters in reverse order into a new string in one pass, where `[::-1]`
  first collects them into a vector of characters and then walks it
  backward.
- **Spot check in phase 1**, not a benchmark: on `nucleoid-phase1.exe`, the
  phase-1 release build, and the accepted revision's release build,
  through the command line with `--json`, rustc 1.97.1, the median of seven
  interleaved runs of each program, including process start, one process
  at a time with nothing else running, each run capped at 1.5 GB and 120
  seconds.
  Times are in milliseconds, with the spellings of the accepted revision
  run on its own build.
  - "One call" reverses once: the 100,000 items of
    `"x".repeat(100000).split("")`, the 100,000 characters of
    `"abc😀".repeat(25000)`, or the 100,000 instances that a `while` loop
    creates; "Build" is the same program without the reversal.
  - "Standing" declares the reversal and then pushes 100 items, or writes
    the string 100 times, from a `while` loop, so that every write
    re-evaluates it; "Build" declares the length instead.

| Program | Build | `reversed()` | `toReversed()` | `reverse()` | `reverse()`, accepted | Build, accepted |
