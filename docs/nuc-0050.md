```

Type: Standards Track

Created: 25-Oct-2026
```

## Abstract

- Add only unshadowed static `Math.toRadians(value)`.
- Intrinsically convert the first input, divide intrinsic `f64` PI by `180.0`,
  then multiply the input by that factor, in that order.
- Preserve accepted arithmetic, numeric controls, call evaluation, reactive
  reads, shadowing, deferral and transactional recovery.

## Motivation

- Name a common, bounded numeric conversion without repeating its factor
  in live headings, class rules and ordinary expressions.
- Retain complete examples, independent numeric/assertion controls and
  expected returns rather than weakening demonstrations to shorten them.

## Rationale

- The caller's one unbiased registry draw selected index `2`,
  `Utility enhancement`; use that confirmed category without a redraw.
- Degree conversion is expressible in accepted arithmetic and fits the
  existing static Math route without new syntax or a runtime representation.
- Division before multiplication is observable: multiplying a finite maximum
  by PI first overflows, whereas multiplying by the precomputed factor does not.
- Ordinary `f64` division and multiplication preserve the accepted composition's
  rounding, signed zeros and nonfinite classification; no higher precision,
  normalization, rescaling, clamping or input shortcut is appropriate.
- Reuse Math's existing first-input conversion and supplied-Undefined gate.
  Do not resolve or invoke shadowable `Number` or `Math.PI` bindings.
- Reject aliases, `Math.toDegrees`, first-class Math method values, extra
  configurability, dependencies and public API/type changes from this scope.
- Depend only on already accepted arithmetic, calls, classes and transactions,
  not another pending proposal.

## Specification

### Numeric and call contract

- The authoritative [degree-conversion section](../nucleoid.spec.md#reactive-degree-to-radian-conversion)
  and its six entries specify the implemented contract and take precedence.
- Evaluate every supplied expression exactly once left to right per call,
  including ignored extras and expressions after Undefined.
- If any supplied value is Undefined, including an ignored extra, return
  Undefined before conversion. Keep all expression reads, dependencies,
  effects, strict errors and deferred property deletion/recovery.
- Otherwise use the dispatcher's existing intrinsic `Value::to_number`
  conversion for the first input. Omission supplies numeric NaN.
- Numbers retain their values; literal null becomes zero; booleans, trimmed
  strings, empty/singleton lists and dates retain their existing conversion.
  Other nonnumeric conversions yield numeric NaN, not a new type error.
- Compute `factor = std::f64::consts::PI / 180.0`, then `result = first * factor`,
  using exactly those separate ordinary `f64` operations. Do not compute
  `(first * PI) / 180`.
- Finite maxima remain finite. Zero signs and subnormal rounding, including
  underflow to signed zero, match independent accepted binary controls.
  Infinities retain their signs; numeric NaNs remain NaN.
- Compare expected NaNs by classification, never payload bits; every
  non-NaN result, including zero, agrees with division-first arithmetic by bits.
- Ignore extra resulting values numerically without converting them.
  Intrinsic literal-null conversion does not override live assignment or
  parameter-null deferral.
- Conversion and the factor never resolve, invoke or track shadowable
  `Number` or `Math.PI`. State/local Math bindings and ordinary `.Math`
  members keep their existing lookup routes.
- Reading `Math.toRadians` as a value remains unsupported/Undefined, like
  existing static Math method reads, not a callable reference.
- Wrappers, receivers, frames, scopes, independent class rules, subscriptions,
  caught values, error positions, rollback and recovery use unchanged machinery.
- All sibling Math arms, constants, helpers and accepted syntax remain
  unchanged. The accepted `value * (Math.PI / 180)` remains available.
- New call RHS ASTs and graph rule-source strings intentionally differ
  from arithmetic counterparts; protect observations and transitive behavior,
  not whole-new-program AST or immediate-graph equality.

```nuc
degrees = 180
converted = Math.toRadians(degrees)

degrees = 360
assert(converted, Math.PI * 2)
degrees = 0

degrees = -0
```

## Errors

- Introduce no numeric, conversion, range or arity error.
- Omitted inputs, numeric NaN and nonfinite results are not errors.
- Argument/application failures keep their inherited kinds, exact messages,
  statement positions, caught values and transactional recovery.
- Never skip an argument expression because an earlier supplied value is
  Undefined; a later expression can still raise its ordinary error.

| Condition | Exact inherited error |
| --- | --- |
| Strict unknown argument `missing`, including extras or after Undefined | `ReferenceError("missing is not defined")` |
| Unsupported static `Math.random()` argument | `TypeError("Math.random is not supported")` |
| Unknown static `Math.unknown()` | `TypeError("Math.unknown is not a function")` |
| Excluded static `Math.toDegrees(180)` | `TypeError("Math.toDegrees is not a function")` |
| Calling through numeric state `Math = 7` | `TypeError("number.toRadians is not a function")` |

- Existing unknown/random Math dispatch still uses the supplied-Undefined
  gate; ordinary shadowed receivers keep their own existing method errors.
- User throws propagate unchanged, including `"ANGLE_ROLLBACK"` in the
  normative transaction entry, and restore its prior relationship.
