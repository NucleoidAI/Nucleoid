## Abstract

- Propose optional `def add left right:` before a genuine indented statement
  suite, exactly equivalent to accepted `def add left, right:` with that body.
- Require at least two wholly untyped ordinary identifiers; omit every parameter
  comma or none, retaining the final colon and existing real-indentation guard.
- Preserve all accepted syntax and behavior; introduce no new function,
  implicit return, runtime capability, representation or resource bound.
- Accepted after a fresh independent R2 evaluation with no per-case token
  increase; the outcome below records the unchanged evaluated contract.

## Motivation

- Extend the existing optional comma-free named-arrow spelling to ordinary
  named indented blocks without changing their statement-suite semantics.
- Keep multi-statement bodies, branches, initializers and explicit returns
  readable without repeating separators between simple untyped names.
- Retain every comma-bearing and parenthesized alternative as a supported form.
- Fill the remaining ordinary named-block ergonomics gap beside expression
  arrows, without adding a runtime utility, namespace, callable API or AST form.
- Complete this already-selected pending feature before choosing a distinct
  enhancement; this R2 policy-only rebase is not another enhancement selection.
- Apply all-around priorities to future selections: review recent coverage,
  unmet user needs, expressiveness and API cost, preferring underrepresented
  areas when value is comparable rather than convenient helper variants.
- Keep math eligible without a ban, quota, forced rotation or category redraw.

## Rationale

- Reuse the existing allocation-free complete identifier-run scan rather than
  inventing a second parameter grammar or speculative parse.
- Qualify the entire header and genuine indentation before consuming a name;
  a valid prefix of an invalid header must not change its fallback diagnostic.
- Require the final colon to distinguish a statement suite from an expression
  arrow, and leave that colon to unchanged `suite()`.
- Share the existing checked-untyped-parameter handling so a final suite colon
  cannot become a type annotation.
- Keep the NUC37 helper arrow-only; its new block counterpart checks the exact
  real-layout guard already used by comma-bearing bare blocks.
- Reject partial comma omission, comma-free annotations and other callable
  grammars: they would expand this bounded spelling change.
- Depend only on accepted NUCs; combine no pending proposal or runtime repair.
- Preserve the original single draw of `0`, syntax improvement, and its complete
  grammar, behavior and corpus boundaries; the new all-around selection policy
  does not redraw or broaden this pending feature.

## Specification

### Complete header and body

- The authoritative
  [comma-free bare indented blocks section](../nucleoid.spec.md#comma-free-bare-indented-blocks)
  defines the contract and takes precedence over this proposal.
- After unchanged `Def` and the required ordinary definition name, inspect the
  complete immediate `Identifier Identifier Identifier* Colon` prefix.
- Require at least two ordinary identifiers and no annotations, commas,
  logical layout or other punctuation within that parameter run.
- Spaces and horizontal tabs may separate names; comments cannot bridge a
  logical newline, semicolon, indent or dedent in the header.
- The final colon is required, immediately followed by `Newline` or `Indent`.
- After only the previously accepted `Newline`/`Semicolon` separators from
  that initial body break, require a genuine `Indent`.
- A same-line semicolon after the colon never qualifies, even if a later
  physical line is indented; blank/comment lines use existing suite rules.
- Consume no tokens, allocate no parameter names and skip no header layout
  until the complete list, colon and real-indentation guard have qualified.
- On success consume only ordered checked-untyped names as
  `Parameter { name, type_name: None }`, retaining duplicate binding order.
- Leave the final colon for unchanged `suite()` and retain the same name,
  complete named `FunctionBody::Block`, AST/typed metadata and canonical source.
- Reuse existing block execution, including nested definitions, multi-statement
  bodies, branches and accepted inline/braced statements inside the suite.
- Explicit `return`, bare `return` and absent returns retain their existing
  meanings; bare and absent returns yield `null`, never an implicit expression.
- Apply the same guard at module scope, nesting, methods, `init` and redefinition.
- Keep flat parameter lists uncapped, including 1,024 names; expression,
  statement nesting and postfix/operator chain bounds remain unchanged.

### Compatibility and exclusions

- Keep `def add left, right:` and `def add(left, right):` with the identical
  body fully supported and equivalent to the new optional spelling.
- Preserve all accepted typed/mixed, single/nullary, parenthesized,
  trailing-comma/multiline parameter and arrow forms, including NUC37 arrows.
- Omit all parameter commas or none; retain commas in typed/mixed headers.
- Add no colon-free bare blocks, mixed omission, comma-free typed/mixed
  lists, parenthesized/anonymous/call/class comma omission, inline/braced
  bare suites, defaults/rest/destructuring, return annotations or bare nullary form.
- Preserve every body byte and all list/object/template, anonymous-function,
  call, class and return-expression punctuation.
- Preserve arity, missing/null/extra inputs, parameter assignment, variable
  and callable shadowing, noncapture, caller scopes/frames and callbacks.
- Preserve receiver/init/adoption behavior, `this`/`self`, explicit and bare
  `super`, live aliases, definition/value snapshots and redefinition.
- Preserve observable values, canonical graph source, keys, read dependencies,
  dependency/dependent order, propagation, reasoning and executed assertions.
- Preserve error types/messages/positions, transactions, actual caught and
  uncaught rollback and subsequent recovery.
- Preserve native LF/CRLF/tab file bytes, structured errors, literal EOF,
  stdin/REPL pending input, blank-line commit and error recovery.
- Preserve the inherited REPL's physical-line-end colon detection: a trailing
  colon-header comment does not start buffering there, while file parsing
  still accepts it. This proposal does not repair that framing limitation.
- Add no lexer token, public AST/API, generator/runtime representation,
  dependency, Cargo/version/MSRV/edition or CLI implementation change.
- Do not repair inherited method lookup, noncapture, parameter-dependent-local,
  Windows debug-stack or old whole-suite Git-absent discovery limitations.

## Errors

- Introduce no new error kind or message and no arity/type-validation rule.
- Failed prefixes consume nothing and retain the accepted fallback position.

| Exact condition | Exact inherited error |
| --- | --- |
| `def f left right`, incomplete `def f left right:` or no genuine indent | `SyntaxError("Expected '(' but found identifier 'left'")`, line 1, column 7 |
| `def f left right: return left`, bare brace suite, `:;`, mixed omission/types or logical header breaks | `SyntaxError("Expected '(' but found identifier 'left'")`, line 1, column 7 |
| `def f this right:` before a real indented body | `SyntaxError("Expected '(' but found keyword 'this'")`, line 1, column 7 |
| Newline immediately after `def f` | `SyntaxError("Expected '(' but found end of line")`, line 1, column 5 |
| Semicolon immediately after `def f` | `SyntaxError("Expected '(' but found ';'")`, line 1, column 6 |
| `def f(left, right:):` | `SyntaxError("Expected a type but found ')'")`, line 1, column 20 |
| Four-space `return left +)` after a qualifying header | `SyntaxError("Unexpected ')'")`, line 2, column 19 |
| Four-space `return { left = 1 }` after a qualifying header | `SyntaxError("Expected ':' but found '='")`, line 2, column 19 |
| Four-space `return @` after a qualifying header | `SyntaxError("Unexpected character '@'")`, line 2, column 12 |
| `def f left right:` with body `return missing`, then `f(2, 3)` | `ReferenceError("missing is not defined")`, line 3, column 1 |

- Lexical errors still precede parsing. User throws, caught values, runtime
  body positions and existing bound errors use unchanged machinery.
