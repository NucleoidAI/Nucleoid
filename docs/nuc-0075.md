# NUC 75 -- List and Population Modes

```

Author: Claude <noreply@anthropic.com>
Status: Accepted
Type: Standards Track
Category: Utility enhancement
Created: 02-Nov-2026
Requires: 8, 12, 18, 45, 57, 59, 60, 61, 68, 69, 71
```

## Abstract

- Lists and class instance lists gain the read-only query `mode`.
  `RECEIVER.mode()` returns the receiver's most frequent item, and
  `RECEIVER.mode(selector)` returns the most frequent value of
  `selector(item)`, so `xs.mode(f)` equals `xs.map(f).mode()`.
- Items are counted against the values that `distinct` keeps, under the deep
  equality of `assert`, `includes` and `indexOf`
  ([NUC 61](nuc-0061.md), [NUC 71](nuc-0071.md)). The result is the first
  occurrence of the most frequent value, unchanged. On a tie, the value that
  occurs first wins, so `[3, 4, 4, 3].mode()` is `3`, as Python's
  `statistics.mode` returns the first mode it meets. An empty receiver gives
  undefined, which a declaration stores as `null`.
- The selector, receiver, argument and liveness rules are those of `sum`,
  `max`, `min` and `distinct`. The selector is called once per item with only
  the item, and a supplied first argument that is not a function raises
  `TypeError("mode expects a function")`. Declarations and class-level rules
  that use `mode` stay live.
- At the accepted revision these calls raise
  `TypeError("<receiver>.mode is not a function")`. No syntax, keyword, token,
  error type or public Rust API is added. The authoritative contract is
  [List and population modes](../nucleoid.spec.md#list-and-population-modes).
- **Outcome: Accepted.** The user requested this feature directly. The
  independent evaluation and the caller's integrated-tree checks passed all
  three hard criteria, the independent evaluator decided Accepted, and no
  policy check failed. Token comparison was skipped as `single_proposal`.

## Motivation

- World models ask for the most common value of a collection: the size most
  orders request, the choice most votes make, the defect a production line
  sees most, the room most visits go to. Each has to stay true while the
  collection changes.
- In accepted syntax, the most frequent item of a list `xs` takes three
  declarations: a sorted copy, a run length for every item and an index
  search.

```
sorted = xs.slice().sort()
counts = xs.map(x => sorted.lastIndexOf(x) - sorted.indexOf(x) + 1)
xs[counts.indexOf(counts.max())]
```

- The workaround is quadratic, because every item searches the whole sorted
  copy twice. A population needs a fourth declaration that maps its values
  into a list first.
- It is also wrong whenever different values share a string form. `sort`
  orders items by their string forms, so equal values need not be adjacent,
  and the run length becomes a span rather than a count. For
  `xs = [1, "1", "1", "1", 1]`, `counts` is `[5, 3, 3, 3, 5]` and the
  workaround picks `1`, although `"1"` occurs three times and `1` twice.
- The direct spellings are unavailable at the accepted revision:
  - `xs.map(x => xs.count(y => y == x))` raises
    `ReferenceError("x is not defined")`, because a callback does not capture
    the parameters of an enclosing callback or function;
  - a value form of `count`, such as `xs.count(4)`, raises
    `TypeError("count expects a function")`, which `tests/list_counts.rs`
    pins;
  - `xs.max(selector)` returns the largest selected number
    ([NUC 69](nuc-0069.md)), never the item.
- `xs.mode()` states the rule in one query, and
  `Order.mode(order -> order.size)` keeps a population's most common value
  live. Python's `statistics.mode` and PostgreSQL's `mode()` aggregate name
  the operation the same way.
- NUC 68, 69, 71 and 73 added the totals, extremes, distinct values and
  predicate counts of lists and populations. This NUC adds their most
  frequent value with the same receivers, selector and liveness rules.

## Rationale

- **Category and mode.** The user requested this concrete feature, so the
  caller confirmed the Utility enhancement category, standard built-in
  helpers for collections, without a random draw. The request runs in
  single-proposal mode: token comparison is skipped as `single_proposal`,
  while baselines, behavior, integrity, compatibility and development checks
  all remain. Runtime applicability does not apply to this category.
- **One more shared query.** `mode` is an operation of the read-only list
  query that serves `map`, `filter`, `sum`, `max`, `min`, `distinct` and
  `count`. Lists, list properties, call results such as `filter(...)`,
  `map(...)`, `flatMap(...)` and `slice(...)`, ranges, `.value` snapshots,
  selected versions, class instance lists and `Name.list()` therefore accept
  it through one implementation, with the receiver, argument and liveness
  rules they already share.
- **Counted against `distinct`.** An item that no value kept before it
  matches is kept and counts once for itself. Every other item counts once
  for the earliest kept value that matches it, compared as
  `kept.includes(item)` compares. Every item counts exactly once, the mode
  of a nonempty list is always one of the values `xs.distinct()` keeps, and
  `mode`, `distinct`, `includes`, `indexOf` and `assert` never disagree about
  what a repeat is.
- **The first occurrence, unchanged.** The result is the kept value itself,
  never a copy: an object stays the same object, so `records.mode() == first`
  holds by identity, `[-0, 0].mode()` is `-0`, `[null, xs[9]].mode()` is
  `null` and `[xs[9], null].mode()` is undefined.
- **Ties go to the value that occurs first.** Among values with the same
  count, the one whose first occurrence comes first in receiver order wins:
  `[3, 4, 4, 3].mode()` is `3`. Python's `statistics.mode` has returned the
  first mode it meets since Python 3.8, and over correct counts the index
  formula `xs[counts.indexOf(counts.max())]` picks the same item, because
  `indexOf` finds the first item with the highest count. The result never
  depends on hashing or sorting.
- Rejected: the last tied value, which neither Python nor the index formula
  returns; the smallest, which needs an order that strings, records and mixed
  kinds have only through a conversion `mode` never makes; and every tied
  value, which is Python's `statistics.multimode`, a different query that
  this NUC does not add.
- **Where deep equality forms groups, the counting definition holds.** For
  numbers other than NaN, strings, booleans, dates, `null`, undefined, classes
  and instances, and for lists and records built from them, nested at most 64
  levels, in which no record holds an undefined-valued property, deep
  equality sorts the items into groups. The result is then the item that
  `xs[counts.indexOf(counts.max())]` picks, where `counts[i]` is the number of
  items that match `xs[i]`.
- **Elsewhere, `distinct` decides.** Deep equality has values that match
  nothing and matches that hold in one direction only. A count per item is
  then ill-defined: it depends on the direction of each comparison and can
  name an item that is not a first occurrence. Counting against the kept
  values of `distinct` gives one answer for every list:
  - NaN, functions and regular expressions match nothing, not even
    themselves, so each is a value of its own that occurs once, as `distinct`
    keeps each of them: `[0 / 0, 0 / 0, 1].mode()` is the first NaN, three
    values tied at one, while `[1, 0 / 0, 1].mode()` is `1`;
  - after `a = {k: null, m: 1}` and `b = {k: {}.none, m: 1, z: 5}`,
    `[a].includes(b)` is `true` and `[b].includes(a)` is `false`, so
    `[a, b].mode()` is `a`, which `b` repeats, and `[b, a].mode()` is `b`, two
    values tied at one, as `[a, b].distinct()` keeps one value and
    `[b, a].distinct()` keeps two;
  - an item that matches several kept values counts only for the earliest,
    so counts never add up to more than the items: after
    `c = {l: null, m: 1}` and `d = {k: {}.none, l: {}.none, m: 1, z: 5}`,
    both `a` and `c` match `d`, and `[a, c, c, d].mode()` is `a`, tied with
    `c` at two;
  - a list nested more than 64 levels deep matches nothing, not even itself,
    while an object always matches itself.
- Rejected: counting an item that matches nothing as zero occurrences, under
  which `[0 / 0, 1].mode()` would be `1`. Every item occurs at least once,
  whatever it matches, as `statistics.mode([nan, 1])` returns `nan` in
  Python. Also rejected: SameValueZero, which treats NaN as one value and
  would make `mode` and `distinct` disagree, and counting an item for every
  kept value it matches, which counts it more than once.
- **Compared, never converted.** `mode` is an equality query like `distinct`
  and `includes`, not a numeric query like `sum` and `max`:
  `[1, "1", "1", true, true].mode()` is `"1"`, and a date matches the number of
  its milliseconds, as it does in `includes`.
- **`null` and undefined are one value.** Deep equality matches them, so they
  count together, and the first of them is the result when their count is the
  highest. An undefined item or selector result counts like any other value.
- Rejected: the undefined gate of `sum`, `max` and `min`, under which one
  missing value would make the whole result undefined. Those queries do
  arithmetic, where an unknown operand makes an unknown result; `mode`
  counts.
- **An empty receiver gives undefined.** Nothing is most frequent in nothing.
  Undefined is also what the workaround reads, as `xs[-1]` of an empty list,
  and a declaration stores it as `null`, so `top = sizes.mode()` reads `null`
  until `sizes` gains an item and then re-evaluates.
- Rejected: raising an error, as Python's `statistics.mode([])` raises
  `StatisticsError`. A declaration over a list or population that starts
  empty would then fail when it is declared.
- **Comparisons do not subscribe.** As for `distinct` and `includes`, a
  comparison reads the objects it compares without subscribing to their
  properties. A declaration that uses `mode` follows its list or population,
  its argument expressions and what the selector reads, so after
  `first = {k: 1}`, `records = [first, second, second]` with
  `second = {k: 2}`, and `common = records.mode()`, setting `first.k = 2`
  leaves `common` at `second` until the list itself changes.
- Rejected: subscribing to every property of every compared object, which
  would make each mode depend on whole records and differ from `distinct`.
  Records whose fields matter are better selected:
  `records.mode(record -> record.k)` reads `k` and stays live.
- **No artificial null read.** `mode()` reads items, not bindings, so a
  `null` item is counted and does not settle a declaration to `null`, as in
  `distinct()`. A selector's own reads follow the existing rules:
  `values.mode(value -> value)` over a `null` item settles a declaration to
  `null`, as the same callback does in `map`.
- **The selector selects values, as in `sum`, `max`, `min` and `distinct`.**
  `Order.mode(order -> order.size)` is the most common size, and for every
  selector `xs.mode(f)` equals `xs.map(f).mode()`.
- Rejected: returning the first item whose selected value is the mode, as a
  `maxBy`-style key would. A selector would then mean a value in `sum`, `max`,
  `min` and `distinct` but a key in `mode`. The item stays reachable with
  accepted queries, as
  `Order.find(order -> order.size == Order.mode(each -> each.size))`.
- **The selector is called like `map`'s callback.** It runs once per item, in
  order, with only the item; further parameters stay `null`. Every item is
  visited, so every item's reads are dependencies.
- **A supplied selector must be a function.** Any other first argument,
  including `null`, raises `TypeError("mode expects a function")` after the
  arguments are evaluated, even on an empty receiver, as `sum`, `max`, `min`
  and `distinct` raise for theirs. A two-parameter function is still a
  selector and receives `null` as its second argument.
- **Extra arguments** are evaluated once, left to right, and ignored, as
  every list query does.
- **Instance lists.** On a class name, `Name.mode(...)` is the population
  query even when the class declares an instance method `mode`, as for
  `distinct` and `count`. The method stays reachable through each instance,
  and `Shelf.mode(each -> each.mode())` is the most common of its results.
- **Bounded cost.** `mode` reuses the structural-hash index of `distinct`
  rather than comparing every item with every other. Each value is hashed
  once and compared with deep equality only against kept values with the
  same hash and, for an object holding an undefined-valued property, against
  the kept objects that hold a `null` property and as many defined
  properties. Those candidates are compared in receiver order, and the search
  stops at the first match. A call therefore makes at most one comparison per
  pair of a value and a kept value, at most `n * k` comparisons for `n` values
  and `k` kept values. Choosing the result then reads the `k` counts once.
- For numbers, strings, booleans, dates, `null`, undefined, classes, lists of
  them, and instances and records of them that hold no undefined-valued
  property, deep-equal values share a hash and different ones almost never
  do, so a call makes one comparison per repeat and none per new value.
- Two kinds of input cost more, within the same bound:
  - values whose hashes coincide share a bucket: records holding nested
    objects, lists of records or instances, and lists nested more than eight
    levels deep. Their worst case is one comparison per pair,
    `n(n - 1) / 2` for `n` different values, as NUC 71's evaluation recorded
    for `distinct`;
  - a record holding an undefined-valued property is also compared with
    every kept `null` holder of its size that comes before its match. After
    100 kept records `{k: null, x: i}` and a kept `{m: 1, z: 5}`, every repeat
    `{q: {}.none, m: 1, z: 5}` of that record costs 101 comparisons, where
    `distinct`, which tries the value's own hash first, needs one.
- Both stay below the two full searches per item that the workaround makes.
- Rejected: the plain scan that compares each item with every kept value. It
  gives the same results but needs about 200 million comparisons for 20,000
  different numbers, where the index needs none.
- **One index for `distinct` and `mode`.** Both queries file their kept
  values in the same structural-hash index, so they keep the same values;
  only the search differs. `distinct` drops a value at any match, so it keeps
  NUC 71's search, which tries the values of the same hash first, and every
  `distinct` result and comparison count equals the accepted
  implementation's. `mode` must credit the earliest match, so it merges the
  same candidates in receiver order and counts the repeats of each kept
  value.
- Rejected: one receiver-order search for both queries. It changes no
  `distinct` result, but `distinct` would then compare each repeat of a
  record holding an undefined-valued property with every earlier `null`
  holder of its size: 10,100 comparisons instead of 100 for the input above
  with 100 repeats.
- **Not added.** A global `mode(...)`, `multimode`, `maxBy` and `minBy`, a
  value form of `count`, capture of enclosing parameters by callbacks,
  frequency maps and grouping queries, the most frequent character of a
  string, and a tie-breaking argument.

## Specification

### Most frequent values

- `RECEIVER.mode()` returns the receiver's most frequent item.
  `RECEIVER.mode(selector)` returns the most frequent value of
  `selector(item)` the same way, so it equals `RECEIVER.map(selector).mode()`.
- Items are counted against the values `distinct` keeps. An item that no
  value kept before it matches, under the deep equality of `assert`,
  `includes` and `indexOf` compared as `kept.includes(item)` compares, is
  kept and counts once for itself. Every other item counts once for the
  earliest kept value that matches it.
- The result is the kept value with the highest count, unchanged. Among kept
  values with the same count, the one that comes first in receiver order
  wins.
- The receiver is a list, however it is reached: a variable, a property, a
  call result such as `filter(...)`, `map(...)`, `flatMap(...)`,
  `slice(...)` or `concat(...)`, a range, a literal, a `.value` snapshot or a
  selected version. It may also be a class's instance list, named by the
  class or by a variable that holds the class, in population order; a range
  of one and `Name.list()` are lists.
- An empty receiver gives undefined, which a declaration stores as `null`.

```
sizes = ["M", "S", "M", "L"]
top = sizes.mode()
assert: top, "M"
sizes.push("L")
sizes.push("L")
assert: top, "L"
sizes = []
assert: top, null
sizes = [3, 4, 4, 3]
assert: top, 3
```

```
class Vote(choice, round):
    this.choice = choice
    this.round = round
favorite = Vote.mode(vote -> vote.choice)
assert: favorite, null
first = Vote("tea", 1)
Vote("coffee", 1)
second = Vote("coffee", 2)
late = Vote.filter(vote -> vote.round > 1).mode(vote -> vote.choice)
assert: favorite, "coffee"
second.choice = "tea"
assert: favorite, "tea"
assert: late, "tea"
```

### Equality

- Values are compared, never converted. Numbers, strings, booleans, dates,
  lists, objects and classes are different values unless deep equality
  matches them: `1`, `"1"` and `true` are three values, and a date matches the
  number of its milliseconds.
- `null` and undefined are one value, and the first of them is the one
  returned. An undefined item or selector result counts like any other
  value.
- `0` and `-0` are one value, and the first is returned with its sign.
- NaN, functions and regular expressions match nothing, so each one is kept
  and counts once.
- Lists match when they have the same length and their items match in order.
  Objects match when they hold matching values for the same defined
  properties, in any order. Every instance holds its own `id`, so distinct
  instances never match each other.
- The quirks of deep equality carry over exactly:
  - after `a = {k: null, m: 1}` and `b = {k: {}.none, m: 1, z: 5}`,
    `[a, b].mode()` is `a` and `[b, a].mode()` is `b`, as `[a].includes(b)` is
    `true` and `[b].includes(a)` is `false`;
  - an item that matches several kept values counts only for the earliest;
  - a record holding an instance's `id` and fields matches that instance;
  - a list nested more than 64 levels deep matches nothing, not even itself,
    while an object always matches itself.
- When deep equality sorts the items into groups, as it does for numbers
  other than NaN, strings, booleans, dates, `null`, undefined, classes and
  instances, and for lists and records built from them, nested at most 64
  levels, in which no record holds an undefined-valued property, the result
  is the item that `xs[counts.indexOf(counts.max())]` picks, where
  `counts[i]` is the number of items that match `xs[i]`.
- A comparison reads the objects it compares without subscribing to their
  properties. A declaration that uses `mode` follows its list or population,
  its argument expressions and what the selector reads; changing a property
  of a compared object does not re-evaluate it.
- `mode()` reads items, not bindings: a `null` item is counted without
  settling a declaration to `null`. Reads inside a selector follow the
  existing rules, so a selector that reads a `null` binding or property
  settles a declaration to `null`.

```
inputs = [2, "2", true, "2", 2]
common = inputs.mode()
assert: common, 2
inputs.push("2")
assert: common, "2"
signs = [-0, 1, 0, 1]
zero = signs.mode()
assert: String(1 / zero), "-Infinity"
readings = [0 / 0, 0 / 0, 5]
level = readings.mode()
assert: String(level), "NaN"
readings.push(5)
assert: level, 5
held = {k: null, m: 1}
gap = {k: {}.none, m: 1, z: 5}
records = [held, gap]
kept = records.mode()
assert: kept == held, true
records = [gap, held]
assert: kept == gap, true
```

### Selectors

- A selector is called once for every item, in order, with the item as its
  only argument; further parameters are `null`. The call order and the
  argument are those of `map`, and `RECEIVER.mode(selector)` equals
  `RECEIVER.map(selector).mode()`.
- A supplied first argument that is not a function, including `null`, raises
  `TypeError("mode expects a function")`, even on an empty receiver.
- Every supplied argument, including unused extras, is evaluated once, left
  to right, after the receiver and before the first selector call.
- A null or undefined receiver keeps the existing method-call route: the call
  yields undefined without evaluating its arguments.

```
seen = []
def size(order, position):
    seen.push(position ?? order.id)
    return order.size
orders = [{id: 1, size: "M"}, {id: 2, size: "S"}, {id: 3, size: "S"}]
def common() => orders.mode(size)
assert: common(), "S"
assert: seen, [1, 2, 3]
limit = 2
def band order => order.id > limit ? "late" : "early"
phase = orders.mode(band)
assert: phase, "early"
limit = 0
assert: phase, "late"
```

### Liveness and transactions

- `mode` never writes its receiver. A declaration that uses it depends on the
  list or the population, on its argument expressions and on whatever the
  selector reads, as for `map`, `filter` and `distinct`, and not on the
  properties of the objects it compares.
- Pushing, popping, shifting or replacing a list, creating or deleting an
  instance, and changing a property that a selector reads re-evaluate the
  declaration.
- In a class-level rule, each instance evaluates its own mode, and `$Class`
  inside a selector or a filter is the instance the rule is evaluated for.
- Selector errors propagate through the existing transaction, so a failed
  standing re-evaluation rolls back the change that triggered it, including a
  list write or a new instance, and the list keeps its order.

```
class Team(name): this.name = name
class Vote(team, choice):
    this.team = team
    this.choice = choice
$Team.favorite = Vote.filter(vote -> vote.team == $Team).mode(vote -> vote.choice)
red = Team("red")
Vote(red, "tea")
swing = Vote(red, "coffee")
Vote(red, "coffee")
assert: red.favorite, "coffee"
swing.choice = "tea"
assert: red.favorite, "tea"
```

### Cost

- The receiver and the arguments are evaluated once per call, and the
  selector once per item.
- Each value is hashed once, by the structural key of `distinct` that
  deep-equal values share, and compared with deep equality only against kept
  values with the same key. An object that holds a property whose value is
  undefined is also compared with the kept objects that hold a `null`
  property and as many defined properties, the only values that can match it
  outside its key. NaN, functions and regular expressions match nothing and
  are kept without a comparison.
- The candidates are compared in receiver order, and the search stops at the
  first match, the earliest kept value that matches.
- A value is compared with each kept value at most once, so a call makes at
  most `n * k` comparisons for `n` values and `k` kept values. Choosing the
  result reads the `k` counts once.
- For numbers, strings, booleans, dates, `null`, undefined, classes, lists of
  them, and instances and records of them that hold no undefined-valued
  property, a call makes one comparison per repeat and none per new value.
  Records holding nested objects, lists of records or instances, and lists
  nested more than eight levels deep share hashes and can need one comparison
  per pair. A record holding an undefined-valued property is also compared
  with every kept `null` holder of its size that comes before its match.
- `distinct` files its kept values in the same index but keeps NUC 71's
  search, which tries a value's own hash first; its results and comparison
  counts are those of the accepted implementation.
- Unit tests count these comparisons exactly: none for 20,000 different
  numbers, one per repeat for 20,000 numbers modulo ten and for 20,000
  records with a `null` property in 100 groups, none for NaN, one for an item
  that matches two kept values, and 101 per repeat of a record holding an
  undefined-valued property after 100 non-matching `null` holders of its
  size, where `distinct` makes one.

### Compatibility

- Parsing, the syntax tree, canonical rendering and graph keys are unchanged;
  `mode` stays an ordinary method name. `top = values.mode()` renders as
  `top = values.mode()` in `why`.
- Every accepted case keeps its source, assertions, expected return and
  executed coverage. No accepted document, test or dataset record calls
  `mode` on a list or population.
- `distinct` keeps every result and every comparison count of the accepted
  implementation; it shares only the structural-hash index with `mode`.
- These are the result changes. "The orders" are `class Order(region):` with
  the body `this.region = region`, then `Order("n")`, `Order("s")` and

  `def mode(): return 9`, then `shelf = Shelf()`. Every accepted error was

## Reference Implementation

- `src/lang/ast/array.rs`: `list_query`, the read-only query shared by lists
  and class instance lists, gains `mode` beside `distinct`. It validates the
  optional selector with the shared `optional_selector`, whose message is
  `mode expects a function`, selects the values with the shared
  `Runtime::select_items`, once per item and in order, and returns
  `Runtime::mode_value` of them. Lists reach the query through
  `call_list_method` and populations through `call_class_method`, unchanged,
  so the receiver and the arguments are evaluated once by the existing routes
  and the null-receiver route stays in front of it.
- `src/lang/ast/object.rs`: NUC 71's two maps, the kept positions by
  `Runtime::equality_key` hash and the kept `null` holders by their number of
  defined properties, move into a private `EqualityIndex`.
  `EqualityIndex::candidates` returns the two ascending candidate sequences
  for a key, and `EqualityIndex::insert` files a kept position under it.
- `Runtime::distinct_by` keeps NUC 71's own search,
  `bucket.chain(loose).any(..)`, over that index, so `distinct` compares the
  same pairs in the same order as the accepted implementation and builds no
  tally.
- The private `Runtime::tally_by(values, matches)` uses the same index and
  keeps the same values. A small `ascending` iterator merges the two
  candidate sequences so that the search meets candidates in receiver order
  and stops at the earliest match, and a private `Tally` records each kept
  value and the number of values it stands for. The crate-private
  `Runtime::mode_value` returns `Tally::into_mode`: the kept value with the
  highest count, the earliest on a tie, or undefined for no values.
- Four unit tests in `src/lang/ast/object.rs` pin the tally and the two
  searches.
  - `the_mode_is_the_earliest_of_the_highest_counts` covers ties, an empty
    input and the sign of a kept `-0`.
  - `repeats_count_once_for_the_earliest_kept_value_they_match` counts one
    comparison for a record that both a `null` holder and a record of its
    hash could stand for, in either order, and for a record that two `null`
    holders match, crediting the earlier each time.
  - `a_tally_compares_each_repeat_once_with_the_value_it_repeats` counts
    19,991 comparisons for 20,000 numbers modulo ten plus one, none for
    20,000 different numbers, 19,900 for 20,000 records with a `null`
    property in 100 groups, and none for NaN.
  - `distinct_tries_the_hash_bucket_first_and_a_tally_tries_receiver_order`
    keeps the same 101 values both ways from 100 non-matching `null` holders
