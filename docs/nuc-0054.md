# NUC 54 -- Literal Parameter Defaults

```
NUC: 54
Title: Literal Parameter Defaults
Author: Can Mingir <canmingir@gmail.com>
Status: Accepted
Type: Standards Track
Category: Runtime features
Created: 26-Oct-2026
Requires: 53
```

## Abstract

- Add immutable scalar literal defaults to explicitly parenthesized
  user-defined formal parameter lists.
- Bind a default only for an absent argument position or constructor key;
  supplied values retain their existing semantics.
- Initialize the fresh parameter slot with its effective value, including its
  version-zero history, without an intermediate synthetic Null.
- The authoritative contract is
  [Literal parameter defaults](../nucleoid.spec.md#literal-parameter-defaults);
  independent acceptance is recorded in the evaluation section below.

## Motivation

- Repeated literal arguments obscure the argument that actually varies.
- A function, constructor or method can express its constant omitted value at
  the formal, while callers still supply explicit alternatives.
- Parameter histories must start with the value the body actually receives,
  rather than recording an implementation-only fallback write.
- The six specification entries from `Nucleoid fills omitted literal default
  parameters` through `Nucleoid restores defaulted function callers after
  failed redefinitions` preserve their pre-executed counterparts' observations.

## Rationale

- The caller read the live category registry and made one uniform
  `Get-Random` draw across its four eligible categories: index 1 selected
  **Runtime features**, with probability **1/4**. No redraw is performed.
- Literal defaults introduce core omitted-argument binding and initial
  storage-value semantics, not merely an alternate spelling; the confirmed
  category is therefore Runtime features, independently of Standards Track.
- Require parentheses so every accepted bare/comma-free signature keeps its
  exact grammar and behavior without ambiguous assignment prefixes.
- Restrict defaults to immutable scalar data: no evaluation-time expression
  semantics, mutable shared values, closure capture, new keywords or crates.
- Use presence, not nullishness or truthiness. Null, Undefined, false, zero and
  empty Strings are supplied values, not omission markers.
- Allow defaults in any formal slot; do not add arity enforcement or a
  required-after-default restriction to the existing permissive signatures.
- Reuse ordinary invocation and validated constructor binding instead of
  wrappers or separate call conventions. Function argument assignments remain
  positional expressions.

## Specification

### Signatures and literals

- After an ordinary parameter name and optional ordinary-identifier
  annotation, a parenthesized formal may append `= literal`.
- Supported locations are named functions with block or arrow bodies,
  function expressions, parenthesized arrows, user methods, explicit class
  constructor parameters and adopted `init` signatures.
- Allowed literals are finite numbers with at most one optional `+` or `-`,
  quoted Strings, Booleans and null with its existing lexical aliases.
  Preserve the numeric sign bits, including exact signed zero.
- Reject arrays, objects, regexes, templates, identifier references, calls,
  grouped expressions, compound expressions and nonfinite numeric tokens.
- Preserve parameter order, annotations, trailing commas, multiline
  parenthesized layout and all existing body grammars/resource limits.
- Bare and comma-free formals receive no default syntax. Native built-in
  signatures and automatic named constructors without formal slots are
  unchanged.
- The typed-function/arrow entry specifies annotations and a negative numeric
  default; the falsy-values entry specifies Boolean/null defaults and quoted
  caller values. Additional focused checks cover signs, signed zero and
  unsupported literals under the same root contract.

### Effective values and histories

- A supplied positional Value or constructor key binds unchanged. Only
  absence selects the formal's literal; absence without a default still binds
  the existing Null.
- Choose that effective value before `Scope::declare`; initialize one binding
  and one initial history entry in the ordinary fresh frame.
- Preserve extra-argument evaluation, non-enforcing annotations, shadowing,
  frame isolation and noncapture. Defaults may precede required parameters.
- Preserve deferred/null propagation and every existing `.value` snapshot
  boundary; defaults do not repair unrelated null propagation.
- `Nucleoid preserves supplied falsy arguments when defaults exist` retains
  `.value` on `suppliedNull` and `nullA`/`nullB`/`nullC`, all original expected
  arrays and all thirteen assertions.
- `Nucleoid starts defaulted parameter histories at their effective values`
  keeps global `step = 100`, three omitted calls, supplied `9`, local mutation
  and initial/latest history observations.

```nucleoid
step = 100
def sample(seed, step = 4) => [seed, step = step + 1, step@first, step@last]
one = sample(1)
two = sample(2)
three = sample(3)
provided = sample(4, 9)
assert(one, [1, 5, 4, 5])
assert(two, [2, 5, 4, 5])
assert(three, [3, 5, 4, 5])
assert(provided, [4, 10, 9, 10])
assert(step, 100)
```

### Calls, constructors and transactions

- Ordinary calls, live aliases, callbacks, methods and function-value calls
  use the same effective-value binding. Historical/frozen function Values
  retain their captured definition/default metadata under ordinary identity
  semantics; they do not capture surrounding locals.
- Constructor positional/named/mixed calls, inherited effective constructors
  and `super` use the selected signature's defaults.
- Preserve complete strict label validation before RHS evaluation, argument
  source order/single evaluation, surplus evaluation, receiver capture and
  class/parent resolution timing. Named calls still pin the validated
  signature/body before values; positional selection still occurs afterward.
- Preserve nearest-nonempty-constructor selection and initializer adoption.
  A bodyless child signature does not replace its inherited effective body.
- `Nucleoid binds independent literal constructor and method defaults`
  specifies per-instance construction and method calls, including all
  snapshots and nine assertions: first count `5`, other counts `3`, supplied
  count `9`, saved `one = 3` and saved `again = 5`.
- Live redefinition and failure recovery use existing State/graph/function/
  class transactions. Default metadata travels with those definitions;
  local Scope mutations retain the accepted nontransactional boundary.
- `Nucleoid restores defaulted function callers after failed redefinitions`
  keeps both defaults at `10`, all thirteen assertions, the temporary `+ 1`
  body, exact throw/catch and restoration of four live callers.
- Preserve namespace-history restrictions, negative selector rejection,
  ordinary dot fields, snapshots, serializers and previously accepted
  [read-only state versions](../nucleoid.spec.md#read-only-state-versions).

## Errors

- All three new failures are parsing-time `SyntaxError`s, not invocation-time
  fallback failures; invalid source installs no partial definition.
- An unsupported or missing default literal raises
  `SyntaxError("Expected a scalar literal parameter default")`.
- A nonfinite numeric token, with or without the permitted sign, raises
  `SyntaxError("Parameter default must be a finite number")`.
- A scalar followed by a token other than `,` or `)` raises
  `SyntaxError("Expected ',' or ')' after parameter default")`.
- Existing parameter/type/delimiter diagnostics, bare-signature diagnostics,
  resource limits and constructor TypeErrors retain their existing paths.
  Defaults introduce no new arity or annotation-enforcement error.
- These errors are defined by the root
  [literal-default contract](../nucleoid.spec.md#literal-parameter-defaults)
  and checked outside the measured corpus without weakening assertion walkers.

## Reference Implementation

- The isolated prototype adds public typed `ParameterDefault` scalar data
  and `Parameter.default`, parser support confined to parenthesized formals,
  canonical default/signature/class rendering and one effective-value helper
  used by ordinary invocation and constructor binding.
- Literal data have no executable children for AST/dependency visitors to
  traverse. Existing function/class cloning and transaction restoration carry
  their default metadata without a parallel metadata registry.
- The public Rust `Parameter` field/type addition requires **human SemVer
  review**: external struct literals must supply `default: None` or a typed
  default. No project version, dependency, MSRV or Cargo metadata is changed.
