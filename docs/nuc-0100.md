## Abstract

- Add unshadowed static `Math.cot(value)` for the existing numeric operation
  `1 / Math.tan(value)`, with angles in radians and exactly the same ordered
  tangent and reciprocal operations, including their rounding.
- Reuse Math's intrinsic first-argument conversion, supplied-undefined gate,
  left-to-right argument evaluation, ignored extras, reactive dependencies,
  shadowing and transaction behavior.
- Preserve accepted tangent and arithmetic spellings, sibling helpers,
  ordinary property reads and user-defined methods. Add no syntax, token,
  public Rust API, dependency, option or project version.
- This is a continuous Utility enhancement. Every measured case requires
  a behavior-equivalent accepted-syntax counterpart and must use the same or
  fewer lexer tokens; all hard criteria remain mandatory.
- Accepted after independent evaluation and the caller's integrated-tree
  recheck passed every hard criterion and the required token policy.

## Motivation

- Geometry and trigonometric models use cotangent as the reciprocal of the
  tangent. A named helper states that operation directly in live expressions
  and class-level rules instead of repeating a reciprocal around `Math.tan`.
- The existing tangent and division already define the numeric contract.
  The helper must preserve that exact composition rather than substitute
  `Math.cos(value) / Math.sin(value)`, rearrange floating-point operations or
  claim improved numerical accuracy or performance.
- The utility is a bounded addition to the existing static Math dispatcher,
  not a new equality, syntax, scope or numeric model.

## Rationale

- Cotangent names an already accepted tangent and reciprocal composition;
  adding one unary arm to the existing Math dispatcher is sufficient.
- Convert once intrinsically, then compute exactly `1.0 / first.tan()`.
  Cosine divided by sine, algebraic rearrangements, angle normalization,
  endpoint shortcuts, higher precision and accuracy/performance claims are
  outside this contract.
- Preserve the shared argument evaluator and supplied-Undefined gate instead
  of introducing special call handling. Ignored extras are still observable
  through effects, strict errors, dependencies and deferral.
- The caller selected Utility enhancement with one uniform draw from NUC 1's
  five eligible categories: index 2, probability `1/5`, without redrawing.
  A bounded built-in numeric helper is its primary purpose, not new syntax
  or a change to the numeric model.
- The caller's continuous mode requires independent per-case lexer-token
  non-regression. Runtime applicability is `not_applicable`; runtime-category
  environment inputs are unset. No user hint was supplied.

## Specification

- Add only unshadowed static `Math.cot(value)`, taking radians as `Math.tan`
  does. The accepted `1 / Math.tan(value)` remains available unchanged.
- Evaluate every supplied argument expression exactly once from left to right,
  including extras and expressions after Undefined, using the existing call
  machinery. Preserve all effects, reads, dependencies and strict errors.
- Return Undefined if any supplied value is Undefined, before numeric
  conversion. Otherwise convert only the first value with intrinsic
  `Value::to_number`; an omitted first value supplies numeric NaN.
- Compute exactly `1.0 / first.tan()` using the same ordered tangent and
  reciprocal as the accepted expression. Every non-NaN result agrees by bits;
  NaNs agree by classification without a payload guarantee.
- Positive and negative zero yield positive and negative infinity respectively.
  Finite extremes, subnormal inputs and tangent rounding follow the accepted
  composition; infinite and NaN inputs yield numeric NaN.
- Literal null converts to zero, booleans to zero/one, trimmed strings and
  empty/singleton lists keep existing numeric conversion, and dates contribute
  milliseconds. Nonnumeric conversions yield numeric NaN, not a new error.
  No shadowable `Number` name is resolved or tracked by conversion.
- Extras are numerically ignored and not converted. Their Undefined values,
  including those from missing/deleted properties, still defer the call.
  Later definitions restore the live result. Literal-null conversion does not
  override inherited live-input or parameter-null deferral.
- Independent class rules, functions, scopes, call frames, receivers, graph
  subscriptions and transaction rollback use unchanged machinery.
- State/local `Math` bindings retain shadowing; ordinary `.cot` properties
  and user methods retain lookup. Reading `Math.cot` as a value remains
  unsupported/Undefined, not a first-class method or alias.
- Add no lexer/parser form, token, public Rust API/type, dependency, option
  or project version. Keep every sibling Math helper and accepted diagnostic
  except that formerly unknown unshadowed `Math.cot(...)` calls may now succeed.
- The authoritative [reactive cotangent contract](../nucleoid.spec.md#reactive-cotangent)
  is exercised by `Nucleoid keeps cotangents reactive`; the paired reference
  case is `Nucleoid preserves cotangent argument dependencies`, and the
  [class-rule example](examples.md#reactive-cotangent) is
  `Cotangents keep directional ratios live as angles change`.
- Append exactly those three caller-supplied identities. In each, replace only
  its designated executable reciprocal-tangent RHS with `Math.cot(...)`;
  preserve every other statement, canonical tangent assertion, explicit
  expected return and executed assertion coverage. Keep all existing corpus
  cases unchanged.

## Errors

- Introduce no arity, coercion, numeric or range error.
- Strict unknown argument names, including ignored extras or arguments after
  Undefined, retain `ReferenceError("<name> is not defined")`.
- Unknown static methods other than the newly defined `cot` retain
  `TypeError("Math.<name> is not a function")`; `Math.random()` retains
  `TypeError("Math.random is not supported")`, after the same Undefined gate.
- A numeric receiver such as `Math = 7` retains the ordinary lookup failure
  `TypeError("number.cot is not a function")`.
- Preserve inherited error positions, caught values, rollback and recovery.
  An unshadowed `Math.cot(...)` previously reached the unknown-method error
  when its arguments were defined; defining that operation is the intended
  extension, not a change to an accepted non-error result.
