# NUC 43 -- Direct Conditional Alternatives

```
NUC: 43
Title: Direct Conditional Alternatives
Author: Can Mingir <canmingir@gmail.com>
Status: Accepted
Type: Standards Track
Created: 16-Oct-2026
```

## Abstract

- Optionally omit the second `if` in an existing conditional chain:
  `else condition:` and `elif condition:` spell `else if condition:`
  only before a genuine indented suite.
- Lower both spellings to the complete existing nested `Stmt::If`.
  No keyword, public interface or runtime behavior is added.
- The root [direct conditional alternatives contract](../nucleoid.spec.md#direct-conditional-alternatives)
  is normative for this accepted implementation.
- This R2 revision repairs the document/JSONL statement exporter's coupling
  to the new spellings. The earlier R1 remains a frozen, unevaluated Draft;
  R2 is the independently evaluated and accepted revision.

## Motivation

- Reactive routing and classification often test several conditions before
  a final fallback; repeating `else if` adds syntax without a new concept.
- Recent accepted collection and text revisions broadened data processing.
  This bounded syntax improvement broadens control-flow expression rather
  than adding another math helper or function-header variant.
- Existing first-match evaluation, live dependency tracking, returns and
  transactional failures already supply the required semantics.

## Rationale

- Reuse the existing lexer mapping of both `else` and `elif` to `Else`.
  Do not repurpose the alias or change public `Keyword`, `Token`, `Spanned`,
  AST or Rust interfaces.
- Preserve explicit `else if` first, all its accepted body forms and every
  unconditional final `else`/`elif` form.
- Require a complete balanced header, colon and genuine indent before
  selecting the new path. Failed qualification must not consume tokens or
  mask the original final-else parser's diagnostics.
- The exporter recognizes whole `else`/`elif` keywords using the lexer's
  existing identifier boundary, not only a literal space prefix. Share its
  actual splitter with regression tests rather than add a speculative parser.
- Use token lookahead, not speculative AST parsing, cloning, error catching,
  rewinds or evaluation. Reuse the existing real-indented-suite predicates.
- Reject inline/braced direct bodies, colon-free condition headers and `:;`
  shortcuts. Do not add standalone alternatives, general REPL continuation,
  newline-separated literals or pending runtime features.
- Keep all 579 historical measured cases and all 24 earlier training files
  unchanged; only the eight pre-executed counterpart cases use new spellings.
- The caller's single sealed syntax-category draw is retained. Selection
  considered reasoning, dependencies, functions/scope, control flow,
  collections/text, modeling and diagnostics; no redraw, rotation, quota,
  math ban or weaker compatibility requirement is used.

## Specification

- Recognize a direct conditional alternative only after the `Else` token of
  a parsed `if` chain, after first checking for explicit `If`.
- Scan the nonempty header without consuming tokens. Match parentheses,
  brackets and braces; delimiter-nested colons belong to the condition,
  including slices, calls, object literals and parameter annotations.
- Stop on any mismatched delimiter or top-level logical newline, semicolon,
  indent, dedent or EOF. Only a balanced top-level colon may qualify.
- At that colon reuse `has_indented_suite`/`has_indented_body`: require
  immediate newline/indent, then a real indent after only ordinary
  newline/semicolon layout. Blank/comment-only lines create no indent.
- If qualification fails, use the unchanged final-else parser with the
  original tokens, diagnostics and source positions. If it succeeds,
  ordinary condition and whole-suite parsing propagate their real errors.
- Lower exactly to the complete nested conditional of the explicit form,
  including recursive alternatives and nested/mixed dangling-else association.
  Keep full ASTs, canonical rendering and top-level positions equivalent.
- Both new spellings retain the condition's colon. Explicit `else if` and
  `elif if` retain indented, inline, semicolon-separated and braced suites.
  Final `else:`/`elif:` and accepted colon-free indented final alternatives
  remain unconditional.
- Existing truthiness, first-match/short-circuit order, actual reads,
  dependency replacement, independent class rules, scopes/receivers,
  explicit returns, live/frozen functions, noncapture, queue ordering,
  transactions, rollback and limits remain unchanged.
- `MAX_NESTING = 64` and `MAX_CHAIN = 128` remain in force. Existing
  recursive else-if-chain quirks are not repaired or re-specified.
- The document/JSONL statement exporter retains either whole alternative
  keyword with its top-level chain. Spaces, tabs, compact delimiter-, string-
  and regex-started conditions, balanced multiline headers, LF/CRLF and comments
  preserve that grouping. The parser still decides whether the header is valid.
- The exporter's boundary matches the existing `[A-Za-z_][A-Za-z0-9_]*`
  lexer identifiers. `elsewhere`, `else1` and `elif_name` stay independent
  statements; existing explicit and final alternatives stay in their chain.
  No catch/finally regrouping or broad continuation rewrite is introduced.
- No lexer, canonical AST renderer, runtime, CLI, Cargo dependency, version,
  edition or MSRV change is required. The CLI already buffers the initial
  colon-bearing `if` and its whole chain until blank-line commit or EOF.
- Trace routing to `Nucleoid selects direct conditional alternatives`,
  class rules to `Nucleoid keeps direct conditional class alternatives reactive`,
  order and missing reads to `Nucleoid preserves direct alternative evaluation order`,
  receiver-scope returns to `Nucleoid preserves direct alternative scope and return flow`,
  and transaction recovery to `Nucleoid rolls back failed direct alternatives`.
- Those five appended spec cases execute 33 protected assertions and retain
  string returns `"wait"` and `"skip"`. The appended reference, README and
  examples cases execute 17 additional assertions; no assertion, definition,
  body line, title or expected return is weakened.

## Errors

- No new error kind or runtime message is introduced.
- For exact `if false: pass\nelse ready: pass`, `else ready: { pass }`,
  `else ready:;\n    pass`, `else ready:\npass` or
  `else ready\n    pass`, failed qualification retains
  `SyntaxError("Expected ':' but found identifier 'ready'")` at line 2,
  column 6. Equivalent `elif` prefixes have the same diagnostics.
- Exact `if false: pass\nelse true +:\n    pass` qualifies and raises
  `SyntaxError("Unexpected ':'")` at line 2, column 12.
- Exact `if false: pass\nelse true:\n    value = (1 +)` raises
  `SyntaxError("Unexpected ')'")` at line 3, column 18.
  An indented `value = @` retains
  `SyntaxError("Unexpected character '@'")` at line 3, column 13.
- An executed `missing` read retains
  `ReferenceError("missing is not defined")`; runtime positions remain the
  existing enclosing top-level statement positions. Thrown values, caught
  errors and transactional rollback use their existing machinery.
- Final colon-free `else`/`elif`, explicit `else if`, lexical failures and
  resource errors retain the exact diagnostics specified by the root
  contract and existing regression tests.
- A receiver-property update can queue a method body after its receiver
  frame has gone away, producing the inherited
  `ReferenceError("this is not defined")`. The retained failed preparation
  case reports line 21, column 1; this proposal neither repairs that failure
  nor claims unsupported receiver-property propagation. The valid V2
  counterpart instead calls each branch in an explicit receiver scope.

## Reference Implementation

- The accepted implementation changes private conditional parsing helpers in
  `src/lang/ast/parser.rs`; condition and suite parsing are shared with the
  existing explicit path, unchanged from the frozen R1 prototype.
- `build.rs` uses the private `build_statements.rs` splitter. Its only grouping
  change recognizes the two complete alternative keywords; other statement,
  comment, delimiter and catch/finally handling is retained.
- `tests/document_statements.rs` exercises that same production function,
  compares whole-program and split ASTs and execution, checks actual lexer
  boundaries and verifies the generated top-level direct-`else` class case.
  The canonical AST generator is unchanged, distinct from this build exporter.
- `tests/direct_conditional_alternatives.rs` and focused private parser
  tests cover new/legacy spellings, balanced layout, exact inherited
  diagnostics, full AST/canonical/position equivalence, real execution,
  reactivity, return/scope/freeze behavior, rollback, CLI bytes and limits.
- Preserve all historical measured programs as accepted-syntax controls.
  Append only the eight already paired cases and transform their 18
  qualifying keyword sites, using both direct `else` and `elif`.
- Add four canonical, self-contained non-math routing records in
  `dataset/nucleoid.synth.24.jsonl`, leaving all older training bytes intact.
  They are development-executed training data, not normative generated tests.
- Regenerate `dataset/nucleoid.spec.jsonl` from the root source and
  `tests/nucleoid.spec.rs` from that export with the repository's tools.
- Independent evaluation accepted the frozen R2 Draft blob
  `bc2332e761649255974475a124ed57b385399cfc` against accepted revision
  `69bfdc1d90440cd637b3093b613be604c6decb97`, after the required Rust pass.
  All 587 paired cases passed: 8 use fewer lexer tokens, 579 are unchanged,
  and none increased. Total tokens changed from 56,285 to 56,267.
- All 2,666 protected assertions executed and all 44 explicit expected
  returns matched. Accepted-syntax compatibility, development checks,
  generated exports and native Git-absent checks passed independently.
  No case, assertion, expected return or executed coverage was weakened.
- The inherited exporter limitation for column-1 lines inside multiline
  conditions remains the same for accepted explicit and new direct forms;
  it is not repaired or presented as new behavior. Receiver/frame and
  host-stack limitations also remain unchanged.
- The immutable baseline, complete 587-case report, independent evidence
  and frozen R1/R2 handoffs remain in the session workspace. Status/index
  updates record this outcome without revising the evaluated implementation.
