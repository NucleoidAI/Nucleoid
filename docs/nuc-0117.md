# NUC 117 -- First and Last Element Methods

```
NUC: 117
Title: First and Last Element Methods
Author: Can Mingir <canmingir@gmail.com>
Status: Accepted
Type: Standards Track
Category: Language compatibility
Created: 18-Nov-2026
Requires: 61
```

## Abstract

- Lists and class populations gain the `first` and `last` methods that
  Kotlin, Rust, Swift, Ruby and C#'s LINQ spell, as aliases of accepted
  queries:
  - `RECEIVER.first()` gives `RECEIVER.at(0)` and `RECEIVER.last()` gives
    `RECEIVER.at(-1)`, so a population's first and last instances are the
    first and latest created;
  - with a function, Kotlin's and LINQ's predicate overloads,
    `RECEIVER.first(PREDICATE)` gives `RECEIVER.find(PREDICATE)` and
    `RECEIVER.last(PREDICATE)` gives `RECEIVER.findLast(PREDICATE)`.
- Each alias behaves as its accepted spelling does: an empty list gives
  undefined and a class without instances `null`, as `at` gives them; a
  predicate that accepts nothing gives `null`; further arguments are
  evaluated and ignored; a declaration that holds the call stays live as
  the receiver, and what the predicate reads, change; and any other first
  argument raises the error that `find` and `findLast` raise for it, with
  the name as written: `TypeError("first expects a function")` or
  `TypeError("last expects a function")`.
- At the accepted revision each of these calls raises
  `TypeError("<receiver>.<name> is not a function")`, unless an argument
  raises first. Only those calls change, along with the programs that
  caught that error. Every other reading of the names is kept: instance
  methods, callable properties and functions named `first` or `last` keep
  running, strings and other values keep their accepted errors, reads
  without a call such as `xs.first` stay undefined, and the state versions
  `xs@first` and `xs@last` are unchanged.
- `at`, `find` and `findLast` stay the canonical spellings. No token,
  keyword, syntax-tree node, error type or message format, dependency or
  public item is added.
- The authoritative contract is
  [First and last element methods](../nucleoid.spec.md#first-and-last-element-methods).

## Motivation

- Programs and models written by people and LLMs that know Kotlin, Rust,
  Swift, Ruby or C# ask a collection for its first and last elements by
  name: `list.first()` and `list.last()` in Kotlin and Rust, `first` and
  `last` in Swift and Ruby, and `First()` and `Last()` in LINQ, where
  Kotlin and LINQ also take a predicate, as in
  `orders.first { it.open }`. In Nucleoid every one of them raises
  `TypeError("<receiver>.<name> is not a function")`, so a world model that
  reads a sensor's latest reading with `readings.last()` or the next job
  with `queue.first()` fails before it runs, although the accepted
  spellings `readings.at(-1)` and `queue.at(0)` say the same thing, and
  `orders.find(order -> order.open)` says what the predicate overload says.
- World models read the ends of their collections constantly: the newest
  reading of a sensor, the oldest order in a queue, the latest instance of
  a class, the first item that meets a condition. These reads are standing,
  so they must follow every later push and pop, which the accepted `at`,
  `find` and `findLast` already do and the aliases inherit.
- The aliases advance the language-superset aspiration of the Language
  compatibility category. The accepted `this`/`self`, `=>`/`->`, `append`,
  `contains`, `lower`, `upper`, `strip`, NUC 110's `startswith`, `endswith`
  and `join`, and NUC 116's `size`, `len`, `isEmpty`, `is_empty` and
  `isNotEmpty` follow the same pattern: an equivalent familiar spelling
  beside the canonical one, with no change to any accepted program.
- Kotlin's `first()`, `last()`, `first(predicate)` and `last(predicate)`,
  Rust's `first()` and `last()`, Swift's and Ruby's `first` and `last`,
  and LINQ's `First()` and `Last()` with their predicate overloads are the
  prior art.

## Rationale

- **Category and mode.** The allocating continuous cycle drew Language
  compatibility with one tool-backed uniform draw over the five categories
  that NUC 1's registry marks eligible for automatic selection, index 4
  with probability 1/5 and no redraw, and recorded the requested change in
  the allocation commit `db6acd1d`, which this revision pins. Token
  comparison is therefore skipped as `language_compatibility`. The skip is
  categorical; it is neither a measured comparison nor a passing token
  gate. Runtime applicability does not apply to this category.
- **No counterparts.** Because comparison is skipped, the new cases have no
  accepted-syntax counterparts. They execute their assertions and explicit
  returns with full coverage, and every pre-existing case is unchanged.
- **Optional evidence.** No hint was supplied. Advisory usefulness is
  unscored (`missing_rubric`), not zero. Strategy learning is
  `not_configured`, so this revision is unattributed, with no policy,
  selection receipt, trial or reward.
- **Only former errors.** At the accepted revision every call of the two
  names on a list or population receiver raises
  `TypeError("<receiver>.<name> is not a function")` at the start of the
  running statement, in plain and JSON output alike, unless an argument
  raises first. No accepted test, document case, dataset record or ARC
  dataset calls them on a list or a population, and no test pins that
  error. The accepted calls of a member named `first` are instance-method
  calls on classes that declare the method, among them
  `reader.first(values)` in `Nucleoid preserves implicit iterator loop return flow`,
  and keep their route.
- **One definition for each spelling.** The aliases live in
  `Runtime::list_query`, the read-only list queries that lists and
  populations share. Without an argument they call `list_at`, the function
  behind `at`, with the index `0` or `-1`, so `first()` and `last()` give
  exactly `at(0)` and `at(-1)`, missing positions included. With an
  argument they call `find_item`, the accepted `find` and `findLast` arm
  moved into a helper, where `last` joins `findLast` in searching from the
  back and the error names the method as written, so `first(f)` and
  `last(f)` give exactly `find(f)` and `findLast(f)`. Rejected: rewriting
  the calls at parse time, which would render `at(0)` or `find` where the
  source wrote `first()`, and an implementation of their own, which could
  drift from the accepted queries.
- **The split.** `list_query` had 59 of Clippy's 60 counted lines, so the
  `find` and `findLast` arm moved into `find_item` before the alias arm
  joined, as the Power of 10 adaptation asks of long dispatchers: split
  them into named helpers by category. `list_query` now has 54 counted
  lines. NUC 116's improvement pass rejected a closed enum of its size
  names for the same limit.
- **A supplied argument decides.** Without an argument the alias reads a
  position; with one it searches. A function searches, and anything else,
  `null` and an undefined value included, raises `find`'s error with the
  alias's name, where `at` would read such an argument as an index.
  Reading a number as an index would make `xs.first(2)` a third spelling of
  `xs.at(2)`, against the name; reading it as a count would make one name
  return an item or a list by the type of its argument.
- **Why `at`.** On populations, bracket indexing and `at` already differ at
  the accepted revision: `Name[-1]` reads index 0, the first instance,
  where `Name.at(-1)` reads the latest, which is one reason `last()` is
  defined as `at(-1)`.
- **The receivers of `at` and `find`.** Lists and populations already
  answer `at`, `find` and `findLast` through `list_query`, which every list
  receiver and every class value reach, so the aliases join exactly those
  receivers: a list however it is reached, and a class named by its name,
  by a variable or parameter that holds it, or by `$Name` outside a
  class-level rule or conditional. Every other receiver keeps its route,
  and with it its result.
- **Strings stay out.** Strings have no `at`, and their accepted `find` is
  the Python spelling of `indexOf`, so a string `first(predicate)` would
  have to choose between that `find` and a search. `TEXT[0]` and
  `TEXT[-1]` already read a string's first and last characters.
  `"abc".first()` keeps raising `TypeError("abc.first is not a function")`.
- **Statics and built-in names.** A class declared as `Math`, `Number`,
  `String` or `Date` reaches that namespace's static methods before its
  instances, so `Math.first()` keeps raising
  `TypeError("Math.first is not a function")`, as `Math.at(0)` raises
  `TypeError("Math.at is not a function")` there. `Boolean`, `Class`,
  `Object`, `List`, `Function`, `JSON` and `RegExp` without a declared
  class of that name keep `ReferenceError("<name> is not defined")`; with
  one, as a declared `List`, they reach its population, as their `at`
  does.
- **Population first on a class name.** On a class name the population
  alias wins over an instance method of the same name, as
  [NUC 114](nuc-0114.md) settled for `product`, because that call raised
  `TypeError("<Name>.first is not a function")` at the accepted revision:
  `Reader.first()` is the first instance even when `Reader`'s instances
  declare `first`, and `Reader.first([1, 2])` raises
  `TypeError("first expects a function")`. Instances keep calling their
  methods.
- **Calls only.** Reading `xs.first` or `Item.last` without a call stays
  undefined, and assigning them keeps its accepted `TypeError`. A property
  alias would change accepted outputs, since those reads give undefined
  rather than an error, and it would read like the state versions
  `xs@first` and `xs@last`, which are a different syntax and keep their
  meaning.
- **Arguments.** The receiver is read first, a population's instances
  included, and then every argument once, left to right, as for every
  call. An argument's error therefore propagates before the alias runs, and
  a `null` or undefined receiver stays undefined without evaluating the
  arguments, as the accepted null-safe reading does.
- **Live and rendered as written.** A declaration or class-level rule that
  calls an alias depends on what its accepted spelling depends on: its
  receiver, a population's instances, and the reads its predicate makes
  until it accepts an item. Statements, `why`, `affects`, `--graph` and
  graph keys render the call as every call is rendered, with the name the
  source wrote; nothing renders `at` or `find` in its place.
- **Source-language differences stay documented, not emulated.**
  - Kotlin's, Java's and C#'s `first()` and `last()` throw on an empty
    receiver, and their predicate overloads throw when nothing matches; the
    aliases give what `at` and `find` give, undefined or `null`, so a
    standing rule over an empty queue keeps a value instead of failing
    every propagation.
  - Rust's `first()` and `last()` return an `Option`; Nucleoid has no
    option type, and undefined and `null` play its part.
  - Swift's and Dart's `first` and `last` are properties; the aliases are
    calls only, for the reasons above.
  - Kotlin's `firstOrNull` and `lastOrNull` are not added: `first` and
    `last` already give `null` or undefined instead of throwing, so they
    would be third spellings of the same reads.
  - Java 21's `getFirst` and `getLast` are not added: they throw on an
    empty receiver as `first()` does in Java, and the `get` prefix reads as
    a property getter.
  - C++'s `front` and `back` are not added: two more names for the same
    reads, and `back` also reads as a direction.
  - Scala's and Haskell's `head` is not added: two names for the first
    item are enough, and its usual partners, `tail` and `init`, mean the
    rest of the list rather than an item.
  - Ruby's `first(n)` and `last(n)` take a count and return a list; here a
    number raises `TypeError("first expects a function")`, as any argument
    that is not a function does, and `xs[:n]` and `xs[-n:]` already read
    the first and last `n` items.
  - Python has no such method: it writes `xs[0]` and `xs[-1]`, which
    Nucleoid already accepts.
- **Completion.** The terminal workspace offers the JavaScript names of
  list members and none of the accepted aliases, as
  [NUC 110](nuc-0110.md) and [NUC 116](nuc-0116.md) kept it. This proposal
  follows that precedent and adds no completion entry.
- **Public API.** No public item is added or removed. `list_query` is
  crate-private and the two new helpers are private methods.
  `nucleoid::builtins::string_method` is untouched, so strings keep their
  accepted errors through the public API too.
- **Requires.** [NUC 61](nuc-0061.md), which added `at` and `findLast` to
  lists and class populations, with `at`'s index conversion and its
  missing positions, through the shared list query that the aliases join.
  `find` and the routing of lists and populations are base built-ins that
  no NUC introduced, and NUC 110, NUC 114 and NUC 116 are followed as
  precedents, not depended on.
- **Not added.** Property aliases, `firstOrNull`, `lastOrNull`,
  `getFirst`, `getLast`, `front`, `back`, `head`, counts, aliases on
  strings, objects, instances or other receivers, static forms such as
  `List.first`, noun forms such as `first of xs`, completion entries and
  any change to `at`, `find` or `findLast`.

## Specification

- The normative contract is
  [First and last element methods](../nucleoid.spec.md#first-and-last-element-methods).

### Calls

- `RECEIVER.first(...)` and `RECEIVER.last(...)` are aliases when
  `RECEIVER` evaluates to a list or to a declared class whose instances the
  list queries reach.
- Receivers are reached however the language reaches them: literals,
  names, properties, call and query results, indexes and slices, `.value`
  snapshots, state versions, the results of conditional expressions, a
  class through a variable or a parameter, and `$Name` outside a
  class-level rule or conditional.
- On every other receiver the names keep the readings of
  [Compatibility](#compatibility).

### Without an argument

- `first()` gives `RECEIVER.at(0)` and `last()` gives `RECEIVER.at(-1)`:
  the first and last items of a list, or the first and latest created
  instances of a class. An empty list gives undefined, which a declaration
  stores as `null`, and a class without instances gives `null`.

```
readings = [21, 23]
oldest = readings.first()
newest = readings.last()
assert([oldest, newest], [21, 23])
readings.push(25)
assert([oldest, newest], [21, 25])
readings.shift()
assert([oldest, newest], [23, 25])
class Order(item):
    this.item = item
queued = Order.first()
latest = Order.last()
assert([queued, latest], [null, null])
tea = Order("tea")
cake = Order("cake")
assert([queued, latest], [tea, cake])
assert([Order.first().item, Order.last().item], ["tea", "cake"])
empty = []
assert([empty.first(), empty.last(), [7].first(), [7].last()], [null, null, 7, 7])
readings = []
[oldest, newest]
```

- This returns `[null,null]`: both declarations follow the push, the shift
  and the replacement by an empty list, and `queued` and `latest` follow
  the new instances.

### With a predicate

- When the first argument is a function, `first(PREDICATE)` gives
  `RECEIVER.find(PREDICATE)` and `last(PREDICATE)` gives
  `RECEIVER.findLast(PREDICATE)`: the first item the predicate accepts,
  searching from the front or from the back, or `null` when it accepts
  none. Further arguments are evaluated and ignored, as `find` ignores
  them.

```
class Order(item, open):
    this.item = item
    this.open = open
tea = Order("tea", false)
cake = Order("cake", true)
pie = Order("pie", true)
oldestOpen = Order.first(order -> order.open)
newestOpen = Order.last(order -> order.open)
assert([oldestOpen, newestOpen], [cake, pie])
tea.open = true
assert([oldestOpen, newestOpen], [tea, pie])
pie.open = false
assert(newestOpen, cake)
prices = [12, 7, 30, 4]
cheap = prices.first(price -> price < 10)
pricey = prices.last(price -> price > 10)
assert([cheap, pricey, prices.first(price -> price > 99)], [7, 30, null])
prices.push(3, 50)
assert([cheap, pricey], [7, 50])
assert([prices.last(price -> price > 99, "ignored"), [].first(price -> true)], [null, null])
[cheap, pricey]
```

- This returns `[7,50]`: the population's searches follow the `open`
  properties their predicates read, and the list's follow the push.

### Other first arguments

- Any other supplied first argument raises
  `TypeError("first expects a function")` or
  `TypeError("last expects a function")`, the error that `find` and
  `findLast` raise for it, with the name as written: a number, a string, a
  list, an object, a class, `null` and an undefined value among them, even
  on an empty receiver.

### Evaluation

- The receiver is read first, a population's instances included, and then
  every supplied argument once, left to right, including unused extras, as
  for every call. A missing name among them raises
  `ReferenceError("<name> is not defined")` before the alias runs:
  `xs.first(missing)` raises it, as `xs.find(missing)` does.
- The receiver's items are read before the arguments run, as for `at` and
  `find`, so an argument that changes the receiver does not change the
  answer: after `Item(1)` and `Item(2)`, `Item.last(x -> true, Item(3))`
  is the second instance, and `Item.last()` is the third afterwards; after
  `xs = [1]`, `xs.last(x -> true, xs.push(2))` is `1`.
- A `null` or undefined receiver keeps the accepted route: the call is
  undefined and the arguments are not evaluated, so after `u = null`,
  `u.first(missing)` is undefined.

### Liveness and class-level rules

- A declaration that calls an alias depends on what its spelling depends
  on: pushes, pops, shifts, sorts, appends and replacements of a list,
  writes of the property that holds it, and new and deleted instances of a
  population re-evaluate it, and so do writes of what a predicate read
  before it accepted an item. A search stops at the first item its
  predicate accepts, so the items after it are not dependencies, as for
  `find`.
- In a class-level rule or conditional each instance evaluates its own
  alias over its own properties. There `$Name` is the instance, so
  `$Name.first()` keeps calling the instance's method or giving undefined,
  while `Name.first()` is the population.
- This program is the specification entry
  `Nucleoid rolls back failed updates through first and last aliases`,
  which also exercises [Transactions](#transactions):

```
stock = ["bolt", "nut"]
newest = stock.last()
failure = ""
try:
    stock = 7
catch error:
    failure = error
assert(failure, TypeError("number.last is not a function"))
assert([stock, newest], [["bolt", "nut"], "nut"])
try:
    stock.push("gear")
    assert([stock.first(), newest], ["bolt", "gear"])
    throw "UNDO"
catch error:
    assert(error, "UNDO")
assert([stock.last(), newest], ["nut", "nut"])
try:
    stock.first(2)
catch error:
    failure = error
assert(failure, TypeError("first expects a function"))
class Sensor(name):
    this.name = name
    this.readings = [18]
$Sensor.latest = $Sensor.readings.last()
door = Sensor("door")
try:
    door.readings = 0
catch error:
    failure = error
assert(failure, TypeError("number.last is not a function"))
assert([door.readings, door.latest], [[18], 18])
door.readings.push(21)
door.latest
```

- This returns `21`.

### Rendering and graph keys

- Statements, `why`, `affects`, `--graph` and graph and block keys show the
  call in the canonical rendering of every call, with its name as written:
  after `n = queue.first()`, `(why n)[0].rule` is `"n = queue.first()"`,
  and after `f = queue.first(x -> x > 1)` it is
  `"f = queue.first(function())"`, as `find` renders as
  `"f = queue.find(function())"`.
- The dependencies are those of the accepted spelling: `(why n)[0].from` is
  `["queue"]` after `n = queue.first()`, as after `n = queue.at(0)`,
  `c = Item.last()` depends on `$Item`, as `c = Item.at(-1)` does, and
  `d = Item.last(i -> i.v > 0)` depends on `$Item` and the `v` of the last
  instance, as its `findLast` spelling does.

### Transactions

- Errors of an alias propagate through the existing transaction, so a
  failed standing re-evaluation rolls back the change that triggered it: a
  list replaced by a number, raising
  `TypeError("number.last is not a function")`, and a property written a
  number under a class-level rule, raising the same, as the entry above
  shows. A non-function argument raises
  `TypeError("first expects a function")` inside the `try` that catches
  it. A failed statement or transaction restores declarations that call
  aliases, their values and their dependencies.

### Cost

- Each alias adds one match on its name to the list queries and then runs
  its spelling's code: `list_at` for `first()` and `last()`, and the moved
  `find` arm for a predicate. Its spelling's argument, the index `0` or
  `-1`, is not evaluated, since the alias has none.
- **Measured**, not projected, on the final tree: on `nucleoid-final.exe`,
  its release build, through the command line, rustc 1.97.1, the median of
  five interleaved runs of each program with `--json`, including process
  start, one process at a time with nothing else running, against the
  accepted revision's release build for the accepted spellings. Unless a
  row says otherwise, each program makes 100,000 calls from
  `items.map(x -> ...)`, where `items` is `"x".repeat(100000).split("")`,
  which alone takes 31.2 ms on the final build and 32.0 ms on the accepted
  one; the list holds three items and the class three instances. Times are
  in milliseconds.

  `Item.first(i -> i.v > 1)` varies between runs: twenty-one interleaved
  runs put it at 242.7 against 242.5 ms, and the two list searches at
  182.1 against 182.4 and 181.3 against 182.8, 0.99 to 1.00. Twenty-one
  interleaved runs of the four calls without an argument put `xs.first()`

  does, so with 1,000 instances `Item.last()` and `Item.at(-1)` both take

- A standing search re-runs once per push and scans up to the first item
  its predicate accepts, as `find` does, so 10,000 pushes take about 12 s
  with either spelling; a standing `last()` takes 1.5 to 1.6 s.
- The final build's spellings take 0.95 to 1.05 times the accepted
  revision's in these medians, and 0.99 to 1.02 in the twenty-one
  interleaved runs, where the program that only builds `items` takes 32.1
  against 32.2 ms, so the moved `find` arm and the further match cost
  nothing measurable.

### Compatibility

- Parsing, the syntax tree, canonical rendering and graph keys are
  unchanged; `first` and `last` stay ordinary method names.
- Only inputs that were errors at the accepted revision change: calls of
  the two names on list and population receivers, each of which raised
  `TypeError("<receiver>.<name> is not a function")` at the start of the
  running statement, and the programs that caught that error. Calls whose
  arguments raise first keep that error. "The items" are `class Item(v):`
  with the body `this.v = v`, then `Item(1)` and `Item(2)`.
