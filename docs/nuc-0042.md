# NUC 42 -- Reactive Literal String Replacement

```

Title: Reactive Literal String Replacement
Author: Copilot <223556219+Copilot@users.noreply.github.com>
Status: Accepted
Type: Standards Track
Created: 16-Oct-2026
```

## Abstract

- Add one read-only string-instance method, `replaceAll(search, replacement)`,
  for ordered, non-overlapping literal replacement.
- Empty search inserts at Unicode scalar boundaries, including both ends;
  replacement text is always literal.
- The contract is the normative root
  [Reactive literal string replacement](../nucleoid.spec.md#reactive-literal-string-replacement)
  section and its five appended executable entries.

## Motivation

- Imported labels, normalization pipelines and text templates need to replace
  every occurrence without a split/join recipe or repeated first-only calls.
- Existing `includes`, `startsWith`, `endsWith`, `trim`, `split` and first-only
  `replace` already serve different purposes; this proposal does not re-add them.
- The caller's single tool-backed draw selected **runtime feature** (`1`).
  Preserve that selection without another draw, rotation, quota or math ban.
- Recent NUCs emphasize numeric helpers and function headers; accepted NUC 41
  broadens relational collections. This revision broadens text processing with
  one familiar method and no grammar or namespace expansion.
- The selection reviewed logic/reasoning, reactive dependencies, functions/scope,
  control flow, collections/strings, data modeling and diagnostics. Distinct
  normalization/template value and modest API cost, not convenient baselines
  or token savings, justify the bounded feature.

## Rationale

- Reuse native string dispatch and the existing method-call evaluation path.
  Do not add an AST node, lexer token, parser branch or public Rust API.
- Keep `replace` first-only and accepted split/join programs executable.
  Native all-occurrences replacement is optional, not a reinterpretation.
- Literal matching and literal replacement avoid implicit regex syntax,
  replacement callbacks, dollar expansion, backreferences or escaping modes.
  A regex value is stringified as an ordinary value, not executed as a pattern.
- Unicode scalar boundaries agree with existing indexing and empty `split`;
  do not introduce UTF-16 surrogate boundaries or grapheme segmentation.
- Preserve actual runtime reads and existing deferred/null semantics rather
  than manufacturing reads to imitate a composed recipe.
- Check output-byte arithmetic and reserve fallibly before writing. Reuse the
  typed-error idiom of `string_repeat`, with no arbitrary output cap.
- New reasoning stages, general-loop reinterpretation, reflection, closure
  capture, aliases, options and unrelated runtime repairs are outside this
  revision; no pending proposal is combined.

## Specification

### Matching and results

- `receiver.replaceAll(search, replacement)` requires the ordinary string
  receiver dispatch route and returns a new string without mutating it.
- Visit literal, non-overlapping matches left to right. Each match contributes
  the replacement verbatim; replacement text is not searched again.
- No match returns the original text as a string result.
- Empty search matches once at the start, once between adjacent Unicode scalar
  values and once at the end; an empty receiver has exactly one match.
- The root entries `Nucleoid replaces every literal string match` and
  `Nucleoid replaces empty string matches at Unicode boundaries` specify these
  results alongside first-only `replace` and an executed legacy helper.

```
text = "one|two|one"
joined = text.replaceAll("|", "/")
overlap = "aaaaa".replaceAll("aa", "X")
literal = "a.b.a".replaceAll(".", "$&")
noMatch = "abc".replaceAll("z", "")
assert(joined, "one/two/one")
assert(overlap, "XXa")
assert(literal, "a$&b$&a")
assert(noMatch, "abc")
assert("a.a.a".replace(".", "/"), "a/a.a")
assert(text, "one|two|one")
joined
```

### Evaluation and coercion

- Snapshot the receiver before evaluating arguments, exactly as existing string
  calls do. Evaluate every supplied expression once, left to right, including
  unused extras, before string conversion and replacement.
- Stop on the earliest evaluation failure; later expressions do not run.
  Preserve earlier/later error precedence, source positions and transactions.
- Apply `Value::to_string` to the first two argument values, in order, as
  existing `replace` does. Each omitted value is `Undefined`, ordinarily
  rendered `"undefined"`; there is no argument-count error or undefined gate.
- Literal null, booleans, numbers, strings, lists, objects, classes, functions,
  dates and regexes retain their existing string rendering. Only the first two
  values are converted; extras still execute but are not converted.
- Default/literal values do not imply a variable or member read. Actual
  null/undefined binding, member or parameter reads retain inherited
  null/deferred assignment handling, even in unused extras.
- Null or undefined receivers keep the existing skipped-arguments route and
  recovery when their dependencies become defined; the method adds no read.

### Reactivity, functions and compatibility

- Track actual receiver and argument reads through the ordinary runtime path;
  re-evaluation replaces obsolete dependencies rather than accumulating them.
- Global/property/class rules, class population queries, ordinary scopes and
  noncapture, live/frozen function definitions and `.value` snapshots are
  unchanged.
- The root entries `Nucleoid keeps literal replacement reactive`,
  `Nucleoid replaces literal strings in class rules` and
  `Nucleoid rolls back literal replacement argument failures` specify live
  replacement/search/source updates, rule replacement and failure recovery.
- The reference entry `Nucleoid normalizes live text records`, README entry
  `Literal replacements normalize every occurrence` and examples entry
  `Literal replacement preserves frozen text normalizers` extend those cases
  without altering historical programs.
- Global/local functions, callable object properties and instance methods named
  `replaceAll` retain ordinary lookup and invocation. Native string method
  properties remain non-first-class, just like `replace` and `split`.
- Static `String.replaceAll` remains unsupported. Other string/list methods and
  all previously accepted syntax keep their existing behavior.
- The eight paired programs change only sixteen designated operations. The
  entire empty-search helper and its `legacy` call remain unchanged and run.
  All definitions, comments, assertions, expected returns and coverage remain.
- Runtime-call RHS ASTs and their graph-source rendering intentionally differ
  from split/join recipes. Compare concrete protected outputs and assertions,
  not unconditional complete AST/graph-source parity for those expressions.
- Unchanged wall-clock programs retain their exact source, AST, canonical
  assertions and coverage; cross-run full value equality is not promised.
  Function identity is checked through aliases/snapshots within each runtime,
  not by comparing independently allocated function Arcs across runtimes.

### Resource handling

- Count matches using the host's literal UTF-8 string matcher, which visits only
  scalar boundaries for an empty pattern.
- Compute removed and inserted byte lengths with checked multiplication, then
  checked subtraction and addition for the complete result size.
- Reserve that size with `String::try_reserve_exact` before copying any pieces.
  Copy unmatched spans and literal replacements without further growth.
- Arithmetic and output-buffer reservation errors are explicit typed errors.
  Existing string-conversion or other allocation behavior is not redefined.

## Errors

- Output-byte arithmetic overflow or failed output-buffer reservation raises
  `TypeError("Replaced string is too large")`.
- Static calls still raise
  `TypeError("String.replaceAll is not a function")`, after supplied arguments.
- Other receiver types retain existing dispatch errors, such as
  `TypeError("number.replaceAll is not a function")` for a number receiver;
  ordinary user-defined callable properties/methods remain callable.
- Native string method properties remain undefined/non-first-class; no new
  callable value or property lookup error is introduced.
- Existing receiver/argument failures propagate unchanged, including
  `ReferenceError("missing is not defined")`,
  `TypeError("Math.random is not supported")`, and arbitrary thrown values.
  No new syntax, arity, regex, callback or option errors are introduced.
- The root rollback entry takes the catch branch and checks the original
  source and a successful recovered result. Focused native regressions protect
  argument precedence, positions and restoration of state/dependencies.

## Reference Implementation

- Implemented: one `replaceAll` arm in `src/builtins/mod.rs::string_method`,
  with private literal-copy and checked-buffer helpers.
- Leave `Runtime::call_method`, parsing, public Rust types/signatures, Cargo
  manifests/locks, dependencies, versions, MSRV and edition unchanged.
- `tests/replace_all.rs` contains self-contained accepted controls, exact
  operation-boundary checks, semantic/dispatch/reactivity regressions, native
  CLI byte checks and development execution of five new training records.
- Private buffer tests safely exercise overflow and impossible reservation
  capacities without requesting dangerous large allocations.
- Canonical training additions are confined to
  `dataset/nucleoid.synth.23.jsonl`; old synthesized/ARC bytes remain unchanged.
  Normative exports are generated only from their canonical sources.
- Baseline: accepted Git revision
  `857785905738325ee1e7f6ae17d44e499f74bb61`, with the caller's immutable
  NUC 42 baseline and eight pre-executed accepted counterparts.
- Development and syntax-compatibility evidence remains in the frozen session
  handoff. The caller's sole synchronous Rust-improvement pass returned
  `NO_CHANGE`; the independently evaluated implementation was integrated
  unchanged before recording this outcome.

- Accepted against revision `857785905738325ee1e7f6ae17d44e499f74bb61`;

  no saving offsets an increase in another case.

  their canonical assertions, expected returns and executed coverage, including
  the empty-search helper and its executed legacy control.
- Independent execution preserved 2,616 assertions and 42 explicit expected
  returns. Accepted-syntax compatibility, behavior, source/export consistency,
  formatting and warning-denied Clippy passed without regenerating sources.

  retained helper failures remain in the session workspace.
