# NUC 37 -- Comma-Free Bare Named Arrows

```
NUC: 37
Title: Comma-Free Bare Named Arrows
Author: Copilot <223556219+Copilot@users.noreply.github.com>
Status: Accepted
Type: Standards Track
Created: 15-Oct-2026
Requires: 12, 18, 27, 29, 32
```

## Abstract

- Add optional `def add left right => left + right`, exactly equivalent to
  accepted `def add left, right => left + right`.
- Require at least two untyped ordinary identifier parameters on one logical
  header line, with every parameter comma omitted or none omitted.
- Keep every accepted spelling and the same named function, sole-return
  block, body grammar, canonical rendering, graph and runtime behavior.
- Independent evaluation accepted the frozen candidate without any per-case
  token increase; the caller integrated it unchanged before outcome metadata.

## Motivation

- Avoid redundant parameter punctuation where ordinary names and the final
  arrow already delimit a complete named definition.
- Keep concise relationships readable with two or more inputs without
  inventing implicit calls, a new callable representation or a new scope.
- Preserve the live-input, receiver, snapshot and rollback demonstrations,
  including their original assertions and explicit result.

## Rationale

- Add a separate complete-prefix guard rather than liberalizing NUC27's
  comma grammar or the typed/mixed and indented-block scanner.
- Decide eligibility using existing lexer tokens, not physical-line regular
  expressions, fake comma tokens, speculative parsing or recovery.
- Inspect the complete `Identifier Identifier Identifier* Arrow` prefix
  without consuming tokens or allocating parameter names.
- Reuse `parameter()` after qualification and the entire existing named-arrow
  body path; duplication of parameter conversion or lowering is unnecessary.
- Reject mixed separators, annotations and colon-suite endings in the new
  guard so failed prefixes retain their original parameter-parser diagnostic.
- Keep parentheses, commas and annotations in representative legacy controls;
  optional punctuation must not remove accepted syntax.
- Do not address inherited Windows stack, noncapture or parameter-dependent
  local limitations, or change dependencies, version, MSRV, edition or bounds.

## Specification

### Complete optional header

- The authoritative [specification section](../nucleoid.spec.md#comma-free-bare-named-arrows)
  takes precedence over this document.
- After the unchanged `Def` token and required ordinary definition name,
  qualify exactly `Identifier Identifier Identifier* Arrow`.
- There must be at least two ordinary names; keywords, dollar references,
  literals and punctuation are not parameter names in this guard.
- No comma or annotation is permitted anywhere in this additional prefix.
  Do not skip logical `Newline`, `Semicolon`, `Indent` or `Dedent`.
- Horizontal whitespace, including tabs, separates identifiers. A comment
  cannot join names across a logical newline.
- Look ahead linearly, non-consumingly and without name allocation. Only a
  complete run ending immediately in `Arrow` selects the new branch.
- For a failed prefix, leave the parser at its original position and retain
  every old single/multiple, typed/mixed, block and parenthesized guard.
- After qualification, use the existing parameter parser in order, producing
  `Parameter { name, type_name: None }` for every name.
- Reuse the same named `FunctionBody::Block` containing the single
  `Return(Some(expression))`; do not add an AST variant or synthetic token.
- Keep duplicate-name handling and the existing uncapped flat parameter-list
  behavior, including 1024 ordinary parameters.

```nuc
def add left right => left + right
def scaled left right factor => (left + right) * factor
def pair left right => [left, right]
def coordinates x y => {x, y}
def indented left right =>
    left + right
assert(add(2, 3), 5)
assert(scaled(2, 3, 4), 20)
assert(pair("left", "right"), ["left", "right"])
point = coordinates(2, 3)
assert(point.x, 2)
assert(point.y, 3)
assert(indented(2, 3), 5)
```

### Unchanged body and execution

- The example is the complete basic specification entry without its title
  comment; object, list and argument commas remain present.
- Keep NUC32's genuine indented single expression, leading object expressions
  and an opening parenthesis on the header line continued over physical lines.
- Keep all expression precedence, assignment returns, anonymous functions and
  their comma-bearing parameter/body grammar. No arbitrary statement suite,
  implicit last-statement return or closure capture is introduced.
- Apply the additional guard wherever named definitions already occur,
  including methods, `init`, nesting and redefinition.
- Preserve argument order, missing/null/extra inputs, duplicate names, local
  parameter assignment/shadowing, `this`/`self`, explicit/bare `super` and
  initializer identity/adoption.
- Preserve live references, aliases, callbacks, `.value` definition snapshots,
  redefinition, reactive dependencies, graph keys/source, reasoning, resource
  bounds, statement positions, transactions and rollback.
- Keep native file/stdin/REPL framing, byte-exact LF/CRLF/tab input, blank-line
  commit, EOF execution, structured body errors and subsequent recovery.
- Outside `def`, `add left right` remains three ordinary expression statements,
  not an invocation.

### Compatibility and exclusions

- All old comma-bearing and parenthesized arrows remain optional equivalents,
  including typed/mixed, trailing-comma and multiline parenthesized lists,
  single/nullary definitions, methods and initializers.
- All accepted colon suites and their bare single/multiple typed/untyped
  guards remain unchanged; this revision adds no comma-free block header.
- Do not add mixed `left right, third` or `left, right third` lists,
  comma-free typed/mixed parameters, parenthesized or anonymous comma omission,
  class lists, call punctuation omission, defaults, rest/destructuring,
  return annotations or nullary parenthesis omission.
- New syntax changes no lexer, public AST, runtime, generator or public API.
- Rewrite only complete, already-bare, wholly untyped comma-separated named
  arrow headers in executable documents and eligible canonical training code.
- Remove only those header comma bytes, retaining all existing whitespace,
  comments, bodies and other punctuation. If a comma abuts both identifier
  names, replace it with one ASCII space to retain their token boundary.
- Preserve every document/title identity, relative order, ordered canonical
  assertion, explicit return and actual executed assertion coverage.
- Keep synthesized/ARC IDs, descriptions, returns, all non-code metadata,
  ARC annotations and record order; do not run training as normative tests.
- Regenerate normative JSONL and exported Rust only from their source documents.

## Errors

- Add no error type, message, recovery path or runtime validation.
- Unsupported tokenizable prefixes retain the original parenthesized-parser
  error at the first parameter, not at a partially consumed later token.

- All remaining inherited expression/statement/postfix/chain failures retain
  their types and messages, including `SyntaxError("Expressions are nested too deeply")`,
  `SyntaxError("Expression has too many operands")`,
  `SyntaxError("Expression has too many parts")` and
  `SyntaxError("Statements are nested too deeply")`.
- Existing runtime errors remain unchanged, including
  `ReferenceError("missing is not defined")` in the real rollback entry,
  `ReferenceError("left is not defined")` for inherited noncapture,
  `ReferenceError("this is not defined")` without a receiver and
  `TypeError("operation is not a function")` for a non-callable binding.
- Positions reflect actual physical characters; deleting a header comma can
  shorten a same-line body column, never alter the body grammar or swallow an
  error. Top-level runtime statement positions and caught values are unchanged.
