## Abstract

- A list or a class population gains the read-only query `zip`.
  `SEQUENCE.zip(OTHER)` pairs each item with the item at the same position
  of `OTHER`, a list or a declared class read as its instances in
  population order, and stops at the shorter of the two, so
  `[1, 2, 3].zip(["a", "b"])` gives `[[1, "a"], [2, "b"]]` and
  `Driver.zip(Truck)` pairs the instances of the two classes in population
  order. Each pair is the two-item list `[a, b]`, the receiver's item first.
- With a function as its second argument, `SEQUENCE.zip(OTHER, COMBINE)`
  gives `COMBINE(a, b)` at each position instead of the pair, as Kotlin's
  `zip` with a transform and lodash's `zipWith` combine items, so
  `prices.zip(quantities, (p, q) -> p * q).sum()` totals an order.
- The pairs hold the items themselves. An `OTHER` that is neither a list nor
  a declared class, a missing one included, raises
  `TypeError("zip expects a list")`, and a supplied combiner that is not a
  function raises `TypeError("zip expects a function")`, both even on an
  empty receiver. The combiner is called once per position, first to last,
  with the receiver's item and then `OTHER`'s.
- It joins the List and Population helpers of [NUC 61](nuc-0061.md) and its
  successors: a declaration that holds a `zip` stays live, and follows
  changes to both sequences, to the instances of either class and to what
  the combiner reads, and a failed update rolls back.
- At the accepted revision `zip` called on a list or a class raises
  `TypeError("<receiver>.zip is not a function")`, and only those inputs
  change; a `try` that caught that error now receives the result. No syntax,
  keyword, token or error type is added; the message `zip expects a list` is
  new. A function, property, method or variable named `zip`, and every other
  receiver, keep their readings.
- The authoritative contract is
  [List and population zipping](../nucleoid.spec.md#list-and-population-zipping).

## Motivation

- World models keep parallel facts in step: positions and values, sensors
  and readings, drivers and trucks, prices and quantities. Pairing them
  position by position is a basic step that Python, Kotlin, Rust, Haskell
  and lodash all call `zip`.
- Accepted programs pair parallel lists through positions. Callbacks
  receive no index, so they write `xs.map(x -> [x, ys[xs.indexOf(x)]])`,
  which holds only while `xs` has no repeated items, or a `reduce` that
  grows its result with `concat` and reads `ys[acc.length]`; a result that
  stops at the shorter list also slices the receiver to `ys.length`. Both
  are long, and the first depends on the values. Elementwise arithmetic,
  such as a weighted total, repeats the same positional lookups.
  `xs.zip(ys)` and `xs.zip(ys, f)` state the pairing once.
- The accepted spellings are long. `timetable = stops.zip(minutes)` is 8
  lexer tokens; its shortest accepted spelling found,
  `timetable = [[stop, minutes[stops.indexOf(stop)]] for stop in stops[:minutes.length]]`,
  is 27, and holds only because no stop repeats. The general spelling,
  `timetable = stops[:minutes.length].reduce((pairs, stop) -> pairs.concat([[stop, minutes[pairs.length]]]), [])`,
  is 39. A weighted total over items that repeat,
  `total = prices.zip(quantities, (price, quantity) -> (price - discount) * quantity).sum()`,
  is 26 tokens where its shortest accepted spelling is 42.
- LLM-written code such as `xs.zip(ys)` raises
  `TypeError("xs.zip is not a function")` at the accepted revision.

- **Category and mode.** The caller drew Utility enhancement with one
  tool-backed uniform draw over the five categories that NUC 1's registry
  marks eligible for automatic selection: index 2, with probability 1/5, at
  15:38:25 on 21-Nov-2026, and no redraw. This is a continuous cycle, so the
  token non-regression gate is required. Runtime applicability does not
  apply to this category.
- **Selection.** Within the category the caller chose one bounded helper
  that no NUC proposes, `zip`, in the List and Population family of
  [NUC 61](nuc-0061.md) and its successors. [NUC 103](nuc-0103.md) and
  [NUC 114](nuc-0114.md) set `zip` aside because callbacks receive no index,
  so no fair accepted spelling seemed to exist. Since then
  [NUC 123](nuc-0123.md) to [NUC 126](nuc-0126.md) admitted counterparts
  that hold only for their cases' values, such as
  [NUC 125](nuc-0125.md)'s `indexOf` strides, and a fully general accepted
  spelling exists:
  `xs.reduce((acc, x) -> acc.concat([[x, ys[acc.length]]]), [])`. The caller
  ruled out `chunk` and `groupBy`, whose results need computed keys or
  nested positions, `takeWhile`, running totals and string `count`, whose
  spellings save less, and `Math.hypot` and `Math.log2`, whose correctly
  rounded results are not exactly their accepted spellings.
- **Optional evidence.** No hint was supplied. Advisory usefulness is
  unscored, not zero, because no rubric was frozen. Strategy learning is
  `not_configured`, so this revision is unattributed, with no policy,
  selection receipt, trial or reward.
- **One more query.** `zip` joins `Runtime::list_query` beside the other
  list queries, so lists however they are reached and class instance lists
  accept it through the route and the receiver, argument and liveness rules
  they already share. Rejected: a list-only method, which would leave
  `Driver.zip(Truck)` raising where `Driver.map(...)` runs.
- **Pairs are two-item lists.** Nucleoid has no tuple type, and a list is
  what `partition` already returns for its two halves, so each pair is
  `[a, b]`, read with `pair[0]` and `pair[1]`. Rejected: objects such as
  `{first: a, second: b}`, after Kotlin's `Pair`, which would add property
  names a model must remember.
- **The receiver first.** The receiver's item comes first in each pair and
  is the combiner's first argument, as `zip(xs, ys)` gives `(x, y)` in
  Python and `xs.zip(ys)` gives `Pair(x, y)` in Kotlin.
- **The shorter length.** The result stops at the shorter sequence, as
  Python's `zip`, Kotlin's `zip`, Rust's `Iterator::zip` and Haskell's `zip`
  and `zipWith` do, so a sequence that grows first waits for its partner,
  and an empty sequence on either side gives `[]`. Rejected: padding to the
  longer sequence, as Python's `itertools.zip_longest` pads with `None` and
  lodash's `zip` and `zipWith` pad with `undefined`, which would hand
  combiners missing values; and raising on unequal lengths, as Python's
  `zip(..., strict=True)` does, which would fail a live declaration whenever
  one list grows before the other.
- **An optional combiner.** A function as the second argument replaces each
  pair with its result, as Kotlin's `zip(other) { a, b -> ... }`, Haskell's
  `zipWith` and lodash's `zipWith` do, so elementwise arithmetic needs no
  intermediate pairs. It takes two parameters, like the callback of
  `reduce`. Rejected: a separate name such as `zipWith`, which would add a
  second query for one operation, and a combiner called with the pair as one
  argument, which would make every combiner index its argument.
- **Two sequences.** `zip` takes one other sequence. Rejected: n-ary zips,
  as Python's `zip(*iterables)` and lodash's `zip(...arrays)` accept, since
  the second argument is the combiner; `xs.zip(ys).zip(zs)` nests instead,
  giving `[[x, y], z]`, and a list as the second argument raises
  `TypeError("zip expects a function")`.
- **The other sequence is a list or a declared class.** These are the
  sequences the list queries serve, and a class as the argument is read as
  its instances in population order, as [NUC 97](nuc-0097.md)'s `in` and
  [NUC 62](nuc-0062.md)'s quantifiers read a class collection, through the
  same population read: a declared class is a sequence, and a name that no
  declaration made a class, such as the built-in namespace `Math`, is not.
  [NUC 110](nuc-0110.md)'s `", ".join(Name)` also leaves out a class declared
  with the name of a namespace that has statics, such as `class Math`; `zip`
  reads that class as `x in Math` does. Rejected: strings as sequences of
  characters, as Python zips them, since strings are not receivers of the
  list queries; an object's entries; and converting other values to lists.
- **Messages in the `expects` form.** An `OTHER` that is not a sequence
  raises `TypeError("zip expects a list")`, following the
  `<query> expects ...` messages of the other list queries; a population is
  a class instance list, so "a list" names both. A combiner that is not a
  function raises `TypeError("zip expects a function")` through the
  existing `expect_function` form. Both are raised even on an empty
  receiver, `OTHER` before the combiner, after every argument is evaluated,
  so `xs.zip(5, 6)` reports the sequence. Rejected: an undefined result for
  a `null` or undefined `OTHER`, which would hide a missing list in a
  declaration as `null`.
- **Extra arguments** are evaluated once, left to right, and ignored, as
  every list query does.
- **Items, not bindings.** The pairs hold the items themselves, so
  instances stay the same instances and nested lists stay lists, and `zip`
  reads no item as a binding: a `null` item stays in its pair without
  settling a declaration to `null`, as `concat` and `partition` keep theirs.
  The accepted spellings read the receiver's items through a callback
  parameter, so a declaration that holds them stores `null` once the
  receiver holds a `null` item. A combiner's own reads follow the existing
  rules, as in `map`, so a combiner that reads a `null` parameter settles
  the declaration that holds the `zip` to `null`, as the spelling does.
- **The receiver is never written,** nor is `OTHER`; unlike `sort` and
  `push`, `zip` only returns a new list.
- **Bounded cost.** The receiver and every argument are evaluated once per
  call, a class argument's instances are read once, and one pass over the
  shorter sequence builds the result, calling the combiner once per
  position, without recursion. The `indexOf` spellings search the receiver
  once per item, so their cost grows with the square of its length.
- **Rendered as written.** The call keeps its ordinary rendering:
  `pairs = xs.zip(ys)` explains as `pairs = xs.zip(ys)`, a function argument
  renders as `function()`, and a `zip` and its accepted spelling are
  different statements and graph keys.
- **Instance lists.** On a class name, `Name.zip(...)` is the population
  query even when the class declares an instance method `zip`, as
  [NUC 124](nuc-0124.md) made `Name.quantile(...)`. For a class `Team` that
  declares `def zip(other): return this.name + other`, `Team.zip([1])` raised
  `TypeError("Team.zip is not a function")` at the accepted revision, while
  its instance `red` answers `red.zip("!")` with `red!`, as it still does.
- **The method call only.** `zip` is not added to [NUC 75](nuc-0075.md)'s
  noun queries, so `zip of xs` keeps raising
  `SyntaxError("Unexpected keyword 'of'")`. Rejected: a global
  `zip(xs, ys)` function, as Python spells it, and `Math.zip`; `zip` is a
  common name of user functions and bindings, which keep their meaning, as
  `def zip(a, b) => a.length + b.length` does.
- **Pre-existing defects stay.** A callback in a function body cannot read
  the function's parameters, at both revisions: with
  `def scaled(xs, ys, k) => xs.zip(ys, (a, b) -> a * k)`,
  `scaled([1, 2], [3, 4], 2)` raised `TypeError("xs.zip is not a function")`
  and raises `ReferenceError("k is not defined")` under this NUC, as the same
  body with `map` does at both revisions, measured in phase 2 and on the
  final release binary. This proposal
  neither fixes nor pins the defect, and its cases stay clear of it. The
  defect also keeps the accepted spelling out of function bodies, where
  `zip` needs no callback: `def pairs(a, b)` returning
  `a[:b.length].reduce((acc, x) -> acc.concat([[x, b[acc.length]]]), [])`
  raises `ReferenceError("b is not defined")` for `pairs([1, 2, 3], [4, 5])`
  at both revisions, while the same function returning `a.zip(b)` gives
  `[[1, 4], [2, 5]]` under this NUC.
- **Requires.** [NUC 8](nuc-0008.md), whose functions are the combiners,
  called as values with two arguments, and whose named functions may be
  passed as one; and [NUC 61](nuc-0061.md), whose shared list query,
  population receivers, ranges, `list()`, argument order and null-receiver
  route the query joins. Those already require everything else these rules
  rest on.
- **Not added.** Padding to the longer sequence, length checks, `unzip`,
  n-ary zips, a zip with positions such as Python's `enumerate`, zipping
  strings, objects or other values, a `zipWith` name, a global `zip`
  function, `Math.zip`, noun forms such as `zip of xs`, property-name
  combiners, pairs as objects, and any change to what `concat`, `map`,
  `join` or the other queries return.

## Specification

- The normative contract is
  [List and population zipping](../nucleoid.spec.md#list-and-population-zipping).

### Calls

- `SEQUENCE.zip(OTHER)`, `SEQUENCE.zip(OTHER, COMBINE)` and
  `SEQUENCE.zip(OTHER, COMBINE, ...)` are list queries when `SEQUENCE`
  evaluates to a list, however it is reached: a variable, a property, an
  index, a slice, a call result such as `filter(...)`, `map(...)`,
  `sortBy(...)`, `slice(...)` or `concat(...)`, a literal, a `.value`
  snapshot or a selected version. The receiver may also be a class's
  instance list, named by the class, by a variable that holds the class or
  by `$Name`, in population order; a range such as `Driver[1:]` and
  `Name.list()` are lists.
- The receiver is read once, before the arguments. Every supplied argument
  is then evaluated once, left to right; the first is `OTHER`, the second
  the combiner, and the others are ignored.
- A `null` or undefined receiver keeps the accepted method route: the
  arguments are not evaluated and the call is undefined, so a declaration
  holding it stores `null`.
- On a class name the call is the population query even when the class
  declares an instance method `zip`; `instance.zip(...)` keeps calling the
  method.

### Pairs

- `OTHER` is a list, however it is reached, or a declared class, read as its
  instances in population order. The result is a new list with one item per
  position that both sequences have, from the first position to the last:
  as long as the shorter sequence, and `[]` when either is empty.
- Without a combiner, the item at each position is the new two-item list
  `[a, b]` of the receiver's item `a` and `OTHER`'s item `b` at that
  position. The items are the values themselves: an instance stays the same
  instance, a nested list stays a list, and `null` and undefined items stay
  in their pairs.

```
stops = ["Harbor", "Mill", "Oak"]
minutes = [0, 4, 9]
timetable = stops.zip(minutes)
assert(timetable, [["Harbor", 0], ["Mill", 4], ["Oak", 9]])
stops.push("Park")
assert(timetable.length, 3)
minutes.push(15)
minutes.push(22)
assert(timetable, [["Harbor", 0], ["Mill", 4], ["Oak", 9], ["Park", 15]])
stops.shift()
timetable[0]
```

- A new stop waits for its minute, and the timetable grows when the minute
  arrives; a further minute waits for its stop. Shifting the first stop
  pairs every stop with the minute at its new position, so this returns
  `["Mill", 0]`.

### Populations

- A class on either side is read as its instance list in population order,
  and its population is a dependency of the call.

```
class Driver(name):
    this.name = name
class Truck(plate):
    this.plate = plate
ada = Driver("Ada")
Driver("Bo")
Truck("T-1")
crews = Driver.zip(Truck)
assert([crews.length, crews[0][0], crews[0][1].plate], [1, ada, "T-1"])
Truck("T-2")
Truck("T-3")
assert(crews.map(crew -> crew[0].name + ":" + crew[1].plate), ["Ada:T-1", "Bo:T-2"])
Driver("Cy")
crews.map(crew -> crew[1].plate)
```

- Each crew holds the driver and the truck themselves. New trucks pair with
  waiting drivers until the trucks outnumber them, and a new driver takes
  the waiting truck, so this returns `["T-1", "T-2", "T-3"]`.

### Combiners

- A supplied second argument must be a function. It is called once per
  position, from the first position to the last, with the receiver's item
  and then `OTHER`'s item; further parameters are `null`, as in `map`, and a
  combiner that takes one parameter receives the receiver's item. The
  result at each position is the combiner's result.
- Reads inside the combiner follow the existing rules, and the errors it
  raises and the values it throws propagate unchanged.

```
prices = [4, 4, 2]
quantities = [3, 1, 3]
discount = 0
total = prices.zip(quantities, (price, quantity) -> (price - discount) * quantity).sum()
assert(total, 22)
prices.push(5)
assert(total, 22)
quantities.push(2)
quantities.push(9)
assert(total, 32)
discount = 1
total
```

- The two items at the price `4` carry different quantities, so the total
  is `4 * 3 + 4 * 1 + 2 * 3`. Each new price or quantity waits for its
  partner, and the combiner's read of `discount` is a dependency, so this
  returns `23`.

### Arguments

- `OTHER` is required. A list or a declared class is a sequence; anything
  else raises `TypeError("zip expects a list")`, even on an empty receiver,
  after the arguments are evaluated: a missing argument, a string, a number,
  a boolean, `null`, undefined, an object, an instance, a function, a date,
  a regular expression or a built-in namespace such as `Math`. A class is a
  sequence when a declaration made it one, as for `in` and the quantifiers,
  so a class a program declares as `class Math` is read as its instances.
- A supplied second argument that is not a function, including `null`,
  raises `TypeError("zip expects a function")`, even on an empty receiver,
  after `OTHER` is checked.
- Every supplied argument, including unused extras, is evaluated once, left
  to right, after the receiver and before the first combiner call, so an
  argument that reads an undefined name raises
  `ReferenceError("<name> is not defined")` first, as at the accepted
  revision.

### Accepted spellings

- For lists `xs` and `ys`, `xs.zip(ys)` evaluates to what
  `xs[:ys.length].reduce((pairs, x) -> pairs.concat([[x, ys[pairs.length]]]), [])`
  evaluates to, and `xs.zip(ys, f)` to what the same `reduce` gives with
  `f(x, ys[pairs.length])` in place of `[x, ys[pairs.length]]`, calling `f`
  as often and in the same order. They differ for `null` items of `xs`: the
  spelling reads them through its callback's parameter, so a declaration
  that holds it stores `null` once `xs` holds one, where the declaration that
  holds `zip` keeps the pair. `ys`'s items are read by index there and stay.
- `xs[:ys.length].map(x -> [x, ys[xs.indexOf(x)]])` gives the same pairs
  only while `indexOf` finds every item of `xs` at its own position: `[1, 1, 2]`
  and `[4, 5, 6]` pair as `[[1, 4], [1, 4], [2, 6]]` there and as
  `[[1, 4], [1, 5], [2, 6]]` with `zip`.
- Final-tree result, in the final full suite of [Checks](#checks):
  `zip_equals_its_accepted_reduce_spelling_over_generated_lists`
  compares `xs.zip(ys)` and `xs.zip(ys, f)` with their `reduce` spellings
  over 120 generated pairs of lists of up to six items, drawn from numbers,
  strings, `true`, lists and an object, with five combiners in turn, one of
  them taking one parameter, and a standing `p = xs.zip(ys, f)` with its
  spelling after a push to each list, and they agree.
  `declarations_follow_both_sequences_and_what_the_combiner_reads` steps a
  declaration of each form and of its spelling through pushes, pops,
  shifts, reassignments, a changed property and a changed variable that the
  combiner reads, with the same results and dependencies at every step.
- Final-tree result, on release binaries: of the 2,134 programs of the
  [differential](#compatibility) that change, 896 have an accepted spelling,
  and 895 of those give, on the final binary, what their spelling gives on
  the accepted binary, in plain and JSON output, as on the phase-2 binary.
  The remaining one is a spelling inside a function body, which the
  pre-existing defect of [Rationale](#rationale) breaks at the accepted
  revision.

### Liveness and class-level rules

- The query never writes either sequence. A declaration that uses it
  depends on the receiver, on its argument expressions, on the population
  of a class that either side reads and on whatever the combiner reads for
  every position.
- Pushing, popping, shifting or replacing either list, creating or deleting
  an instance of either class, and changing what the combiner reads
  re-evaluate the declaration.
- In a class-level rule, each instance evaluates its own query, and `$Class`
  inside the arguments or the combiner is the instance the rule is
  evaluated for.

```
class Trail(heights):
    this.heights = heights
$Trail.climbs = $Trail.heights.zip($Trail.heights[1:], (low, high) -> high - low)
$Trail.steep = $Trail.climbs.max() > 100
ridge = Trail([120, 180, 150, 240])
dale = Trail([40, 60, 60, 80])
assert([ridge.climbs, ridge.steep, dale.climbs], [[60, -30, 90], false, [20, 0, 20]])
ridge.heights.push(390)
dale.heights.push(200)
[ridge.climbs, ridge.steep, dale.steep]
```

- This is the `docs/examples.md` case, which returns
  `[[60, -30, 90, 150], true, true]`: every trail pairs each checkpoint with
  the next, and a rule derived from the climbs follows every new
  checkpoint.

### Transactions

- Combiner errors and an `OTHER` that a change makes invalid propagate
  through the existing transaction, so a failed standing re-evaluation rolls
  back the change that triggered it, including a list write or a new
  instance, and a rolled-back transaction restores the results of its
  declarations. `suppose` sees the hypothetical result and restores the
  accepted one when it ends.

```
def gap(load, limit):
    if load > limit:
        throw "OVERLOAD"
    return limit - load
limits = [4, 8, 6]
loads = [3, 5]
spare = loads.zip(limits, gap)
failure = ""
try:
    loads.push(9)
catch error:
    failure = error
assert([failure, loads, spare], ["OVERLOAD", [3, 5], [1, 3]])
try:
    loads.push(2)
    assert(spare, [1, 3, 4])
    throw "UNDO"
catch error:
    assert(error, "UNDO")
assert([loads, spare], [[3, 5], [1, 3]])
class Bay(load): this.load = load
Bay(1)
Bay(7)
room = Bay.zip(limits, (bay, limit) -> gap(bay.load, limit))
failure = ""
try:
    Bay(8)
catch error:
    failure = error
assert([failure, Bay.length, room], ["OVERLOAD", 2, [3, 1]])
Bay(6)
Bay(5)
room
```

- This returns `[3, 1, 0]`: the failed push, the undone push and the failed
  new bay leave the loads, the bays and both results as they were, and the
  fourth bay waits for a limit.

### Rendering and graph keys

- Statements, `why`, `affects` and graph and block keys show the call as
  written, with function arguments rendered as `function()`: the rule that
  `why pairs` reports for `pairs = xs.zip(ys)` is `pairs = xs.zip(ys)`, and
  `why` lists both sequences in the declaration's `from` list. A `zip` and
  its accepted spelling are different statements and keys.
- Errors that quote an expression quote the call: `xs.zip(ys)(1)` raises
  `TypeError("xs.zip(ys) is not a function")`.
