## Abstract

- Add only unshadowed static
  `Math.remap(start, end, targetStart, targetEnd, value)`.
- Remap a live numeric value without clamping, using the exact separate
  ordered arithmetic of accepted inverse interpolation followed by interpolation.
- Preserve accepted syntax, conversions, reactive behavior, argument effects,
  errors, scopes, receivers, class rules and transactional recovery.
- Independent evaluation accepted the frozen candidate: eight cases use
  fewer lexer tokens, 547 are unchanged, and none increase.

## Motivation

- State a relationship between two live ranges without nesting
  `Math.lerp(targetStart, targetEnd, Math.inverseLerp(start, end, value))`.
- Support descending source and target ranges and intentional extrapolation.
- Retain an independent inverseLerp unit control and full executable
  demonstrations, including both actual rollback catches.

## Rationale

- Reuse accepted numeric conversion and arithmetic, not a new numeric model.
- Keep separate rounding rather than improving a mathematical approximation
  with factoring, higher precision, FMA or overflow-avoiding rescaling.
- Reject endpoint, equal-target and zero-width shortcuts: they change NaNs,
  infinities, overflow, cancellation, underflow, subnormals or zero bits.
- Add no production helper, namespace, callable representation or parser rule.
- Evaluate the new call's five listed arguments once left to right.
- The nested accepted spelling evaluates target arguments before the inner
  source arguments; arbitrary effectful expressions are not effect-order
  equivalent. The sealed measured counterparts use pure variable/literal reads.
- Keep numeric conversions pure: never invoke, resolve or track shadowable
  Number or other Math bindings, or recurse through public Math dispatch.
- Depend only on already accepted features; combine no pending proposal.

## Specification

### Numeric contract

- The authoritative
  [Reactive range remapping section](../nucleoid.spec.md#reactive-range-remapping)
  defines the accepted contract and takes precedence over this proposal.
- The sole added unshadowed static signature is
  `Math.remap(start, end, targetStart, targetEnd, value)`.
- Evaluate every supplied expression once left to right through unchanged
  call machinery, including extras and expressions after Undefined.
- Retain Math's existing any-supplied-Undefined gate, including ignored
  extras, before its unchanged first-input conversion for start.
- Intrinsically convert positions one through four to end, targetStart,
  targetEnd and value, in that order, using unchanged `Value::to_number`.
- Every omitted input supplies numeric NaN, not a supplied Undefined or an
  arity error. Extra resulting values are neither converted nor used.
- Numbers retain their values, literal null converts to zero, booleans to
  zero/one, trimmed strings and empty/singleton lists retain numeric
  conversion, and dates contribute milliseconds.
- Other nonnumeric values convert to numeric NaN, not new type errors.
- Compute `numerator = value - start`.
- Compute `denominator = end - start`.
- Compute `weight = numerator / denominator`.
- Compute `delta = targetEnd - targetStart`.
- Compute `scaled = delta * weight`.
- Return numeric `targetStart + scaled`.
- Perform these six separate ordinary `f64` operations in exactly that order.
- Do not clamp, smooth, validate, reorder, factor, fuse, raise precision,
  rescale or shortcut endpoints, equal target ranges or zero source width.
- Both ranges may descend; out-of-range inputs intentionally extrapolate.
- Preserve NaN classification and every non-NaN result's bits, including
  signed zeros, infinities, overflow, underflow, subnormals and cancellation,
  against independent accepted arithmetic.
- Introduce no portable NaN-payload or zero-sign convention.
- Source `[-Number.MAX_VALUE, Number.MAX_VALUE]` with value zero normalizes
  to zero, not `0.5`.
- Equal targets `4, 4` with infinite weight give NaN, not four.
- Target `[-Number.MAX_VALUE, Number.MAX_VALUE]` at weight `0.25` can
  overflow to positive infinity rather than a rescaled finite result.

### Evaluation and compatibility

- Keep every supplied expression's reads, effects, dependencies, strict
  failures and rollback, even for ignored extras and after Undefined.
- Supplied Undefined retains inherited live/deferred assignment handling,
  missing properties, deletion and recovery.
- Intrinsic literal-null conversion does not override live assignment or
  parameter-null deferral.
- Preserve state/local Math shadowing and ordinary `.Math` properties/methods.
- Reading `Math.remap` stays unsupported/Undefined, not a first-class
  callable reference or alias.
- Preserve wrappers, typed metadata, frames, scopes, receivers, aliases,
  callbacks, per-instance class rules, positions, transactions and recovery.
- Keep every existing Math arm, helper, constant, conversion and error
  unchanged, including sign, lerp, inverseLerp, clamp, saturate, smoothstep,
  smootherstep and fract.
- The accepted nested composition and every accepted syntax form remain valid.
- Add no lexer, parser, AST, generator, CLI implementation, public API or
  representation, dependency, version, MSRV, edition or resource-bound change.
- New remap RHS ASTs and immediate graphs intentionally differ from the nested
  composition. Protect all other source/AST metadata, assertions, controls,
  observable values, transitive behavior, returns and executed coverage.
- Do not repair inherited noncapture, parameter-dependent-local, Windows
  debug stack or old whole-suite Gitless discovery limitations.

## Errors

- Introduce no numeric, conversion, range-validation or arity errors.
- Preserve inherited typed errors, exact messages, statement positions,
  caught values, user throws and transactional recovery.

| Condition | Exact inherited error |
| --- | --- |
