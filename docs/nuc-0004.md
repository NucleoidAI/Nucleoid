## Abstract

- Specifies properties on instances: assignment, dependency, chains through references, `value`, and deletion.
- A property assignment behaves like a variable assignment: it records a relationship, not a result.
- Properties may be written before the data they read exists.

## Motivation

- Most state in a program hangs off instances rather than free variables.
- Derived properties -- a total, a label, a status -- are the common case, and they must track their inputs.
- A chain such as `store.city.country.code` must stay correct when any link changes, including when a link is replaced.

## Rationale

- **Reading an undefined property yields `null`; writing through one raises.** Reading is how a rule declared ahead of its data stays inert until the data arrives. Writing through a missing instance has no meaningful target, so it is an error rather than a silent no-op.
- **`value` is reserved as a property name.** It is the operator that freezes a dependency, so allowing it as a name would make `x.value` ambiguous.
- **A dependency is created on behalf of a reference.** Writing `schedule1.template.name = ...` records the rule against the referenced instance, so it holds however that instance is reached.

## Specification

### Assignment

- A property is created by assigning to it.
- The right-hand side may name other properties, variables, or instances.
- A property assignment updates when its dependencies change.

```
class User:
    pass

user1 = User()
user1.name = "sample"
user1.email = user1.name + "@example.com"
```

- `user1.email` is `"sample@example.com"`.
- After `user1.name = "samplex"`, it is `"samplex@example.com"`.

### Assignment before the dependency exists

- A property may be assigned from a property that does not exist yet.
- The result is `null` until the dependency is defined.

```
class Order:
    pass

order1 = Order()
order1.upc = "04061" + order1.barcode
```

- `order1.upc` is `null`.
- After `order1.barcode = "94067"`, `order1.upc` is `"0406194067"`.

### Re-assignment and self-reference

- Assigning again replaces the previous relationship.
- A property that references itself on the right is read as its current value.

```
class Construction:
    pass

construction1 = Construction()
construction1.timeline = 120
construction1.timeline = 2 * construction1.timeline
```

- `construction1.timeline` is `240`.

### Chains through references

- A property may read through another instance.
- The dependency follows the reference, so changes at any link propagate.
- Replacing the referenced instance re-points the dependency.

```
class Plan:
    pass

class User:
    pass

basic = Plan()
basic.rate = 10

pro = Plan()
pro.rate = 30

user1 = User()
user1.plan = basic
user1.bill = user1.plan.rate * 12
```

- `user1.bill` is `120`.
- After `user1.plan = pro`, it is `360`.
- After `pro.rate = 40`, it is `480`.

- Writing through a reference records the rule on the referenced instance.

```
schedule1.template = template1
schedule1.template.name = schedule1.template.type + "-0001"
```

- `template1.name` is `"W-0001"`, reachable as either `template1.name` or `schedule1.template.name`.

### Objects as properties

- An instance may be assigned as a property before or after its own values are set.
- A class-level rule on the assigned type applies once its inputs exist.

```
class Distance:
    pass

$Distance.total = Math.sqrt($Distance.x * $Distance.x + $Distance.y * $Distance.y)

agent1.distance = Distance()
```

- `agent1.distance.total` is `null`.
- After `x = 3` and `y = 4`, it is `5`.

- A plain `Object()` is not an instance of any type, so class-level rules do not reach it.

### Null and undefined

- Any `null` dependency makes the result `null`.
- Reading through a missing link yields `null` rather than raising.

```
class Product:
    pass

product1 = Product()
score = product1.quality.score
```

- `score` is `null`.

### The value property

- `x.value` reads the current value and records no dependency.
- The value of a `null` property is `0`.
- `value` may not be used as a property name.

```
class Weight:
    pass

weight1 = Weight()
weight1.gravity = 1.352
weight1.mass = 1000
weight1.force = weight1.gravity * weight1.mass.value
```

- `weight1.force` is `1352`.
- After `weight1.mass = 2000`, it is still `1352`.
- After `weight1.gravity = 2`, it is `2000`, using the frozen `1000`.

- Applied to a property that was never defined, `.value` raises rather than yielding `0`.

### Deletion

- `delete` removes a property and returns whether anything was removed.
- Dependents of a deleted property become `null`.
- Dependents that did not read it are unaffected.

```
class Report:
    pass

report1 = Report()
report1.year = 2019
report1.month = 4
report1.period = report1.year + "-" + report1.month
report1.label = "P" + report1.year

delete report1.month
```

- `report1.period` is `null`.
- `report1.label` is still `"P2019"`.
- Deleting the same property again returns `false`.

- Deleting an intermediate reference makes dependents `null`; restoring it restores them.

## Errors

| Condition | Error |
| --- | --- |
| Writing a property through an undefined instance | `ReferenceError("<path> is not defined")` |
| Assigning an object through an undefined instance | `ReferenceError("<path> is not defined")` |
| Using `value` as a property name | `TypeError("Cannot use 'value' as a property")` |
| Reading `.value` of a property that is not defined | `ReferenceError("<path> is not defined")` |

- The path in the message is written as it appears in the statement, for example `channel1.frequency` or `worker1.duty`.
- `value` is rejected as a property name on an instance, in a value assignment, inside a block, and at class level.
