## Abstract

- Add only the statement `TARGET &&:= EXPR`: when the current target value
  is truthy under the existing truthiness rules, perform one ordinary
  imperative value assignment; otherwise do nothing and never evaluate the
  right-hand expression.
- Isolate the target lookup, guard and taken action from dependency
  tracking, as NUC 144 does for nullish value assignment. A skip must not
  replace a standing declaration, subscribe to inputs, record history or
  write a value.
- Reuse the existing `&&` and `:=` tokens without changing ordinary logical
  expressions, declarative `&&=`, unconditional `:=` or nullish `??:=`.
  This is a core conditional action, not an alias for a standing law.
- The caller's one uniform eligible-category draw selected Runtime
  features. This continuous revision uses `existing_comparable` runtime
  applicability: concrete accepted `:= target && value` top-level takes
  and snapshot-guarded `if`/`:=` skips and branches supply the selected
  programs' immutable counterparts. Lexer-token comparison and every
  behavior, integrity and development check remain mandatory.

## Motivation

- Models need to consume or replace an enabled value once while leaving
  false, zero, empty text and other falsy targets untouched. A skipped
  replacement must not evaluate an effectful or erroneous expression.
- Ordinary `&&=` installs a logical declaration. An unconditional `:=`
  still writes on the skipped branch. Neither is the isolated, no-write
  skip of a conditional action.
- NUC 144 already establishes the tracking isolation, target preparation,
  flag restoration and taken-write machinery. A truthiness guard can reuse
  it without adding a family of assignment operators or a new truth model.
- Preserve every accepted spelling and diagnostic. No `||:=`, keyword,
  dependency, option, project version or ARC change is requested.

## Rationale

- A truthiness-guarded action belongs to Runtime features: its purpose is
  conditional execution, not another spelling for a standing law or a
  foreign-language compatibility alias. Keep the caller's confirmed category.
- Reuse NUC 144's isolated guard and NUC 66's taken action. A private typed
  guard dispatch selects existing nullishness or existing truthiness without
  changing either value model or the old public syntax-tree variants.
- Reject unconditional `target := target && value` as a general lowering:
  it still files a falsy value, replacing the declaration and dependencies.
  Reject ordinary standing `if target` as a general lowering because its
  guard can subscribe to inputs and its body does not file a top-level fact.
- The two selected concrete programs have executed accepted counterparts.
  Known-truthy top-level takes use `slot := slot && 9`,
  `active := active && 5` and `gate.target := gate.target && 0`; falsy
  skips and the standing branch use snapshot guards. This is equivalence
  for those programs, not a universal lowering of arbitrary falsy inputs.
- Preserve NUC 66's actual context boundary. An action inside `if enabled`
  can set a target now but cannot replace its existing law: after
  `gate.source = 8`, that law gives `gate.target = 9`, not `12`.
- Introduce no sibling `||:=`, keyword, token kind, option, dependency,
  numerical helper or unrelated pending proposal.

## Specification

- The sole new form is the statement `TARGET &&:= EXPR`. Tokenization is
  the existing `&&` followed by existing `:=`. Ordinary inter-token spacing
  and comments are permitted; a logical newline still separates statements.
- Only an expression-statement head's own expression nesting level stops
  ordinary logical conjunction before the exact `&&`/`:=` pair. Validate
  the same grouped, bounded path as `:=` and parse its ordinary receiving
  expression. No assignment expression is enabled inside calls, lists,
  returns, defaults, headers, arrows or other nested expressions.
- Resolve, validate and read the target normally in the current scope.
  An unbound root is an error; an ordinary absent object property may yield
  Undefined. Read-only versions, forbidden properties, invalid owners and
  class boundaries are checked even on otherwise skipped targets.
- Use `Value::truthy` unchanged. Null, Undefined, false, positive zero,
  negative zero, NaN and empty Strings skip. Nonzero numbers, nonempty
  Strings, Lists including empty Lists, objects, classes, functions, Dates
  and regular expressions take the action.
- A skip returns the ordinary `pass` result without evaluating the RHS.
  It files no assignment, records no scope-assignment bookkeeping, changes
  no target identity or declaration, appends no history and replaces no
  dependency or structural subscription. Existing target laws remain live.
- A take performs exactly one ordinary `:=` action, evaluating the RHS
  once and preserving its effects, extra-argument evaluation, lexical
  property receiver, named-constructor binding, local scopes, instance
  rules, target-resolution timing and storage/null-read settlement.
- At top level a take files a literal/fact and replaces the target law.
  Standing-if and other imperative bodies instead carry it out without
  filing, as they do `:=`; later source changes may recompute that law.
  Every subsequent entry checks the current target again.
- Isolate target resolution and guard reads as well as a taken RHS and
  called functions, methods, callbacks and structural queries from all
  enclosing dependency-tracking frames. Do not install a standing guard.
  An enclosing `if enabled` depends on `enabled`, not the action's inputs.
- Restore the enclosing null/undefined-read flags after guard preparation,
  including errors, before any action runs. A skipped Null/Undefined guard
  must not poison a later assignment. Do not turn off ordinary RHS
  null/undefined settlement or surrounding function argument deferral.
- Preserve propagation, transactions and all existing parser, path, call
  and statement limits, including inherited rollback-order and deep
  runtime-value limitations. No stronger general guarantee is introduced.
- Canonical source rendering is `target&&:=value`. A take returns the
  existing action's value. Block identities distinguish the new statement
  from unconditional actions, nullish actions and standing declarations.
- The normative [root contract](../nucleoid.spec.md#truthy-value-assignment)
  and exactly two appended executable cases trace these claims:
  `Nucleoid writes truthy values with one-shot assignments` in the spec and
  `Nucleoid keeps truthy assignment guards isolated` in the reference.
  Each keeps its supplied six ordered canonical assertions and explicit
  expected return `1`; every historical executable source is unchanged.

## Errors

- Unsupported targets report `SyntaxError("Invalid value assignment target")`
  at the `&&`, using the same path validation as `:=`. Existing path and
  nesting limits keep their types and messages.
- An unbound root reports `ReferenceError("<name> is not defined")`;
  undefined/null intermediate owners retain their ordinary lookup errors.
  Missing ordinary leaf properties instead read as Undefined and skip.
- An invalid numeric owner retains
  `TypeError("Cannot assign '<property>' on number")`; other owner kinds
  keep their ordinary typed diagnostics. An attempted `value` property
  retains `TypeError("Cannot use 'value' as a property")`.
- Writes to version slots retain
  `TypeError("State versions are read-only")`; selecting a stored object
  reference still permits its ordinary property writes. Class-level storage outside
  an instance rule retains
  `TypeError("Cannot use ':=' on a class-level property")`.
- Resolve these target errors even when the value would be falsy. A skipped
  RHS cannot raise an error because it is never evaluated. A taken RHS,
  propagation or resource failure follows the existing action and transaction
  paths; recovery does not introduce a new error kind.
- Preserve every accepted parser input, including inputs that fail at
  runtime. Ordinary `&&` and nested conjunction, standing `&&=`/`||=`,
  unconditional `:=`, nullish `??:=`, public `parse_expression`, ignored
  interpolation suffixes and pinned `??=` errors retain their behavior.

## Reference Implementation

- `Stmt::TruthyValueAssign` represents the new statement. The existing
  private expression-head depth boundary is shared with nullish assignment;
  only logical conjunction adds the exact head-level stop. The lexer and
  public parsing entry points keep their interfaces.
- The generator, assignment-name, root-read, class-reference, class-rule
  and protected-assertion traversals handle the new statement explicitly.
  Existing variants and every old public path remain present.
- The private `nuc::guarded_value_assign` module reuses NUC 144's converter
  with typed `Guard::Nullish` and `Guard::Truthy` dispatch. Property
  preparation and property-name checks precede guard reads; identifier
  assignment preparation waits for a take so a skip cannot record it.
- The isolated converter restores both read flags on success and failure.
  A skip returns existing `Nuc::Pass`; a take returns existing
  `Nuc::ValueAssign`. NUC 66's RHS evaluator, literal storage, filing and
  propagation machinery are unchanged; no public runtime node is added.
- `docs/nucleoid.ebnf` records the new statement, contextual head-level
  boundary and unchanged two-token source contract. Reference text, the
  two new canonical synthesized records and generated normative exports
  remain synchronized.
- Ordinary integration regressions cover laziness across value kinds,
  unchanged state/graph on skips, scope bookkeeping, literal filing versus
  branch carry-out, tracking isolation, receiver and instance contexts,
  target validation, transactions, bounds, rendering and legacy syntax.
  Direct converter tests cover both read flags on takes, skips and errors
  for both guards. Every checked language assertion must execute.
- Adding a variant to the existing public closed `Stmt` enum affects
  downstream exhaustive matches and requires human SemVer/API review.
  No project version, MSRV, dependency or Cargo manifest is changed.

## Backward Compatibility

- Keep every accepted source, result, pinned diagnostic, assertion and
  existing test. New contextual parsing applies only to the exact
  statement-head `&&`/`:=` pair at that expression level; ordinary and nested
  logical expressions keep their accepted behavior.
- Preserve all historical case identities, canonical assertions, explicit
  returns and executed coverage. Update only directly derived count and
  locator metadata for the two appended cases, including the sign-copying
  case's reverse ordinal; keep its sealed source and assertions intact.
- Replay the pinned accepted corpus and original version-2 extra sources
  unchanged. The retained failed original controls are precondition evidence,
  not the active baseline; no baseline or sealed control is rewritten.
