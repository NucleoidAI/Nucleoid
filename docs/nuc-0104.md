# NUC 104 -- Any and All Class References

```
NUC: 104
Title: Any and All Class References
Author: Can Mingir <canmingir@gmail.com>
Status: Draft
Type: Standards Track
Category: Syntax enhancement
Created: 10-Nov-2026
Requires: 62, 98
```

## Abstract

- Adds `any NAME` and `all NAME` as spellings of the class reference
  `$NAME`, as [NUC 98](nuc-0098.md) made `every NAME` one. Where an operand
  begins, the name `any` or `all` followed by a name builds the tree of
  `$NAME`, so its evaluation, dependencies, errors and rendering are those
  of `$NAME`:
  - `if any Object.number > 4:` is `if $Object.number > 4:`, the class-level
    condition that holds for each Object whose number is over 4;
  - `all Object.color is red` is `$Object.color is red`;
  - `all Object is red` and `any Object is red` are the predicate sentence
    `$Object is red` of NUC 98, which states `$Object.red = true`.
- A condition about a class then reads with `any`, and the rule it guards
  with `all`:

```
class Object(number):
    this.number = number

every Object.label is square

if any Object.number > 4:
    all Object.color is red

a = Object(3)
b = Object(7)
assert([a.label, b.label], ["square", "square"])
assert([a.color, b.color], [null, "red"])
```

- `any` and `all` keep every reading that NUC 98 keeps for `every`: the
  quantifiers `any NAME in COLLECTION: CONDITION` and
  `all NAME in COLLECTION: CONDITION` of [NUC 62](nuc-0062.md), `any is ...`
  and `all is ...`, a name followed by `:` outside a clause, the top level of
  a template interpolation, and `any` or `all` after `.`, as a declared name,
  parameter, key, label, loop name or binder, or followed by anything but a
  name.
- The user accepted one compatibility break in advance, limited to the
  inputs it names. Where an operand begins, the name `any` or `all` directly
  followed by a name ended one statement or item, and the name began the
  next. So after `all = 3`, `all Human = 4` ran as `all` and `Human = 4`.
  Those inputs now read `$NAME`, and `all Human = 4` raises
  `SyntaxError("Cannot assign to $Human")` when it runs. The four assertions
  that pinned the old reading move to the new one:
  - in `tests/quantifiers.rs::ordinary_names_keep_every_accepted_reading`,
    the program `c = 1`, `all = 2`, `x = all c`, `x`, which returned `2`,
    and `equivalent("x = all c", "x = all\nc")` and
    `equivalent("x = any c", "x = any\nc")`;
  - in
    `tests/quantifiers.rs::parse_expression_now_reads_a_quantifier_and_still_ignores_what_follows`,
    `parse_expression("all x")`, which returned the name `all`.
- Any other change to an accepted parse, behavior, output or pinned test
  still fails backward compatibility.

## Motivation

- Rules about a class are conditions and consequences: if any order's total
  is over 100, the order is a VIP. NUC 98 lets a claim read as it is said,
  `every Human is mortal`, but a condition still needs the sigil:
  `if any Object.number > 4:` raises
  `SyntaxError("Expected ':' but found identifier 'Object'")`.
- `all Object.color is red` runs today as the two statements `all` and
  `Object.color is red`, and raises `ReferenceError("all is not defined")`.
- `$` is Nucleoid's own mark for each instance of a class. `any` and `all`
  are how people and language models say it in a condition and in the rule
  it guards, and world models such as the ARC datasets state their
  transformations as such rules over classes.
- The user requested `any` and `all` as spellings of `$`, with `any` in the
  condition of an `if` and `all` inside its clause, as in the example above.
