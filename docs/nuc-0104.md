## Abstract

- Adds `any NAME` and `all NAME` as spellings of the class reference
  `$NAME`, as [NUC 98](nuc-0098.md) made `every NAME` one. Where an operand
  begins, the name `any` or `all` followed by a name builds the tree of
  `$NAME`, so its evaluation, dependencies, errors and rendering are those
  of `$NAME`:
  - `if any Object.number > 4:` is `if $Object.number > 4:`, the class-level
    condition that holds for each Object whose number is over 4;
  - `all Object.color is red` is `$Object.color is red`;
  - `all Object is red` and `any Object is red` are the predicate sentence
    `$Object is red` of NUC 98, which states `$Object.red = true`.
- A condition about a class then reads with `any`, and the rule it guards
  with `all`:

```
class Object(number):
    this.number = number

every Object.label is square

if any Object.number > 4:
    all Object.color is red

a = Object(3)
b = Object(7)
assert([a.label, b.label], ["square", "square"])
assert([a.color, b.color], [null, "red"])
```

- They are spellings, not quantifiers: each instance is tested on its own,
  as with `$Object`, so only `b` turns red.
- `any` and `all` keep every reading that NUC 98 keeps for `every`: the
  quantifiers `any NAME in COLLECTION: CONDITION` and
  `all NAME in COLLECTION: CONDITION` of [NUC 62](nuc-0062.md), `any is ...`
  and `all is ...`, a name followed by `:` outside a clause, the top level of
  a template interpolation, and `any` or `all` after `.`, as a declared name,
  parameter, key, label, loop name or binder, or followed by anything but a
  name.
- No token, keyword, syntax-tree variant, error type or message, option or
  flag is added, and no public item is added or removed. The authoritative
  contract is
  [Any and all class references](../nucleoid.spec.md#any-and-all-class-references).
- The user accepted one compatibility break in advance, limited to the
  inputs it names. Where an operand begins, the name `any` or `all`
  directly followed by a name ended one statement or item, and the name
  began the next. So after `all = 3`, `all Human = 4` ran as `all` and
  `Human = 4`. Those inputs now read `$NAME`, and `all Human = 4` raises
  `SyntaxError("Cannot assign to $Human")` when it runs. The four assertions
  that pinned the old reading move to the new one:
  - in `tests/quantifiers.rs::ordinary_names_keep_every_accepted_reading`,
    the program `c = 1`, `all = 2`, `x = all c`, `x`, which returned `2`,
    and `equivalent("x = all c", "x = all\nc")` and
    `equivalent("x = any c", "x = any\nc")`;
  - in
    `tests/quantifiers.rs::parse_expression_now_reads_a_quantifier_and_still_ignores_what_follows`,
    `parse_expression("all x")`, which returned the name `all`.
- Any other change to an accepted parse, behavior, output or pinned test
  still fails backward compatibility.
- **Accepted** on 10-Nov-2026 under the user-requested basis of the
  automatic acceptance rule: the frozen candidate meets every hard
  criterion, with the break above and no other. The independent evaluator's
  overall decision is also Accepted. Token comparison was skipped as
  `single_proposal`, the rule for a single-proposal request, not a failed
  check; see [Evaluation](#evaluation).

## Motivation

- Rules about a class are conditions and consequences: if any order's total
  is over 100, the order is a VIP. NUC 98 lets a claim read as it is said,
  `every Human is mortal`, but a condition still needs the sigil:
  `if any Object.number > 4:` raises
  `SyntaxError("Expected ':' but found identifier 'Object'")`.
- `all Object.color is red` runs today as the two statements `all` and
  `Object.color is red`, and raises `ReferenceError("all is not defined")`.
- `$` is Nucleoid's own mark for each instance of a class. `any` and `all`
  are how people and language models say it in a condition and in the rule
  it guards, and world models such as the ARC datasets state their
  transformations as such rules over classes.
- The user requested `any` and `all` as spellings of `$`, with `any` in the
  condition of an `if` and `all` inside its clause, as in the example above.

## Rationale

- **Category and mode.** The user requested this concrete feature, so there
  was no random draw. It is a Syntax enhancement, like NUC 98, which it
  extends, and it runs in single-proposal mode, which skips token
  comparison. Runtime applicability does not apply. No hint was supplied.
- **The user's decisions.** Asked to choose before allocation, the user chose
  exact spellings of `$` over an existential or universal reading, and
  accepted the juxtaposition break in advance, with the four assertions that
  pinned it. The user's capital `If` is read as `if`, which is accepted
  syntax; a capitalized `If` is not.
- **Spellings, not quantifiers.** `any NAME` and `all NAME` build exactly
  `Expr::ClassRef(NAME)`, so `if any Object.number > 4:` is the per-instance
  class-level conditional of `$Object`. Rejected:
  - an existential reading, in which `if any Object.number > 4:` holds once
    some Object qualifies and `all Object.color is red` then paints every
    Object. It needs a new tree or a lowering into
    `if (any o in Object: o.number > 4):` with a population-wide body, and
    the user declined it; the quantifiers of NUC 62 already state it;
  - a universal reading of `all` in a condition, for the same reasons.
- **One recognition rule, generalized.** NUC 98's token rule now accepts the
  three words: where an operand begins, outside the top level of a template
  interpolation, `every`, `any` or `all` followed by a name token that is not
  `is`, and not followed by `:` outside a clause, builds `$NAME`. The rule
  compares three tokens and parses nothing ahead, so each operand is still
  parsed once, and the readings NUC 98 kept for `every` stay kept for `any`
  and `all` by construction.
- **Quantifiers keep their priority.** `primary` asks `Quantifier::starting`
  first, so `all NAME in` and `any NAME in` still begin the quantifiers of
  NUC 62, and `Quantifier::starting` is unchanged.
- **Recognition without state.** The reading depends only on tokens: a
  variable named `all` or `any`, a defined class or the case of `NAME` never
  changes it, as NUC 98 decided for `every`. Rejected:
  - requiring a capitalized name or a declared class, which would make a
    line's meaning depend on the state, and which NUC 98's user decision on
    exact class names already settled;
  - an accepted-first retry as NUC 86 uses. A retry would reach
    `if any Object.number > 4:`, which fails at the accepted revision, but
    never `all Object.color is red` or
    `all Order.big = all Order.total > 10`, which parse there as
    juxtapositions, and a line's reading would then depend on whether
    another part of the program fails;
  - keywords, which would break every variable, function, parameter,
    property, key and binder named `all` or `any`, among them accepted
    specification cases.
- **The break is the juxtaposition of a name.** Where an operand begins,
  `all NAME` could only end one statement or item with `all` and begin the
  next with `NAME`, or fail: no accepted operator or postfix starts with a
  name, `in` and `of` are keywords, and `is` is excluded. The user accepted
  that these inputs read `$NAME`; the other juxtapositions follow, so
  `all x => x`, `all x := 1` and `all all v in xs: v` raise the syntax errors
  of their `$NAME` spelling. Guarding them would add rules that no valid
  program needs.
- **Predicate sentences by construction.** NUC 98's sentence asks only for a
  leading class reference without a property, so `all Human is mortal` and
  `any Human is mortal` state `$Human.mortal = true` with no change of their
  own, in every statement position, and every `is` statement that keeps its
  juxtaposed reading after `$Human` keeps it after `all Human`.
- **Rendering as `$`.** The tree is that of `$NAME`, so graph keys, block
  keys, `--graph` output and the `rule` that `why` and `affects` report use
  the `$` spelling, and `if any Order.total > 10:` and
  `if $Order.total > 10:` are one rule and one graph key: either replaces
  the other. Rejected: rendering the word, which needs a marker in the tree
  and would make the spellings different rules.
- **No REPL or terminal change.** The REPL's colon-free header scan and the
  direct-alternative lookahead are lexical: they already buffered
  `if any Object.number > 4` and qualified `else any Object.number > 4` with
  an indented body, and the accepted parser then failed. Only the parse at
  submission changes. Their quantifier pairing still asks
  `Quantifier::starting`.
- **Names.** The private helpers become `starts_spelled_class` and
  `spelled_class`, and the grammar's `everyClass` becomes `spelledClass`,
  because they now read three words. No public name changes.
- **Host stack.** No parser function is added; the renamed pair keeps its
  place in `primary`, and `primary` keeps its debug frame, as Measured cost
  records.
- **Optional evidence.** Advisory usefulness is unscored (`missing_rubric`),
  not zero. Strategy learning is `not_configured`; this revision is
  unattributed, without a policy, selection receipt, trial or reward.

## Specification

- The normative contract is
  [Any and all class references](../nucleoid.spec.md#any-and-all-class-references).

### Class references

- Where an operand begins, outside the top level of a template
  interpolation, the name `any` or `all` followed by a name token `NAME`
  builds `Expr::ClassRef(NAME)`, the tree of `$NAME`, exactly where
  NUC 98's `every NAME` builds it. A block comment may stand between them;
  outside parentheses and brackets a line break separates them, and they
  keep their accepted reading.
- It does not apply, and `any` or `all` keeps its accepted reading, when:
  - `in` follows `NAME`, which is a quantifier of NUC 62;
  - `NAME` is `is`;
  - `:` follows `NAME` outside a clause. The clauses are statement headers,
    `suppose` premises, subscript starts, the consequent after `?`,
    Python-style conditions and quantifier collections.
- Inside a template interpolation, parentheses, brackets, call arguments
  and the consequent after `?` select the class reference, as for `every`.
- Everything else about `any` and `all` is unchanged: either word followed
  by anything but a name, after `.` as a property or method, as in
  `xs.any(v => v > 2)` and `Member.all()`, and as a declared name, function,
  parameter, key, label, loop name, binder or class name.
- `parse_expression` reads the class reference and still ignores what
  follows, so `parse_expression("all x")` returns `$x`.

```
class Order(total):
    this.total = total
small = Order(5)
all Order.big = all Order.total > 10
if any Order.total > 100:
    all Order.vip = true
large = Order(200)
assert([small.big, large.big], [false, true])
assert([small.vip, large.vip], [null, true])
small.total = 150
assert([small.big, small.vip], [true, true])
```

### Predicate sentences

- A class reference spelled `all Class` or `any Class`, possibly grouped in
  parentheses, is a leading class reference without a property, so NUC 98's
  predicate sentence applies to it unchanged: `all Human is mortal` and
  `any Human is mortal` build the tree of `$Human.mortal = true` in every
  statement position of [NUC 93](nuc-0093.md), when the token after the word
  ends a line statement.
- Every other `is` statement on such a subject keeps its juxtaposed reading,
  as after `$Human`: `all Human is mortal z1 = 1` is `$Human`, `is`, `mortal`
  and `z1 = 1`, and `all Human is 5` is `$Human`, `is` and `5`.
- `is` inside an expression keeps NUC 86's comparison, so
  `if all Human is mortal:` compares.

```
class Human(name: str):
    this.name = name
plato = Human("Plato")
all Human is mortal
any Human is wise
socrates = Human("Socrates")
assert([plato.mortal, socrates.mortal], [true, true])
assert((why socrates.mortal)[0].rule, "$Human.mortal = true")
```

### Kept readings beside class references

- Variables named `all` and `any`, and the quantifiers that start with
  them, stand beside the class references in one program: the class-level
  rule reads the variable `any`, and each quantifier ranges over the
  variable `all`.

```
class Item(x):
    this.x = x
all = [1, 2, 3]
any = 2
all Item.big = all Item.x > any
first = Item(1)
third = Item(3)
assert([first.big, third.big], [false, true])
assert(all n in all: n > any, false)
assert(any n in all: n > any, true)
assert(all.length + any, 5)
```

### Rendering

| Statement | Rendering |
| --- | --- |
| `all Human.mortal = true` | `$Human.mortal=true` |
| `if any Order.total > 10:` with `all Order.big = true` | the rendering of `if $Order.total > 10:` with `$Order.big = true` |
| `all Human is mortal` | `$Human.mortal=true` |
| `any Human is mortal` | `$Human.mortal=true` |
| `{ all Human is mortal }` | the block key of `{ $Human.mortal = true }` |
| `if any Object.number > 4:` over an instance `b` | the graph key `if($Object.number>4)@b` |

- No error type or message is added. Class references spelled with `any` or
  `all` raise the errors of their `$NAME` spelling:
