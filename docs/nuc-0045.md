# NUC 45 -- Colon-Led Assertion Statements

```
NUC: 45
Title: Colon-Led Assertion Statements
Author: Can Mingir <canmingir@gmail.com>
Status: Accepted
Type: Standards Track
Category: Syntax enhancement
Created: 16-Oct-2026
```

## Abstract

- Add optional `assert: actual, expected` statements as exact syntax sugar
  for existing two-argument `assert(actual, expected)` expression statements.
- Keep the complete existing call AST, canonical source and runtime behavior.
  Ordinary calls remain supported; this is not a new assertion API.
- The accepted specification contract is
  [Colon-led assertion statements](../nucleoid.spec.md#colon-led-assertion-statements).

## Motivation

- Verification and diagnostics are cross-cutting needs for executable logic
  models and LLM-generated programs, not a numerical utility niche.
- Recent NUCs covered collections, text, conditional control and records.
  Short equality checks improve verification throughout those areas without
  adding another runtime operation or alternate comparison semantics.
- Existing scopes, receivers, reactivity, snapshots, failures and transactions
  already supply the necessary behavior.

## Rationale

- Honor the caller's single sealed draw selecting syntax improvement; do not
  redraw or substitute a fixed rotation. Selection considered reasoning,
  dependencies, functions/scope, control, collections/text, modeling and
  diagnostics, without a math ban or quota.
- Recognize only an existing lowercase identifier and colon in statement
  position, after the accepted typed-declaration branch has priority.
- Reuse ordinary expression parsing for each argument, including the outer
  expression nesting level used by a call. Do not bypass resource limits.
- Reject truthiness assertions, generic bare calls, aliases, new keywords,
  multiline continuation, trailing commas and extra colon-form arguments.
- Preserve every historical measured program and earlier training file.
  Append only the eight independently pre-executed V2 accepted-call controls,
  changing only their statement assertion delimiters.

## Specification

- Match `Identifier("assert") Colon` only in `statement_inner`, after its
  original typed-declaration guard. Whitespace follows ordinary lexer rules.
- Keep `is_type_declaration` unchanged: a following identifier plus the
  original `Newline`, `Semicolon`, `Dedent` or `Eof` boundary wins.
  Exact `assert: int` remains `Stmt::Declaration`, including its inherited
  runtime failure. Do not add `RightBrace` to those boundaries.
- Parse two ordinary whole expression arguments, separated by the original
  comma, and reject a comma following the second expression.
  No special argument grammar, layout skipping or continuation is added.
- Lower precisely to `Stmt::Expression(Expr::Call)` with callee
  `Expr::Identifier("assert")` and arguments `[actual, expected]`.
  No lexer, public AST, runtime, generator or CLI representation changes.
- Keep the statement depth, call's outer expression depth and each argument's
  depth. Operator and postfix chains retain their existing budgets.
- Canonical output stays `assert(actual,expected)`. Ordinary call syntax,
  expression uses, argument-count behavior and its optional trailing comma
  remain unchanged.
- Bindings, parameters, annotations, class fields and object keys named
  `assert` retain their existing grammar and meaning.
  The existing direct named-call helper runs before scope/name lookup:
  a variable or parameter named `assert` does not shadow that helper.
- Arguments run once, left to right, with existing deep equality, null helper
  result, collected failures and assertion counters. Failed operands stop
  later arguments and use the existing transactional rollback path.
- The same assertion-expression classification excludes checks from program
  results, dependency nodes and reasoning observers. Reads do not install the
  check itself as a reactive rule; enclosing functions/rules retain their
  existing re-execution, including repeated body assertion executions.
- Preserve ordinary scopes, functions, return flow, receivers, `.value`
  snapshots, caught whole errors and recovered reactive dependencies.
- Trace structural equality to
  `Nucleoid checks values with colon-led assertion statements`.
  Trace graph exclusion and live dependencies to
  `Nucleoid keeps colon-led assertions out of reactive reasoning`.
- Trace local parameters, snapshots and returns to
  `Nucleoid preserves scope and return flow around colon-led assertions`.
  Trace left-to-right effects to
  `Nucleoid preserves colon-led assertion argument evaluation order`.
- Trace whole caught errors and rollback to
  `Nucleoid checks caught errors and rollback with colon-led assertions`.
  The five spec entries, one reference, one README and one examples entry
  preserve 30 actually executed assertions and returns `7` and `true`.
- The following program is the argument-order spec entry without its title:

```
log = []
def note(label):
    log.push(label)
    return 7
assert: note("actual"), note("expected")
assert: log, ["actual", "expected"]
assert: log.length, 2
```

## Errors

- No new runtime error kind, equality rule or assertion exception is added.
  Mismatches still collect the existing actual/expected failure pair instead
  of throwing; counters and the null helper value retain their behavior.
- Missing operands use the ordinary expression parser's
  `SyntaxError("Unexpected <token>")`, including
  `SyntaxError("Unexpected end of input")` for `assert:` or `assert: 1,`.
- Missing separating commas use the ordinary expectation diagnostic
  `SyntaxError("Expected ',' but found <token>")`.
  Exact `assert: 1` raises `Expected ',' but found end of input`;
  `assert: 1 2` raises `Expected ',' but found number 2`.
- A comma following the second expression, including a trailing comma,
  raises `SyntaxError("Assertion statements expect exactly two arguments")`.
- Exact `assert: 1,\n1` and `assert:\n    1, 1` raise
  `SyntaxError("Unexpected end of line")`. This revision does not introduce
  a layout continuation facility.
- Exact `assert\n    : 1, 1` raises `SyntaxError("Unexpected ':'")`.
  Exact `assert: 1,\n    1` also raises
  `SyntaxError("Unexpected end of line")`.
- Horizontal lexer whitespace remains space, tab, form feed and carriage
  return. A non-breaking space in `assert : 1, 1` raises
  `SyntaxError("Unexpected character ' '")`; Unicode whitespace is not an
  alternate delimiter. Existing grouped multiline expressions remain valid
  wherever their ordinary expression grammar permits them.
- Exact `assert: int` keeps `ReferenceError("Missing definition")`.
  The original accepted parser permits the declaration, not a successful
  runtime declaration; this revision neither reinterprets nor repairs it.
- The rollback spec entry keeps
  `ReferenceError("missing is not defined")`. Compare the complete caught
  error against `ReferenceError(...)`, not an unsupported error member.
  Other ordinary operand errors propagate unchanged.
- Resource errors remain `SyntaxError("Expressions are nested too deeply")`,
  `SyntaxError("Statements are nested too deeply")`,
  `SyntaxError("Expression has too many operands")` and
  `SyntaxError("Expression has too many parts")`.
- Syntax positions name tokens in the actual source. Differently spelled
  inputs need not have equal physical columns; unchanged legacy inputs
  retain their positions.

## Reference Implementation

- The accepted implementation adds the statement branch only in `src/lang/ast/parser.rs`.
  Runtime helper dispatch and assertion-result exclusion remain untouched.
- Extract the existing exporter's balanced/quoted argument scanner into
  `build_statements.rs`, sharing it with actual exporter regressions.
  Direct, caught and scoped export paths recognize both assertion spellings.
- Treat that scanner only as an export-shape classifier, never a syntax
  validator. Before extracting a colon-form assertion, the generated test
  executes the complete original record with the actual `common::runner`,
  real parser and AST-based assertion-coverage check.
  Preserve raw source through Rust string escaping, including unsupported
  Unicode and invalid layout; append only explicit return metadata.
- Use a separate fresh runner for this original-source execution so operand
  effects cannot be duplicated in the extracted program's runtime.
  Keep the existing extracted expectations as additional checks.
  Malformed original source must fail before a literal extracted expectation
  can pass; no whitespace grammar, continuation ban or success default is
  substituted for the parser.
- Keep deferred function/method checks with their invocation in one generated
  program, so local operands and actual executed coverage are not extracted
  into an unrelated top-level expectation.
- Preserve expression context when exporting a brace-leading actual operand;
  run it as a parenthesized object expression, not a statement-leading block.
- Replace substring counting in `tests/common/mod.rs` with the existing
  `common::assertions::protected_assertions` AST traversal.
  Comments, literal text and object keys do not count; nested/template/function
  bodies do. Untaken checks must fail coverage.
- Honor explicit snippet `# return:` metadata, using the same convention as
  case documents; keep historical snippets without metadata unchanged.
- Add focused paired regressions for AST/canonical equivalence, legacy
  declarations, names, result and graph exclusion, receivers/snapshots,
  failures/counters, operand errors, rollback, malformed syntax, coverage
  and exact parser resource boundaries.
- Exercise the actual renderer on all four caller-reproduced malformed forms,
  horizontal lexer whitespace, Unicode/delimiter/layout boundaries, scoped
  extraction, inherited declarations and old/new grouped expressions.
  Compile and execute its emitted named tests as development evidence,
  including expected failures of invalid original programs; ordinary tests
  do not require a native compiler or skip these checks when Git is absent.
- Update only the generated-record total from 398 to 403 in the existing
  `tests/comma_free_object_properties.rs` exporter regression. Preserve all
  its original fixtures, assertion checks, errors and positions.
- Paired regressions retain the inherited non-propagating argument assignment,
  frozen-local name-reuse result, plain-value loop skipping and repeated
  function assertion executions; this revision does not repair those paths
  or treat an unexecuted assertion as successful coverage.
- Add four self-contained verification records in
  `dataset/nucleoid.synth.26.jsonl`, keeping all 26 previous training files
  (25 synthesized shards plus ARC) byte-for-byte unchanged.
  Actual synthesized size grows from 1,099 to 1,103;
  the normative spec grows from 398 to 403 entries.
- Regenerate `dataset/nucleoid.spec.jsonl` only through
  `UPDATE_DATASET=1 cargo test --test dataset`, and `tests/nucleoid.spec.rs`
  only through `UPDATE_SPEC_TESTS=1 cargo build`.
- Run development and legacy compatibility checks without the proposal gate.
  Freeze source fingerprints, command evidence and a task-only patch for the
  caller's required Rust pass and a fresh independent evaluator.
- Baseline revision is `0320e765c0843a32d11e27371097e867a1f3185a`.
  The caller's immutable baseline contains 603 cases, 2,736 canonical
  assertions and 48 explicit expected returns. No before-count is inferred
  from the candidate.
- Inherited noncapture, reserved `value`, whole caught-error representation,
  queued receiver behavior and column-1 multiline exporter limitations remain
  unchanged; this bounded grammar revision does not repair them.
- Independent evaluation accepted the frozen R2 Draft blob
  `c8e2bf88289251886bf7130f06f3618feb8ef06a` against the accepted baseline,

- All 603 paired cases passed: eight use fewer lexer tokens, 595 are

- All 2,736 protected assertions executed and all 48 explicit expected
