# NUC 6 -- Blocks and Scope

```

Title: Blocks and Scope
Author: Can Mingir <canmingir@gmail.com>
Status: Draft
Type: Standards Track
Created: 31-Jul-2026
Requires: 1, 2, 3, 4, 5
```

## Abstract

- Specifies blocks, local variables, shadowing, nesting, and `return`.
- A block groups statements and introduces a scope for names assigned inside it.
- A local is an intermediate step: it does not survive the block, but the dependencies it carries do.

## Motivation

- A derived value often needs an intermediate that is not itself worth keeping in the state.
- Without a scope, every intermediate would collide with the global name space.
- The dependency must survive even though the name does not, so that the outer result still tracks its inputs.

## Rationale

- **A local disappears but its dependencies do not.** The block is evaluated as one relationship, so `j` still follows `h` after the block that computed `value` has ended. A local that severed the chain would make blocks useless for derived values.
- **The innermost binding wins.** Shadowing is resolved by scope depth, so a block can reuse a common name without disturbing the state.
- **A block is a single transaction.** Every statement in it takes effect together or not at all, which is what makes a partially-evaluated block impossible to observe.

## Specification

### Blocks and locals

- A block is written with braces.
- A name first assigned inside a block is local to it.
- The local is not in the state after the block.
- Assignments to outer names persist, carrying the local's dependencies.

```
h = 1

{
    value = h * 2
    j = value * 2
}
```

- `j` is `4`.
- After `h = 2`, `j` is `8`, though `value` no longer exists.

- One local may feed several outer assignments.

```
side = 3

{
    area = Math.pow(side, 2)
    surface = area * 6
    volume = area * side
}
```

- `surface` is `54` and `volume` is `27`.
- After `side = 4`, they are `96` and `64`.

### Nesting

- Blocks may nest to any depth.
- An inner block sees the enclosing block's locals.

```
radius = 10

{
    area = Math.pow(radius, 2) * 3.14
    {
        volume = area * 5
    }
}
```

- `volume` is `1570`.

### Shadowing

- A local shadows an outer name of the same name.
- The outer name is unchanged by assignments to the shadow.
- Lookup takes the binding at the lowest enclosing scope.

```
e = 2.71828
number = null

{
    e = 3
    number = e
}
```

- `number` is `3`.

```
barcode = "barcode"

{
    barcode = "barcode"
    {
        barcode = "barcode2"
    }
}
```

- Inside the inner block `barcode` is `"barcode2"`.
- Outside, `barcode` is still `"barcode"`.

### Instances and objects in blocks

- Instances may be created in a block and assigned outward.
- Class-level rules apply to them as usual.
- An instance created in a block without a variable name still gets a generated id.

```
class Device(name: str):
    this.name = name

$Device.key = "X-" + $Device.name

{
    name = "Hall"
    device1 = Device(name)
}
```

- `device1.key` is `"X-Hall"`.

- Built-in objects and plain objects may be locals too.
- A local list may be built and filtered, and the result tracks its dependencies.

```
factor = 2

{
    numbers = [1, 2, 3]
    total = numbers.filter(n => n > factor)
}
```

- `total.length` is `1`.
- After `factor = 0`, it is `3`.

### Locals holding instances

- A local may hold an instance obtained from the state.
- Properties assigned through it are recorded on that instance.
- The rule re-evaluates when the query's inputs change.

```
bugs = []
ticket = 1

{
    bug = bugs.find(b => b.ticket == ticket)
    bug.selected = true
}
```

- `bug1.selected` is `true`, `bug2.selected` is `null`.
- After `ticket = 2`, `bug2.selected` is `true`.

- A local may also hold a class-level reference, before or after the referenced property is set.

```
{
    trip = $Plane.trip
    $Plane.time = trip.distance / $Plane.speed
}
```

### Guarding on a local

- A local may be tested before use.
- A block may throw when the query finds nothing.

```
{
    device = Device.find(d => d.code == "A0")
    if not device:
        throw "INVALID_DEVICE"
    return device
}
```

- Returns `{ "id": "device1", "code": "A0" }`.
- With a code that matches nothing, the block throws `"INVALID_DEVICE"`.

### Return

- `return` yields a value from a block.
- The first `return` reached is the result; later ones do not run.
- A returned value may be a local, a property of a local, or an inline object or list.

```
{
    return 123
    return "abc"
}
```

- Returns `123`.

```
{
    return { "number": 123, "string": "ABC", "bool": true }
}
```

- Keys may be quoted or bare; both return the same object.

### Blocks and class-level rules

- A block may declare a class-level rule from its locals.
- A block that reads a specific instance may not; see [NUC 5](nuc-0005.md).

## Errors

| Condition | Error |
| --- | --- |
| Writing a property through an undefined local | `ReferenceError("<local>.<property> is not defined")` |
| Using `value` as a property name in a block | `TypeError("Cannot use 'value' as a property")` |
| Declaring a class-level rule in a non-class block | `SyntaxError("Cannot define class declaration in non-class block")` |

- A block is a single transaction: if any statement in it throws, including in a nested block, the whole block is rolled back; see [NUC 9](nuc-0009.md).
