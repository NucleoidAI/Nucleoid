## Abstract

- Extend accepted NUC53 read-only property histories to fixed self-anchors in
  per-instance class property rules and conditionals.
- Keep `@first` identical to `@0`: the concrete property slot's first recorded
  value, not a declaration-time or first-activation snapshot.
- Prototype exactly the user's tag-and-anchor-shift feature, isolated from
  accepted revision `1167438abd629b0007cd81d0df5dfed2f3c98a82`.

## Motivation

- An orientation-180 object should receive tag `"l4214"` and coordinates one
  less than its own first stored coordinates, without accumulating another
  decrement whenever its rule re-evaluates.
- Class rules need to express this relationship without shared class history,
  hidden original-value fields, manual snapshots or separate bookkeeping.
- The user explicitly confirmed both the effect and first-recorded-per-instance
  interpretation. The runnable constructor must store its orientation too.
- The confirmed category is Runtime features: this extends property-history
  execution, not grammar or the category registry. No random selection applies.

## Rationale

- At the pinned runtime, the fully seeded conditional example already executes.
  Ordinary `$Obj.x = $Obj.x@first - step` rules instead fail static class-cycle
  checking, because the property visitor treats the version as a live self-read.
- The pinned conditional path also writes a deferred missing self-read back as
  Null, accidentally seeding the fixed history it was waiting for. Deferring
  only unavailable fixed self-anchors prevents that placeholder from becoming
  `@first` and permits later recovery from real input.
- Exempt only fixed historical reads of the rule's own destination from static
  class-cycle checking. Preserve other property reads and transitive cycles.
  Do not disable graph tracking for Version expressions or class properties.
- An unavailable self-anchor must wait for an actual external entry, not
  manufacture its own successful input. An available recorded Null remains
  Null under the existing assignment rules.
- Moving selectors are not anchors. Accepted imperative conditional bodies
  already allow `@last` and `@previous` self-reads, including repeated effects
  on guard changes; preserve those effects and history order. Direct moving
  self-rules retain static Circular Dependency checks. Do not introduce a new
  runtime selector prohibition or disable genuine graph-cycle checks.
- An explicit `.value` snapshot still has its accepted detached meaning.
- Runtime applicability is `existing_comparable`: accepted programs can save
  each instance's original property values manually and use them in class
  rules. This single concrete-feature request skips token comparison, not
  behavior, integrity, syntax compatibility, coverage or development checks.
- Do not add a selector, keyword, history lifetime, deep snapshot, public Value
  representation, dependency, manifest change or release/version bump.

### Example

- This is the complete constructor and rule from the first specification entry.
  Every matching receiver is anchored independently; a later orientation
  change back to 180 produces the same coordinates, not a second decrement.

```nuc
class Obj(x: int, y: int, orientation: int):
    this.x = x
    this.y = y
    this.orientation = orientation
first = Obj(10, 20, 180)
first.x = 70
first.y = 80
if $Obj.orientation == 180:
    $Obj.tag = "l4214"
    $Obj.x = $Obj.x@first - 1
    $Obj.y = $Obj.y@first - 1
second = Obj(30, 40, 180)
waiting = Obj(50, 60, 0)
assert([first.x, first.y, first.tag], [9, 19, "l4214"])
assert([second.x, second.y, second.tag], [29, 39, "l4214"])
assert([waiting.x, waiting.y, waiting.tag], [50, 60, null])
waiting.x = 90
waiting.orientation = 180
assert([waiting.x, waiting.y, waiting.tag], [49, 59, "l4214"])
first.orientation = 0
first.orientation = 180
second.orientation = 180
assert([first.x, first.y, second.x, second.y], [9, 19, 29, 39])
assert(first.x@first, 10)
assert(first.x@0, 10)
assert(second.x@first, 30)
assert(second.x@2, null)
[first.x, first.y, second.x, second.y]
```

### Fixed anchors, tracking and missing entries

- Numeric `@n` and `@first` are fixed positions for one slot lifetime.
  An ordinary class property rule may reference its own fixed position
  directly, including a computed literal property name.
- Static validation ignores only that fixed self-reference. A concurrent live
  self-read, a moving self-selector or a cycle through other class properties
  retains the existing error. Public expression-inspection behavior is intact.
- Runtime assignment tracking identifies the actual destination NodeKey on
  the active class receiver, including inherited receivers and helper calls.
  A missing fixed self-entry defers only that assignment: return Null, keep any
  current destination value, and make no State/history write. A missing guard
  retains the ordinary conditional deferral of its entire branch.
- Keep concrete property dependencies and receiver/key dependencies. Conditional
  rules and non-self observers therefore wake on later writes and slot resets.
  Fixed positions do not freeze an observer to an obsolete slot lifetime.
- Instance property assignments still override their ordinary property rule;
  deleting that property still removes its instance rule. A surviving class
  conditional continues to observe its inputs and can recover after recreation.
- `@last` and `@previous` are moving live reads, not fixed anchors. Direct
  class property rules using moving self-history retain their static Circular
  Dependency error. Imperative conditional bodies preserve accepted same-slot
  reads, including helpers and computed receivers; each activation uses the
  then-selected entry. An inactive branch is not evaluated speculatively.
- Missing moving entries keep accepted deferred-Null assignment behavior;
  only an unavailable fixed self-anchor suppresses the destination write.
  In particular, a missing `@previous` can record Null through an ordinary
  conditional assignment and become available on later activations.
- Preserve non-self `@n`, `@first`, `@last`, `@previous` observations and their
  existing graph-cycle checks. Ordinary non-class variable/property
  self-assignments keep accepted current-value behavior.

### Compatibility, lifetime and rollback

- Preserve all NUC53 selector parsing and aliases, read-only destinations,
  per-slot identities/lifetimes, null/deferred rules, `.value` freezing,
  object identity, list-value copies and transaction semantics.
- Retain State histories across successful runs. Failed runs and try savepoints
  restore rule templates, instance rules, State, histories and graph edges
  together. A deleted/recreated property begins again at zero.
- Preserve class declaration order, ordinary rules and conditionals, subtype
  overrides, receiver selection, constructor storage and explicit snapshots.
  No new constructor behavior or implicit fields are introduced.
- Preserve the accepted conditional `$Counter.x = $Counter.x@last - 1`:
  starting from 10, two guard activations produce 9 then 8, with first 10
  and previous 9. A seeded `@previous` body likewise retains its selected
  values and their recording order, rather than raising a new cycle error.
- Append normative cases rather than rewrite any of the 669 pinned executable
  corpus cases. Preserve their identities, assertions/order, expected returns
  and executed coverage. Replay unchanged pinned sources with the existing
  ignored development helper; there are no original extra-baseline sources.
- The former focused negative test for fixed self-history is now a positive
  feature case; its negative cycle control uses `@last`. No historical
  executable-document assertion is replaced or weakened.

## Errors

- `TypeError("Circular Dependency")` for direct live class self-cycles, mixed
  live/anchored direct self-cycles, non-self transitive dependency cycles, and
  direct moving self-rules. The appended direct-cycle specification entry
  executes these boundaries; the final entry preserves successful imperative
  moving conditionals. No selector-specific runtime error is added.
- `TypeError("State versions are read-only")` for assignment, compound
  assignment, deletion or mutable-list write-back targeting a selected version;
  the direct-cycle entry executes selected writes, deletion and list write-back.
- `TypeError("State versions require a variable or object property")` for a
  non-slot selection, including `Math.PI@first`; that entry executes it.
- `SyntaxError("Expected a non-negative integer, 'first', 'last', or 'previous' after '@'")`
  retains NUC53 malformed-selector behavior, traced to the root specification's
  **Read-only state versions** contract and unchanged state-version regressions.
- `ReferenceError("$Empty.x@first is not defined")` for a missing
  `$Empty.x@first.value` snapshot; the direct-cycle specification entry
  executes it. Other missing snapshots render their own expression in the
  same established message.
- An unavailable fixed self-anchor is not an error and must not create a history
  entry. Deferred history reads do not bypass explicit snapshot validation.
- Existing unsupported compound targets, source positions, depth/chain limits
  and propagation diagnostics retain their exact established messages.

## Reference Implementation

- Add a crate-private fixed-selector predicate, destination-aware static class
  property inspection and scoped assignment-target history tracking.
- Keep the existing State/History/Graph representation. Ordinary dependency
  tracking still observes every selected property; only the existing
  assignment self-edge exclusion applies to the destination's own node.
- `PropertyEvaluation` carries a pending-anchor result so unavailable fixed
  self-reads cannot write a placeholder. Scoped tracking and null state unwind
  on errors; existing transactions perform rollback without a parallel history
  store.
- Property-version tracking is infallible: always record the concrete slot,
  then mark a pending assignment only for an unavailable fixed self-anchor.
  Moving reads use the unchanged execution and graph validation paths.
- `tests\class_state_versions.rs` covers constructor/rule ordering, first-value
  ownership, numeric aliases, inherited receivers, helpers/computed slots,
  missing fields/guards, Null, snapshots, accepted moving conditional effects
  and history order, direct cycles, read-only writes, failed runs, caught
  rollback, observers and ordinary legacy forms.
- Synchronize the consolidated reference, executable reference, README, examples
  and four self-contained `dataset\nucleoid.synth.35.jsonl` records. Regenerate
  normative JSONL and exported Rust only with the repository's update commands.
- Execution mode remains `NUC_PROPOSAL_MODE=single`; token comparison is skipped
  for this concrete feature request, not claimed to pass. The immutable
  accepted baseline has 669 cases at the pinned revision; no before-counts,
  new counterparts or extra baseline artifacts are invented.
- No new public exhaustive enum variants or public struct fields are introduced;
  the helper/result/tracking additions are crate-private. Human SemVer review

- Preparation did not decide acceptance. The caller-owned Rust improvement
