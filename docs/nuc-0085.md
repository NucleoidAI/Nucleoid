# NUC 85 -- Fixed Cross-Property Class Anchors

```
NUC: 85
Title: Fixed Cross-Property Class Anchors
Author: Claude <noreply@anthropic.com>
Status: Automatic-Accepted
Type: Standards Track
Category: Runtime features
Created: 05-Nov-2026
Requires: 53, 55
```

## Abstract

- Extend NUC 55's class-cycle exemption from a rule's own fixed anchor to
  fixed history reads of the receiver's other properties. A class property
  rule may read `$C.q@first`, `$C.q@n` with a literal non-negative `n`, or
  the indexed spellings `$C["q"]@first` and `$C["q"]@n`. Such a read is a
  *fixed anchor*.
- A class cycle whose every edge is a fixed anchor, including fixed
  self-anchors, is no longer a circular dependency. With
  `$Box.width = $Box.height@first` and `$Box.height = $Box.width@first`, every
  box swaps its first recorded width and height, whether the rules are
  declared before or after the instances.
- Fixed anchors stay tracked, as other non-self history readers are: they
  wake on writes to the slot they read and on its deletion and recreation,
  following the slot's current lifetime instead of freezing like `.value`.
  The cycle settles because a recorded position never changes during its
  slot's lifetime.
- A cycle containing a live read, a moving `@last` or `@previous` read, a
  compound self-assignment or any other kind of edge still raises
  `TypeError("Circular Dependency")`, before instances exist when the static
  class check sees it.
- No syntax, keyword, token, error type, dependency or version changes. Only
  programs that raised `TypeError("Circular Dependency")` at the accepted
  revision change. No public type, field, variant or signature changes. The
  authoritative contract is
  [Fixed cross-property class anchors](../nucleoid.spec.md#fixed-cross-property-class-anchors).
- **Automatic-Accepted** on 5-Nov-2026: the candidate meets every hard
  criterion, but the independent evaluation's policy decision was Rejected.
  Fixed-only cycles whose rules build fresh objects never settle, contrary to
  the settlement claims below: `$Pair.a = {v: $Pair.b@first}` with
  `$Pair.b = {v: $Pair.a@first}` reaches the 100,000-step propagation limit
  and raises `TypeError("Propagation did not settle")`, where the accepted
  revision raised `TypeError("Circular Dependency")` at once. See
  [Evaluation](#evaluation).

## Motivation

- A world model often relates an object's properties as they were, not as
  they are: a quarter turn exchanges coordinates, a mirror swaps two extents,
  a rotation passes values around a ring. Each new value reads another
  property's original value.
- NUC 55 lets a class rule read its own first recorded value, so
  `$Obj.x = $Obj.x@first - 1` does not subtract again whenever it
  re-evaluates. It kept every other property read as an ordinary class-cycle
  edge, so two rules that read each other's first value are rejected:

```nuc
class Box(width, height):
    this.width = width
    this.height = height
$Box.width = $Box.height@first
$Box.height = $Box.width@first
```

- The accepted runtime raises `TypeError: Circular Dependency (line 5,
  column 1)` for it. Neither rule can change what the other reads: a slot's
  first entry is fixed for the slot's lifetime. The cycle exists only because
  the check treats a fixed read like a live one.
- The accepted workaround is an explicit snapshot,
  `$Box.width = $Box.height@first.value`. It gives the same first result but
  detaches the rule from the slot it read: after `delete box.height` and
  `box.height = 7`, a tracked reader follows the recreated slot to 7 while the
  snapshot keeps 2.
- An ARC world model requested the feature for a quarter turn that keeps each
  object's rules declarative. Its coordinates exchange through each other's
  first values, the fixed-only cross-property cycle that the accepted runtime
  rejects:

```nuc
$Obj.orientation = ($Obj.orientation@first + 270) % 360
$Obj.x = $Obj.y@first
$Obj.y = canvas_width - $Obj.x@first - $Obj.width@first
```

- The feature is general. This NUC adds no ARC data, puzzle identifiers,
  grids, helpers or tests, and changes nothing under `arc/`.

## Rationale

- **Category and selection.** The caller confirmed Runtime features, NUC 55's
  category: the feature extends property-history execution, not grammar. It
  is an explicit ARC-requested concrete feature, so no random category draw
  applies, and it is a single-proposal request, so token comparison is
  skipped. Behavior, integrity, compatibility and development checks are not.
- **Runtime applicability: `existing_comparable`.** The feature extends NUC
  55's fixed anchors, which are themselves `existing_comparable`. For
  instances whose constructor sets every property a cycle reads, each enabled
  rule set has an accepted equivalent spelled with `@first.value`, which gives
  the same values. Tracked recovery through such a cycle after slot deletion
  has no accepted counterpart; it is new behavior inside the extension.
- **Strategy.** The caller's pre-draft receipt selected `reuse_first` for
  trial `arc-ed36ccf7-nuc-0085-t2`. The implementation therefore generalizes
  NUC 55's existing destination-only exemption in the class-property visitor
  and reuses the existing tracking frames, dependency edges, graph cycle
  check, propagation queue and transaction log. It adds no edge table, no
  parallel history store and no new public API.
- **Why a fixed-only cycle settles.**
  - A fixed position of a slot is missing until the slot records that entry
    and never changes afterwards, until the slot is deleted.
  - A rule on such a cycle can therefore change its value only when an input
    outside the cycle changes or a position it reads is first recorded.
    Storing an equal value records no history entry and, inside a cascade,
    wakes nothing.
  - Each position is first recorded at most once per slot lifetime, so a
    change propagates around the cycle a bounded number of times and then
    stops. The existing `MAX_PROPAGATION` bound still applies.
- **Every edge must be fixed.** A cycle with a live or moving edge reads a
  value that the cycle itself keeps rewriting; whether it settles depends on
  the values. The accepted checks reject such cycles and accepted tests pin
  them, for example `$Sample.x = $Sample.y@first` with
  `$Sample.y = $Sample.x + 1`. This NUC relaxes only cycles whose every read
  is a position that, once recorded, never changes.
- **Missing entries read null.** A missing entry of another property reads
  null inside a cycle, as every non-self history read does. Only a rule's own
  fixed self-anchor waits, as NUC 55 defined.
  - Whether a rule lies on a cycle depends on the whole rule set. Waiting only
    inside cycles would make the same `$C.q@first` read behave differently
    depending on unrelated rules.
  - Accepted non-self readers are pinned: `$Sample.first = $Sample.x@first`
    reads null after `delete item.x` and recovers when `x` is recreated.
  - A null written this way is an ordinary recorded value. When
    `class Missing(width)` stores only `width = 3` and the swap rules read
    `height@first`, width first records null, height records 3 from width's
    first entry, and width records 3 again: width's history is
    `[3, null, 3]`. Constructors that set every property a cycle reads never
    see this; the fifth specification entry pins the `Missing` case.
  - Rejected: waiting on every missing non-self fixed entry, which would
    change accepted non-cycle readers.
  - Rejected: waiting only inside cycles, which is non-local.
- **Only direct reads on the rule's own receiver.** An anchor is written
  directly on the class that the rule's target names, `$C`.
  - Reads through helpers, `this`, other objects, an alias of the same
    instance and populations keep their existing checks. Any live or moving
    read of the same slot in the same evaluation, including one inside a
    helper, makes that edge an ordinary dependency.
  - The static class check does not see into helpers. A cycle whose only live
    or moving read is hidden in a helper is therefore reported when an
    instance applies the rules, as other helper-hidden cycles already are,
    rather than at declaration.
  - Rejected: treating every fixed read of the receiver as an anchor,
    including helper reads, which would silently accept cycles that the
    accepted runtime reports.
- **Edges stay, frozen values do not.** The graph keeps every anchor edge, so
  readers still wake on writes, deletion and recreation. The anchor set is
  recorded on the reading property rule inside its graph node, so failed runs
  and caught savepoints restore it together with the node.
  - Rejected: dropping anchors from the dependency set as `.value` does,
    which would freeze them.
  - Rejected: a separate edge table in the graph, which would need its own
    rollback records.
- **Queue order.** The queue's ordering pass is unchanged: upstream work runs
  first and ready rules keep declaration order, so every program the
  accepted runtime runs keeps its exact order.
  - Rules on an anchor cycle that are queued together wait for each other in
    that pass. Only when every queued rule waits for another, which the
    accepted runtime reports as a circular dependency, does a second pass
    look again. There a rule goes next when every queued rule it waits for,
    itself included, is reached through fixed anchors alone, the edges the
    static check accepts.
  - A rule that waits through any other edge, such as a live read or the
    structural link of a reasoning selection, keeps waiting. When no rule can
    go, the queue raises `TypeError("Circular Dependency")` exactly as
    before. Where no fixed-only cycle exists, every queued rule still waits in
    the second pass, so the same error comes at the same statement, and no
    rule runs first.
  - Rejected: letting a rule skip every path back to itself. A reasoning
    selection that a rule reads back observes that rule structurally, so
    such a skip ran queue cycles that the accepted runtime reports, some
    without bound. The caller's Rust improvement pass found this in the
    first prototype.
- **`.value` keeps its meaning.** An explicit snapshot is still detached and
  records no dependency.
- Do not add a selector, keyword, history lifetime, deep snapshot, public
  value representation, dependency, manifest change or release/version bump.

## Specification

- The normative candidate contract is `nucleoid.spec.md`, section **Fixed
  cross-property class anchors**. The **Class-level state version anchors**
  section's exemption sentence now refers to it. Its appended entries trace
  every implemented claim:

| Specification entry | Behavior |
| --- | --- |
| `Nucleoid swaps two class properties through fixed cross anchors` | Two-property swap, instances before and after declaration, first entries, no extra history |
| `Nucleoid exchanges coordinates and turns rectangles through fixed cross anchors` | Coordinate exchange, four-property quarter turn beside a live variable |
| `Nucleoid rotates class properties with numeric first and indexed anchors` | Three-property rotation with `@0`, `@first` and `$C["q"]@first`, a self-anchor beside a cross anchor, rules on a parent and a child class |
| `Nucleoid keeps fixed cross anchors tracked through slot deletion and recreation` | Null after deletion, recovery after recreation, history, contrast with `.value` |
| `Nucleoid settles fixed cross anchor cycles beside live inputs and readers` | Shared live input, downstream live reader, a missing position that appears, a missing property read as null |
| `Nucleoid keeps live and moving reads in class cycles as circular dependencies` | Live, moving, mixed, helper-hidden and compound cycles fail and roll back; a fixed cycle then stands |

### Example

- This is the first specification entry. Rules declared after `early` exists
  and before `box` exists both swap each instance's first recorded values,
  and storing them records exactly one new entry per property.

```nuc
class Box(width, height):
    this.width = width
    this.height = height
early = Box(4, 1)
$Box.width = $Box.height@first
$Box.height = $Box.width@first
box = Box(3, 2)
assert([box.width, box.height], [2, 3])
assert([early.width, early.height], [1, 4])
assert([box.width@first, box.height@first], [3, 2])
assert([box.width@1, box.height@1, box.width@2], [2, 3, null])
assert([early.width@1, early.height@1, early.width@2], [1, 4, null])
[box.width, box.height, early.width, early.height]
```

### Fixed anchors and cycles

- A fixed anchor is `$C.q@first`, `$C.q@n`, `$C["q"]@first` or `$C["q"]@n`
  in a class property rule written on `$C`, where `q` is a property of the
  same receiver. `@0` is `@first`.
- The static class check walks the class's property rules and remembers
  whether its path has crossed a read that is not a fixed anchor. A rule is
  rejected only when that walk returns to its destination after crossing
  one. A fixed self-anchor is an anchor like any other.
- A property read both as an anchor and in any other way in the same rule is
  an ordinary read: `$S.x = $S.y@first + $S.y` reads `y` live.
- At run time, the graph keeps each anchor edge. A new edge may close a
  cycle only when it and every other edge on that cycle are anchors. An edge
  that was an anchor and is now read live is checked again.
- Anchors are only direct reads on the rule's own receiver. Reads through
  helpers, `this`, other objects, aliases and populations are ordinary, as is
  any anchor slot that the same evaluation also reads live or at a moving
  position.

### Tracking, missing entries and settling

- Fixed anchors observe their actual slot. A write to it wakes the reader,
  which recomputes from the same fixed entry; storing an equal value records
  no entry. Deleting the slot wakes the reader too: the missing entry reads
  null. Recreating the slot starts its history again at zero, and the reader
  follows the new first entry.
- Deleting a property still removes that instance's rule for it, and an
  instance assignment still overrides its rule; this feature does not
  silently reinstall them.
- A missing entry of another property reads null, as for every non-self
  history read; only a rule's own unavailable fixed self-anchor waits.
- A fixed-only cycle settles within the existing propagation bound.
- Propagation order is unchanged. When every queued rule waits for another,
  a rule whose waits all run through fixed anchors goes next, in declaration
  order. A rule that waits through any other edge, including the structural
  link of a reasoning selection, keeps waiting, and a queue that cannot go on
  still raises `TypeError("Circular Dependency")`.
- `.value` keeps its detached snapshot meaning.

### Compatibility

- Only programs that raised `TypeError("Circular Dependency")` at the
  accepted revision change. Every accepted program keeps its parse, values,
  history, order and errors, including every pinned cycle error:
  `live_class_cycles_and_non_self_history_cycles_still_fail_before_instances_exist`
  and the specification entry
  `Nucleoid protects direct class history cycles and read only destinations`.
- A cycle whose only live or moving read is hidden in a helper, alongside
  direct fixed reads that were ordinary edges before, now fails when an
  instance applies the rules instead of at declaration; with no instance
  yet, its declarations stand. Its error is unchanged.
- Accepted graphs have no value cycles, so the graph check behaves exactly as
  before for them. The queue's ordering pass is unchanged, and its second
  pass runs only where the accepted queue raised Circular Dependency; without
  a fixed-only cycle it raises the same error at the same statement.
  A queue cycle through a reasoning selection keeps its accepted result or
  error. Beside a fixed cycle, which the accepted runtime rejected, it
  behaves as it does alone: the same error at the statement that wakes it, or
  the same values. Reasoning walks already keep visited sets and terminate on
  anchor cycles.
- Preserve NUC 53 and NUC 55 selectors, read-only destinations, slot
  lifetimes, deferred self-anchors, snapshots, transactions and rollback.
- Append normative cases rather than rewrite any of the 970 pinned executable
  corpus cases.

## Errors

- `TypeError("Circular Dependency")` for every class cycle that contains a
  live read, a moving read, a compound self-assignment or any edge that is
  not a fixed anchor. The static class check raises it before instances exist
  when the cycle is visible there; otherwise the graph check raises it when
  an instance applies the rule. The last specification entry executes these
  boundaries.
- `TypeError("Circular Dependency")` from the propagation queue, unchanged,
  when queued rules wait for each other through any edge other than a fixed
  anchor, such as a reasoning selection's structural link.
- No new error is added. `TypeError("State versions are read-only")`,
  `TypeError("State versions require a variable or object property")`, the
  malformed-selector `SyntaxError`, the missing-snapshot `ReferenceError` and
  `TypeError("Propagation did not settle")` keep their exact messages.

### Failed policy check: independent behavior

The evaluator's overall decision is **Rejected** because fixed-only cycles
whose rules build fresh object values never settle. Each fixed read wakes on
every write to the slot it reads, and a newly built object never equals the
previous one, so the cycle keeps waking itself. This contradicts the
settlement claims of this NUC's Rationale and Specification, of
[Fixed cross-property class anchors](../nucleoid.spec.md#fixed-cross-property-class-anchors)
("Such a cycle settles") and of the language reference; no executable case
covers it:

```nuc
class Pair(a, b):
    this.a = a
    this.b = b
$Pair.a = {v: $Pair.b@first}
$Pair.b = {v: $Pair.a@first}
p = Pair(1, 2)
```

On a release build this program raises
`TypeError("Propagation did not settle")` at the 100,000-step limit after
0.89 seconds and 428 MB; with a 100-element list inside each object it takes
1.98 seconds and 993 MB, and with object spread 1.24 seconds and 437 MB. The
accepted revision rejects all three at once with
`TypeError("Circular Dependency")`. The memory matches accepted programs that
already reach that limit, so the finding is the broken guarantee, not new
unbounded growth.

- Cascades across many instances slow down sharply. When one live input
  wakes the fixed two-property cycles of N instances, a release build took
  1.03, 5.56 and 40.5 seconds for N = 1,000, 2,000 and 4,000, against 0.11,
  0.14 and 0.26 seconds for the accepted equivalent: each queued pair blocks
  the queue's first pass, so nearly every step rescans the queue.
- Minor, without a behavior change: accepted programs that run to the
  100,000-step limit peak about 12 MB higher, from 75.3 MB to 88.1 MB.
- The ARC quarter turn, the reasoning-selection queue cycles `o8` and `s3`,
  helper-hidden cycles and live cycles all behaved as documented. Fixing
  either finding needs a fresh proposal and evaluation pair, so this outcome
  records them instead of repairing the candidate.
