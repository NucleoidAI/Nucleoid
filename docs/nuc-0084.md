## Abstract

- Lists and class instance lists gain the read-only query `median`.
  `RECEIVER.median()` returns the middle value of the items in ascending
  numeric order and `RECEIVER.median(selector)` the middle value of
  `selector(item)`.
- With an odd number of values the median is the middle value itself,
  unchanged. With an even number it is the mean of the two middle values,
  `(lower + upper) / 2` in 64-bit floating point, so `[4, 1, 3, 2].median()`
  is `2.5`.
- The values are converted with the numeric conversion of
  [NUC 68](nuc-0068.md)'s `sum` and ordered by a stable ascending sort of a
  private list of numbers. The receiver is never sorted or written.
- An empty receiver and any value that converts to NaN give NaN. An
  undefined value makes the result undefined, which a declaration stores as
  `null`.
- The selector is called once for every item, in order, with only the item,
  as `sum` and `average` call theirs. A supplied first argument that is not a
  function raises `TypeError("median expects a function")`, even on an empty
  receiver.
- `median` follows [NUC 61](nuc-0061.md)'s shared query rules beside `sum`
  and [NUC 80](nuc-0080.md)'s `average`. It accepts every receiver they
  accept, reads the receiver before its arguments, never writes it, and stays
  live in declarations and class-level rules.
- At the accepted revision these calls raise
  `TypeError("<receiver>.median is not a function")`. No syntax, keyword,
  token, error type or public Rust API is added, and `median` is not a noun
  query, so `median of xs` keeps raising
  `SyntaxError("Unexpected keyword 'of'")`. The authoritative contract is
  [List and population medians](../nucleoid.spec.md#list-and-population-medians).
- **Outcome: Accepted.** The independent evaluation and the caller's
  integrated-tree checks passed all three hard criteria, and the independent
  evaluator decided Accepted. The required token comparison ran in
  continuous mode: 11 cases use fewer tokens, 959 the same and none more. No
  policy check failed.

## Motivation

- World models keep typical values: the usual wait of a delivery route, the
  typical rent of a district, the middle lap time of a runner, the normal
  reading of a room's sensors. A mean answers the question only when no value
  is extreme; one stuck sensor, one penthouse or one lost parcel drags it far
  from every other value. The median is the standard robust answer:
  `[12, 3, 45, 7, 300].median()` is `12` while `average()` is `73.4`, and
  `[12, 3, 45, 7, 3000].median()` is still `12`.
- At the accepted revision a median has to be assembled from a sorted copy,
  an index computed from the length and a branch or an average for even
  counts. The shortest general accepted spelling found,
  `typical = waits[:].sort(lambda a, b: a - b)[waits.length / 2 - 0.5 : waits.length / 2 + 1].average()`,
  is 39 lexer tokens and names its receiver three times, where
  `typical = waits.median()` is 7. The spelling familiar from other
  languages,
  `s = waits.slice().sort((a, b) -> a - b)` followed by
  `typical = (s[Math.floor((s.length - 1) / 2)] + s[Math.floor(s.length / 2)]) / 2`,
  is 58.
- Over a population the selector has to be mapped first:
  `pace = Trip.map(.minutes).sort(lambda a, b: a - b)[Trip.length / 2 - 0.5 : Trip.length / 2 + 1].average()`
  is 42 tokens where `pace = Trip.median(.minutes)` is 9. In a class-level
  rule the accepted spelling repeats the filtered list to measure its length:
  `$Room.mid = Sensor.filter(sensor -> sensor.room == $Room).median(.temp)` is
  22 tokens and states its filter once, while the accepted spelling states it
  three times in 77.
- Two traps make the hand-written median easy to get wrong. `sort()` without
  a comparator orders by text, so `[12, 3, 45, 7].sort()` is
  `[12, 3, 45, 7]`, and `sort` on a variable or a property sorts in place and
  writes the list back ([NUC 58](nuc-0058.md)), so a declaration that sorts
  its own receiver rewrites the model it reads.
- Python's `statistics.median`, NumPy's `numpy.median`, pandas'
  `Series.median`, R's `median`, Excel's `MEDIAN` and SQL's
  `PERCENTILE_CONT(0.5)` name the operation, and all of them average the two
  middle values of an even count. JavaScript has none, and LLM-written code
  such as `orders.median(o => o.total)` raises
  `TypeError("orders.median is not a function")` at the accepted revision.

  not apply to this category.
- **Selection.** `median` is the next member of the List and Population
  family (NUC 61's shared queries, 68 `sum`, 69 `max` and `min`, 71
  `distinct`, 73 `count`, 75 `mode`, 77 `maxBy` and `minBy`, 80 `average`).
  The name is unused in the accepted case documents, tests and datasets.
  `Math.toDegrees` was set aside because `tests/math_to_radians.rs` pins it as
  not a function, and `product` because accepted cases use it as a user
  method name, as in `calculator.product(2, 3, 4)`.
- **Optional evidence.** No hint was supplied. Advisory usefulness is
  unscored (`missing_rubric`), not zero. Strategy learning is
  `not_configured`, so this revision is unattributed, with no policy,
  selection receipt, trial or reward.
- **One more shared query.** `median` is an operation of the read-only list
  query that serves `map`, `filter`, `reduce`, `sum`, `average`, `max`, `min`
  and NUC 61's queries. Lists, list properties, call results such as
  `filter(...)`, `map(...)`, `slice(...)` and `concat(...)`, ranges, `.value`
  snapshots, selected versions, class instance lists and `Name.list()`
  therefore accept it through one implementation, with the receiver, argument
  and liveness rules they already share.
- **Numeric order.** The median orders numbers, not the text order of
  `sort()` without a comparator, so `[10, 9, 1].median()` is `9`. The order is
  a stable ascending sort, so values that compare equal keep their receiver
  order; the only such values that differ are `0` and `-0`, and
  `[0, -0, -0].median()` is `-0`.
- **The middle value itself.** For an odd count the result is the middle
  value with no arithmetic, so its bits are kept: `[1e308, 1.5e308, 1]` gives
  `1e308`, and `-0` stays `-0`.
- **The mean of the two middle values.** For an even count the result is
  `(lower + upper) / 2`, the conventional definition of the libraries above
  and of Python's `statistics.median` exactly. It follows 64-bit floating
  point: `[0.1, 0.2].median()` is `0.15000000000000002`,
  `[1e308, 1e308].median()` overflows to `Infinity` as `(1e308 + 1e308) / 2`
  does, and `-Infinity` beside `Infinity` gives NaN.
- **Two `-0` values.** The formula is applied literally, so
  `[-0, -0].median()` is `-0`, as Python's `statistics.median` gives, where
  `[-0, -0].average()` is `0` because `sum` starts from `0`. An even median of
  equal values is then that value, as an odd median is, and this is the only
  input on which the median of two values differs from their `average()`.
- Rejected: the lower or the upper middle value, as Python's `median_low` and
  `median_high` return. They keep an actual item but disagree with the common
  definition. Also rejected: an overflow-safe `lower + (upper - lower) / 2`,
  which rounds differently from the common `(lower + upper) / 2`, and
  `[lower, upper].average()`, which would turn two `-0` values into `0`.
- **An empty receiver gives NaN.** There is no middle value, and NaN is the
  value `average` gives for the same receiver. The result stays a number, so
  a declaration over a population that starts empty has a value rather than
  failing the statement that declares it, and `Number.isNaN` tells it apart
  from `null`.
- Rejected: raising an error, as Python's `statistics.median([])` does, which
  would fail a live declaration over an empty class when it is declared, as
  NUC 69 argued for `max`. Also rejected: `null`, as SQL returns, which a
  declaration would store as a missing value.
- **NaN makes the median NaN.** A NaN has no place in an order, so any value
  that converts to NaN, such as `"x"`, an object or a two-item list, makes the
  median NaN, as NumPy's `median` does. Rejected: skipping NaN, as pandas
  does by default, which would silently change which items the median is
  over, and sorting NaN to one end, which would make the result depend on how
  many NaN values there are.
- **Undefined stays unknown.** An undefined item or selector result makes
  the median undefined, as it makes `sum` and `average` undefined, so a
  declaration stores `null` and waits for every value to be defined. Every
  item is still visited, so every item's reads are dependencies.
- **Undefined wins over NaN.** When a receiver holds both an undefined value
  and a value that converts to NaN, the median is undefined, whatever their
  order, as `average` is on the accepted runtime. The undefined gate comes
  first in both queries, so they agree on when a declaration stores `null`
  and waits.
- **The conversion of `sum`.** Each value is converted with the numeric
  conversion of `-`, `*`, the Math helpers, `sum` and `average`: `null`,
  `false`, empty strings and empty lists are `0`, `true` is `1`, numeric
  strings and one-item lists are their number, a date is its time in
  milliseconds, and objects, other strings and longer lists are NaN. A list
  that `sum` totals therefore has a median of the same numbers.
- **No artificial null read.** `median()` reads items, not bindings, so a
  `null` item counts `0` without settling a declaration to `null`, as in
  `sum`. A selector's own reads follow the existing rules: a selector that
  reads a `null` property settles a declaration to `null`, as the same
  selector does in `sum` and `average`.
- **The selector is called like `map`'s callback.** It runs once per item, in
  order, with only the item; further parameters stay `null`.
- **A supplied selector must be a function.** Any other first argument,
  including `null`, raises `TypeError("median expects a function")` after the
  arguments are evaluated, even on an empty receiver, as `average` raises
  `TypeError("average expects a function")`. Rejected: a number argument as
  a quantile, as in `xs.median(0.9)`, which stays an error rather than a
  silent percentile.
- **Extra arguments** are evaluated once, left to right, and ignored, as
  every list query does.
- **Instance lists.** On a class name, `Name.median(...)` is the population
  query even when the class declares an instance method `median`, as NUC 68
  made `Name.sum(...)`. The method stays reachable through each instance,
  `bag.median()`, and `Bag.median(each -> each.median())` takes the median of
  it.
- **The method call only.** `median` is not added to
  [NUC 75](nuc-0075.md)'s noun queries, so `median of xs` keeps its accepted
  `SyntaxError("Unexpected keyword 'of'")`, which `tests/noun_queries.rs`
  pins. Rejected: a global `median(...)`, `Math.median` and a `mid` alias.
  They would add names beside the list query, while `median` and `mid` are
  common names of user functions and bindings, which keep their meaning.
- **The receiver is never sorted.** Unlike `sort`, which writes a writable
  receiver back, `median` sorts a private list of the converted numbers, so a
  declaration that uses it never changes the list it depends on.
- **Bounded cost.** The receiver and the arguments are evaluated once per
  call, the selector once per item, and each value is converted once. One
  list of numbers is sorted, in O(n log n) time and O(n) extra space, with no
  recursion. The call keeps its ordinary rendering in graph keys and `why`.
- **Not added.** `median of xs`, a global `median(...)`, `Math.median`,
  aliases, lower and upper medians, quantiles and percentiles, weighted
  medians, a `medianBy` that returns an item, NaN-skipping medians,
  property-name selectors such as `xs.median("total")` and default values for
  empty receivers.

## Specification

### Medians

- `RECEIVER.median()` returns the median of the receiver's items, and
  `RECEIVER.median(selector)` the median of `selector(item)` for every item.
  The values are converted to numbers and ordered ascending by a stable sort.
  With an odd number of values the result is the middle value itself; with an
  even number it is `(lower + upper) / 2` of the two middle values, in 64-bit
  floating point.
- The receiver is a list, however it is reached: a variable, a property, a
  call result such as `filter(...)`, `map(...)`, `slice(...)` or
  `concat(...)`, a range, a literal, a `.value` snapshot or a selected
  version. It may also be a class's instance list, named by the class or by a
  variable that holds the class, in population order; a range of one and
  `Name.list()` are lists.
- An empty receiver gives NaN. The result is a number, or undefined when any
  value is undefined.
- `median` never sorts or writes its receiver.

```
waits = [12, 3, 45]
typical = waits.median()
assert: [typical, waits, (why typical)[0].from], [12, [12, 3, 45], ["waits"]]
waits.push(7)
assert: typical, 9.5
waits.push(300)
assert: [typical, waits.average()], [12, 73.4]
```

```
class Listing(area, price):
    this.area = area
    this.price = price
def perMeter listing => listing.price / listing.area
Listing(50, 200000)
loft = Listing(40, 400000)
typical = Listing.median(perMeter)
roomy = Listing.filter(listing -> listing.area > 45).median(perMeter)
recent = Listing[-3:].median(listing -> listing.area)
assert: [typical, roomy, recent], [7000, 4000, 45]
Listing(80, 72000)
assert: [typical, roomy, recent], [4000, 2450, 50]
```

### Numeric order

- Values are ordered as numbers: negative numbers, decimals and numbers of
  different digit counts take their numeric places, so
  `[21, 9, -3, 7.5].median()` is `8.25`, where `sort()` without a comparator
  would order the same values as text.
- Values that compare equal keep their receiver order. Only `0` and `-0`
  compare equal while differing, so `[0, -0, 1].median()` is `-0` while
  `[-0, 0, 1].median()` is `0`, and `[-0, 0].median()` is `0`.
- An even count applies `(lower + upper) / 2` literally, so
  `[-0, -0].median()` is `-0`, where `[-0, -0].average()` is `0`. For every
  other pair of values the median of two is what their `average()` gives.

```
north = [21, 9]
south = [-3, 7.5]
middle = north.concat(south).median()
warm = north.filter(temp -> temp > 0).median()
assert: [middle, warm], [8.25, 15]
north.push(-8)
assert: [middle, warm, north], [7.5, 15, [21, 9, -8]]
```

### Conversion and special values

- Each value, an item or a selector result, is converted with the numeric
  conversion of `-`, `*`, the Math helpers, `sum` and `average`: a number is
  itself; `null`, `false`, an empty or whitespace-only string and an empty
  list are `0`; `true` is `1`; a numeric string, after trimming, is its
  number; a one-item list is its item's number; a date is its time in
  milliseconds; objects, instances, classes, functions, regular expressions,
  other strings and longer lists are NaN.
- A value that converts to NaN makes the median NaN.
- Infinities take their places in the order. An even count follows 64-bit
  floating point, so `[1e308, 1e308].median()` is `Infinity` and
  `-Infinity` beside `Infinity` gives NaN; an odd count returns the middle
  value unchanged.
- An undefined value makes the median undefined, which a declaration stores
  as `null`. Every item is still visited.
- An undefined value wins over a NaN value: when both occur, in either order
  and whether they are items or selector results, the median is undefined,
  as the average is.
- `median()` reads items, not bindings: a `null` item counts `0` without
  settling a declaration to `null`. Reads inside a selector follow the
  existing rules, so a selector that reads a `null` binding or property
  settles a declaration to `null`.

```
flags = [true, false, true]
share = flags.median()
entries = [2, "3", " 4 ", "", null, [5], []]
mid = entries.median()
assert: [share, mid], [1, 2]
entries.push("x")
assert: Number.isNaN(mid), true
assert: 1 / [0, -0, -0].median(), Number.NEGATIVE_INFINITY
assert: [1e308, 1.5e308, 1].median(), 1e308
assert: [1e308, 1e308].median(), Number.POSITIVE_INFINITY
```

### Selectors

- A selector is called once for every item, in order, with the item as its
  only argument; further parameters are `null`. The call order and the
  argument are those of `map`, `sum` and `average`.
- A supplied first argument that is not a function, including `null`, raises
  `TypeError("median expects a function")`, even on an empty receiver.
- Every supplied argument, including unused extras, is evaluated once, left
  to right, after the receiver and before the first selector call.
- A null or undefined receiver keeps the existing method-call route: the call
  yields undefined without evaluating its arguments.

```
seen = []
def weigh(item, position):
    seen.push(position ?? item)
    return item * item
items = [4, 1]
def spread() => items.median(weigh)
assert: [spread(), seen], [8.5, [4, 1]]
floor = 2
def price item => Math.max(item, floor)
cost = items.median(price)
assert: cost, 3
floor = 3
items.push(12)
assert: [cost, spread(), seen], [4, 16, [4, 1, 4, 1, 12]]
missing = null
skipped = missing.median(weigh(9))
assert: [skipped, seen], [null, [4, 1, 4, 1, 12]]
```

### Liveness and transactions

- `median` never writes its receiver. A declaration that uses it depends on
  the list or the population, on its argument expressions and on whatever the
  selector reads, as for `sum` and `average`.
- Pushing, popping, shifting or replacing a list, creating or deleting an
  instance, and changing a property that a selector reads re-evaluate the
  declaration.
- In a class-level rule, each instance evaluates its own median, and
  `$Class` inside a filter or a selector is the instance the rule is
  evaluated for.
- Selector errors propagate through the existing transaction, so a failed
  standing re-evaluation rolls back the change that triggered it, including
  a list write or a new instance. A `suppose` block sees the hypothetical
  median and restores the accepted one when it ends.

```
class Room(name): this.name = name
class Sensor(room, temp):
    this.room = room
    this.temp = temp
$Room.mid = Sensor.filter(sensor -> sensor.room == $Room).median(sensor -> sensor.temp)
$Room.warm = $Room.mid > 21
lab = Room("lab")
hall = Room("hall")
Sensor(lab, 8)
probe = Sensor(lab, 25)
Sensor(lab, 30)
Sensor(hall, 18)
Sensor(hall, 23)
spread = Room.median(room -> room.mid)
assert: [lab.mid, lab.warm, hall.mid, hall.warm, spread], [25, true, 20.5, false, 22.75]
probe.temp = 21
assert: [lab.mid, lab.warm, spread], [21, false, 20.75]
probe.room = hall
assert: [lab.mid, hall.mid], [19, 21]
```

### Rendering

- The call keeps its ordinary rendering. `typical = waits.median()` renders
  as `typical = waits.median()` in `why`, and `why` lists the receiver in the
  declaration's `from` list. A lambda selector renders as `function()`, as in
  `typical = Order.median(function())`, and a property selector as written,
  as in `picked = Order.median(.amount)`.
- Graph and block keys use the same form: `if temps.median() > 20:` is the
  standing condition `if(temps.median()>20)`.
- Errors that quote an expression quote the call: `temps.median()(1)` raises
  `TypeError("temps.median() is not a function")`,
  `all t in temps.median(): t` raises
  `TypeError("temps.median() is not a collection")`, and
  `why temps.median()` keeps raising
  `TypeError("Cannot explain temps.median()")`.
- An accepted spelling of the same median renders differently, so the two
  are different graph keys, as `sum of xs` and `xs.sum()` are.

### Compatibility

- Parsing, the syntax tree, canonical rendering and graph keys are unchanged;
  `median` stays an ordinary method name. Only inputs that were errors at the
  accepted revision change.
- Every accepted case keeps its source, assertions, expected return and
  executed coverage. At the accepted revision the word occurs only in NUC 80's
  list of what it did not add; no accepted case, test, dataset record or ARC
  file uses the name `median`.

## Reference Implementation

- `src/lang/ast/array.rs`: `list_query`, the read-only query shared by lists
  and class instance lists, sends `median` to `aggregate_items` beside `sum`
  and `average`. After the existing `optional_selector` validates the
  selector with the message format `<query> expects a function`,
  `aggregate_items` collects the values with the existing `select_items`,
  which calls the selector once per item in order, and passes them to the new
  private function `median_value`. It returns undefined if any value is
  undefined, then NaN if any converted value is NaN; otherwise it sorts the
