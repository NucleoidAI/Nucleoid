## Abstract

- Adds an optional final `...name` formal to explicitly parenthesized
  user-defined signatures.
- Binds surplus positional arguments, in source order, to a fresh List;
  no surplus values produce `[]`.
- Reuses fixed/default binding for functions, methods, function Values,
  explicit constructors, adopted `init` signatures and `super`.
- Preserves all accepted fixed-only syntax, AST Debug/display, canonical
  graph keys, diagnostics and behavior, including runtime-failing inputs.
- Adds no call-site spread, bare rest signatures, closures, keywords,
  dependencies, project version change or built-in calling convention.
- Accepted after independent policy evaluation and the caller's integrated
  hard-criteria recheck; no policy check failed.

## Motivation

- A user-defined operation may need any number of positional operands:
  measurements, records, events or items to collect.
- Accepted calls evaluate surplus arguments but cannot bind a variable
  number of those values. Passing one explicit list changes the calling
  convention instead of providing variadic positional binding.
- A final rest list makes that binding available without changing fixed
  arguments or making callers construct wrapper lists.

## Rationale

- **Confirmed category.** The caller made one unbiased `Get-Random` draw
  over NUC 1's five eligible categories and selected zero-based index 1,
  Runtime features. New core argument-binding semantics fit that category;
  this worker has not redrawn or changed it.
- **Preserved mode.** The caller's invocation is continuous. This worker
  prepares exactly this one revision; continuation belongs to the caller.
- **Runtime applicability.** `new_feature`: accepted binding takes one
  supplied value per fixed formal and ignores surplus values after evaluating
  them. It has no variadic binder. Passing a list explicitly is not a
  behavior-equivalent counterpart with the same calling convention.
- **Accepted evidence.** At accepted revision
  `0ceace07bbb977740e9a7be4f2ffed5d6e18bc3e`,
  `def collect(head, ...tail) => [head, tail]` followed by
  `collect(1, 2, 3)` exits 1 with
  `SyntaxError: Expected a parameter but found '.' (line 1, column 20)`.
  The caller preserved this in external `nuc-0074-accepted-probe.log`.
  Inspection of the accepted invocation and constructor loops independently
  confirms the missing variadic binding.
- **Token policy.** Continuous Runtime features with `new_feature` skips
  token comparison entirely as `new_runtime_feature`. This is not a
  measured zero-case comparison or a passing token gate. The immutable
  accepted corpus, behavior/integrity, compatibility and development checks
  remain mandatory; no before-counts or extra baselines are invented.
- **Minimal syntax.** Recognize three adjacent existing Dot tokens only in
  the parenthesized formal parser. Do not globally retokenize dots or
  alter bare-header lookahead, lambdas, expressions or call parsing.
- **Constructor labels.** Labels continue to name fixed slots, not the
  collected list. Named-only calls therefore get an empty rest list.
  Reject naming a rest formal before any argument values run, rather than
  choosing between nesting an explicit list, flattening it or dropping it.
  Valid mixed calls retain the existing leading-positional/fixed-label
  convention.
- **Distinct rest name.** A rest name may not duplicate a fixed name.
  Otherwise a later declaration would overwrite that fixed slot and its
  initial history instead of giving the rest list its own version zero.
  Duplicate fixed names retain their accepted semantics.
- **Not added.** Rest defaults, multiple/nonfinal rest formals, destructured
  formals, call-site spread, rest-specific arity/type enforcement, closures,
  deep-copy semantics and receiver/callback argument changes are out of scope.
- **Optional evidence.** No hint or rubric was supplied. Advisory scoring is
  unconfigured (`missing_rubric`), not zero. Strategy learning is
  `not_configured`; this revision is explicitly unattributed, without a
  policy, receipt, trial, selected strategy, assessment or learner update.

## Specification

- The authoritative contract is
  [Final rest parameters](../nucleoid.spec.md#final-rest-parameters).

### Signatures and fixed binding

- Allow `...name` or `...name: Type` at the end of an explicitly
  parenthesized user signature, with the existing optional trailing comma.
  The dots must be adjacent; ordinary spacing before the name is permitted.
- The same parser serves named block/arrow functions, anonymous
  `function(...)` expressions, parenthesized arrows with either arrow
  spelling/body form, methods, explicit class headers and adopted `init`.
- Require at most one final rest formal, no rest default, and a rest name
  distinct from fixed names. Keep the existing ordinary-identifier and
  single-identifier annotation grammar; annotations remain non-enforcing.
- Bind the fixed prefix without change: missing positions/constructor keys
  use scalar defaults or Null, required slots may follow defaults, supplied
  Null/Undefined/falsy values remain supplied, and duplicate fixed names
  keep their existing local history/overwrite behavior.
- Collect all remaining positional values in order into a fresh outer
  `Value::List`. Bind `[]` if none remain, even for a rest-only signature.
  A supplied list is one element, not flattened. Contained Objects retain
  ordinary identity; this does not add a deep snapshot.
- Declare the complete effective value once so the rest slot's first
  history entry is that list, never a synthetic Null or a sequence of
  element writes.

```
def collect(head = 1, ...tail) => [head, tail]
empty = collect()
many = collect(2, 3, 4)
assert(empty, [1, []])
assert(many, [2, [3, 4]])
```

### Calls, receivers and constructors

- Evaluate supplied arguments once, left to right, per actual invocation.
  Existing propagation and list-valued assignment settlement may perform
  further invocations; rest binding does not change those boundaries.
- Ordinary, aliased, callback, callable-property/list-item, returned and
  stored Function Values share invocation binding. Higher-order helpers
  still pass only their existing arguments. A method captures its receiver
  at the accepted point; that receiver is not a positional argument.
- Function/method argument assignments remain positional expressions.
  This adds no named function arguments and changes no built-in dispatch.
- Constructor labels bind only fixed formals. Missing fixed keys retain
  default/Null behavior, while a named-only call binds an empty rest list.
  Mixed calls first fill the leading fixed positions, then remaining fixed
  labels; positional extras are collected only after the fixed prefix is
  filled. No positional argument may follow a label.
- Validate unknown/duplicate labels, positional-after-named arguments and
  a label targeting the rest formal before evaluating any argument values.
  Preserve every existing label diagnostic except for the newly introduced
  named-rest rejection.
- Keep raw positional extras until the shared formal binder builds the
  list once. A named constructor's prepared values represent fixed holes
  followed by raw extras, never an already-wrapped rest list.
- Keep effective-constructor selection and `init` adoption unchanged.
  Bodyless headers do not create fields; a bodyless rest header may still
  defer to the nearest inherited nonempty constructor, whose signature
  determines labels and binding.
- Pure positional constructors still select their signature/body after
  argument evaluation; labeled calls pin them before evaluation.
  `super` uses the selected parent and same receiver under these existing
  timing rules, including invocation from methods.

### Scope, identity, reactivity and rollback

- Initialize rest in the same fresh Scope frame as the fixed formals.
  It shadows state, is not a graph node, and does not capture an enclosing
  function's locals. Mutating a local rest list leaves caller list bindings
  unchanged, subject to normal contained-Object identity.
- Local histories and nontransactional locals are unchanged. A caught
  failure can retain a mutation to a parameter in an enclosing local
  frame while State and graph writes roll back.
- Ordinary reads/dependencies and `.value` snapshots/settlement are
  unchanged. Each standing re-evaluation creates a new invocation frame.
  Rest binding neither freezes external reads nor changes nullish/deferred
  value handling.
- Live named callers observe a redefinition. Frozen and historical
  Function Values retain their captured signature/body, including rest
  metadata, while their ordinary external reads remain live.
- Failed updates restore Function identities, class/method metadata,
  instances, State histories and graph dependencies through existing
  transaction rollback. No new transaction or closure mechanism is added.
- Keep every accepted fixed-only signature, bare invalid form and
  diagnostic intact. Omit false rest metadata from AST Debug and retain
  every old display/generator branch byte-for-byte; only rest-bearing
  declarations need the new complete signature rendering.

## Errors

- A formal after the rest formal, including a second rest formal, raises
  `SyntaxError("Rest parameter must be last")`.
- `=` after a rest formal raises
  `SyntaxError("Rest parameter cannot have a default")`, without evaluating
  or parsing a default expression.
- A rest name already used by a fixed formal raises
  `SyntaxError("Rest parameter '<name>' duplicates a fixed parameter")`.
- Naming the rest formal in a constructor call raises
  `TypeError("Rest parameter '<name>' cannot be a named constructor argument for <class>")`;
  `<class>` is the selected effective constructor's class.
- Missing/invalid names and annotations keep the parameter parser's
  `Expected a parameter but found <token>` and
  `Expected a type but found <token>` SyntaxErrors. Separated dots are not
  a rest marker and retain the ordinary parameter diagnostic.
- Constructor unknown/duplicate/positional-after-named diagnostics,
  argument/body errors, and every fixed-only diagnostic remain unchanged.
  This introduces no error kind.

  `parameter.rs` conditionally displays/debugs rest metadata and shares one
  effective fixed/rest value binder between invocation and construction.

  new rest restrictions. Bare parser paths initialize `rest: false`;
  `lexer.rs` is unchanged.

  iterator of supplied values. `src/nuc/object.rs` retains constructor
  timing and labels, reserving absent keys for fixed slots and leaving raw

  renders default-bearing ones. All old Debug/display and graph-label
