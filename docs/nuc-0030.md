# NUC 30 -- Bare Typed Multiple-Parameter Indented Blocks

```
NUC: 30
Title: Bare Typed Multiple-Parameter Indented Blocks
Author: Copilot <223556219+Copilot@users.noreply.github.com>
Status: Accepted
Type: Standards Track
Created: 15-Oct-2026
Requires: 24, 28, 29
```

## Abstract

- Named block definitions may optionally omit parentheses around two or more ordinary identifier parameters with existing optional ordinary-identifier annotations.
- `def add left: int, right: int:` with a real indented body is exactly `def add(left: int, right: int):` with that same body, including methods and `init`.
- Mixed headers such as `def add left: int, right:` preserve the complete named block, ordered parameter metadata and behavior of the parenthesized form.
- At least one annotation identifies the new forms; entirely untyped multiple lists remain accepted NUC28 behavior.
- Preserve every accepted spelling and introduce no type grammar, type enforcement or runtime feature.

## Motivation

- Multiple-input block definitions can retain annotations without two parameter delimiter tokens.
- Complete the optional block spelling alongside accepted NUC24 single typed blocks, NUC28 untyped multiple blocks and NUC29 typed/mixed multiple arrows.
- Prepare exactly the caller-selected syntax improvement, retaining its original category draw and only accepted dependencies.

## Rationale

- Recognize a complete immediate header before consuming any parameter or layout token.
- Extend the shared linear allocation-free scanner instead of duplicating annotation grammar or changing lexer/public AST/runtime types.
- An annotation no longer excludes a complete multiple-parameter list from the real-indented block path; NUC29's arrow behavior remains intact.
- Keep a final untyped parameter's suite colon out of `parameter()` while retaining that parser's strict annotation errors everywhere else.
- Preserve the exact single typed/untyped guards and leave body layout to the unchanged suite parser.
- Exclude inline/braced bare multiple suites, logical header breaks, trailing bare commas, defaults, rest, destructuring, return annotations and richer type grammar.
- Keep flat lists uncapped without confusing parameter count with expression-chain limits.
- Retain representative parenthesized alternatives in the specification, current reference and tests; do not revise earlier accepted NUC documents.

## Specification

### Grammar and lowering

- The authoritative [bare typed multiple-parameter indented block definitions](../nucleoid.spec.md#bare-typed-multiple-parameter-indented-block-definitions) section governs the accepted implementation.
- Parse `def` and its required ordinary definition name exactly as before.
- Recognize the complete immediate token sequence `Identifier (Colon Identifier)? (Comma Identifier (Colon Identifier)?)+ Colon`.
- Require at least two ordinary parameter identifiers, with at least one annotation describing this addition; all-untyped lists retain NUC28 behavior.
- Every comma immediately needs another parameter, with no trailing bare comma.
- Each annotation is exactly the existing `Colon Identifier` metadata; arbitrary undeclared ordinary names remain legal without lookup, dependency or runtime checking.
- Look ahead without consumption, AST cloning, parameter-name allocation or skipping logical `Newline`, `Semicolon`, `Indent`, `Dedent` or comment-induced header breaks.
- Preserve every NUC29 typed/mixed arrow through the same shared scan.
- Immediately after the suite colon require `Newline` or `Indent`, then a real `Indent` after only normal `Newline`/`Semicolon` layout.
- A colon immediately followed by `Semicolon` never qualifies, even when indentation follows later.
- Blank/comment lines and normal body layout remain the existing `suite()` parser's responsibility.
- After qualification, consume names, optional annotations and commas in order, reusing `parameter()` where applicable.
- For a final untyped parameter, its following colon belongs to the suite, not annotation parsing.
- A final typed parameter instead has its annotation `Colon Identifier` and a separate suite `Colon`.
- Leave the final suite colon and every layout/body token for unchanged `suite()`; do not globally relax `parameter()`.
- Preserve ordered `Parameter { name, type_name }` metadata, the complete named `FunctionBody::Block`, full AST and canonical rendering of the parenthesized definition.
- Failed complete lookahead consumes nothing and falls back to the unchanged single guards or parenthesized parameter parser.

### Behavior and compatibility

- Multiple statements, local assignments, branches, nested definitions and ordinary inner inline/braced statements retain their existing block grammar.
- Explicit returns, bare returns and bodies with no return retain their behavior; the latter two yield `null`, never an implicit final-expression return.
- Missing/null/extra/string arguments and local shadowing retain accepted bindings with unchecked annotation metadata.
- A null callable parameter retains deferred `null`; a non-callable parameter still shadows an outer function and raises the existing error.
- Noncapturing scopes and inherited parameter-dependent local/nested propagation failures remain unchanged, not repaired by the spelling.
- Methods, `init`, `this`/`self`, explicit and bare `super`, initializer adoption, property mutation and instance identity retain parenthesized behavior.
- Reactive arguments and body inputs, live aliases, `.value` definition snapshots, redefinition, graph IDs/dependencies, reasoning, transactions, caught values and rollback are unchanged.
- Preserve NUC24's exact single typed block guard, NUC28 untyped multiple blocks, NUC29 typed/mixed multiple arrows and every other accepted single/multiple form.
- Preserve all parenthesized typed/untyped/mixed, nullary, multiline, trailing-comma, indented, inline and braced alternatives.
- Calls, anonymous functions, class parameter lists, ordinary identifier references and keyword meanings retain their existing grammar.
- Add no bare multiple inline/braced or missing-indent suites, trailing bare commas, defaults, rest, destructuring, return annotations, new type syntax or call syntax.
- Flat typed/mixed lists remain uncapped through 1,024 parameters; existing body nesting, operator and postfix limits remain in force.
- Introduce no lexer, public AST, runtime, generator, API, dependency, MSRV or project-version change.
- Append only the eight caller-supplied pre-executed counterparts: five specification cases and one each for executable reference, README and examples.
- Preserve all 475 historical case identities and ordering, ordered canonical assertions, expected returns and executed assertion coverage.
- Keep the final measured corpus at 328 specification, 66 reference, 17 README and 72 examples cases: 483 total.
- Rewrite only eligible typed/mixed multiple-parameter block headers; keep all assertion and body text intact.
- Keep current reference boundaries and generated normative exports synchronized; preserve all 1,081 synthesized records' IDs, order, fields, descriptions, assertions/results and ARC annotations.
- No existing synthesized record has an eligible typed/mixed multiple block header, so those canonical sources remain unchanged rather than receiving artificial records or unrelated rewrites.

```nuc
def add left: int, right: int:
    total = left + right
    return total
def scaled left: number, right, factor: number:
    return (left + right) * factor
def largest left, right: number:
    if left > right:
        return left
    return right
assert(add(2, 3), 5)
assert(scaled(2, 3, 4), 20)
assert(largest(7, 3), 7)
assert(largest(2, 9), 9)
```

## Errors

- Introduce no new error kind or message; nonqualifying tokenizable prefixes fall through untouched.
- The normative typed multiple-block boundary section gives the exact syntax, lexical, body and runtime rules below.
- A final untyped parameter followed by a real suite colon is valid, not a missing annotation.

| Exact input or condition | Exact error | Position |
| --- | --- | --- |
| `def f left: int, right:` at EOF, with no real indent, with only comments, with inline/braced body or immediate `:;` | `SyntaxError("Expected '(' but found identifier 'left'")` | line 1, column 7 |
| Trailing bare commas, missing names/types, unsupported type/parameter grammar, return annotations or logical header breaks beginning `def f left` | `SyntaxError("Expected '(' but found identifier 'left'")` | line 1, column 7 |
| `def f this: int, right:` with an indented body | `SyntaxError("Expected '(' but found keyword 'this'")` | line 1, column 7 |
| Logical newline immediately after `def f` | `SyntaxError("Expected '(' but found end of line")` | line 1, column 5 |
| Semicolon immediately after `def f` | `SyntaxError("Expected '(' but found ';'")` | line 1, column 6 |
| Four-space-indented `def reading left: int, right,:` after `class Gauge:` and a newline | `SyntaxError("Expected '(' but found identifier 'left'")` | line 2, column 17 |
| `def f(left: int, right:):` | `SyntaxError("Expected a type but found ')'")` | line 1, column 25 |
| `def f(a:):` | `SyntaxError("Expected a type but found ')'")` | line 1, column 10 |
| `def f left: int \| str, right:` | `SyntaxError("Unexpected character '\|'")` | line 1, column 17 |
| `def f left: int?, right:` | `SyntaxError("Unexpected character '?'")` | line 1, column 16 |
| Qualifying header followed by four-space-indented `return left +)` | `SyntaxError("Unexpected ')'")` | line 2, column 19 |
| Qualifying header followed by four-space-indented `return { left = 1 }` | `SyntaxError("Expected ':' but found '='")` | line 2, column 19 |
| Qualifying header followed by four-space-indented `return @` | `SyntaxError("Unexpected character '@'")` | line 2, column 12 |
| Evaluated body/object read of undefined `missing` | `ReferenceError("missing is not defined")` | existing top-level statement position |
| Returned anonymous function reads uncaptured `left` | `ReferenceError("left is not defined")` | existing top-level statement position |
| Unbound `this` or `self` | `ReferenceError("this is not defined")` | existing top-level statement position |
| Non-callable `operation` shadows an outer function | `TypeError("operation is not a function")` | existing top-level statement position |
| Excessive body expression nesting | `SyntaxError("Expressions are nested too deeply")` | existing expression position |
| Excessive body operator chain | `SyntaxError("Expression has too many operands")` | existing expression position |
| Excessive body postfix chain | `SyntaxError("Expression has too many parts")` | existing expression position |

- Lexical failures still precede parsing; body-line and unsupported-prefix positions remain unchanged.
- Removing parentheses can shift later columns on the same physical header line, not body-line positions.
- Caught error values omit positions as before; null callable deferral does not execute a TypeError catch.
- Inherited parameter-dependent local/nested failures retain the accepted error and rollback rather than gaining capture.

## Reference Implementation

- The accepted implementation changes only private header scanning and parameter-list consumption in [`src/lang/ast/parser.rs`](../src/lang/ast/parser.rs).
- The shared scanner accepts optional ordinary annotations before either the existing arrow or a suite colon after at least two parameters.
- The block guard still requires real indentation; its final untyped parameter is consumed without treating the suite colon as an annotation.
- All other parameters reuse unchanged `parameter()`; single guards, `suite()`, named block construction, lexer/public AST/runtime/generator/API and bounds remain unchanged.
- [`tests/bare_typed_multiple_indented_blocks.rs`](../tests/bare_typed_multiple_indented_blocks.rs) checks full metadata/AST/canonical equality, every annotation position, final typed/untyped colons, layout, exact prefix/body diagnostics and positions, legacy forms and flat lists through 1,024.
- Distinct runtime pairs use the new typed/mixed block headers and explicitly reject identical pair inputs.
- Runtime regressions cover local/multiple/branching/nested bodies, explicit/bare/no returns, binding/null/non-callables, methods/init/receivers/explicit and bare super/adoption, objects/templates/noncapture, reactive arguments/body inputs, aliases/snapshots/graphs/reasoning, redefinition/rollback, inherited failures and CLI recovery.
- Existing negative suites and the affected CLI fixture retain error strength/positions using still-invalid same-prefix trailing-comma variants; former valid-under-NUC30 inputs gain positive pairs.
- Ordinary tests depend on neither Git nor session artifacts.
- Two history/training audits are explicitly `#[ignore]`; they require Git and accepted revision `c007624a00d1f7d949de3bb1e2c109c53b6f36a4` and fail on missing prerequisites rather than silently skipping.
- Run them explicitly with `cargo +stable-x86_64-pc-windows-gnu test --locked --target x86_64-pc-windows-gnu --test bare_typed_multiple_indented_blocks -- --ignored`.
- The NUC30 corpus audit protects its checked prefix of 475 historical complete ASTs and eight own appended counterparts, totaling 1,835 ordered protected assertions; later proposals' appended cases remain outside this historical audit.
- The corresponding NUC29 audit protects its own 467 historical cases and eight additions, totaling 1,796 ordered protected assertions, without inventing later-proposal counts.
- Both integration modules borrow checked historical/addition slices, fail explicitly on any missing protected prefix, and have ordinary in-memory regressions covering later tails and every shorter prefix.
- These bounded historical audits leave the full current 483-case identity/order, assertion, expected-return, executed-coverage, proposal-gate and generated-export safeguards intact; the shared harness is unchanged.
- The training audit protects every synthesized record and ARC annotations.
- Normative JSONL/Rust exports are regenerated from their source documents; synthesized records and ARC remain unchanged, with no Markdown mirrors.
- The caller's sole Rust improvement pass changed only the two typed multiple-parameter integration modules' prefix selection and associated ordinary regressions, preserved in the independently evaluated revision 2.
