## Abstract

- Adds the exponentiation operator `base ** exponent` and its compound
  assignment `target **= exponent`. Each is one lexer token.
- `a ** b` yields exactly the value of the accepted `Math.pow(a, b)` for every
  pair of operands, including its coercions, NaN, infinities and signed zeros.
  It does not read the name `Math`.
- `**` binds tighter than `*`, `/` and `%` and is right-associative:
  `2 ** 3 ** 2` is `512`. Prefix operators follow Python: `-x ** 2` is
  `-(x ** 2)`, and `2 ** -1` is `0.5`.
- `target **= exponent` is an optional spelling of
  `target = target ** (exponent)` under every rule of
  [NUC 13](nuc-0013.md)'s compound arithmetic assignment.
- A declaration that uses `**` follows the existing arithmetic rules for
  dependencies, null settling, `.value` freezing, class-level rules,
  reasoning and transactions.
- No accepted program changes meaning. Outside strings, comments, template
  text and regular expressions, adjacent `**` or `**=` was always a syntax
  error, except in the trailing tokens of a template interpolation, which are
  still ignored.
- The authoritative contract is the
  [exponentiation](../nucleoid.spec.md#exponentiation) section.

## Motivation

- World models compute areas, volumes, growth, decay, energy and distances.
  Powers appear in each: `side ** 3`, `100 * (1 + rate) ** years`,
  `0.5 * mass * speed ** 2`, `(dx ** 2 + dy ** 2) ** 0.5`.
- The accepted spelling `Math.pow(base, exponent)` spends six tokens around
  its operands, `Math`, `.`, `pow`, `(`, `,` and `)`, where `**` spends one.
- Repeated multiplication repeats the base: `$Tank.side * $Tank.side *
  $Tank.side` costs 11 tokens where `$Tank.side ** 3` costs 5. `Math.sqrt`
  and `Math.exp2` cover only the exponent `0.5` and the base `2`, and no
  accepted spelling handles a variable exponent without a call.
- `**` and `**=` are the spelling of Python and JavaScript, and of
  TypeScript, Ruby and Fortran. LLMs write them readily, and a formula such as
  `principal * (1 + rate) ** years` reads as it does in a textbook.

## Rationale

- **Category and mode.** The caller selected the Syntax enhancement category
  by one uniform draw over the four eligible registry categories, index 0
  with probability 1/4 and no redraw, in continuous mode, so the token
  non-regression gate applies. Each new case is paired with the most compact
  accepted-syntax counterpart found, recorded in the evaluation baseline.
- **Exactly `Math.pow`.** The operator converts both operands with the
  existing `to_number` and calls the same host `powf` as `Math.pow`, after
  the same rule that an undefined operand makes the result undefined. A unit
  test compares the bits of both for all 91,204 ordered pairs of a 302-value
  matrix that covers every value kind, signed zeros, subnormals, infinities,
  NaN and 256 pseudo-random numbers.
- Rejected: lowering `a ** b` to the call `Math.pow(a, b)`. The call reads
  the name `Math`, so a variable named `Math` would change or break the
  operator, and the call would render as `Math.pow(a,b)`. A new
  `BinaryOp::Power` keeps the operator independent of names and gives it its
  own rendering.
- **Not reading `Math` is intentional.** After `Math = 1`,
  `Math.pow(2, 3)` raises `TypeError("number.pow is not a function")` as it
  did before, while `2 ** 3` stays `8`.
- **Prefix operators follow Python.** Python, Ruby, Fortran and mathematical
  notation read `-x²` as `-(x²)`. JavaScript rejects the unparenthesized
  `-2 ** 2` as ambiguous, so no valid JavaScript program changes meaning
  under the Python reading, and every Python program keeps its own. That makes
  Nucleoid a superset of both.
- Rejected: JavaScript's error, which would reject valid Python and require
  parentheses where mathematics needs none. Rejected: binding prefix
  operators tighter than `**`, as spreadsheets do, which makes `-x ** 2`
  positive for every `x`.
- One rule covers every prefix operator: `-`, `+`, `!`, `not`, `typeof`,
  `delete` and prefix reasoning stages such as `why` apply to the whole power
  that follows them. `new` is part of a primary in the accepted grammar and
  has no runtime effect, `new Shape(2)` being `Shape(2)`, so it stays with
  its operand.
- The exponent is a unary operand, so `2 ** -1`, `2 ** -x` and
  `2 ** not flag` need no parentheses, as in Python and JavaScript.
- **Right associativity** follows mathematics, Python and JavaScript:
  `a ** b ** c` is `a ** (b ** c)`.
- **The existing nesting budget.** Each `**` parses its exponent as a nested
  unary expression, so a chain takes one level of the existing 64-level
  budget per operator, as prefix chains and conditional alternates do.
  Rejected: a separate 128-operand loop like the left-associative operators
  use, since 61 powers in one chain exceed any real formula.
- **`**=` joins NUC 13's family** as `CompoundOp::Arithmetic(BinaryOp::Power)`
  and shares its target validation, bound and lowering; no assignment path is
  added.
- **Grouped rendering.** [NUC 59](nuc-0059.md), [NUC 60](nuc-0060.md) and
  [NUC 62](nuc-0062.md) render their nodes so that graph keys and `rule`
  text stay distinct and read back as the same expression. `**` parenthesizes
  only the operands that would otherwise read back differently: `(-x)**2`
  against `-x**2`, `(x**2)**3` against `x**2**3`, and `x**(a+b)`.
  Rejected: the unparenthesized rendering of the other binary operators,
  which would render `(-x) ** 2` and `-(x ** 2)` identically as `-x**2`.
  Rejected: always grouping the whole power, which renders `(-x) ** 2` as
  `(-x**2)`, a text that reads back as `-(x ** 2)`, and adds parentheses to
  `side**2`.
- **Existing `Math.pow` cases are kept.** Three accepted cases use
  `Math.pow(a, 2)` incidentally, and rewriting their operand line would save
  five tokens each. Six accepted suites seal the title, source and return
  bytes of every historical case: `comma_free_object_properties`,
  `direct_conditional_alternatives`, `flat_map`, `math_remap`, `replace_all`
  and `string_iteration`. Rewriting a historical case would require changing
  those protected tests, so this revision leaves every accepted case
  byte-identical. `assert(Math.pow(2, 10), 1024)` in the executable reference
  tests `Math.pow` itself and also stays.
- **Not added.** Integer division `//`, `in` and `not in`, comprehensions,
  destructuring, Python's `**kwargs`, `^` as a power operator, and any change
  to `Math.pow`.

## Specification

### Syntax

- `**` and `**=` are single lexer tokens, matched longest first: `* *` stays
  two tokens, `***` is `**` followed by `*`, `**==` is `**=` followed by `=`,
  and `***=` is `**` followed by `*=`. The characters must be adjacent.
- Grammar, between the prefix operators and postfix expressions:

```
unary    := ("-" | "+" | "!" | "not" | "typeof") unary
          | STAGE unary
          | exponent
exponent := postfix ["**" unary]
```

- Member access, calls, subscripts and version selectors bind tighter than
  `**`; `**` binds tighter than `*`, `/` and `%`, and so than every binary
  operator, conditional expression, `??`, `|>` and assignment.
- A prefix operator written before a base applies to the whole power. The
  operand after `**` is a unary expression, so it may carry prefix operators
  and nests to the right.
- `delete` in expression position parses its operand as a unary expression,
  which now includes a power. `new` stays inside its primary.
- A `/` after `**` or `**=` starts a regular expression, as after `*`.
- Template interpolations parse `**` like any other expression; trailing
  tokens after a complete interpolated expression are still ignored.

```
tower = base ** exponent ** 2
grouped = (base ** exponent) ** 2
scaled = 3 * base ** exponent + 1
negated = -x ** n
grouped = (-x) ** n
inverse = x ** -n
```

### Semantics

- `a ** b` converts both operands with the conversion of `*`: `null`,
  `false`, the empty string and an empty list are `0`, `true` is `1`, a
  numeric string or a one-item list is that item's number, a date is its time
  in milliseconds, and objects, classes, regular expressions, functions,
  other strings and longer lists are NaN. It then returns the host `powf` of
  the two numbers, exactly as `Math.pow(a, b)` does.
- An undefined operand makes the result undefined, which a declaration stores
  as `null`.
- The left operand is evaluated before the right one, as `Math.pow` evaluates
  its arguments.
- `**` never reads the name `Math`.
- A declaration that uses `**` depends on what its operands read,
  re-evaluates when they change and replaces obsolete dependencies, as other
  arithmetic declarations do. A stored declaration whose evaluation read a null
  binding or property settles to `null`, as `y = x * 2` and
  `y = Math.pow(x, 2)` do with a null `x`; a literal `null` operand is `0`.
- `.value` operands are frozen when a declaration is stored.
- Class-level rules validate the names in both operands and take part in
  `TypeError("Circular Dependency")` checks when declared; each instance
  evaluates its own power.
- `why` and `affects` report a power declaration with the same nodes, values,
  states and supporting nodes as the `Math.pow` spelling; only its `rule` text
  differs, as in `y = x**n`.
- Errors propagate through the existing transaction, so a failed standing
  re-evaluation rolls back the change that triggered it.

```
base = "3"
power = 2
result = base ** power
literal = null ** power
assert(result, 9)
assert(literal, 0)
base = [2]
assert(result, 4)
base = true
power = 3
assert(result, 1)
base = 0
power = -1
assert(result, Number.POSITIVE_INFINITY)
assert(literal, Number.POSITIVE_INFINITY)
base = null
assert(result, null)
```

### Compound exponentiation

- `target **= exponent` lowers to `target = target ** (exponent)` with the
  existing assignment and binary nodes.
- Targets are names or plain dotted paths rooted in a name, `$Class`, `this`
  or `self`; a class or receiver root needs a property; at most 128 dotted
  links across grouped paths; computed targets raise
  `SyntaxError("Invalid compound assignment target")` before any cloning.
- It has assignment precedence and right associativity:
  `a **= b **= 2` is `a = a ** (b = b ** 2)`.
- A standing assignment keeps a relationship that re-evaluates with the
  target's current value when the exponent changes; class-level
  self-reference raises `TypeError("Circular Dependency")`.
- Locals, receivers, expression returns, rollback and the canonical expanded
  rendering `amount=amount**step` follow the expanded assignment.

```
value = 4
step = 2
value **= step
assert(value, 16)
step = 0.5
assert(value, 4)
```

### Canonical rendering

- `**` renders as `base**exponent`.
- A base is parenthesized when it is a prefix, binary, logical (other than
  `??`), assignment, `delete`, pipeline or function expression, or a negative
  number literal.
- An exponent is parenthesized when it is a binary expression other than
  `**`, or a logical (other than `??`), assignment, pipeline or function
  expression.
- Conditional expressions, `??` and quantifiers keep their own grouping.
- The text reads back as the same expression: `(-x)**3`, `-x**2`,
  `(x**2)**3`, `x**2**3`, `x**(1+1)`, `(2*x)**2`, `2*x**2` and `(x|>why)**2`.
- Compound assignments render expanded: `amount **= step + 1` renders
  `amount=amount**(step+1)`.
- `+`, `-`, `*`, `/`, `%`, comparisons and every other node keep their
  rendering.

### Compatibility

- **Token streams.** In the accepted grammar, `*` and `*=` must be followed
  by an operand, and neither can begin one. So adjacent `**` or `**=` outside
  strings, comments, template text and regular expressions made every accepted
  parse fail. The only exception is the ignored trailing tokens of a template
  interpolation. Every other token, including the decision whether a `/`
  starts a regular expression, lexes as before; the new lexer only merges
  `*` `*` into `**` and `*` `*=` into `**=`.
- **Template interpolations.** After `x = 3`, `` t = `${x y ** 2}` `` makes
  `t` equal to `"3"` at the accepted revision and under this NUC, because
  `y ** 2` is ignored trailing text in both. `` u = `${x ** 2}` `` raised
  `SyntaxError("Unexpected '*'")` at line 1, column 6 of the interpolation at
  the accepted revision and now makes `u` equal to `"9"`.
- **`parse_expression`.** The public Rust function returns
  `Expr::Binary { operator: BinaryOp::Power, .. }` for `2 ** 3`, where it
  returned `SyntaxError("Unexpected '*'")`. It still ignores trailing tokens:
  `x y ** 2` gives the name `x` in both versions.
- **Native REPL and terminal workspace.** Their header scans are token-based
  and treat `**` and `**=` as ordinary tokens. `if side ** 2 > limit`
  buffers as a colon-free header exactly as `if side * side > limit` does.
  `area = side ** 2`, `area **= 2`, `pattern = /x**y/` and `label = "2**8"`
  run at once, as before. Completion lists words, not operators, and is
  unchanged.
- **Accepted documents.** All 747 accepted cases keep their exact bytes,
  titles, canonical assertions, returns and token counts.
- **Public Rust API.** `Token` gains `Token::StarStar` and
  `Token::StarStarAssign`, and `BinaryOp` gains `BinaryOp::Power`. Neither
  enum is `#[non_exhaustive]`, so exhaustive downstream matches stop compiling.
  This needs a human SemVer decision; no project version is changed.
- These sources were syntax errors and now run or fail differently:

- The evaluator found these inaccuracies. The accepted text is unchanged,
  and they are recorded here:
  - `Requires` omits [NUC 62](nuc-0062.md), although the Rationale cites it
    for grouped rendering and the rendering rules cover quantifiers;
  - the specification's canonical-rendering bullet leaves function
    expressions out of its parenthesized lists, but the NUC and the code
    group them, as in `((a=1)=>a)**2`;
  - the Rationale calls `**=` Fortran's spelling too; Fortran has `**` but no
    `**=`;
  - "as before" for `area = side ** 2` and `area **= 2` in the REPL holds
    only for the buffering decision; both inputs raised `SyntaxError` at the
    accepted revision;
  - "all 747 accepted cases keep their exact bytes" holds for trimmed
    sources, tokens, assertions and returns, but in extraction the two
    previously last cases, `Nucleoid rolls back failed quantifier updates`
    and `Nucleoid states live facts with all and any`, lose their trailing
    newline before the appended `---`;
  - the coercion list says the empty string is 0, but whitespace-only
    strings are 0 as well.
