# NUC 164 -- Distances of Reasoning Selections

```
NUC: 164
Title: Distances of Reasoning Selections
Author: Can Mingir <canmingir@gmail.com>
Status: Draft
Type: Standards Track
Category: Reasoning enhancement
Created: 28-Nov-2026
Requires: 82, 112
```

## Abstract

- Add the final reasoning stage `SELECTION |> distances`. It returns one
  non-negative integer Number for every selected step, in selection order:
  the step's distance, the number of edges on the shortest dependency path
  by which the most recent walking stage reached it from that stage's
  input, as [NUC 82](nuc-0082.md)'s `depth` measures it. Steps that no walk
  produced are at distance 0, and the stages that keep their steps'
  distances keep them here too, so the stage lists exactly the values that
  `depth` filters by.
- `total |> why |> distances` says how far each step of the total's
  explanation lies from it: 0 for the total, 1 for what it reads directly,
  2 for what those read. `price |> affects |> distances` says how far a
  change of the price travels to each node it reaches.
- At the accepted revision `|> distances` raises the parse-time
  `TypeError("distances is not an operation")`, and only those programs
  change. `distances` stays an ordinary identifier: variables, parameters,
  properties, keys, functions and methods named `distances` keep their
  meanings, and a binding of that name shadows the stage as bindings shadow
  `depth`. No prefix or call form, keyword, token kind, record field or
  graph mutation is added.
- This continuous Reasoning enhancement requires the token comparison:
  each new case is paired with its accepted spelling, which reads the same
  distances through `depth` limits.

## Motivation

- Explanations come in layers: a conclusion rests directly on some facts
  and indirectly on others. [NUC 82](nuc-0082.md) made the layers
  selectable, since `c |> why |> depth(1)` keeps `c` and what it reads
  directly, but no stage says which layer a step lies in.
- At the accepted revision, with `price = 4`, `qty = 3`,
  `subtotal = price * qty`, `tax = subtotal / 10` and
  `total = subtotal + tax`, the explanation `total |> why` lists `total`,
  `subtotal`, `tax`, `price` and `qty`, and
  `total |> why |> depth(1) |> nodes` is `["total", "subtotal", "tax"]`.
  The distances `[0, 1, 1, 2, 2]` take one `depth` selection for every
  layer and a comparison of each step's node against those node lists,
  which also needs to know how deep the explanation goes, while
  `total |> why |> distances` raises
  `TypeError("distances is not an operation")`.
- `nodes`, `holds`, `edges` and `indegrees` project the steps' metadata.
  The distance is the one ranking that every walk already computes and
  that `depth` already filters by, and no stage projects it.
